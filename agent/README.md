# studio-agent

Windows-компонент проекта studio, исходники — `agent/` в общем репозитории.

Мост для Windows: держит канал к студии `https://studio.example.com` и отдаёт ей Claude Code, Codex и OpenCode этого
компьютера — проекты, чаты, ход с карточками разрешений, файлы, git. В студии это раздел «Код».
Работают установленные помощники с их аккаунтами, провайдерами и правилами разрешений.

**Codex (с 0.3.0).** Установите Codex CLI или расширение Codex в VS Code и войдите своим аккаунтом
(`codex login`). Мост находит `codex.exe` из PATH, установки npm или расширения и запускает локальный
[app-server](https://learn.chatgpt.com/docs/app-server) по stdio, без открытого порта и отдельного API-ключа.
Работают правила и настройки вашего Codex. В разделе «Код» студии выберите проект → «Новый чат Codex»
(или «+» → тот же пункт); чаты помечены именем помощника, список моделей приходит от установленного Codex.
«Да, для этой сессии» подтверждает разрешение в текущей сессии Codex; обычное «Да» — один запрос.
Файлы и git — общие для проекта. Лимит двух одновременных ходов общий для всех помощников.
Вход в студию и PIN компьютера остаются прежними. Обновлять нужно и студию, и мост; старый мост
поддерживает только Claude Code. Файл `codex-chats.json` в каталоге настроек связывает вкладки студии с
сессиями Codex — сохраняйте его вместе с настройками при переносе моста.

**OpenCode (с 0.5.0).** Установите OpenCode с поддержкой ACP (проверено на 2.2.4), настройте
провайдеры в нём и выберите **«+ OpenCode»** в проекте Studio. Модели и варианты усилия берутся
из установленного OpenCode; отдельный ключ Studio не нужен. История остаётся в OpenCode на машине.
«Правила OpenCode» сохраняют его разрешения, «Автоматически» подтверждает запрашиваемые действия,
сохраняя явные запреты CLI. Вопросы и разрешения показываются в чате; ход можно остановить.
Файл `opencode-chats.json` связывает вкладки Studio с сессиями OpenCode, а `opencode/choices.json`
хранит выбор модели, усилия и доступа — сохраняйте их при переносе моста. Скриншоты поддерживаются,
если выбранная модель умеет принимать изображения.

С 0.3.3 мост принимает скриншоты в чатах Claude Code и Codex: кнопка «Скриншот», вставка из буфера
или перетаскивание в студии. До 4 картинок PNG/JPEG/WebP/GIF, 5 МиБ на файл и 8 МиБ на сообщение;
текст необязателен. Изображение идёт в содержимое сообщения помощника, без временных файлов.
Обновите студию и мост; прежний мост картинки не принимает, текстовые задания продолжают работать.

## Установка

В 0.4.1 исправлено продолжение Codex-чата после показа настроек и контекста: чтение состояния
больше не удерживает сессию для записи. Обновление и перезапуск моста освобождают блокировку,
оставшуюся от версии 0.4.0. При действительно занятой другим процессом сессии показана её причина.

Версия 0.4.0 добавляет выбор прав доступа и показ фактических настроек/контекста в чате Studio.
Выбор прав в чате применяется к следующему ходу; настройки CLI без явного выбора сохраняются.
Для Codex в Studio доступен прямой Chrome DevTools MCP: нужен Node.js с npm и Chrome 144+.
Он подключается к вашему открытому профилю и вкладкам через `--autoConnect`. В Chrome включите
Remote Debugging на `chrome://inspect/#remote-debugging` и разрешите подключение по его запросу.
Отдельный профиль не создаётся; текущий Chrome не перезапускается. Пакет MCP закреплён на 1.12.0,
при первом использовании npx загружает его в обычный кэш npm. Телеметрия MCP и CrUX выключены.
Первое соединение может занять больше времени. Остальные функции моста не требуют Node.js.

С 0.3.4 мост включает Claude in Chrome (`--chrome`) при запуске хода и чтении каталога. Расширение
и вход настраиваются в Chrome/Claude Code; разрешения сайтов остаются у расширения. MCP и плагины
обоих помощников берутся из их локальных настроек. Каталог может работать и при заблокированных
ответах аккаунта. Встроенное управление всем рабочим столом Claude CLI на Windows не поддерживается;
у Codex нативный Computer Use работает через `@oai/sky`, браузерный host приложения нужен отдельно.

Окно показывает отдельные строки **Claude Code**, **Codex** и **OpenCode**: проверка, доступен (с числом моделей)
или недоступен. Это результат чтения каталога каждого помощника при запуске и раз в час; общий статус
«На связи» относится к каналу со студией. Доступность каталога не проверяет остаток квоты генерации.
В «Настройках» можно выбрать **«Светлая»** или **«Тёмная»** — окно меняется сразу и запоминает тему после
перезапуска. До первого выбора используется тема Windows. На форме входа переключатель находится под заголовком.

Нужны Windows, Python 3.11+ (среду заводит новейший Python лаунчера `py -3`, нет лаунчера — `python` из PATH; старее
3.11 — установка остановится с понятной ошибкой), git и Claude Code: мост берёт `claude.exe` новейшего расширения VS
Code, а если его нет — встроенный в Agent SDK. Расширение VS Code обновляет само и удаляет прежнюю папку — мост находит
новый `claude.exe` перед следующим ходом, перезапускать его не нужно. Вход в Claude (подписку) делается как обычно, в VS
Code или `claude` в терминале: мост своего входа не имеет.

**Из студии** (обычный путь): «Настройки» → «Прочее» → «Компьютеры (Claude Code)» → «Скачать мост для Windows» (или
та же ссылка в пустом разделе «Claude Code»). Распакуйте `studio-agent.zip` и запустите `install.cmd` двойным щелчком.
Установка кладёт мост в `%LOCALAPPDATA%\Programs\studio-agent`, заводит там `.venv`, ставит `requirements.txt`,
снимает с файлов пометку «скачано из интернета» и запускает мост без консоли. Появится значок в трее и окно «Studio
Agent» — войдите логином и паролем студии. **Обновление** — новый архив и `install.cmd` поверх: работающий мост
останавливается сам, файлы обновляются, среда `.venv` и настройки остаются. Ошибка установки — окно консоли не
закроется, пока не нажмёте клавишу.

**Для разработки** — git-копия, мост работает прямо из неё:

    git clone https://git.example.net/xadmin/studio.git C:\work\projects\studio
    powershell -ExecutionPolicy Bypass -File C:\work\projects\studio\agent\install.ps1

Из `studio/agent/` в git-копии `install.ps1` ничего не копирует: `.venv` рядом, пакеты, запуск.
Обновить: `git -C C:\work\projects\studio pull --ff-only`, выйти из моста в трее, `agent/install.ps1` снова.
Второй экземпляр не запускается — скажет «Мост уже запущен».

## Окно и трей

Окно «Studio Agent» (щелчок по значку или «Открыть Studio Agent» в меню; Escape и крестик закрывают окно — мост
работает дальше в трее). Вид — палитра студии, светлая или тёмная по теме Windows.

- **Вход** (компьютер не подключён): **Адрес студии** (по умолчанию `https://studio.example.com`), **Логин** и **Пароль**
  студии, **Имя компьютера** (его видно в студии), **Папка проектов** (например `C:\work\projects`: проекты — её
  подпапки), **PIN** по желанию, **Запускать при входе в Windows** (значение `StudioAgent` в `HKCU\…\Run`).
  «Подключить» заводит компьютер в студии: пароль уходит один раз и на компьютере не хранится, мост получает свой ключ
  устройства и держит его шифром Windows (DPAPI) — прочесть его может только этот пользователь Windows. Неверный пароль
  считается вместе с неудачами входа в студию, с теми же паузами.
- **Подключение**: состояние («На связи», «Подключается…», «Нет связи — переподключаюсь», «Компьютер отозван в
  студии», «Ключ используется другим мостом»), студия, учётка («Вход») и имя компьютера; «Настройки» — папка проектов
  («Изменить…» сохраняет сразу), автозапуск (галочка — по реестру: включён ли он для этой копии), PIN («Задать PIN»,
  «Изменить PIN», «Убрать PIN», «Снять блок»). Имя компьютера меняется только новой привязкой.
- **«Отключиться»** — после подтверждения ходы прерываются, мост просит студию забыть компьютер (он уходит из списка),
  стирает ключ устройства и PIN и возвращается к виду «Вход»; адрес, имя, папка и автозапуск остаются. Студия
  недоступна — ключ стирается всё равно, а окно скажет «Студия недоступна — компьютер остался в её списке: отзовите его
  в «Настройки» → «Компьютеры»». Отозванный компьютер — «Войти заново» (то же, без запроса к студии). Ключ взял другой
  мост — «Подключить снова»: ничего не стирается, этот компьютер заберёт канал у другого моста.
- **Трей** — значок студии с точкой состояния: зелёная — на связи, серая — подключается или не подключён, жёлтая — нет
  связи, красная — отозван или заменён. Подсказка и первая строка меню — состояние и логин («● На связи — ivanov»).
  Уведомление Windows — когда компьютер впервые подключился после входа, отозван в студии или его ключ взял другой мост.

Без окна, из консоли: `.venv\Scripts\python -m studio_agent enroll` (пароль — скрытым вводом), затем
`run --console` (канал и журнал в консоли, выход — Ctrl+C). Все команды: `python -m studio_agent --help` (`status`,
`set-pin`, `clear-pin`, `reset-pin`).

## PIN

PIN (4–8 цифр) проверяет сам мост; студия его не хранит, поэтому угнанные пароль или сессия студии компьютер с PIN не
откроют. Открытость — на одну сессию студии (вход на одном устройстве) и пропадает через 3 часа без запросов, при новом
канале (перезапуск студии или моста, обрыв сети) и при запирании студии — тогда PIN вводят снова.
Трёхчасовой срок действует с версии моста 0.3.2; прежние установленные копии нужно обновить.

После **5 неверных PIN подряд** мост PIN не принимает («PIN заблокирован — снимите блок на самом компьютере»).
Снять блок — только на этом компьютере: меню значка «Снять блок PIN», «Снять блок» в окне или
`python -m studio_agent reset-pin`. Задать, изменить или убрать PIN — в окне (старый PIN не спрашивается: на компьютере —
владелец учётки Windows); студия узнаёт о нём сразу, а открытые сессии закрываются. `set-pin` / `clear-pin` из консоли
действуют на новые открытия сразу, а студия узнает о PIN после перезапуска моста.

## Отзыв

Студия: «Настройки» → «Прочее» → «Компьютеры (Claude Code)» → «Отозвать». Мост на связи получает закрытие, значок
краснеет («компьютер отозван», уведомление Windows), идущие ходы прерываются (открытые карточки — отказ, `claude.exe`
гаснет), и мост больше не подключается. Вернуть компьютер — «Войти заново» в окне, затем логин и пароль. Отвязать с
самого компьютера — «Отключиться» (раздел «Окно и трей»). Смена пароля студии мост не отключает.
Если тот же ключ запущен где-то ещё (скопировали каталог моста), студия оставит последний мост, а прежний остановится —
«ключ используется другим мостом» — и тоже прервёт свои ходы. «Подключить снова» в его окне вернёт канал ему (тогда
остановится другой).

## Где что лежит

- Мост из архива — `%LOCALAPPDATA%\Programs\studio-agent` (код и `.venv`). Включённый автозапуск установка переводит на
  эту копию, выключенный не включает.
- Каталог моста — `%LOCALAPPDATA%\studio-agent`: `config.json` (адрес, имя, логин, папка, автозапуск), `key.bin` (ключ
  устройства, DPAPI), `pin.bin` (хеш PIN и счёт неверных, DPAPI), `choices.json` (модель и усилие по чатам). Битый
  `config.json` мост не перезаписывает сам: строка в журнале, мост «не настроен», окно входа; «Подключить» записывает
  новый. Нечитаемый `pin.bin` студия видит как «PIN задан».
- **Журнал** — `%LOCALAPPDATA%\studio-agent\agent.log` (меню значка «Открыть журнал»; 1 МиБ × 3 файла). В нём только
  id, коды и числа: ни ключа, ни PIN, ни пароля, ни имён проектов и файлов, ни текстов.
- Чаты — обычные сессии Claude Code (`~/.claude/projects`): видны и в VS Code; начатые в студии помечены `studio`.

## Неполадки

- **Студия говорит «PIN задан», а открытие отвечает «ошибка моста»** — `pin.bin` не читается (сброс пароля Windows,
  перенос профиля, порча). На этом компьютере: `python -m studio_agent set-pin` (задать PIN заново) или
  `python -m studio_agent clear-pin` (убрать), затем перезапустить мост — студия узнает о PIN в новом знакомстве.
- **Мост «не настроен», хотя настраивали** — `config.json` битый или без прав на чтение (строка «config.json не
  читается» в журнале): окно покажет «Вход», «Подключить» запишет новый (это новый компьютер в студии — прежний
  отзовите там).
- **«файл только для чтения» при сохранении** — у файла стоит атрибут «Только чтение»: мост такие файлы не правит.
  Снять атрибут в свойствах файла и сохранить снова (прочие атрибуты — скрытый, системный — правка сохраняет).

## Что мост делает и чего не делает

Делает: список проектов (подпапки папки проектов), чаты проекта (и из VS Code или терминала), историю, ход — новый или
продолжение сессии, модель и усилие, карточки разрешений и вопросов агента, «Остановить»; файлы проекта — список,
чтение, правка текстов до 2 МиБ (с проверкой, что файл не изменился), PDF до 10 МиБ на просмотр; статус git (только
своего `.git` проекта: папка без него внутри чужого репозитория — «не репозиторий git»). Ход идёт на компьютере и
переживает обрыв связи: вернувшись, студия догонит его снимком. Одновременно — не больше 2 ходов, в чате — один.
«Остановить» прерывает ход; не послушался — второе «Остановить» гасит `claude.exe` хода. Огромный ввод шага или
карточки (больше 1 МиБ) студия видит урезанным или пометкой «ввод не показан — слишком большой» — Claude Code получает
его целиком.

Не делает: не ходит за пределы папки проектов (ни по ссылкам, ни по junction), не создаёт, не удаляет и не
переименовывает файлы, не меняет git, не обходит правила разрешений Claude Code (`permission_mode` не задаётся —
действуют настройки пользователя и проекта, как в VS Code), не открывает портов (канал — исходящий, к студии), не
хранит пароль студии, не передаёт ходам переменные сессии того, кто его запустил (Claude Code или терминал VS Code:
`CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`, `VSCODE_*`, …; прочее окружение — как есть). Перезапуск или выход моста
прерывает идущий ход («ход прерван: мост остановлен» — уходит в студию до закрытия канала), но не сессию.
