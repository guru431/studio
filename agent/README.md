# studio-agent

Windows-компонент проекта studio, исходники — `agent/` в общем репозитории.

Мост для Windows: держит канал к студии `https://studio.example.com` и отдаёт ей Claude Code, Codex и OpenCode этого
компьютера — проекты, чаты, ход с карточками разрешений, файлы, git. В студии это раздел «Агенты».
Работают установленные помощники с их аккаунтами, провайдерами и правилами разрешений.

С 0.16.2 Claude запускается без терминального окна Windows, включая короткую проверку
версии SDK перед каждым ходом и чтением каталога моделей. Для применения нужна новая
версия моста; обновление дожидается завершения активных заданий.

С 0.13.0 повторные чтения проектов и сессий используют общие снимки в памяти компьютера.
Каталоги помощников читаются параллельно, проверка GitHub обновляется отдельно от локального Git,
а чтение квоты Codex не задерживает навигацию. Журналы и Git сверяются по кнопке обновления;
внешние изменения подхватываются следующим чтением после истечения срока снимка. PIN и правила доступа действуют
для каждого запроса. Установка/обновление работающего моста ждёт окончания заданий; сервер можно
выкладывать отдельно, запускать новую копию поверх активного исполнителя нельзя.

С 0.9.2 сводка проектов показывает состояние публичной копии GitHub: синхронизация или отставание
в коммитах относительно текущей ветки. Нужен remote `github` либо GitHub `origin`; проверка анонимная,
без ключей, fetch и изменения репозитория. Подробности — в подсказке рядом с GitHub в списке проектов.

С 0.10.1 сводка перечисляет все настроенные Git remotes. В списке проектов дополнительные копии,
включая `cld`, видны рядом с Git и GitHub. Их состояние считается по локальным remote-tracking refs,
без сети, запроса пароля и fetch; актуальное состояние сервера может отличаться. Нет загруженной
ветки или надёжной истории — remote виден со знаком `?`. Имена и счётчики передаются без URL и ключей.

**Рабочие инструменты (0.8.0).** Подсказки `@файл`, цветные диффы, ограниченный поиск по содержимому
локальных чатов, очередь с редактированием и паузой, штатные ветки Claude/Codex и просмотр их подзадач,
создание Git-worktree как отдельного проекта. Обновите сервер и мост вместе; существующие задания
сначала завершите и выйдите из трея. Сценарии и пределы — [руководство Студии](../docs/guide.ru.md#агенты-claude-code-codex-и-opencode),
контракт — [§11 протокола](../docs/superpowers/specs/2026-10-28-studio-code-bridge-protocol.md).

**Уточнения и несколько окон (с 0.6.0).** Обновите сервер Studio и мост вместе. Во время задания
можно отправлять уточнения: Codex и Claude Code получают их в работающем клиенте, OpenCode — после
текущего ответа. Если чат открыт в другом окне Studio, новое окно предлагает дождаться результата
или перенести управление сюда без остановки задания. Если writer удерживает внешний Codex Desktop,
можно подождать освобождения либо явно продолжить копию истории; исходный процесс мост не завершает.
При отказе до начала хода текст и вложения возвращаются в поле. Всё это остаётся в памяти моста/страницы
и локальной истории CLI, в журнал тексты не попадают.

**Codex (с 0.3.0).** Установите Codex CLI или расширение Codex в VS Code и войдите своим аккаунтом
(`codex login`). Мост находит `codex.exe` из PATH, установки npm или расширения и запускает локальный
[app-server](https://learn.chatgpt.com/docs/app-server) по stdio, без открытого порта и отдельного API-ключа.
Работают правила и настройки вашего Codex. В разделе «Агенты» студии выберите проект → «+» в ряду
вкладок → «Codex»; чаты помечены именем помощника, список моделей приходит от установленного Codex.
С моста 0.14.2 в статистике подписки видно количество доступных сбросов лимита Codex.
Ноль означает, что сбросов нет; «Не сообщается» — что Codex не передал счётчик.
С моста 0.14.3 под счётчиком показаны сроки действия каждого доступного сброса в часовом поясе учётки.
Если срок или часть списка неизвестны, это явно указано.
«Да, для этой сессии» подтверждает разрешение в текущей сессии Codex; обычное «Да» — один запрос.
Файлы и git — общие для проекта. Лимит одновременных заданий общий для всех помощников на компьютере,
по умолчанию — 8. В окне Studio Agent → «Настройки» → «Одновременных заданий» укажите целое число
больше нуля и нажмите «Сохранить». Настройка действует сразу, сохраняется после перезапуска и не
прерывает текущие задания. При уменьшении лимита новые задания доступны, когда занятых мест станет меньше лимита.
Настраиваемый лимит поддерживается с версии 0.9.1; у прежних настроек без этого поля применяется 8.

С 0.8.1 дерево файлов в студии позволяет создавать файлы и папки, переименовывать, перемещать
и удалять их через меню «⋯» (также правая кнопка мыши, Shift+F10). Перемещение принимает путь
от корня проекта вместе с именем и не перезаписывает существующее. Удаление папки со всем содержимым
необратимо и требует подтверждения. Несохранённый открытый файл сначала нужно сохранить.
Обновите мост после завершения заданий и выхода через трей; работающий мост из его задания не завершайте.
Вход в студию и PIN компьютера остаются прежними. Обновлять нужно и студию, и мост; старый мост
поддерживает только Claude Code. Файл `codex-chats.json` в каталоге настроек связывает вкладки студии с
сессиями Codex — сохраняйте его вместе с настройками при переносе моста.

**OpenCode (с 0.5.0).** Установите OpenCode с поддержкой ACP (проверено на 2.2.4), настройте
провайдеры в нём и выберите «+» в ряду вкладок проекта Studio → **«OpenCode»**. Модели и варианты усилия берутся
из установленного OpenCode; отдельный ключ Studio не нужен. История остаётся в OpenCode на машине.
«Правила OpenCode» сохраняют его разрешения, «Автоматически» подтверждает запрашиваемые действия,
сохраняя явные запреты CLI. Вопросы и разрешения показываются в чате; ход можно остановить.
Файл `opencode-chats.json` связывает вкладки Studio с сессиями OpenCode, а `opencode/choices.json`
хранит выбор модели, усилия и доступа — сохраняйте их при переносе моста. Скриншоты поддерживаются,
если выбранная модель умеет принимать изображения.

С 0.7.0 скрепка, вставка и перетаскивание принимают файлы любого типа во всех трёх помощниках:
до 8 файлов, 5 МиБ на файл, 8 МиБ суммарно; текст необязателен. До 4 картинок PNG/JPEG/WebP/GIF
идут в содержимое сообщения. Остальные файлы доступны помощнику по локальным временным путям
до завершения задания и удаляются после отключения CLI. При отказе до начала задания черновик возвращается.
Обновите студию и мост вместе. Новая версия также отдаёт статусы всех проектов и лимиты подписки:
кнопка справа от контекста, кэш 60 с, OAuth остаётся на компьютере; неизвестные месячные лимиты не оцениваются.

## Установка

С 0.10.0 в дереве проектов Студии после имени компьютера видна версия Studio Agent и круглая кнопка
обновления с двумя стрелками. Когда опубликована более новая версия, кнопка выделена, а номер версии —
в её подсказке. Совместимому агенту на связи кнопка запускает удалённое обновление; в остальных случаях
(старый агент без версии, компьютер не на связи, уже актуальная версия) она скачивает установщик Windows.
Агент скачивает ZIP с того же сервера по HTTPS, проверяет размер и SHA-256 и устанавливает
зависимости в отдельную копию `%LOCALAPPDATA%\Programs\studio-agent\releases\release-*`.
Затем ждёт завершения заданий Claude Code, Codex и OpenCode, штатно выходит и запускает новую копию.
Пока обновление готовится, новые задания и изменения файлов не принимаются; текущие задания,
ответы на вопросы и очередь продолжаются. В панели видны подготовка, ожидание и перезапуск.
Если задан PIN, обновление продолжится после его ввода. Привязка, PIN, чаты и настройки сохраняются;
после перезапуска компьютер потребуется снова открыть PIN-ом. Включённый автозапуск переключается
на новую копию, выключенный остаётся выключенным. Прежняя копия сохраняется для возврата:
если новый процесс сразу завершается с ошибкой, помощник запускает её снова. После подтверждённого
обновления более старые выпуски в `releases` удаляются: остаются текущий и откатный (и выпуск, на который
указывает автозапуск).

Для агентов до 0.10.0 один раз скачайте `studio-agent-setup.exe` кнопкой обновления у компьютера (или
блоком установщика вверху «Настроек»), дождитесь
завершения заданий, выйдите из трея и запустите установщик. Дальнейшие обновления выполняются кнопкой.

В 0.4.1 исправлено продолжение Codex-чата после показа настроек и контекста: чтение состояния
больше не удерживает сессию для записи. Обновление и перезапуск моста освобождают блокировку,
оставшуюся от версии 0.4.0. При действительно занятой другим процессом сессии показана её причина.

Версия 0.4.0 добавляет выбор прав доступа и показ фактических настроек/контекста в чате Studio.
Выбор прав в чате применяется к следующему ходу; настройки CLI без явного выбора сохраняются.
Для Codex в Studio доступен прямой Chrome DevTools MCP: нужен Node.js с npm и Chrome 144+.
Он подключается к вашему открытому профилю и вкладкам через `--autoConnect`. В Chrome включите
Remote Debugging на `chrome://inspect/#remote-debugging` и разрешите подключение по его запросу.
Отдельный профиль не создаётся; текущий Chrome не перезапускается. Пакет MCP закреплён на 1.12.0,
при первом использовании npx загружает его в обычный кэш npm. Телеметрия MCP и CrUX выключены.
Первое соединение может занять больше времени. Остальные функции моста не требуют Node.js.

С 0.3.4 мост включает Claude in Chrome (`--chrome`) при запуске хода и чтении каталога. Расширение
и вход настраиваются в Chrome/Claude Code; разрешения сайтов остаются у расширения. MCP и плагины
обоих помощников берутся из их локальных настроек. Каталог может работать и при заблокированных
ответах аккаунта. Встроенное управление всем рабочим столом Claude CLI на Windows не поддерживается;
у Codex нативный Computer Use работает через `@oai/sky`, браузерный host приложения нужен отдельно.

Окно показывает отдельные строки **Claude Code**, **Codex** и **OpenCode**: проверка, доступен (с числом моделей)
или недоступен. Это результат чтения каталога каждого помощника при запуске и раз в час; общий статус
«На связи» относится к каналу со студией. Доступность каталога не проверяет остаток квоты генерации.
В «Настройках» можно выбрать **«Светлая»** или **«Тёмная»** — окно меняется сразу и запоминает тему после
перезапуска. До первого выбора используется тема Windows. На форме входа переключатель находится под заголовком.

Нужны Windows, Python 3.11+ (среду заводит новейший Python лаунчера `py -3`, нет лаунчера — `python` из PATH; старее
3.11 — установка остановится с понятной ошибкой), git и Claude Code: мост берёт `claude.exe` новейшего расширения VS
Code, а если его нет — встроенный в Agent SDK. Расширение VS Code обновляет само и удаляет прежнюю папку — мост находит
новый `claude.exe` перед следующим ходом, перезапускать его не нужно. Вход в Claude (подписку) делается как обычно, в VS
Code или `claude` в терминале: мост своего входа не имеет.

**Из студии** (обычный путь): наверху корня «Настроек» → «Скачать агент для Windows (.exe)» (или
та же ссылка в пустом разделе «Агенты»). Скачайте один файл `studio-agent-setup.exe` и запустите двойным щелчком.
Распаковывать файлы вручную не нужно; права администратора не требуются. Нужны установленный Python 3.11+
и интернет для установки пакетов Python.
Установка кладёт мост в `%LOCALAPPDATA%\Programs\studio-agent`, заводит там `.venv`, ставит `requirements.txt`,
снимает с файлов пометку «скачано из интернета» и запускает мост без консоли. Появится значок в трее и окно «Studio
Agent» — войдите логином и паролем студии. **Обновление** — дождитесь завершения заданий, выберите «Выйти» в трее,
затем запустите новый `studio-agent-setup.exe`: файлы обновятся, среда `.venv` и настройки останутся.
С версии 0.7.2 установщик отказывается обновлять работающий мост и не останавливает его принудительно.
Ошибка установки — окно консоли не
закроется, пока не нажмёте Enter.

**Для разработки** — git-копия, мост работает прямо из неё:

    git clone https://git.example.net/xadmin/studio.git C:\work\projects\studio
    powershell -ExecutionPolicy Bypass -File C:\work\projects\studio\agent\install.ps1

Из `studio/agent/` в git-копии `install.ps1` ничего не копирует: `.venv` рядом, пакеты, запуск.
Обновить: `git -C C:\work\projects\studio pull --ff-only`, выйти из моста в трее, `agent/install.ps1` снова.
Второй экземпляр не запускается — скажет «Мост уже запущен».

## Окно и трей

Окно «Studio Agent» (щелчок по значку или «Открыть Studio Agent» в меню; Escape и крестик закрывают окно — мост
работает дальше в трее). Вид — палитра студии, светлая или тёмная по теме Windows.
После подключения окно разделено на вкладки **«Подключение»**, **«Работа»** и **«Настройки»**:
они не занимают высоту одновременно. Переключение — мышью или Ctrl+Tab / Ctrl+Shift+Tab.
Высота ограничена рабочей областью экрана: если всё содержимое не помещается, его можно прокрутить
колесом или полосой справа. Переход Tab к полю или кнопке сам прокручивает окно к ним.

- **Вход** (компьютер не подключён): **Адрес студии** (по умолчанию `https://studio.example.com`), **Логин** и **Пароль**
  студии, **Имя компьютера** (его видно в студии), **Папки проектов** (например `C:\work\projects` и `D:\Work`:
  проекты — их подпапки), **PIN** по желанию, **Запускать при входе в Windows** (значение `StudioAgent` в `HKCU\…\Run`).
  «Подключить» заводит компьютер в студии: пароль уходит один раз и на компьютере не хранится, мост получает свой ключ
  устройства и держит его шифром Windows (DPAPI) — прочесть его может только этот пользователь Windows. Неверный пароль
  считается вместе с неудачами входа в студию, с теми же паузами.
- **Подключение**: состояние («На связи», «Подключается…», «Нет связи — переподключаюсь», «Компьютер отозван в
  студии», «Ключ используется другим мостом»), студия, учётка («Вход») и имя компьютера; «Настройки» — список папок проектов
  («Добавить…» и «Убрать» сохраняют сразу), автозапуск (галочка — по реестру: включён ли он для этой копии), PIN («Задать PIN»,
  «Изменить PIN», «Убрать PIN», «Снять блок»). Имя компьютера меняется только новой привязкой.
- **«Отключиться»** — после подтверждения ходы прерываются, мост просит студию забыть компьютер (он уходит из списка),
  стирает ключ устройства и PIN и возвращается к виду «Вход»; адрес, имя, папка и автозапуск остаются. Студия
  недоступна — ключ стирается всё равно, а окно скажет «Студия недоступна — компьютер остался в её списке: отзовите его
  в «Настройки» → «Компьютеры»». Отозванный компьютер — «Войти заново» (то же, без запроса к студии). Ключ взял другой
  мост — «Подключить снова»: ничего не стирается, этот компьютер заберёт канал у другого моста.
- **Трей** — значок студии с точкой состояния: зелёная — на связи, серая — подключается или не подключён, жёлтая — нет
  связи, красная — отозван или заменён. Подсказка и первая строка меню — состояние и логин («● На связи — ivanov»).
  Уведомление Windows — когда компьютер впервые подключился после входа, отозван в студии или его ключ взял другой мост.

Без окна, из консоли: `.venv\Scripts\python -m studio_agent enroll` (пароль — скрытым вводом), затем
`run --console` (канал и журнал в консоли, выход — Ctrl+C). Все команды: `python -m studio_agent --help` (`status`,
`set-pin`, `clear-pin`, `reset-pin`).

В мост можно добавить несколько папок с проектами: кнопка **«Добавить…»** открывает выбор ещё одной папки,
**«Убрать»** исключает выбранную из доступа Студии. Хотя бы одна папка должна остаться. Проекты из всех папок
появляются общим списком; одинаковые имена дополнены именем родительской папки и короткой меткой.
Удаление папки из списка не удаляет файлы и локальные чаты. Прежняя папка и идентификаторы проектов сохраняются
при обновлении. В консольной привязке `enroll` дополнительные папки вводятся по одной; Enter завершает список,
пустой первый ввод сохраняет ранее выбранные папки. `status` показывает весь список.

## Рабочий стол

С версии 0.12.0 агент умеет передавать экран текущего сеанса Windows, мышь, клавиатуру
и текстовый буфер обмена. **При первой установке и обновлении прежней версии доступ выключен.**
Только человек в окне агента на компьютере включает «Настройки» → «Разрешить удалённый рабочий стол».
Выбор сохраняется в локальной конфигурации и восстанавливается после перезапуска и обновлений.
Удалённой настройки, команды протокола или CLI для изменения разрешения нет.

В Студии кнопка с монитором и стрелкой рядом с компьютером открывает пульт; обычный PIN компьютера остаётся обязателен,
если задан. «Подключиться» открывает единственный сеанс управления. Локальное выключение сразу
отзывает его, не останавливая задания Claude/Codex/OpenCode. Окна самого агента удалённый ввод не принимают.
Закрытие/фон пульта, блокировка Студии, обрыв канала или 10 секунд без запросов завершают сеанс
и отпускают нажатые клавиши и кнопки. Разрешение при этом сохраняется.
После перезапуска нужна новая PIN-сессия и новое подключение к экрану.

Окно и трей показывают, подключён ли удалённый рабочий стол, сколько заданий выполняется и
сколько из них ждёт ответа. «Завершить этот сеанс» сразу освобождает удерживаемые клавиши и
кнопки, сохраняя разрешение следующего подключения. Содержимое экрана и заданий здесь не показывается.
«Выйти после завершения» ждёт всех заданий, включая вопросы и очередь, отключения рабочего стола
и окончания запросов канала; ожидание можно отменить. Число заданий видно над кнопками выхода.

Экран входа и защищённый рабочий стол Windows недоступны; повышенные приложения могут отклонять ввод.
Буфер передаётся вручную в обе стороны, до 65 536 UTF-16 единиц; кадры JPEG — до 2560 px по длинной
стороне (по умолчанию 1600, выбор 640–2560) и 700 КиБ base64. Экран, ввод и буфер живут в памяти,
без журналирования или записи на диск.

## PIN

PIN (4–8 цифр) проверяет сам мост; студия его не хранит, поэтому угнанные пароль или сессия студии компьютер с PIN не
откроют. Открытость — на одну сессию студии (вход на одном устройстве). Отдельный таймер в студии:
«Настройки» → «Агенты» → «PIN компьютера», от минуты до семи суток, по умолчанию 3 часа без запросов.
Настраиваемый таймер поддерживает агент ≥ 0.9.0. Срок продлевают действия владельца; фоновые проверки
студии (метки вкладок, Git, сводки, повтор загрузки) мост с `passive_requests` не считает. Открытость пропадает по таймеру,
при перезапуске моста или смене папок проектов/PIN. Обрыв сети, перезапуск сервера и блокировка экрана
студии сохраняют оставшийся срок; запертая студия не допускается к компьютеру.
Сохранение срока при переподключении действует с версии моста 0.7.1; установленную копию нужно обновить.

После **5 неверных PIN подряд** мост PIN не принимает («PIN заблокирован — снимите блок на самом компьютере»).
Снять блок — только на этом компьютере: меню значка «Снять блок PIN», «Снять блок» в окне или
`python -m studio_agent reset-pin`. Задать, изменить или убрать PIN — в окне (старый PIN не спрашивается: на компьютере —
владелец учётки Windows); студия узнаёт о нём сразу, а открытые сессии закрываются. `set-pin` / `clear-pin` из консоли
действуют на новые открытия сразу, а студия узнает о PIN после перезапуска моста.

## Отзыв

Студия: «Настройки» → «Агенты» → «Компьютеры (Claude Code, Codex и OpenCode)» → «Отозвать». Мост на связи получает закрытие, значок
краснеет («компьютер отозван», уведомление Windows), идущие ходы прерываются (открытые карточки — отказ, `claude.exe`
гаснет), и мост больше не подключается. Вернуть компьютер — «Войти заново» в окне, затем логин и пароль. Отвязать с
самого компьютера — «Отключиться» (раздел «Окно и трей»). Смена пароля студии мост не отключает.
Если тот же ключ запущен где-то ещё (скопировали каталог моста), студия оставит последний мост, а прежний остановится —
«ключ используется другим мостом» — и тоже прервёт свои ходы. «Подключить снова» в его окне вернёт канал ему (тогда
остановится другой).

## Где что лежит

- Мост из установщика — `%LOCALAPPDATA%\Programs\studio-agent` (код и `.venv`). Включённый автозапуск установка переводит на
  эту копию, выключенный не включает.
- Каталог моста — `%LOCALAPPDATA%\studio-agent`: `config.json` (адрес, имя, логин, папки, автозапуск), `key.bin` (ключ
  устройства, DPAPI), `pin.bin` (хеш PIN и счёт неверных, DPAPI), `choices.json` (модель и усилие по чатам). Битый
  `config.json` мост не перезаписывает сам: строка в журнале, мост «не настроен», окно входа; «Подключить» записывает
  новый. Нечитаемый `pin.bin` студия видит как «PIN задан».
- **Журнал** — `%LOCALAPPDATA%\studio-agent\agent.log` (меню значка «Открыть журнал»; 1 МиБ × 3 файла). В нём только
  id, коды и числа: ни ключа, ни PIN, ни пароля, ни имён проектов и файлов, ни текстов.
- Чаты — обычные сессии Claude Code (`~/.claude/projects`): видны и в VS Code; начатые в студии помечены `studio`.

## Неполадки

- **Студия говорит «PIN задан», а открытие отвечает «ошибка моста»** — `pin.bin` не читается (сброс пароля Windows,
  перенос профиля, порча). На этом компьютере: `python -m studio_agent set-pin` (задать PIN заново) или
  `python -m studio_agent clear-pin` (убрать), затем перезапустить мост — студия узнает о PIN в новом знакомстве.
- **Мост «не настроен», хотя настраивали** — `config.json` битый или без прав на чтение (строка «config.json не
  читается» в журнале): окно покажет «Вход», «Подключить» запишет новый (это новый компьютер в студии — прежний
  отзовите там).
- **«файл только для чтения» при сохранении** — у файла стоит атрибут «Только чтение»: мост такие файлы не правит.
  Снять атрибут в свойствах файла и сохранить снова (прочие атрибуты — скрытый, системный — правка сохраняет).

## Что мост делает и чего не делает

Делает: список проектов (подпапки папки проектов), чаты проекта (и из VS Code или терминала), историю, ход — новый или
продолжение сессии, модель и усилие, карточки разрешений и вопросов агента, «Остановить»; файлы проекта — список,
чтение, правка текстов до 2 МиБ (с проверкой, что файл не изменился), PDF до 10 МиБ на просмотр; статус git (только
своего `.git` проекта: папка без него внутри чужого репозитория — «не репозиторий git»). Ход идёт на компьютере и
переживает обрыв связи: вернувшись, студия догонит его снимком. Одновременно — до заданного в окне моста
числа заданий (по умолчанию 8), в чате — одно.
«Остановить» прерывает ход; не послушался — второе «Остановить» гасит `claude.exe` хода. Огромный ввод шага или
карточки (больше 1 МиБ) студия видит урезанным или пометкой «ввод не показан — слишком большой» — Claude Code получает
его целиком.

Встроенный файловый интерфейс работает только в настроенных корнях проектов, не проходит через ссылки и
junction. Сам корень может быть junction, ссылкой или сетевым диском: окно сохраняет и показывает его
настоящий путь (для сетевого диска — `\\сервер\…`), id проектов при этом не меняются.

Статус Git мост читает, не исполняя ничего из конфигурации самого проекта: `core.fsmonitor`, драйверы
фильтров clean/smudge/process из `.git/config` проекта отключены (системные и пользовательские, например
git-lfs, работают), правки внутри подмодулей не видны (виден сдвиг их коммита), хуки не запускаются.
Создание worktree — ваше действие: там фильтры и хуки работают как у вашего git.

`codex app-server` и `opencode acp` работают в своём Job Object: при отключении или падении моста гаснут
и запущенные ими MCP-серверы и оболочки. `claude.exe` так не охвачен: фоновые задачи Claude переживают ход.
Запросы разрешений и вопросы субагентов Codex и OpenCode приходят в чат родителя обычными карточками. Он умеет создавать файлы и папки, переименовывать и переносить их без перезаписи назначения,
удалять файлы и папки (включая содержимое), читать и сохранять текст с проверкой версии.

Эти корни ограничивают встроенный файловый интерфейс, а не полномочия запущенных помощников.
CLI получает выбранный в Студии режим доступа; Claude может запускаться с `bypassPermissions`,
Codex — с `danger-full-access`. Полный доступ разрешает помощнику читать и менять доступные ему
файлы за пределами проекта и выполнять команды. При режиме по умолчанию действуют настройки CLI
пользователя и проекта; видимые карточки разрешений зависят от выбранного режима и правил CLI.

Мост не открывает портов (канал — исходящий, к студии), не хранит пароль студии и не передаёт ходам
переменные сессии того, кто его запустил (Claude Code или терминал VS Code: `CLAUDECODE`,
`CLAUDE_CODE_SESSION_ID`, `VSCODE_*`, …; прочее окружение — как есть). Перезапуск или обычный выход моста
прерывает идущий ход («ход прерван: мост остановлен» — уходит в студию до закрытия канала), но не сессию.
Поэтому мост обновляют после завершения заданий. Закрытие Студии на телефоне, уход в фон и блокировка
экрана снимают только просмотр: задание продолжает работать, результат доступен после возвращения.
Запрос вашего ответа или разрешения ждёт ответа и не отменяется из-за закрытого телефона.
