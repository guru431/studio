# Проверка функций OpenCode в Студии — 2026-11-14

Проверены интерфейс, серверные маршруты, Windows-мост и установленный OpenCode 2.2.4.
Первичная матрица дополнена реализацией Studio 0.14.0 / моста 0.26.0 в рабочем дереве.
Новые возможности требуют публикации сервера и штатного обновления моста после завершения заданий.
Это проверка интеграции; все инструменты, модели и сценарии реального проекта не запускались.

## Лимиты Go

Подготовлено чтение трёх окон Go: пятичасового, недельного и месячного. Выбранная модель
определяет провайдера; смена провайдера не оставляет на экране предыдущую квоту. Неизвестные
значения остаются неизвестными. Поддерживаются локальный ключ Go и виртуальный ключ шлюза.
Ключ подписки шлюз подставляет сам, клиенту и Студии его не передаёт. Маршрут разрешён только
потребителю OpenCode. Общая квота подписки не заменяется бюджетом виртуального ключа.

Маршрут шлюза и интерфейс опубликованы ранее. Сейчас работающий мост уже имеет версию 0.25.0;
его установленный модуль получил все три окна Go с числовыми процентами. Перезапуск не потребовался.
Личное окно сайта закрыто входом; отображение реального снимка квоты проверяется в изолированной
учётке локального стенда с теми же сервером и интерфейсом, без входа в учётку владельца.

## Что есть

| Функция | Результат проверки реализации |
|---|---|
| Каталог моделей и вариантов рассуждения | ACP-каталог читается; варианты проверяются для выбранной модели |
| Новые и существующие чаты | UUID Студии связаны с сессиями OpenCode, каталог фильтруется по проекту |
| Ответ, продолжение, остановка | Реализованы через `session/prompt`, `session/load`, `session/cancel` |
| История, страницы, поиск | История восстанавливается из ACP replay; поиск использует общий механизм моста |
| Картинки и файлы | Картинки идут встроенными блоками; остальные вложения — общим механизмом файлов |
| Картинки в истории | Читаются только из выбранного принадлежащего проекту чата |
| Разрешения и вопросы | Разрешить один раз/всегда/отказать, формы, стабильные ID вариантов и свободный ответ |
| Режим прав | Правила OpenCode и явный автоматический ответ на разрешения; это не выбор агента Build/Plan |
| Очередь | Последовательные сообщения после текущего ответа, редактирование и пауза общей очереди |
| Несколько наблюдателей | Общие watch, snapshot, claim, права владельца хода и восстановление связи |
| Контекст | Использованные токены и размер окна из `usage_update` |
| Инструменты и диффы | Шаги, результаты, ошибки, изменения файлов и карточки разрешений |
| Файлы, Git, worktrees, сводка проекта, экран и визуализации | Общие функции машины, отдельной OpenCode-заглушки в маршрутах нет |
| Совместные проекты и защита | Общие серверные и PIN-проверки; квота доступна владельцу компьютера |

## Подключённые возможности OpenCode 2.x

| Функция | Возможность OpenCode | Состояние Студии и необходимая работа |
|---|---|---|
| Ветвление чата | ACP `session/fork`, нативный API `before` | Полная копия и ветка перед выбранным сообщением; исходный чат сохраняется, текст возвращается черновиком |
| Список и отдельная история подагентов | Нативный API и ACP replay | Проверяются проект и цепочка родителей; обычные ветки исключаются |
| События подагентов | `_meta["opencode/child-session"]` | Проверяются parentID/depth; текст, рассуждения и контекст отделены от родителя; разрешения получают имя ребёнка |
| Выбор основного агента Build/Plan | ACP config option `mode` | Выбор из каталога сессии; предпросмотр не меняет исходную сессию |
| Счётчики токенов | `usage` результата prompt | Вход, выход, всего и рассуждения накапливаются для ходов моста; внешние ходы в эту сумму не входят |
| Стоимость сессии | `usage_update.cost` | Отображается общая стоимость в USD; ноль не подменяет расход квоты Go |
| Текст рассуждений | `agent_thought_chunk` | Свёрнутый отдельный шаг в ходе и истории |
| Сжатие контекста | compaction updates и `opencode/compaction` | Показаны начало, завершение и ошибка, состояние входит в снимок хода |
| Повторные попытки | `opencode/retry` | Номер, время и HTTP-код, очистка при ответе; тело ошибки не выдаётся |
| Каталог slash-команд | `available_commands_update` | Выбор команды вставляет её в поле задания |
| Дополнительные каталоги сессии | ACP `additionalDirectories` | До восьми полных существующих путей, только владелец; чтение истории/состояния сохраняет текущие разрешения |

Уточнение во время текущего ответа не передаётся параллельным prompt: OpenCode разрешает только
один prompt на сессию. Студия реализует очередь «после ответа». Это ограничение выбранного
ACP-механизма, а не потерянная кнопка. MCP, навыки и инструкции берутся из конфигурации OpenCode;
редактора этой конфигурации в Студии нет.

## Проверки и границы

- Изолированная живая сессия в проектном временном каталоге: initialize → new → один короткий
  ответ → fork → удаление только созданных диагностических сессий. Ответ и fork подтверждены.
- Из ответа выведены только типы событий, возможности и числовые счётчики. Пользовательские
  сессии, их тексты, ключи и работающий мост не менялись.
- Отказ ACP при попытке ветвления пустой диагностической сессии сам по себе не доказал
  отсутствие возможности: после ответа моделью ветвление прошло успешно.
- Проверки квоты используют подставные ответы, включая смену провайдера, отсутствие периодов,
  401/403, недопустимые адреса и отсутствие секретов в ответе. Живая проверка нового маршрута
  шлюза возможна после его выкладки; её нельзя заменить тестом исходного YAML.
- Отдельный запрос к живому Go usage API подтвердил числовые проценты и даты сброса всех трёх
  окон. Значения успешно разобраны тем же нормализатором; генерация для этой проверки не нужна.
- Браузерная проверка проходит через настоящий сервер и WebSocket подставного компьютера;
  она подтверждает запрос модели, обновление недельного процента при смене провайдера и
  отбрасывание задержанного ответа предыдущего провайдера.
- Быстрые наборы сервера/интерфейса, моста и шлюза проверены; ограничения и недостающая
  интеграция первоначальной проверки были записаны в `FINDINGS.md` и затем реализованы.
  Первичная проверка до расширения: сервер — 1879 passed; мост — 852 passed, 1 skipped; шлюз — 334 passed,
  1 skipped. Девять браузерных случаев проверяют OpenCode и регрессию панели Codex.
- Финальная проверка после реализации и разбора новых замечаний cron: сервер — 1887 passed / 40,66 с;
  мост — 869 passed, 1 skipped / 22,07 с. Дополнительно прошли 18 браузерных сценариев кэша/инструментов/
  OpenCode, четыре сценария gone/параметров пробы, настоящий Git и нативные ветки/дети OpenCode без генерации.
