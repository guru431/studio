# Cleaner в Studio

Cleaner обрабатывает текст перед обращением к облачной модели и восстанавливает найденные данные
в ответе. Studio хранит историю, файлы и задания; Cleaner хранит зашифрованную таблицу соответствий
отдельно для каждого диалога или перевода. Распознавание скана выполняется в Studio один раз.

## Подключение

1. В Cleaner под собственной учётной записью создать личный ключ с доступом к облачному подключению и нужным моделям. Ключ без
   доступа к модели и ключ подписки агента для этого интерфейса не подходят. Облачный ключ остаётся
   в Cleaner. Слои распознавания задаются настройками Cleaner; недоступный включённый слой блокирует запрос.
   Разным пользователям нужны разные учётные записи Cleaner: несколько ключей одного владельца
   имеют доступ к его чатам и не создают отдельную границу пользователей.
2. Администратору Studio добавить адрес Cleaner в список разрешённых. Для домашнего экземпляра —
   IP и порт `10.77.1.15:5464`. Это настройка доступа, новая версия не добавляет адрес автоматически.
3. Если у Cleaner собственный сертификат, доверенную публичную часть установить на хост Studio,
   например `/usr/local/share/studio/cleaner-cert.pem` (root:root, 0644; каталог 0755), и задать `STUDIO_CLEANER_CA` этим путём в
   `/etc/studio/studio.env`. Проверка TLS остаётся включённой; дополнительное доверие применяется
   только к Cleaner. Сертификат с публично доверенной цепочкой отдельного файла не требует.
   Каталог секретов `/etc/studio` остаётся 0700 root: публичный сертификат служба читает из отдельного каталога.
4. В настройках чата или перевода создать подключение вида **Cleaner · защита данных**, адрес без
   `/api/v1`, ввести личный ключ Cleaner, обновить модели и отметить нужные.

Запросы идут только через сервер Studio. Ключ зашифрован в базе и не выдаётся браузеру. Смена
режима обычного подключения на Cleaner требует повторного ввода ключа.

## Чат и документы

Перед отправкой открывается «Что получит модель»: системная инструкция, вся отправляемая история
и извлечённый текст вложений, включая их названия. Можно скрыть дополнительный фрагмент или снять
ошибочную замену через «Исправить замены». Эти правила действуют только в текущем диалоге.
Изменение текста, модели, ключа или истории после просмотра требует нового предпросмотра.

Отправка использует одноразовую зашифрованную квитанцию Cleaner, действующую десять минут;
квитанция привязана к ключу, версии контекста, подключению и точному запросу. Studio принимает её
девять минут, хранит только в ограниченной памяти процесса и удаляет истёкшие записи при фоновой уборке.
Перезапуск требует повторной проверки.
Cleaner перед отправкой повторяет проверку политик и утечек. До подтверждения модель не вызывается.

Ответ приходит потоком с восстановленными данными. «Ответ модели» показывает исходный ответ с
условными обозначениями; «Восстановленный ответ» возвращает обычный вид. Внешние ссылки не получают
восстановленных оригиналов. «Очищенная копия» отдельно обрабатывает сообщение вместе с его текстовыми
документами и показывает текст для копирования без нового обращения к облачной модели.

Расшифровка из «Разговоров» передаётся обычным текстовым вложением через существующее «В чат»;
дальше достаточно выбрать модель подключения Cleaner. Сам аудиофайл облачной модели не передаётся.

## Перевод

Подключение Cleaner доступно в «Переводе». Нажатие «Перевести» запускает очистку и проверку каждого
куска перед его отправкой. Один перевод, включая продолжение, использует один контекст замен.
Отдельного окна подтверждения каждого куска нет. Автоопределение языка выполняется в инструкции
перевода, без дополнительного прямого запроса с исходным текстом. Ошибка очистки останавливает перевод.

## Границы и удаление

- Обрабатывается текст. Картинки в чате отклоняются, в том числе картинки старых сообщений:
  очистка подписей не очищает пиксели. PDF-скан сначала должен завершить локальное распознавание.
- «Интернет» у подключения Cleaner отключён: поисковые запросы в Exa являются отдельным каналом
  передачи. Прямого обращения к модели при недоступности Cleaner нет.
- Найдены только распознанные значения; полного обезличивания система не обещает. Контекст может
  раскрывать сведения даже без имён. Перед отправкой и копированием нужно проверить текст.
- Оригиналы остаются в истории Studio и таблице Cleaner. Удаление диалога, перевода, подключения
  или пользователя ставит удаление соответствующих контекстов Cleaner в устойчивую очередь.
  Повтор — раз в минуту; после 401/403/429 — через час, чтобы отозванный ключ не блокировал другие запросы.
  Количество ожидающих контекстов видно в «Хранилище» и после стирания истории.
- Очередь использует зашифрованный снимок ключа и прежний адрес, с действующей проверкой списка
  разрешённых и TLS. При отозванном ключе или убранном адресе удаление остаётся ожидающим:
  контекст можно удалить в Cleaner под его владельцем. Сроки резервных копий служб действуют отдельно.

## Агенты

Claude Code, Codex и OpenCode обращаются к моделям с компьютера моста. Для них используется уже
существующий шлюз агентов Cleaner и штатные настройки провайдеров установленного CLI — см.
`cleaner/CLAUDE.md`, «Запуск для разработки». Настройка веб-подключения Studio сама по себе не
перенастраивает CLI. Ключи подписок и сертификаты остаются на машине агента; политики разрешений
команд продолжают действовать в CLI. Шлюз агентов восстанавливает аргументы инструментов иначе,
чем веб-чат, поэтому его маршрут не используется для браузерного ответа Studio.

## Проверки

Быстрые контракты — `tests/test_cleaner.py`. Сквозной тест запускает настоящий Cleaner на петлевом
адресе с его собственной средой Python и синтетическим провайдером; проверяет HTTP и TLS, предпросмотр,
отправку, защиту ссылок и удаление. Браузерная приёмка — ширины 320 и 1280, ручная правка и копирование.

    .venv/Scripts/python -m pytest -q -n0 tests/test_cleaner.py
    .venv/Scripts/python -m pytest -q -n0 -m integration tests/test_cleaner_contract.py tests/test_ui_cleaner.py

Для сквозных тестов нужен соседний `cleaner/.venv`; другой путь задаётся `CLEANER_TEST_REPO`.
Настоящие модели, облачные ключи и пользовательские документы эти проверки не используют.
