# «Агенты» на странице и возможности по capability

Пометка «(мост ≥ X)» — с какой версии мост объявляет нужную capability; без неё страница скрывает кнопку или сервер
отвечает 409 `unsupported`. Полная таблица — [agent-bridge.md](agent-bridge.md#capability-и-версии-моста).

## Ссылки на файлы в ответах

`code-file-links.js` распознаёт в ответах помощника относительные пути проекта, абсолютные пути Windows
(включая `/C:/…`, `file:///C:/…`, пробелы, URI-кодирование и суффикс номера строки) и абсолютные пути
macOS/Linux (`/Users/…`, `file:///home/…`; регистр различается). Любая ссылка от корня `/` поэтому считается
путём машины, а не адресом Студии; адрес своего сайта с `https://` — локальный только с буквой диска.
Папку проекта мост ≥ 0.41.0 сообщает владельцу полем `dir` списка проектов (второй корень, одноимённые
папки); прежнему мосту абсолютные пути сопоставляются с `projects_root` и именем. Участнику мост не отдаёт ни
корня, ни `dir`: проект — первая папка пути с именем проекта (у одноимённых папок — ещё и с родителем из подписи
«имя · родитель · хвост id»), регистр — по ОС пути; файл открывает мост в пределах проекта. `markdown.js`
нормализует их до очистки DOMPurify; `code-chat.js` открывает через `openFile`, не отправляя путь в HTTP URL.
Одинаково для истории, worker-разбора и потока; путь вне текущего проекта не становится HTTP-ссылкой.
`POST …/projects/{pid}/image` читает `raw` через обычные owner/PIN/CSRF guards, проверяет в потоке
base64/10 МиБ/формат PNG, JPEG, WebP, GIF/16 Мп и повторно проверяет сессию после проверки изображения.
Изображение не сохраняется и не кэшируется; blob страницы освобождается при смене файла и уходе.

## Инструменты рабочего места

Кнопка сведений рядом с компьютером открывает отдельное окно с системными данными и блоком «Программы».
Мост 0.27.0 (`hello.software_versions`) показывает установленные и актуальные версии Codex, Claude Code,
OpenCode (мост 0.46.0 — и DeepSeek Harness: npm-установка обновляется, Python-пакет и Desktop — «вручную») и кнопки обновления. Для расширений VS Code подписан источник, версия CLI при отличии показана отдельно.
Установленная актуальная версия выделена зелёным, устаревшая — красным; неизвестные версии остаются нейтральными.
«Обновить» внизу окна повторяет проверку версий; кнопка у программы запускает установку на выбранном компьютере.
«Обновить все агенты» (мост 0.39.0) ставит доступные обновления Claude Code, Codex, OpenCode и DeepSeek Harness на этом компьютере
в последовательную очередь и показывает результат для каждой программы.
Ниже (мост 0.47.0, `code-diagnostics.js`) — «Самопроверка» по кнопке «Проверить» (`hello.self_check`: git, четыре
помощника и вход в них, папки проектов, запись в каталог моста, канал, рабочий стол, свободное место — цветом
состояния) и «Журнал агента» (`hello.agent_log`: последние 200 строк `agent.log` в `<pre>` и «Скачать» файлом из
браузера). Обе — владельцу после PIN, только пока открыта карточка; устройство — [agent-bridge](agent-bridge.md#самопроверка-и-журнал-0470).
Состояния ожидания, установки и проверки результата опрашиваются только в открытом окне; снимки не сохраняются
в хранилище браузера. Ожидание активных заданий можно отменить; закрытие окна не отменяет уже заказанное обновление.
Старый мост предлагает обновить мост, отсутствующая программа и недоступный установщик объяснены под версией.
Контракт — §21 [протокола](../superpowers/specs/2026-10-28-studio-code-bridge-protocol.md).

studio-agent 0.8.0: `file_suggestions`, `chat_search`, `queue_edit`, `chat_fork`, `subagents`, `worktrees` —
необязательные возможности `hello`, §11 [протокола](../../docs/superpowers/specs/2026-10-28-studio-code-bridge-protocol.md).
Поиск/пути только на компьютере; сервер ретранслирует POST body. `code-autocomplete.js`, `code-diff.js`,
`code-queue.js`, `code-subagents.js`, `code-worktrees.js` дополняют рабочее место; новые кнопки скрыты для
старых мостов. Редактирование ставит очередь на паузу до сохранения/отмены; удаление последнего задания
снимает паузу и на мосту. Исходное задание не прерывается. Ветвление резервирует исходный чат до завершения
копирования: новый ход и повторное ветвление получают `running`, даже если запрос копирования уже отменён.
Ветвление/дети — Claude и Codex через штатные API; worktree открывается отдельным проектом из HEAD,
переписка и локальные настройки туда не копируются. Отправка нового хода, когда снимок «Агентов»
(`code-activity.js`, `hello.project_activity`) видит работающий другой чат того же проекта, сначала показывает
`#code-busy-notice`: «Отправить здесь» или «Запустить в отдельной копии» — `code.js` создаёт worktree (`task-<время
base36>`), новый чат того же помощника в нём и передаёт ему текст поля (`copyStart`, только память страницы); поле
исходного чата очищается. Копия — только владельцу с `worktrees`, без вложений; мост не менялся. Проверки: `test_code_discovery.py`, `test_ui_code_tools.py`,
сценарий `code_file_hints_and_held_queue` в `test_ui_webkit.py`, соответствующие тесты `agent/tests/`.

## Зеркало проекта

Владелец открывает «Зеркало» между «Файлы» и «Доступ», выбирает другой подключённый компьютер,
одну из разрешённых папок проектов и имя папки копии. Нужен мост 0.39.0 на обеих машинах.
Существующую папку можно привязать. Сравнение показывает добавления, изменения и удаления по именам и
содержимому, независимо от Git. Небольшие текстовые файлы можно раскрыть прямо в сравнении.

### Группа копий

Все копии проекта на компьютерах владельца — одна группа равноправных копий (шаг схемы 63, `mirror_groups`;
таблица `project_mirrors` остаётся как была и новым кодом не читается). Данные — на сервере, мосты ничего не хранят:
группа (`mirror_groups`) держит общие постоянные исключения шифром `STUDIO_DATA_KEY`; копия (`mirror_copies`) — компьютер,
`pid` проекта на нём и адрес папки (`root`, `name_key` — `mirror_groups.name_key` имени без учёта регистра, имя и
папка шифром); пара (`mirror_pairs`) — состояние двух копий на момент их последней синхронизации (манифест каждой
стороны шифром) и её время. Копия открытого проекта находится по компьютеру и `pid` (`mirror_groups.find`), на компьютере
в группе — одна копия (две бывают только после переноса прежних зеркал). Маршруты те же, `/api/code/agents/{aid}/projects/{pid}/mirrors`, а `{aid, pid}` — текущая
копия, источник любой отправки; сравнение, разница файла и передача идут по паре «текущая копия → копия `{cid}`».
Забрать правки из другой копии в текущую нельзя: чтобы разнести правки с другого компьютера, открывают проект на нём.

Список (`GET …/mirrors`) не обращается к мостам: текущая копия, остальные копии с компьютером, папкой, «на связи»,
временем синхронизации с текущей копией, признаком `reenter` и ходом передачи, исключения группы. Из него страница
берёт цифру на кнопке «Зеркало» (число остальных копий, `aria-label`; нет копий — цифры нет), без обращений к мостам.
`POST …/locate` (окно зовёт его при открытии) дозаполняет недостающее через мосты компьютеров группы: `pid` копии — из
`mirror_destination`, `root` и имя копии-источника — из `mirror_identity`; поэтому у бывшего назначения перенесённого
зеркала, пока окно на нём не открывали, цифры нет. Отказы окно различает по признакам, а не по словам (их переводит
страница): 404 с `gone: true` — копии с этим id больше нет (отвязана, строка слита), окно перечитывает список; 409 с
`local: true` — передача остановлена локальными изменениями.

**Перенос прежних зеркал.** Шаг 63 переносит `project_mirrors` одним проходом при запуске (`mirror_groups.adopt`): строки с
одним `source` и `project` образуют группу (зеркала A→B и A→C — группа {A, B, C}), состояние назначения в паре —
прежняя база сравнения, состояния источника нет, исключения групп объединяются (лишнее сверх
`mirror_groups.EXCLUDE_MAX` отбрасывается). Каждая строка переносится под своей точкой сохранения: строка, перенос
которой упал, не отмечается и не останавливает запуск службы (в журнал — число и типы ошибок), следующий запуск
пробует снова. Тот же проход удаляет группы без копий (все компьютеры группы отозваны). У перенесённых копий `pid` назначения и `root` источника неизвестны, их
дозаполняет `locate` и любое сравнение (`mirror_groups.place`). Если выясняется, что две строки — одна папка (владелец
раньше делал обратное зеркало вручную), они сливаются, пары переводятся на оставшуюся копию (из двух пар с одной
второй копией остаётся более поздняя по синхронизации), группы объединяются. Настройки при переносе не удаляются,
папки не трогаются: если на одном компьютере оказались две копии, окно показывает обе, лишнюю владелец отвязывает сам.

**Присоединение и слияние.** «Добавить зеркало» (`POST …/mirrors`) с папкой F на компьютере Y: F ни в какой группе —
F входит в группу текущей копии (группа создаётся, если её не было; при первом зеркале проекта сервер регистрирует
текущую копию через `mirror_identity`, нужен `hello.mirror_groups`); F уже в группе G, а у текущей копии группы нет —
текущая копия присоединяется к G; F в другой группе G, а у текущей копии своя — группы сливаются, если в них нет копий
на одном компьютере, иначе 409 `conflict` с названиями компьютеров. Папка в чужой группе требует подтверждения:
409 `grouped` с компьютерами группы, повтор с `join: true`. Если в G уже есть копия на компьютере Y (проект
переименован, осталась прежняя папка), 409 `exists` с `former: true`, повтор с `replace: true` снимает прежнюю
строку вместе с её парами. F уже в своей группе — 409 `exists`. У проекта уже есть копия на Y в другой папке —
409 `exists`. Отказ `exists` о чужой копии (прежней или уже имеющейся на Y) несёт `name` — имя её папки, без пути
(`project_mirrors._named`; адрес неизвестен или нечитаем — без поля): окно называет, какому проекту она назначена. «Найденные копии» помечают папку чужой группы
(`grouped`: «В группе копий с …», кнопки «Присоединить» и «Объединить») и не показывают компьютеры с копией в своей
группе. Отвязка (`DELETE …/{cid}`) удаляет только настройки выбранной копии; осталась одна копия — группа удаляется
вместе с исключениями.

**Что записывается в пару и «локальное изменение».** После отправки X → Y в паре — состояние Y
(`project_mirrors._next_baseline`: оставленные в копии файлы сохраняют прежнее состояние) и состояние X
(`project_mirrors._source_state`: манифест X до приведения к платформе назначения, кроме путей, не применённых в Y —
оставленных в копии, пропущенных, исключённых; для них остаётся прежнее состояние X). Запись Y по пути `p` — «локальное
изменение» (замена только с подтверждением или «Оставить в копии»), если не верно ни одно из: она совпадает с записью
X; равна состоянию Y в паре X–Y; входит в то, что X уже держал на момент одной из своих синхронизаций — его нынешняя
запись новее (`mirror_groups.held`: накопленное копии X и её состояния в парах). Накопленное — столбец
`mirror_copies.held` шифром: после каждой синхронизации X → Y (и первой сверки совпадающих копий) в накопленное
каждой копии добавляются её прежнее состояние в этой паре (у перенесённого зеркала — прежняя база) и новое, последние
`mirror_groups.HELD_MAX` (8) различных на путь; путей, которых в новом состоянии копии нет, накопленное больше не
держит (удалённые файлы и `.git/objects` после `git gc` не копятся; цена — разовый конфликт при распространении
удаления, осторожная сторона). Слияние строк одной папки переносит в накопленное и состояния отброшенных или
перезаписанных пар. Разбор и шифрование накопленного — в потоке (`mirror_groups.compute`, `mirror_groups.held_from`),
чтение и запись базы — на цикле событий; изменилось за это время — посчитать заново (`project_mirrors._record`).
Поэтому передача, переписавшая состояние X в одной паре, не делает ложным конфликтом сравнение с другой копией — ни
в одном проходе «Отправить во все копии» (и первом с бывшего назначения перенесённых зеркал), ни при отправке по
одной копии, ни после перезапуска службы. **Известная граница:** правило сравнивает содержимое без времени, поэтому
откат в копии к содержимому, которое X держал на одной из прошлых синхронизаций (отмена правки, `git restore`),
считается более старым, и отправка X его заменит без вопроса. Режим файла — часть записи: копия, где над содержимым, которое X держал, поставили бит исполнения, —
локальное изменение, если новая запись этот бит не сохраняет (`project_mirrors._held`). Удалённый в Y файл
проверяется только по состоянию пары. Нет состояния стороны (новая пара, перенос) и третье правило не сработало — отличие
считается локальным изменением. Первая сверка совпадающих копий фиксирует оба состояния (`mirror_groups.seal`).
Правило не даёт отставшей копии молча затереть правку, которую третья копия получила от другой.

«Отправить во все копии» — действие страницы, не сервера: она сравнивает текущий проект с каждой копией, которая на
связи и открыта (компьютер без PIN открывается сам), затем одно подтверждение со сводкой по копиям и передачи по
очереди, с `overwrite: false`. Копии с локальными изменениями, не на связи, с настройкой `reenter`, с идущей
передачей и требующие PIN в общую отправку не входят — строка помечена причиной; PIN вводят после «Сравнить» в строке
копии, в общем поле окна. Копия с ещё неизвестным адресом на связи входит: сравнение дописывает адрес, прежний мост
отвечает «Обновите мост на компьютере копии». Передача сравнивает заново
и принимает план только при совпавшем токене; решение о конфликтах при этом то же, что при сравнении: накопленное
«держал» передачей в другую копию только пополняется.

**SQLite.** Мост с `hello.mirror_groups` больше не отказывает во всём сравнении из-за открытой базы: служебные
`-wal`, `-shm`, `-journal` рядом с файлом SQLite пропускаются всегда, сама база — если рядом непустой `-wal` или
`-journal`, пустой журнал открытой базой не считается. Причину сервер просит полем `reasons: true` в
`mirror_scan` и `mirror_destination` (только у мостов с возможностью): пропуск приходит как `["skip", причина, 0, 0]` с
причиной из `project_mirrors.SKIP_REASONS` — `sqlite` (база с непустым журналом) или `sqlite-journal`; в ответе
сравнения — `reasons: {путь: причина}` от обеих сторон, окно показывает «Пропущен · открытая база SQLite» и «Пропущен ·
служебный файл SQLite». Любой другой `kind == "skip"` (причина будущего моста) — тоже пропуск, без подписи. Мост без
возможности не получает `reasons` и по-прежнему отказывает при открытой базе — сервер отвечает 409 `unsupported`
«Обновите мост на компьютере «…», чтобы он пропускал открытые базы SQLite» (`project_mirrors.OLD_SQLITE`). Копия такого
моста с известными `root` и `pid` (бывшее назначение) работает и как назначение, и как источник. Отказы — только при
регистрации текущей копии первым зеркалом проекта (общий отказ `require_capability` «Обновите мост на компьютере для
этой возможности») и когда адрес другой копии ещё неизвестен, а её мост прежний («Обновите мост на компьютере копии»,
409 `unsupported`). Протокол — §23.3 спеки моста.

С мостом 0.40.0 «Найденные копии» проверяют папки проектов на других компьютерах владельца.
Совпадение Git-репозитория определяется по локальным адресам `origin` и `github`, поэтому
клон можно найти и под другим именем. Совпадение только имени папки помечено отдельно.
Закрытый компьютер требует PIN. Кнопка «Привязать» выбирает конкретную найденную папку
и открывает сравнение с открытым проектом. Поиск запускает только «+ Добавить зеркало», а не каждое открытие окна. Если каталог недоступен, Studio показывает частичный
результат и оставляет в списке копии из проверенных папок.

Синхронизация направлена от открытого проекта к выбранной копии. В неё входят обычные скрытые и игнорируемые
файлы, содержимое `.git` и пустые папки. Внутренние относительные ссылки копируются как ссылки, внешние
ссылки, junction и специальные объекты показаны как пропущенные, как и файлы с именем, которого ОС
компьютера не принимает в протоколе (на Windows — `aux.c` или имя с точкой в конце). Копия на Windows
(`hello.platform` назначения) не получает ссылок и путей, которых Windows не создаёт: `project_mirrors._portable`
помечает их пропущенными до плана (`project_mirrors._windows_name`), иначе первая же такая запись откатывала бы всю
синхронизацию общим «не удалось записать зеркало». Базы SQLite с непустым журналом — см. «SQLite» выше. Для связанного Git worktree выберите основной репозиторий
или отдельный клон. При обновлении существующего файла из Windows право исполнения в копии
Linux или macOS сохраняется. Если файлы существующей копии совпали, это сравнение служит
исходной точкой для обнаружения локальных правок.

«Постоянные исключения» (мост 0.41.0 на обеих машинах) — до `mirror_groups.EXCLUDE_MAX` (64) точных
относительных путей без шаблонов, например `.venv` или `web/node_modules`; `.git` переносится целиком. Мост
не обходит и не читает их ни в проекте, ни в копии: план показывает их пропущенными, в копии они не удаляются,
а большие каталоги зависимостей не упираются в предел записей. Список принадлежит группе копий, хранится шифром и виден в окне всегда, пока группа есть, — и без успешного сравнения.

В списке различий «Оставить в копии» исключает выбранный локальный файл из текущей синхронизации.
Список сразу показывает оставшиеся изменения. Замена локальных правок и удаления требуют подтверждения
по актуальному сравнению. Отвязка копии удаляет настройки, папка остаётся на компьютере.

Передача (`project_mirrors._sync`) — фоновая задача сервера. Запуск (`POST …/sync`) проходит обычные проверки
незапертой сессии и PIN обоих компьютеров; дальше её просьбы (`_ask(background=True)` →
`claude_code.ask(while_locked=True)`) сверяют живую сессию, включённую учётку и владение компьютерами, но не
блокировку экрана: заперлась студия по таймеру — передача доходит, а выход, гашение сессии, отзыв компьютера
и аварийный выход её обрывают. `mirror_abort` идёт той же фоновой просьбой.

**Синхронизация после хода** (шаг схемы 77, `mirror_copies.auto`). Флажок копии «Отправлять изменения в копии после
каждого хода» — в окне «Зеркало» (текущая копия) и в общем списке; оба пишут `PUT /api/code/mirrors/{cid}/auto`
`{auto}`. Ход владельца запоминает свой запрос (`bridge.owner_turn`, `bridge.TURN_REQUESTS`, только память; ход
участника ставит на его место свою отметку). Запись ставится до просьбы `turn` (быстрый `done` опережает ответ
моста), а ход, которого мост не принял (`running`, отказ, обрыв без квитанции), возвращает прежнюю — только пока
место за ним: отказанный ход соавтора не снимает запрос идущего хода владельца, отказанный ход владельца во время
хода соавтора не запускает синхронизацию его сессией. Наблюдатель получает 403 `readonly` до записи
(`project_access.editable`). Уточнения и очередь моста — часть того же хода: решает тот, кто ход начал. Событие
`done` со статусом `done` (`bridge._after_turn`, не `stopped`/`error` и не досланное `completions`) зовёт `project_mirrors.after_turn`: копия проекта с флажком сравнивается с каждой
другой копией группы той же сессией — фоном, без открытой страницы, как ручная передача (блокировка экрана не
мешает, выход и отзыв обрывают; закрытая сессия — ничего). Просьбы мостам идут с `X-Studio-Passive` (срок PIN не
продлевают); компьютер копии или источник без PIN, закрытый для сессии (не открывался или закрылся по простою за
долгий ход), открывается сам и при запертой студии (`claude_code.open_without_pin` с `while_locked`; открывается
тот, чей мост ответил `closed`), с PIN, не открытый этой сессией, — ход `failed`. План применяется (`project_mirrors._sync` с готовой сверкой) только без локальных
изменений копии, без удалений и не в отсутствующую копию; иначе ход `differs` (окно и список: «после хода не
отправлено: есть различия — откройте сравнение») и push вида `service` (`project_mirrors.DIFFERS`: «компьютер ·
проект» и имя компьютера копии, без файлов). Копия, в которую уже идёт передача, пропускается. Ход передачи помечен
`auto: true`.

**Все зеркала учётки** — «Настройки» → «Агенты» → «Зеркала проектов» (`mirror-list.js`, `project_mirrors.all_router`).
`GET /api/code/mirrors` — копии компьютеров учётки (компьютер → проект → остальные копии группы с временем
синхронизации с этой копией и ходом передачи), флажок `auto` и `missing` — «проекта больше нет»: мост компьютера на
связи (фоновая просьба `projects`, без PIN — открыть) не знает `pid` копии; не ответил или заперт PIN — без пометки.
`DELETE /api/code/mirrors/{cid}` отвязывает копию (папка остаётся; осталась одна — группа удаляется); идёт передача с
её участием — 409 `busy`. Так снимается копия переименованного или удалённого проекта, до которой окно «Зеркало» уже
не дотягивается (его открывают от текущего `pid`).

Копия ключуется компьютером и `pid`, а папка занята по `UNIQUE(agent, root, name_key)`. После переименования или
удаления проекта прежняя копия держит папку: добавление нового имени на том же компьютере отказывает 409 `exists` с
`former: true`, «Найденные копии» показывают прежнюю папку как копию группы, а `replace: true` одной транзакцией снимает
прежнюю копию вместе с её парами и добавляет новую — без прежней базы сравнения (все различия — локальные
правки). Своё зеркало `replace` не трогает.

После обрыва на видимой странице Studio повторяет полное обновление с увеличивающейся паузой.
Адрес, черновик текста и квитанция незавершённой отправки сохраняются в текущей вкладке
(`sessionStorage['studio-agent-drafts']`, `code-drafts.js`). Текст очищается при отправке, блокировке Студии,
выходе, аварийном выходе и уходе на вход из-за кончившейся сессии (`api.js::toLogin` шлёт `studio-signed-out`);
страница входа (`login.js`) стирает их при любом пути к ней. Вложения черновика живут в памяти страницы.

`code_attention_seen`: id компьютера, чата, учётки и просмотренная ревизия; `code_attention.unread`): участник не

`done`, независимо от наблюдателей; SSE и свежая история передают ревизию `attention`. Ходы, кончившиеся

моста) и CSRF, снимает только переданную ревизию и только у своей учётки.

фоновая вкладка и прокрутка старых сообщений отметку не снимают. Часового ограничения нет;
фоновые проверки скрывают данные закрытого/offline компьютера. Обновлять мост для этого не требуется.
Проверки — `test_code_activity.py`, `test_ui_agent_attention.py`, миграция в `test_foundation.py`.
Месячный лимит не выдумывается, неизвестные окна — available=false; Claude OAuth usage недокументирован.
Круг контекста: <50 зелёный, 50 жёлтый, 70 оранжевый, 90 красный. `code-context.js` открывает подробности
сессии по нажатию: окно, занято/свободно, расход, модель/права/id. Мост 0.7.4 добавляет необязательный

30 минут, Claude — 5 минут или час только по отчёту `cache_creation` (смешанный кэш — короткий срок).

длинные названия ограничены двумя строками с полным текстом в title. Браузерные проверки — `tests/test_ui_agent_controls.py`.
(мост ≥ 0.7.3) `hello.project_summary` объявляет `GET …/projects/<pid>/summary` → op `project_summary`.
Счётчики активных `FINDINGS.md`/`IDEAS.md`, изменённых файлов, незапушенных коммитов и дата изменения —
`agent/studio_agent/project_summary.py`, без содержимого и путей в ответе. В `code-panel.js` четыре параллельных
чтения. С 0.13.0 снимки панели сохраняются между переходами, отдельно по учётке и компьютеру;
сначала читаются видимые строки, скрытая мобильная панель очередь не запускает; после её выезда
чтение запускается по завершению перехода. Готовые строки
рисуются сразу; общая кнопка обновления Studio принудительно перечитывает весь список.
`.code-panel-footer` вне прокрутки содержит сортировку, создание проекта и дату обновления сведений.
Отдельной кнопки обновления списка нет. Между точкой состояния и именем компьютера — логотип Windows/macOS,
если мост сообщил платформу.

Ускорение 0.13.0: `GET /api/code/agents/<aid>/access` проверяет владение и PIN перед показом
кэшированной истории. Список сессий и история обновляются в фоне; при известном движке текст не ждёт
полного каталога. Современный мост должен подтвердить параметры сессии до отправки; неизвестный
движок из неполного списка не угадывается. Начальная история — 12 сообщений, прежние — по 30, со стрелками;
содержимое закрытых шагов ленивое, Markdown разбивается на кадры с общим бюджетом 6 мс. Тексты свыше 8000
знаков разбираются в Worker; DOMPurify и подсветка остаются в странице, отказ Worker оставляет безопасный текст.
Worker завершается при очистке доступа и имеет таймаут 10 с; история и Markdown на диск не попадают. Поток большого
ответа показывает текст до окончательной разметки. Кэш историй ограничен также оценкой памяти 8 МиБ,
очищается при блокировке, закрытии компьютера и отзыве доступа. Опрос Git/каталога — 20 с при работе,
60 с в спокойном проекте; статус активности общий для значка и панели. Настройки объединяют чтение компьютеров.

## Панель проектов, файлы, сводка, GitHub и remote

Владелец создаёт проект кнопкой «Новый проект» под списком проектов выбранного компьютера.
На телефоне (≤760 px) это значок плюса справа от сортировки; на десктопе — прежняя текстовая кнопка выше неё.
Мост ≥ 0.24.0 объявляет `hello.project_create`; старые и совместные компьютеры кнопку не показывают.
`GET …/project-roots` → `project_roots` возвращает id и пути настроенных папок после проверки PIN;
при одной папке она выбрана автоматически, при нескольких нужен явный выбор. Имя и выбранный id
передаются телом `POST …/projects` → `project_create {root,name}`. Мост создаёт только новую пустую
подпапку, без Git и регистрации внешних репозиториев. Существующие файлы, папки и junction не меняются.
Успех (HTTP 201) обновляет список и открывает проект. Отказ оставляет введённое имя и папку;
истёкший PIN закрывает окно и возвращает ввод PIN. Создание не доступно участникам проекта.
Названия и пути остаются на машине и в памяти браузера, в журналы и базу не попадают.

Названия проектов выделены полужирным, строки разделяет небольшой отступ. Дата изменения стоит
сразу после сведений Git и дополнительных remote, без прижатия к правому краю панели.

Во время перечитывания проектов и их сводок ↻ вращается, строка даты показывает «Обновляю сведения…»;
`aria-busy` и блокировка кнопки снимаются при успехе и ошибке, ответы прежнего компьютера не меняют новый.
При `prefers-reduced-motion` остаётся текст без вращения. Установщик EXE и пояснение о необходимости моста —
вверху корня «Настроек», перед разделами; во вложенных настройках блок скрыт. В пустом разделе «Агенты» — та же подсказка.
Выбор сортировки сохраняется в localStorage `studio-code-project-sort:<user_id>`, отдельно для каждой
учётки в этом браузере; восстанавливается до показа панели, неизвестное значение — «По имени».
При выборе «По размеру кода» панель запрашивает сводки с `code_size=true` для всего списка.
Сначала идут проекты с наибольшим числом байтов исходного кода, при равенстве — по имени.
Нулевой размер предшествует неизвестному. Строка показывает десятичные КБ, сортировка сравнивает байты.
Список разрешённых проектов моста 0.36.0 уже содержит последний успешный размер каждого измеренного проекта.
Он задаёт порядок до загрузки сводок и остаётся виден при ошибке нового замера.
«Сначала публичные»/«Сначала приватные» группируют по подтверждённой публичной копии `summary.github`:
есть копия / `null`; неизвестный статус, `github_pending` без прежней копии, старые мосты без поля и

настройки CLI. В «Настройках» → «Агенты» — `codeDefaultsBlock` и компьютеры (`agentsBlock`), каталоги подключённых машин из
`/api/agents`. `code-chat.js` берёт их только для нового/пустого чата; начатый сохраняет прежние
настройки моста, выбор в чате больше не переписывает умолчания новых чатов и localStorage не использует.
Недоступные на машине значения сопровождаются сообщением, не уходят в `turn` как неизвестная модель.
«Приоритет агентов» меняет порядок кнопок создания чата и выбор агента для автоматического Git-чата.
`priority` — строгие целые 1–4 без повторов у всех четырёх агентов; прежний набор 1–3 у Claude, Codex и OpenCode
без DeepSeek Harness остаётся верным (DeepSeek Harness — последним); без них порядок Claude, Codex, OpenCode,
DeepSeek Harness (`account_profile.code_defaults`).
Приоритет хранится в существующем JSON без миграции базы; изменение моделей и прав его сохраняет.
В новой сессии кнопки «Claude», «Codex», «OpenCode», «DeepSeek» стоят в один ряд (на 320 px — короткая подпись
«DeepSeek», полное имя — в `title` и `aria-label`). Справа от поиска — переключатель
«По заголовкам» / «По содержимому» (`role=switch`), по умолчанию поиск заголовков в памяти страницы;
по содержимому — только явный выбор и прежний POST на компьютер, со старым мостом переключатель скрыт.

(мост ≥ 0.4.0) `hello.chat_state` объявляет `POST …/chats/<id>/state` → просьбу `state`
мосту с `{project, chat, model, effort, access}`. Ответ — `settings` конкретного CLI и `context`
`{used, limit, percent}` либо null. `hello.defaults` и `hello.codex.defaults` — текущие настройки
корня проектов для панели настроек. В чате модель, усилие и права показываются конкретно, без
пункта «по умолчанию»; `null` на проводе продолжает сохранять настройки сессии. Новый ход может
нести `access`, отдельно проверяемый по помощнику; старый мост с ним — 409 unsupported.
События `settings`/`context` и поля снимка обновляют индикатор; число берётся из CLI, не из текста.
Chrome для Codex — `studio_chrome` (Chrome DevTools MCP, открытый профиль, --autoConnect);
отдельный browser access host приложения Codex мост не эмулирует.
В мосте 0.4.1 `state` существующего Codex-чата читает эфемерную копию через `thread/fork`,
не захватывая writer исходной сессии; временная копия отписывается в finally.

Изображения раздела «Агенты» (studio-agent ≥ 0.3.3): `hello.images: true` → `/api/agents.images`;
`Turn.images` — до 4 `{mime, data}` (base64), PNG/JPEG/WebP/GIF, 10 МиБ на файл / 30 МиБ всего с
`hello.large_attachments` (без capability — прежние 5/8 МиБ). Тело хода читается через `auth.small_body`
до 44 МиБ; кадр канала — до 48 МиБ. Base64 проверяется в потоке, на машине
`image_input.validate` повторяет пределы и сверяет сигнатуру. Старый мост с картинками — 409
`unsupported`, без картинок контракт прежний. `code-chat.js` — выбор, paste, drop, превью и черновик
в памяти по чату; пустой текст допустим при картинке. В Agent SDK — поток user-сообщения с image/source
base64, в Codex `turn/start.input` — image с data URL. В базе, журнале и временных файлах картинок нет;
история машины показывает прежний маркер `[изображение]`.

Codex (2026-10-30, мост studio-agent ≥ 0.3.0): общий раздел «Агенты» (`#/code`), «Новый чат Codex» на экране «+»;
история и модели разделены полем `engine` (`claude` по умолчанию, `codex`). Шаг схемы 21 добавляет
`code_chats.engine` без изменения прежних строк. API чатов принимает `?engine=codex` для сессий машины без
отметки; у отмеченных помощник берётся из базы, противоречивый параметр — 409 `engine`. Сервер добавляет
`engine: codex` к просьбам моста, сверяет модели с необязательным `hello.codex` и отдаёт каталог в `/api/agents`.
Старый мост продолжает работать с Claude; Codex без объявленной поддержки — 409 `unsupported`. Тексты и
файлы Codex хранятся на машине; студия хранит отметки, вкладки, имя помощника и умолчания учётки;
push общий для раздела «Агенты».
Вкладки несут отдельную `.code-tab-engine`, список — `.code-engine` у каждой сессии. Имя помощника не часть
названия сессии. В `.code-head` — место и `.code-project-tools`: статус Git, затем «Git · Файлы · Зеркало · Доступ · Чат».
Ряд вкладок `code-tabs-host` находится под этой строкой на всех экранах. «+» открывает `?tab=new`:
`#code-tab-menu` в основной области на всю ширину, создание чатов и сессии без открытых вкладок (`sessionList`).
При отсутствии вкладок этот экран показывается сразу. Codex/OpenCode/DeepSeek Harness доступны при наличии каталога машины.
`code-git.js` `projectGit` — один снимок Git проекта для `#code-repo-status`, дерева
и вкладки Git: ветка со `*`, ↑/↓ при upstream; обновление при входе/возвращении, сохранении файла и опросом 20 с (в спокойном проекте — 60 с)
только на видимой странице в течение 30 минут после действия. `code-files.js` — ленивое вложенное дерево
`li[data-path]` / `ul[role=group]`, папки раскрываются на месте, цвета и M/U/A/R/D/! из снимка Git, у папок — точка.
Раскрытие папки не закрывает редактор; смена файла и переход по пути сохраняют защиту несохранённых правок.
Textarea отдаёт строки только с `\n`; при сохранении `line-endings.js` возвращает неизменённым строкам в начале
и конце файла прежние разделители (CRLF, LF, CR), изменённым — самый частый в файле.
Отказ `conflict` (файл изменился на компьютере) перечитывает файл и показывает `#code-conflict`: сравнение
`code-diff.js::changeView` «на компьютере ↔ правка» и выбор — взять версию компьютера, сохранить свою поверх
(второй `PUT` с перечитанным `version`) или скопировать свою в буфер.
Срок открытого PIN компьютера задаётся отдельно в настройках «Агенты» (`users.computer_pin_timeout`,
60–604800 с, по умолчанию `OPEN_IDLE_SEC = 10800`). Агент ≥ 0.9.0 объявляет `hello.pin_timeout`, сервер
передаёт `idle_sec` в каждом запросе; старому агенту с нестандартным таймером — 409 `unsupported`.
Поле PIN компьютера (панель, «Зеркало», «MCP агентов») — только `computerPin` из `ui.js`: text с точками
`.computer-pin` вне `<form>`, чтобы менеджер паролей не предложил сохранить PIN.
`studio-agent` ≥ 0.7.1 сохраняет
остаток срока после переподключения, перезапуска сервера и блокировки экрана. Явная настройка и перезапуск моста сбрасывают доступ;
опрос страницы по-прежнему прекращается через 30 минут без действий владельца.

## Поведение страницы

- `code-chat.js::loadHistory`: первая удачная загрузка истории (флаг `opened`) запрашивает `/state` и выполняет
  отложенное Git-действие; `onVisibility` не открывает live второй раз. `#code-reload` «Повторить» в
  `.code-status-bar` при любой ошибке загрузки (на узком экране — значок); сам повторяет через `RETRY_MS` при
  `offline`/`network`/`timeout`/≥ 500 фоновым запросом (`x-studio-passive`). Обёртка `api` в `chatView` передаёт
  заголовки. Перечитывая историю при идущем ходе (возврат на экран, `online`), `loadHistory` оставляет ответ хода
  последним узлом ленты и сам ход (`turn`) до снимка live: текст не мигает. Ход кончился, пока страница была
  скрыта, — до ответа live `idle` ответ виден поверх свежей истории, затем `idle` перечитывает её до итоговой.
  Проверка — `test_ui_browser.py::test_code_return_to_tab_keeps_running_turn_text`.
- Повтор «Отправить» после обрыва связи: задание и уточнение несут `request_id` (`Turn.request_id`), он живёт вместе с
  вводом — тот же текст и те же картинки уходят с тем же id, правка даёт новый. Сервер держит квитанцию в памяти
  процесса (`claude_code.RECEIPTS`, `claude_code.RECEIPT_SEC` (600) с, не больше `claude_code.RECEIPTS_MAX` (1000)
  завершённых): повтор, пока первая просьба ждёт мост, ждёт её исхода (обрыв первого запроса просьбу не отменяет),
  после принятия отвечает JSON `{"repeat": "turn"|"steer", …}` без второй просьбы мосту; отказ первой квитанцию
  снимает. Страница при обрыве POST хода (status 0, `TimeoutError`, 502/503/504) ввод вслепую не возвращает: сверяет
  историю (`loadHistory`), подтвердилось — открывает live; нет — возвращает ввод в поле с той же квитанцией и всё
  равно открывает live. Ответ `repeat` — «Это задание уже принято»: поле очищается, второй ход не начинается.
  Протокол моста не меняется. Проверки — `test_code.py` (`request_id`), `test_ui_send_reliability.py`.
- `code.js::failed` очищает кэши (`studio-code-clear`) только при `closed` и 404 компьютера (`computer: true`), а не
  при любом `not_found` «Файлов».
- `code-panel.js::select`: повторный выбор того же компьютера отменяет идущее обновление сводок и снимает занятость ↻.
- `code-desktop.js`: смена монитора сохраняет текст и буфер, их очищает только `stop()`.
- `picker.js::picker`: модель, усилие и права — отдельные кнопки на всех экранах, рядом с отправкой.
  Меню поддерживает стрелки, Home/End, Esc/Tab и возвращает фокус; закрывается при прокрутке/ресайзе.
- `code-status-bar.js`: текст состояния получает не меньше 40% строки, кнопки — до 60%, дополнительные действия — панель «⋯».
  Справа постоянно видны шесть кнопок: подзадачи, команды, изменённые файлы, кэш, контекст и подписка.
  Счётчики подзадач, команд и файлов оформлены одинаковыми цифрами без цветной заливки.
  Если помощник или мост не поддерживает подзадачи/кэш, соответствующая кнопка недоступна и показывает «—».
  Действия переносятся по одному по измеренной ширине; круг контекста сохраняет форму. В панели — явные подписи,
  а счётчики находятся внутри своих строк. Размеры подстраиваются под свободные 60% строки и масштаб.
  `code-subagents.js` обновляет число работающих по событиям хода и опросом при видимой странице; опрос идёт,
  только пока идёт ход или открыто окно подзадач, и не дольше 30 минут после действия владельца в чате или окне
  (как опрос live): мосты до `passive_requests` считали бы каждый запрос действием. Без хода — одно чтение при
  открытии чата и возврате на страницу. Завершённые остаются в списке вместе с их историей.
  У каждой строки показаны время запуска в часовом поясе учётки, длительность и расход токенов;
  отсутствующие сведения обозначены «нет данных». Активные строки выделены зелёным, их длительность обновляется
  каждую секунду, пока окно открыто и страница видима; закрытие раздела убирает таймер.
  Открытая история выбранной подзадачи обновляется каждые две секунды и кнопкой «Обновить» вместе со списком;
  позиция чтения, раскрытые команды и фокус сохраняются. При скрытии страницы запросы отменяются.
  Служебные `<task-notification>` Claude отображаются отдельными карточками с названием, состоянием и выводом;
  внутренние инструкции и маркеры сканера скрыты, кнопки ветвления у уведомлений нет. Вывод остаётся обычным текстом.
- `code-commands.js`: постоянная кнопка статуса со счётчиком активных Shell/Bash-команд; в покое показывает `0`,
  по нажатию — «Нет выполняемых команд». Открытая панель сохраняется и после завершения последней команды.
  Панель содержит раскрываемые шаги с командами и живым выводом; завершённые уходят из активного списка, сохраняясь
  на своём месте в ленте. Сводка над ответом больше не дублирует активные команды; план и подзадачи остаются.
- `code-chat-images.js`: ссылки `messages[].images` загружаются возле экрана через защищённый POST `/image`.
  Изображения остаются в памяти открытого чата; при прокрутке и уходе освобождаются blob и запросы.
  Смена чата и возврат восстанавливают изображение на компьютере через мост с `hello.history_images`.
  Картинки уточнений отображаются и в живом событии, и после восстановления снимка хода (мост ≥ 0.19.1);
  байты читаются тем же защищённым запросом, отдельно от компактного снимка.
- Рамка поля ввода остаётся внутри `.code-compose-area` при вложениях, длинном тексте и низком окне;
  прокручивается содержимое формы, строка отправки закреплена внутри рамки.
- `code-chat.js::grow`: лента следует за ходом, включая отложенную разметку Markdown и изменения высоты.
  Небольшой отход от конца сохраняет слежение; прокрутка далеко вверх и переход к старому сообщению отключают его.
- `code-chat.js::askNode` выводит `p.code-ask-subtask` «Подзадача · <имя>» для вопросов и разрешений субагентов.
  Снимок хода (каждое открытие `live`: возврат вкладки, обрыв потока) строит заново только карточки новых запросов:
  карточка того же `request_id` остаётся с набранным «Своим ответом», отметками и «Что сделать вместо этого».
- Опрос меток вкладок и Git: `code.js` `IDLE_POLL_SEC` — 20 с, пока в проекте идёт ход или ждёт ответа, иначе 60 с;
  не дольше `IDLE_POLL_FOR_SEC` после действия владельца, только при видимой странице. Порядок кнопок в шапке —
  статус Git → Git → Файлы → Зеркало → Доступ → Чат (`code.js`, «Зеркало» и «Доступ» — отдельные действия между
  видами `VIEWS`).

## Задания, вкладки, клавиатура

- Вся кнопка «Агенты», включая число и точку (`.tab-count`/`.tab-dot`, `#code-inbox-dot`), открывает рабочее место.

- Плашка ожидающего вопроса над полем ввода: `#code-ask-pin`, `#code-ask-pin-allow|deny|show` нажимают кнопки самой
  карточки; обновление — MutationObserver ленты.
- Черновики: `drafts`/`imageDrafts` в `code-chat.js` — класс `Drafts`; событие `studio-code-draft {key: "aid/chat",
  draft}`, `code.js` держит `draftKeys`. `code-tabs.js::tabBar` — опция `move`, `show({drafts, offline})`; классы
  `.code-tab-draft` (✎), `.code-tab-offline` (кольцо «не на связи»), `.dragging`, `.reordering`. Ряд вкладок
  отключённого компьютера виден.
- Перетаскивание вкладок (`op: move` рабочего места, [agents.md](agents.md)): мышь — после 6 px, палец — после
  удержания 400 мс; клавиатура — Shift+←/→.
- Если вкладки не помещаются, колесо мыши над их рядом прокручивает его вбок. При выборе вкладки ряд показывает её.
- Звезда в строке проекта закрепляет его над другими при любой сортировке. `workspace` хранит только идентификаторы
  закреплённых проектов в учётке (`op: pin`). Закрытие вкладок проекта не меняет закрепление.
- `code.js::shortcut`: Ctrl+Alt+←/→ — соседняя вкладка; Ctrl/⌘+K — поиск сессий (без проекта — поиск проектов);
  клавиши — по `event.code` (работает в русской раскладке); в поле ввода на macOS Ctrl+K не перехватывается.
- `code-panel.js`: `lastSeenText` («был на связи сегодня/вчера в …», в поясе учётки), поиск проектов
  `#code-project-search` — первое поле панели сортировки `#code-project-sort-menu` (регистр и е/ё не различаются,
  Escape сначала очищает, затем закрывает панель), `.code-project-read` «Отметить прочитанными ·
  N» (`POST …/projects/{pid}/seen`).
- Тесты — `tests/test_ui_agent_inbox.py`, `tests/test_workspace.py`, `tests/test_code_activity.py`. На хосте разработки
  Chromium сообщает `prefers-reduced-motion: reduce` — сценарии анимаций это учитывают.

## Ловушки

- Метку записи истории `{entry: n}` ставит роутер `app.js` каждой показанной записи; по ней `code.js` `hold()`
  отличает «Назад»/«Вперёд» (запись с меткой — не трогать, адрес файла с правкой — новой записью после неё) от новой
  записи. Раздел, меняя адрес своей записи, пишет `history.replaceState(history.state, …)`, а не `null`: иначе метка
  пропадёт, и «Остаться» с несохранённой правкой затрёт запись, куда ушли (сторожат
  `test_code_unsaved_edit_back_*`).

- Плашка пути раздела — `#code-place`, а не `#code-path`: этот id — путь папки во «Файлах» (`code-files.js`), и
  `.code-crumbs` / `.code-crumb-here` остались только у него.
