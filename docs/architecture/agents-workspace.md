# «Агенты» на странице и возможности по capability

Пометка «(мост ≥ X)» — с какой версии мост объявляет нужную capability; без неё страница скрывает кнопку или сервер
отвечает 409 `unsupported`. Полная таблица — [agent-bridge.md](agent-bridge.md#capability-и-версии-моста).

## Ссылки на файлы в ответах

`code-file-links.js` распознаёт в ответах помощника относительные пути проекта и абсолютные пути Windows
(включая `/C:/…`, `file:///C:/…`, пробелы, URI-кодирование и суффикс номера строки). `markdown.js`
нормализует их до очистки DOMPurify; `code-chat.js` открывает через `openFile`, не отправляя путь в HTTP URL.
Одинаково для истории, worker-разбора и потока; путь вне текущего проекта не становится HTTP-ссылкой.
`POST …/projects/{pid}/image` читает `raw` через обычные owner/PIN/CSRF guards, проверяет в потоке
base64/10 МиБ/формат PNG, JPEG, WebP, GIF/16 Мп и повторно проверяет сессию после проверки изображения.
Изображение не сохраняется и не кэшируется; blob страницы освобождается при смене файла и уходе.

## Инструменты рабочего места

studio-agent 0.8.0: `file_suggestions`, `chat_search`, `queue_edit`, `chat_fork`, `subagents`, `worktrees` —
необязательные возможности `hello`, §11 [протокола](../../docs/superpowers/specs/2026-10-28-studio-code-bridge-protocol.md).
Поиск/пути только на компьютере; сервер ретранслирует POST body. `code-autocomplete.js`, `code-diff.js`,
`code-queue.js`, `code-subagents.js`, `code-worktrees.js` дополняют рабочее место; новые кнопки скрыты для
старых мостов. Редактирование ставит очередь на паузу до сохранения/отмены; исходное задание не прерывается.
Ветвление/дети — Claude и Codex через штатные API; worktree открывается отдельным проектом из HEAD,
переписка и локальные настройки туда не копируются. Проверки: `test_code_discovery.py`, `test_ui_code_tools.py`,
сценарий `code_file_hints_and_held_queue` в `test_ui_webkit.py`, соответствующие тесты `agent/tests/`.

## Раздел, активность, контекст, Git, сводки

Раздел называется «Агенты» (адреса `#/code` и `/api/code/*` прежние). studio-agent 0.7.0:
`hello.attachments` — произвольные `{name,mime,data}` через `Turn.attachments`, 8 файлов вместе с images,
5 МиБ/файл и 8 МиБ суммарно; файлы живут в приватном temp машины до disconnect CLI.
`hello.project_activity` — `GET …/agents/<aid>/activity` → op `activity`, только project/chat/engine/running/asking
всех трёх Runner, без истории. `hello.subscription_usage` — `GET …/agents/<aid>/usage?engine=…&refresh=…`,
`code_usage.py` фильтрует ответ, `subscription.py` кэширует 60 с и объединяет одновременные проверки.
`GET /api/code/activity` добавляет названия из `chats` моста и непрочитанные завершения. В «В работе»
и панели проектов — работающие сессии, требующие действия и завершённые непрочитанные, с названиями
и ссылками. Схема 28, `code_attention`: только id компьютера/проекта/чата, случайная ревизия завершения,
время и отметка просмотра; названия и переписка в базе не сохраняются. `bridge.deliver` отмечает каждый
`done`, независимо от наблюдателей; SSE и свежая история передают ревизию `attention`.
`POST …/chats/<chat>/seen` требует владения, открытого PIN и CSRF, снимает только переданную ревизию.
`code-chat.js` подтверждает просмотр после отрисовки конца ответа в видимом чате; открытие меню,
фоновая вкладка и прокрутка старых сообщений отметку не снимают. Часового ограничения нет;
фоновые проверки скрывают данные закрытого/offline компьютера. Обновлять мост для этого не требуется.
Проверки — `test_code_activity.py`, `test_ui_agent_attention.py`, миграция в `test_foundation.py`.
Месячный лимит не выдумывается, неизвестные окна — available=false; Claude OAuth usage недокументирован.
Круг контекста: <50 зелёный, 50 жёлтый, 70 оранжевый, 90 красный. `code-context.js` открывает подробности
сессии по нажатию: окно, занято/свободно, расход, модель/права/id. Мост 0.7.4 добавляет необязательный
`context.usage`: накопленные счётчики Codex и главной сессии Claude (SDK-история без дублей по message.id).
Слева от контекста `#code-cache` показывает оценку оставшегося времени кэша: Codex GPT-5.6+ —
30 минут, Claude — 5 минут или час только по отчёту `cache_creation` (смешанный кэш — короткий срок).
Мост 0.15.2 передаёт необязательный `context.cache {updated_at?, model, ttl_seconds?, message_id?}`;
Codex восстанавливает время последнего изменения счётчиков из ограниченного хвоста JSONL,
Claude сохраняет начало ответа SDK и сверяет API message.id при чтении истории. Повторные блоки,
открытие чата и перезагрузка не продлевают отсчёт. Неизвестное — «—», ноль не доказывает удаления
серверного кэша; все числовые таймеры помечены «≈». OpenCode не показывает этот индикатор.
Справа `code-usage.js` показывает остаток недели сразу при открытии чата, по нажатию — остальные лимиты.
(мост ≥ 0.14.2) статистика Codex показывает `summary.available_resets` из
`account/rateLimits/read.rateLimitResetCredits.availableCount`, включая ноль. Если счётчик не передан,
показано «Не сообщается»; число не выводится из списка credits. Просмотр не расходует сбросы.
(мост ≥ 0.14.3) `statistics.reset_credits[].expires_at` передаёт сроки доступных сбросов Codex:
индивидуальные даты в поясе учётки, неизвестное — «Не сообщается», неполный список явно подписан.
`code-git.js::gitLevel` задаёт красный/жёлтый/зелёный цвет Git в шапке и боковой панели; неизвестное — нейтральное.
В шапке порядок: статус Git → Git → Файлы → Доступ → Чат («Доступ» — владельцу проекта). Нажатие статуса открывает окно с четырьмя действиями:
коммит; коммит и пуш; коммит и пуш во все Git; коммит, пуш во все Git и деплой. Во вкладке Git этих кнопок нет.
Каждое действие проверяет diff и тесты и создаёт коммит при наличии изменений; пустые коммиты не создаются.
Действие возвращает в выбранный чат проекта и отправляет задание текущему помощнику, сохраняя черновик.
Без выбранного чата автоматически создаётся чат первого доступного агента по приоритету учётки; при подготовке действия и занятости чата
кнопки недоступны. `code.js` сверяет список чатов при открытии окна действий и перед выполнением действия.
Окончание задания обновляет Git и сводку проекта; `gitinfo.status` без upstream добавляет unpushed по локальным refs.
`appearance.js` и ранний `theme.js` применяют размер текста 85–150% и масштаб 50–100% с шагом 5% из localStorage
(только настройки вида). `code-tabs.js` сохраняет узлы; `code-chat.js` кэширует до 12 историй только в памяти
с обязательной сверкой при возврате, сбрасывает историю по closed/done. Серверная история и тексты не кэшируются
на диске браузера. `code.js` держит в памяти списки названий 20 последних проектов с ключом учётка/компьютер/проект;
«+» показывает сохранённый список сразу и обновляет в фоне, одновременные обновления объединяет.
`code-sessions.js` ищет по словам названия (регистр и е/ё не различаются), сохраняет запрос при обновлении;
длинные названия ограничены двумя строками с полным текстом в title. Браузерные проверки — `tests/test_ui_agent_controls.py`.
(мост ≥ 0.7.3) `hello.project_summary` объявляет `GET …/projects/<pid>/summary` → op `project_summary`.
Счётчики активных `FINDINGS.md`/`IDEAS.md`, изменённых файлов, незапушенных коммитов и дата изменения —
`agent/studio_agent/project_summary.py`, без содержимого и путей в ответе. В `code-panel.js` четыре параллельных
чтения. С 0.13.0 снимки панели сохраняются между переходами, отдельно по учётке и компьютеру;
сначала читаются видимые строки, скрытая мобильная панель очередь не запускает. Готовые строки
рисуются сразу; ручное обновление принудительно проверяет весь список и сохраняет прежние значения при ошибке.
`.code-panel-footer` вне прокрутки содержит сортировку, кнопку и дату обновления показанных сведений.
Сортировка и компактная кнопка ↻ с подсказкой «Обновить сведения» — в один ряд, дата — ниже.

Ускорение 0.13.0: `GET /api/code/agents/<aid>/access` проверяет владение и PIN перед показом
кэшированной истории. Список сессий и история обновляются в фоне; при известном движке текст не ждёт
полного каталога. Современный мост должен подтвердить параметры сессии до отправки; неизвестный
движок из неполного списка не угадывается. Начальная история — 12 сообщений, прежние — по 30, со стрелками;
содержимое закрытых шагов ленивое, Markdown разбивается на кадры с общим бюджетом 6 мс. Тексты свыше 8000
знаков разбираются в Worker; DOMPurify и подсветка остаются в странице, отказ Worker оставляет безопасный текст.
Worker завершается при очистке доступа и имеет таймаут 10 с; история и Markdown на диск не попадают. Поток большого
ответа показывает текст до окончательной разметки. Кэш историй ограничен также оценкой памяти 8 МиБ,
очищается при блокировке, закрытии компьютера и отзыве доступа. Опрос Git/каталога — 20 с при работе,
60 с в спокойном проекте; статус активности общий для значка и панели. Настройки объединяют чтение компьютеров.

## Панель проектов, файлы, сводка, GitHub и remote

Во время перечитывания проектов и их сводок ↻ вращается, строка даты показывает «Обновляю сведения…»;
`aria-busy` и блокировка кнопки снимаются при успехе и ошибке, ответы прежнего компьютера не меняют новый.
При `prefers-reduced-motion` остаётся текст без вращения. Установщик EXE и пояснение о необходимости агента —
вверху корня «Настроек», перед разделами; во вложенных настройках блок скрыт. В пустом разделе «Агенты» — та же подсказка.
Выбор сортировки сохраняется в localStorage `studio-code-project-sort:<user_id>`, отдельно для каждой
учётки в этом браузере; восстанавливается до показа панели, неизвестное значение — «По имени».
«Сначала публичные»/«Сначала приватные» группируют по подтверждённой публичной копии `summary.github`:
есть копия / `null`; неизвестный статус, `github_pending` без прежней копии, старые мосты без поля и
папки без Git идут в конце. Внутри группы — по имени; отложенный ответ GitHub обновляет порядок.
Подпись сортировки — не мельче 11px. Кнопка открывает панель с поиском первым полем и вариантами сортировки;
текст поля и вариантов одинакового размера, на сенсоре не меньше 16px (без автозума iOS).
Экран новой вкладки `code.js::sessions` сбрасывает прокрутку `#view`, чтобы список истории начинался сверху.
Дерево `code-files.js` показывает расширение, размер файла в байтах, даты создания/изменения;
счётчики файлов/подпапок — только непосредственные дети, после раскрытия (при truncated — нижние границы `≥`).
Таблица прокручивается по горизонтали внутри своей области. После сохранения перечитывается родительская папка.
(мост ≥ 0.8.1) `hello.file_operations` включает создание файлов/папок и меню «⋯» для переименования,
перемещения и удаления: `POST …/files/operate` → `file_operation {project,operation,path,destination}`.
Назначение не перезаписывается (`exists`, HTTP 409), корень и пути через reparse-point запрещены.
Удаление папки рекурсивное с явным подтверждением в интерфейсе; вложенные junction не обходятся.
Операция над открытым несохранённым файлом/его предком отклоняется интерфейсом до сохранения.
Сохранения и операции сериализованы в мосте; успешная операция сбрасывает статистику и обновляет дерево/Git,
перенос открытого файла меняет путь редактора. Проверки: `test_file_operations.py` обоих наборов,
`test_ui_file_operations.py` (320/1280 px и старый мост).
Необязательный `files.items[].created` появляется с мостом 0.7.5; старый мост — `—`, без выдуманной даты.
(мост ≥ 0.7.6) кнопка «Просчитать все подпапки» → `POST …/files/stats` → op `file_stats`, один обход
`agent/studio_agent/file_stats.py`. В памяти дерева — рекурсивные размеры/счётчики и дата, без раскрытия папок;
сохранение, изменение состава Git и closed сбрасывают снимок. Неполные данные — нижние границы `≥`.
Пределы: 20 с, 5000 папок вместе с корнем, около 4 МиБ ASCII-JSON; ссылки не обходятся, содержимое не читается.
`project_name` в кадрах `ask`/`done` всех трёх помощников добавляет имя проекта в push рядом с компьютером;
только имя папки, не полный путь и не название чата. Старый мост сохраняет прежний текст push.
У проекта показаны название с `(П: N · И: N)`, затем Git и короткая дата; ссылки переносятся, если не помещаются. Счётчики —
отдельные ссылки `?tab=files&journal=findings|ideas` (фиксированные журналы), Git — `?tab=git`;
обычная защита несохранённых правок `code.js::hold` действует и для этих переходов.
Свободная область обеих строк проекта пересылает нажатие его ссылке с сохранением модификаторов;
самостоятельные ссылки журналов и Git, а также выделение текста не перехватываются.
Проверки — `tests/test_project_summary.py`, `tests/test_ui_project_summary.py`, `tests/test_ui_webkit.py`
и `agent/tests/test_project_summary.py`; активному мосту обновление из его задания не применять.
(мост ≥ 0.9.2) необязательное `summary.github` добавляет статус публичной копии текущей ветки:
`{state: current|behind|ahead|diverged|missing|unknown, behind, ahead}`, `null` — нет публичного remote.
`agent/studio_agent/github_status.py` читает `remote.github.url` (либо GitHub origin), анонимно получает
smart-HTTP refs без GitHub API, ключей, fetch и записи refs; считает разницу по локальному графу.
Неизвестный объект/shallow/ошибка — unknown. `code-panel.js` показывает все ссылки; GitHub ↓N красный,
✓ зелёный, ↑N жёлтый, устаревшие сведения нейтральные. Проверки — `agent/tests/test_github_status.py`
и перечисленные браузерные сценарии, нажатие GitHub проходит обычную защиту несохранённых файлов.
(мост ≥ 0.10.1) необязательное `summary.remotes` — список `{name, state, behind, ahead}` всех настроенных
remote, кроме `upstream`. `agent/studio_agent/remote_status.py` читает имена через `git remote` и сравнивает
`refs/remotes/<name>/<branch>` с HEAD; без сети, credentials и fetch, общий бюджет 5 с.
Отсутствующий ref, shallow/detached/пустая история и ошибки — unknown. Это локальный снимок,
актуальное состояние сервера может отличаться. `code-panel.js` показывает дополнительные remote
(`cld` и другие); `origin` уже представлен общей меткой Git, живая метка GitHub не дублируется.
API фильтрует имена и счётчики, URL/ключей нет. Проверки — `agent/tests/test_remote_status.py`
и существующие API/Chromium/WebKit сценарии сводки, включая stale и защиту несохранённых файлов.

## OpenCode, ход по шагам, индикаторы, выбор модели

OpenCode (2026-10-30, studio-agent ≥ 0.5.0) — третий помощник раздела «Агенты»: `engine: opencode`,
необязательный каталог `hello.opencode` → `/api/agents.opencode`. Модели — `provider/model` до 300
знаков, варианты усилия — из CLI до 64 знаков; прежние ограничения Claude/Codex сохранены.
Шаг схемы 23 расширяет CHECK `code_chats.engine`, сохраняя записи, id, индекс и каскады.
Умолчания учётки также принимают `opencode`; права — `default`/`auto` (правила OpenCode/подтверждение
его запросов). Старый мост без каталога — 409 `unsupported`. История и тексты остаются на машине;
ACP по stdio, связи сессий и локальные настройки — [agent/CLAUDE.md](../../agent/CLAUDE.md).
Мост 0.15.0: `timeline` в истории и снимке хранит порядок текстовых сегментов и шагов без
копии текста; смещения — UTF-16 для JS, включая emoji. `timeline.py`, `Feed.note`, общий `_send`;
нормализация Claude/Codex/OpenCode сохраняет тот же порядок. Урезка истории удаляет позиции,
которые стали неверными, и интерфейс использует совместимое представление. `progress` и
`step_update` ретранслируются обычным защищённым SSE. Codex передаёт общий diff/план/дочерних
агентов, поток вывода, process id, duration/exit code; снимок атомарно копирует порядок и сводку
до фонового кодирования. `code-progress.js` раскрывает сводку лениво, `code-diff.js` показывает
сравнение рядом на широком экране и единым потоком на узком. Сводка не пишет тексты на диск;
после завершения история содержит только сведения, сохранённые CLI.
`code-changes.js` показывает файлы последнего ответа в строке кэша/контекста/статистики:
значок со счётчиком → список → diff выбранного файла → обычный `openFile` полного файла.
План, процессы и дочерние агенты остаются в сводке ответа; список файлов обновляется из progress/steps.
Пакетная правка в заголовке шага показывает количество уникальных файлов и отдельную ссылку каждого.
Проверки:
`agent/tests/test_codex_progress.py`, `tests/test_ui_code_progress.py` (Firefox/Chromium/WebKit,
320/1280, reload и оба оформления).

WebSearch передаёт действие и ограниченную выдачу из событий Codex через обычные поля шага `input` и `text`.
Карточка обновляет ввод при получении результата. В открытом чате прокручивается `#code-chat-scroll`,
а статус и поле задания занимают отдельное место под лентой.
Команды по умолчанию свёрнуты, включая небольшие диффы; `#code-toggle-steps` между стрелками
переключает все шаги. Выбор действует в открытом представлении, новые шаги его наследуют;
повторное открытие начинает со свёрнутых. Markdown сегмента истории ставится в очередь при
добавлении его узла в ленту; ожидание отрисовки списка включает вложенные задания Markdown,
чтобы `data-loaded` и подтверждение просмотра не опережали текст длинной истории.

Индикатор `#code-activity` над полем задания показывает думает/инструмент/ответ/ожидание/итог;
событие `activity {state, tool?}` и `snapshot.activity` несут стадию Codex/OpenCode, без текста
рассуждений. Старые мосты — по `text/step/result/ask/done`. Очистка, скрепка и микрофон — компактной
колонкой справа; статус — над рамкой. В этой же строке справа — иконки ветки и подзадач,

вертикальной колонкой справа поверх ленты над полем задания. Превью команды ограничено двумя строками.
Кэш открывает отдельное окно только со счётчиками чтения/записи и оценкой времени кэша;
параметры сессии и заполненность остаются в окне контекста.
Принятое уточнение вставляется в текущую хронологию: новые команды и текст идут после него,
ранее начатая команда обновляется на прежнем месте. Мост 0.15.3 сохраняет это место в снимке активного хода.
Переключатель доставки уточнения — в поле справа от прав доступа.
Дублирующая шапка чата убрана, закрытие — крестиком вкладки.
Поле ограничено 25dvh. На сенсорных устройствах поля и select имеют минимум 16px с учётом масштаба интерфейса

Поле закреплено внизу и в пустом чате; открытие истории и возврат во вкладку показывают её конец.

## Поведение страницы

- `code-chat.js::loadHistory`: первая удачная загрузка истории (флаг `opened`) запрашивает `/state` и выполняет
  отложенное Git-действие; `onVisibility` не открывает live второй раз. `#code-reload` «Повторить» в
  `.code-status-bar` при любой ошибке загрузки (на узком экране — значок); сам повторяет через `RETRY_MS` при
  `offline`/`network`/`timeout`/≥ 500 фоновым запросом (`x-studio-passive`). Обёртка `api` в `chatView` передаёт
  заголовки.
- `code.js::failed` очищает кэши (`studio-code-clear`) только при `closed` и 404 компьютера (`computer: true`), а не
  при любом `not_found` «Файлов».
- `code-panel.js::select`: повторный выбор того же компьютера отменяет идущее обновление сводок и снимает занятость ↻.
- `code-desktop.js`: смена монитора сохраняет текст и буфер, их очищает только `stop()`.
- `code-picker.js::codePicker`: модель, усилие и права — отдельные кнопки на всех экранах, рядом с отправкой.
  Меню поддерживает стрелки, Home/End, Esc/Tab и возвращает фокус; закрывается при прокрутке/ресайзе.
- `code-status-bar.js`: текст состояния получает не меньше 40% строки, кнопки — до 60%, дополнительные действия — панель «⋯».
  Справа постоянно видны шесть кнопок: подзадачи, команды, изменённые файлы, кэш, контекст и подписка.
  Счётчики подзадач, команд и файлов оформлены одинаковыми цифрами без цветной заливки.
  Если помощник или мост не поддерживает подзадачи/кэш, соответствующая кнопка недоступна и показывает «—».
  Действия переносятся по одному по измеренной ширине; круг контекста сохраняет форму. В панели — явные подписи,
  а счётчики находятся внутри своих строк. Размеры подстраиваются под свободные 60% строки и масштаб.
  `code-subagents.js` обновляет число работающих по событиям хода и опросом при видимой странице;
  завершённые остаются в списке вместе с их историей.
  Открытая история выбранной подзадачи обновляется каждые две секунды и кнопкой «Обновить» вместе со списком;
  позиция чтения, раскрытые команды и фокус сохраняются. При скрытии страницы запросы отменяются.
- `code-commands.js`: постоянная кнопка статуса со счётчиком активных Shell/Bash-команд; в покое показывает `0`,
  по нажатию — «Нет выполняемых команд». Открытая панель сохраняется и после завершения последней команды.
  Панель содержит раскрываемые шаги с командами и живым выводом; завершённые уходят из активного списка, сохраняясь
  на своём месте в ленте. Сводка над ответом больше не дублирует активные команды; план и подзадачи остаются.
- `code-chat-images.js`: ссылки `messages[].images` загружаются возле экрана через защищённый POST `/image`.
  Изображения остаются в памяти открытого чата; при прокрутке и уходе освобождаются blob и запросы.
  Смена чата и возврат восстанавливают изображение на компьютере через мост с `hello.history_images`.
  Картинки уточнений отображаются и в живом событии, и после восстановления снимка хода (мост ≥ 0.19.1);
  байты читаются тем же защищённым запросом, отдельно от компактного снимка.
- Рамка поля ввода остаётся внутри `.code-compose-area` при вложениях, длинном тексте и низком окне;
  прокручивается содержимое формы, строка отправки закреплена внутри рамки.
- `code-chat.js::grow`: лента следует за ходом, включая отложенную разметку Markdown и изменения высоты.
  Небольшой отход от конца сохраняет слежение; прокрутка далеко вверх и переход к старому сообщению отключают его.
- `code-chat.js::askNode` выводит `p.code-ask-subtask` «Подзадача · <имя>» для вопросов и разрешений субагентов.
- Опрос меток вкладок и Git: `code.js` `IDLE_POLL_SEC` — 20 с, пока в проекте идёт ход или ждёт ответа, иначе 60 с;
  не дольше `IDLE_POLL_FOR_SEC` после действия владельца, только при видимой странице. Порядок кнопок в шапке —
  статус Git → Git → Файлы → Доступ → Чат (`code.js`, «Доступ» — отдельное действие между видами `VIEWS`).

## Ловушки

- Метку записи истории `{entry: n}` ставит роутер `app.js` каждой показанной записи; по ней `code.js` `hold()`
  отличает «Назад»/«Вперёд» (запись с меткой — не трогать, адрес файла с правкой — новой записью после неё) от новой
  записи. Раздел, меняя адрес своей записи, пишет `history.replaceState(history.state, …)`, а не `null`: иначе метка
  пропадёт, и «Остаться» с несохранённой правкой затрёт запись, куда ушли (сторожат
  `test_code_unsaved_edit_back_*`).

- Плашка пути раздела — `#code-place`, а не `#code-path`: этот id — путь папки во «Файлах» (`code-files.js`), и
  `.code-crumbs` / `.code-crumb-here` остались только у него.
