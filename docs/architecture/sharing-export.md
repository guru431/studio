# Ссылки «Поделиться» и экспорт

`chat_shares.py`, схема 33: один отзываемый снимок на обычный или агентский чат.
`GET/POST/DELETE …/chats/<id>/share` остаются под сессией, CSRF и блокировкой раздела;
создание снимка «Агентов» читает все страницы `history` через обычный owner/PIN guard и
повторяет проверку после хеширования PIN, перед публикацией. Ссылку на агентский чат создаёт и отзывает
только владелец компьютера (`chat_shares._own_computer`): участнику совместного проекта POST/DELETE — 403
`owner_only`, GET — `enabled: false`, меню `chat-share.js` без `share` прячет «Поделиться ссылкой». Строки
участников, записанные прежним кодом, удаляет `chat_shares.disown()` при старте (`main.lifespan`), отзыв
участника (`project_access.drop`) — его ссылки на проект. Каждое создание меняет адрес
и отзывает предыдущих читателей; очистка истории и аварийный выход удаляют все снимки учётки и снимки чатов
её компьютеров, удаление чата/компьютера/учётки — каскадом. PIN — строго четыре ASCII-цифры, scrypt; секрет ссылки — случайные 32 байта,
в БД digest и зашифрованная копия для владельца. Публичная `/share#<token>` — отдельная оболочка
без учётной сессии; `/share/unlock`, `/share/check`, `/share/file` получают секреты телом JSON
(не URL), ограничивают тело 4096 байт и запрещают чужой Origin. Просмотр каждый раз требует PIN,
read-токен живёт только в памяти страницы, не даёт прав API учётки и истекает через 8 часов.
Паузы после пяти попыток на ссылку и 30 на IP за 15 минут хранятся в SQLite; попытка резервируется
до await. Вложения — только из снимка, скачивание с `attachment`, `octet-stream`, CSP sandbox;
отзыв перепроверяется при чтении. Всё публичное — `no-store`, `no-referrer`, `noindex`.
`chat-share.js` — окно владельца; `share-view.js` — только просмотр, без cookie и browser storage;
возврат Back/Forward тоже стирает текст и просит PIN. Тесты — `test_chat_shares.py`,
`test_ui_chat_shares.py` (Firefox/Chromium/WebKit, 320/1280).

Хранение и пределы (шаг схемы 36, `db.SHARES_36`):

- Снимок — только шифром `STUDIO_DATA_KEY`: `chat_shares.sealed` (как токены подключений). В прежнем столбце
  `chat_shares.snapshot` — заглушка `chat_shares.PLACEHOLDER` («Ссылка недоступна» / «попросите прислать ссылку
  заново»): её покажет прежний код после отката. Открытые снимки (до шага 36 или записанные прежним кодом) шифрует
  `chat_shares.seal()` в `main.lifespan` сразу после `migrate` (на время — `PRAGMA secure_delete`, после —
  `wal_checkpoint`). Сменили ключ данных — получателю 404 `share_gone`, владельцу `url: null` с пояснением; без 500.
- Срок `ShareIn.days`: 1, 7, 30 или null (бессрочно), `chat_shares.DAYS`, `chat_shares.DAYS_DEFAULT` (7). Истёкшая
  удаляется со снимком при старте и при любом обращении к ссылкам (`chat_shares._expire`). GET/POST ссылки отдают
  `expires`, `views`, `viewed`, `fails`; окно владельца показывает срок, открытия, последнее открытие, неверные PIN.
- Рассуждение модели в ссылку по умолчанию не входит: `ShareIn.reasoning` (строгий bool, false);
  `chat_shares.regular_snapshot(uid, chat_id, reasoning=True)`. Агентский снимок рассуждения не содержит.
- Предел PIN: каждый неверный — журнал `share_pin_fail` (с адресом посетителя); начало 15-минутной паузы —
  `share_locked`/`pause`; после `chat_shares.FAILS_MAX` (50) неверных в сумме ссылка удаляется — `share_locked`/`revoked`,
  владельцу push и ntfy «Ссылка «Поделиться» отключена: 50 неверных PIN» (без содержимого). Число 50 дублировано в
  `chat-share.js`.
- Срок жизни снимка: до срока ссылки, отзыва, `FAILS_MAX` неверных PIN, удаления исходного чата/компьютера/учётки,
  «Удалить всю историю» или аварийного выхода — и в ночных копиях базы (шифром), пока их не вытеснят 7 более новых
  успешных копий. Выгрузка истории (`takeout`) снимков не содержит.

## Экспорт

`chat_exports.py` использует те же `regular_snapshot` / `agent_snapshot` и owner/PIN-проверки для
`POST …/chats/<id>/export {format: "md"|"pdf"}`. Экспорт не создаёт публичную ссылку; включает
всю переписку, команды/вывод и имена вложений. После PDF повторяются проверки сессии, раздела,
поколения истории и исходного чата; у «Агентов» — ещё живой PIN. PDF — через общий CLI `md2pdf.py`,
строго закреплённый `deploy/md2pdf.sha256` (доставка байт-в-байт из `STUDIO_MD2PDF_SOURCE` или
`~/.claude/bin/md2pdf.py`). Markdown перед рендером разбирается без HTML; изображения превращаются
в текст, внешние/локальные ресурсы не загружаются. Файлы и профиль браузера — в локальном приватном
`tmp/chat-export-*`, удаляются в finally и при старте; ключ данных не передаётся конвертеру.
`HOME`, `XDG_CONFIG_HOME` и `XDG_CACHE_HOME` дочернего процесса тоже указывают в этот каталог:
у службы HOME `/nonexistent`, без этого Chromium отказывает `chrome_crashpad_handler: --database is required`.
Одновременно не больше двух PDF на службу и одного на учётку, бюджет конвертера 45 с.
Кнопка в строке состояния `code-chat.js` и кнопка обычного чата используют `chat-share.js::shareMenu`:
нативный popover с размещением внутри экрана, четыре пункта, клавиатура и закрытие при смене чата/раздела. Тесты:
`test_chat_exports.py`, `test_ui_chat_exports.py` и прежние сценарии общего доступа.

- Экспорт без выделения берёт полный снимок: рассуждение обычного чата входит (файл владельца, не публичная ссылка); выбора
  для экспорта (`ExportIn.reasoning`) нет.
- `chat_exports._safe_html` выдаёт один HTML-блок (переводы строк внутри `<pre>` → `&#10;`, пустые строки вне `<pre>`
  убраны): md2pdf (`MarkdownIt("commonmark", {"html": True})`) пропускает его без изменений — ни `<img>` из кода, ни
  заголовков/курсива. Регрессия прогоняет вывод через markdown-it.
- Конвертер — `chat_exports.converter`: `STUDIO_MD2PDF`, иначе `deploy/md2pdf.py` выкладки (его хеш сверяет `install.sh`
  с `deploy/md2pdf.sha256`), иначе `~/.claude/bin/md2pdf.py` (разработка; без сверки хеша). На хосте нужен Chromium
  (`chromium` и `fonts-dejavu-core` входят в Docker-образ, в прежней установке их ставит `install.sh`);
  два PDF сразу — два Chromium в пределах 2 ГБ. Песочница Chromium в Docker включена:
  [профиль seccomp и SYS_CHROOT](deploy-docker.md).

### PDF выделенного фрагмента

`chat-selection.js` читает нативный DOM Range только внутри ленты текущего чата. Копирует
выбранные текстовые узлы вместе с их предками: частично выбранные strong/code, ячейки таблиц,
отступы pre, классы подсветки и исходные номера ol сохраняются. Служебные кнопки и скрытые блоки
не копируются. Меню сохраняет выбор в памяти до перевода фокуса на кнопку/мобильное меню;
смена чата, закрытие раздела, шторка и уход со страницы очищают его. Browser storage не используется.
Выравнивание Markdown-таблиц сохраняется уже при показе чата: `markdown.js` выдаёт ячейкам только
разрешённые значения `align` (left/center/right), а стили `.md` их отображают. Произвольный `style`
по-прежнему удаляется при очистке; это относится и к фоновой отрисовке длинной истории.

`ExportIn.selection` — необязательный HTML-фрагмент до 1 000 000 символов, только для PDF.
Серверный `chat_export_selection` заново пропускает его через разрешённые теги оформления,
атрибуты списков/таблиц, web/mailto-ссылки и классы подсветки. Пользовательские стили, изображения,
скрипты и внешние ресурсы не допускаются; печатные стили задаёт сервер. Фрагмент передаётся
md2pdf одним HTML-блоком и не разбирается повторно как Markdown. Название чата используется
для имени файла, в документ добавляется только выбранный текст. Путь использует те же
лимиты PDF, приватный временный каталог, проверки владельца и повторные проверки после рендера.
У «Агентов» до и после рендера проверяется история с limit=1, без скачивания остальных страниц.
