# «Open WebUI»: учётки Open WebUI внутри Студии

Раздел `#/owui` — второе окно к серверам Open WebUI 0.13+ владельца: дерево чатов учётки, чтение, продолжение и
новые чаты с выбором модели, живой поток, «Остановить», вложения, пауза ответа (вопрос модели, подтверждение
инструмента) и push. В Open WebUI ходит только сервер Студии; браузер не получает ни токена, ни адреса запроса.
Переписка не оседает ни в базе, ни в журнале Студии: в базе — только учётка (`owui_accounts`, шаг схемы 63).
Решения и протокол — [спека](../superpowers/specs/2026-11-22-studio-open-webui-design.md); проверено на 0.13.4.

## Учётка и вход (`owui`)

`POST /api/owui/accounts {label, url, email, password, cert_sha256?}`, по шагам:

1. Подпись — до `owui.LABEL_MAX` (80) знаков, пробелы схлопываются. Адрес — схема, хост, порт и путь без `/` в
   конце, без userinfo, query и fragment. Адрес проверяется списком разрешённых до счёта попытки и до ввода-вывода:
   нет записи — 422 `unlisted` («попросите администратора добавить `host:port`»); имя — только https и только
   публичные адреса, частный сервер — IP-записью. Студия сама в список ничего не добавляет.
2. `GET /api/config` системными корнями. Сертификат не проверился — сервер получает его рукопожатием без проверки
   (`upstream.fetch_certificate`, срок `upstream.CERT_FETCH_SEC` (10)) и отвечает 409 `certificate`
   `{sha256, subject, not_after}`; повтор с `cert_sha256` сверяет отпечаток свежего сертификата и запоминает PEM.
   Версия ниже 0.13 или без `features.auth_sessions` — 422 `unsupported`.
3. Вход: неверный пароль — 422 `owui_login` (**не** `login`: этот код `api.js` понимает как конец сессии Студии и
   уводит на `/login`); учётка ждёт одобрения — 422 `pending`; второй код — 422 `mfa`; свой предел Open WebUI —
   429 `owui_locked`. Та же учётка Open WebUI на том же адресе — 409 `exists` (до создания сессии).
4. Постоянная сессия с именем `owui.SESSION_NAME`; строка пишется одним INSERT, JWT входа и пароль забываются сразу.

Неудачи входа — на учётку Студии: `owui.LOGIN_FAILS` (5) за `owui.LOGIN_WINDOW_SEC` (900), дальше 429 `owui_locked`
без запроса к Open WebUI; место занимается до запроса, так что параллельные попытки тоже считаются.
`POST …/{id}/login {password, email?}` — вход заново сохранённым email (другой пользователь Open WebUI — 409
`other_user`); новая пара пишется под блокировкой обновления, прежняя сессия отзывается JWT входа (неудача не мешает).
Сохранённое не читается (сменили `STUDIO_DATA_KEY`: в списке — `reenter: true` и `state: relogin`) — email берётся из
тела; без него — 422 `owui_email` до запроса и без счёта неудач; та же учётка Open WebUI в другой строке — 409 `exists`.
`POST …/{id}/certificate {sha256}` — принять сменившийся сертификат. `PATCH` — подпись. `DELETE` — закрыть
соединение, отозвать сессию (не дольше `owui.REVOKE_SEC` (5), отказ не мешает), удалить строку. Удаление учётки
Студии (`account.delete_user_data`) зовёт `owui.drop_user` до каскада; отключение администратором — то же без
отзыва (сессии живут до «Включить»). Аварийный выход учётки Open WebUI не трогает. Чужой и несуществующий id —
одинаковый 404 `not_found`.

## Токены (`owui_tokens`)

Рабочий токен сессии — только в памяти (`owui_tokens.TOKENS`, срок по часам Студии — `owui_tokens.TOKEN_SEC` (900));
долгий — шифром в `secret_enc` вместе с `session_id` и `pending_request_id`. Обновление — когда до конца меньше
`owui_tokens.REFRESH_AHEAD_SEC` (120), под блокировкой учётки; перед запросом пишется `pending_request_id`, и обрыв
между ответом Open WebUI и записью восстанавливается повтором того же `request_id`. `owui.call` на 401 сначала
сверяет тот же токен `owui.CHECK_PATH` (`owui._rejected`: Open WebUI 0.13.4 отвечает 401 и на чужой или
несуществующий чат, а частота обновлений ограничена на адрес); отвергнут — `owui_tokens.renew` с `stale=`: обновляет,
только если в памяти всё ещё он, — параллельные 401 дают одну ротацию; принят — 401 ресурса возвращается как есть.
401 на обновление и нечитаемый `secret_enc` — `state = relogin` (`owui_tokens.relogin`, 409 `relogin`); нет связи
или не та форма — `owui_tokens.Unavailable` (503 `owui_offline`). Фонового продления нет: учётка без дела дольше срока сессии
Open WebUI тоже попадает в `relogin`.

## Запросы и сертификат

Все запросы — `upstream` с явным `Authorization` (`auth=`) и без переадресаций; срок обычного — `owui.TIMEOUT_SEC` (15).
Доверенный сертификат — якорь ровно для себя: `upstream.pinned_context` (`cadata` без системных корней, без
проверки имени, частичная цепочка, без `VERIFY_X509_STRICT` — строгость RFC 5280 при якоре-самом-сертификате ничего
не добавляет), клиент на сертификат — `state.pinned_http`, не больше `state.PINNED_MAX` (32); вытесненный
закрывается через `state.PINNED_GRACE_SEC` (600) — им может пользоваться идущий запрос. Несверенный сертификат в
любом запросе — 409 `certificate` с отпечатком нынешнего; сервер показал ровно закреплённый, а проверку тот не прошёл
(истёк) — 502 `owui_certificate`, без повторного подтверждения. WebSocket — `upstream.ws_target`: те же
проверки, соединение на проверенный IP, SNI и `Host` — имя.

Неожиданный JSON обновлённого Open WebUI (нет ключа, список вместо словаря, цикл в ветке) — 502 `owui_shape` со словами
про версию (`owui.shape_error`), не 500; сервер молчит — 503 `owui_offline` за ограниченное время, остальная Студия
работает. id чата, папки и файла в путь Open WebUI — только `owui.OWUI_ID`, иначе 404.

## Чтение

`GET …/tree` — закреплённые, папки (плоско, с `parent_id`; 403 Open WebUI — без папок) и первая страница чатов без
папки (по 60); `GET …/chats?page=N`; `GET …/folders/{fid}/chats` — страницы по 10, не больше `owui.FOLDER_PAGES_MAX`
(10); `POST …/search {text}` — запрос телом (строку запроса пишет журнал Apache), до `owui.SEARCH_MAX` (256) знаков;
`GET …/models` — модели без `agent:*` и скрытых, `default` — модель последнего чата или первая.

`GET …/chats/{chat}` — `owui_view.branch`: от `currentId` истории чата по `parentId`, шагов не больше числа сообщений,
цикл и пропавший родитель — конец ветки. У сообщения — текст, рассуждение (текст и секунды), инструменты (результат
обрезан до `owui_view.RESULT_MAX` (2000) знаков), файлы, прочие элементы `output` типами («элемент <тип>»), `done`,
`error`, `pending`; плюс `active` чата (`GET /api/tasks/chat/{id}`). Неизвестный и чужой чат Open WebUI отдаёт
**401**, а не 404: Студия отвечает 404 без обновления токена (сверка `owui._rejected`).
`GET …/files/{fid}` — поток с `no-store`, `nosniff`, `sandbox`; не картинка, звук или видео — `attachment`.

## Отправка, стоп, пауза, вложения

Новый чат `POST …/chats {model, text, files}` (201 `{chat_id, message_id}`) и продолжение `POST …/chats/{chat}/messages
{model, text, files, parent_id}` (`{message_id, queued}`) — серверный ход Open WebUI 0.13 (`POST /api/chat/completions`
с `session_id` сокета Студии — без него Open WebUI не включает встроенные инструменты). id сообщения и ответа — uuid4
Студии. `tool_ids` и `features` — как у страницы Open WebUI (возможности модели, `defaultFeatureIds`, настройки
пользователя); интерпретатор кода на `pyodide` и веб-поиск с подтверждением не включаются. `params.tool_approval_mode`
уходит, только если пользователь Open WebUI выбрал значение из `owui.APPROVAL_MODES`; `full` Студия не шлёт никогда.
`files` продолжения — прежние документы чата (`files` тела чата, что ещё есть в сообщениях ветки, —
`owui_view.chat_files`) и новые вложения-не-картинки без повторов по `id`, как страница Open WebUI 0.13.4: Open WebUI
перезаписывает присланным `files` тела чата и ищет по документам только в них. Итог ответа, пришедший раньше ответа
POST, ход не «воскрешает» (`owui_link.rekey`).
Ответ `{queued: true}` — ответ не держит сокет, наблюдателям — событие `queued`.

`POST …/stop` → `POST /api/tasks/chat/{chat}/stop`. `POST …/resolve {message_id, call_id, action, answers}` →
`resolve` Open WebUI; `answers` — по форме `owui.OptionAnswer` / `owui.OtherAnswer` и только к `answer`; уже решено —
409 `resolved`. После решения ответ снова «идёт» (`owui_link.track`), продолжение — тем же id ответа.

`POST …/files` — сырое тело до `owui.FILE_MAX` (20 МиБ) (больше — 413 без запроса), имя — `X-Studio-Name`; загрузка
не дольше `owui.UPLOAD_SEC` (120), затем опрос обработки раз в `owui.FILE_POLL_SEC` (1) с не дольше `owui.FILE_WAIT_SEC`
(300) (дольше — 504 `file_slow`). Обработка не удалась — 200 с `failed: true`: страница Open WebUI такой файл тоже
прикладывает, Студия показывает предупреждение на чипе. Картинку (`image/*`, кроме SVG) страница Open WebUI грузит
без обработки (`?process=false`) и не ждёт — так и Студия: статус такой картинки навсегда `pending`, а обработка
картинки как документа кончается `failed`. В сообщении — не больше `owui.FILES_MAX` (10) вложений.

## Соединение (`owui_link`)

Своё минимальное подключение Engine.IO 4 / socket.io 5 поверх `websockets`, только websocket, одно на учётку
(`owui_link.LINKS`). Открыто, пока есть наблюдатель SSE или идёт ответ на сообщение из Студии. Перед каждым сокетом —
`GET /api/v1/auths/` через `owui.call`: Open WebUI 0.13.4 принимает сокет с любым токеном (`always_connect`) и
отозванную сессию видно только по REST. Подключение (и `owui_link.ensure` отправки) ждёт не дольше
`owui_link.CONNECT_WAIT_SEC` (10). Ответ «держит» сокет до итога, ошибки, паузы или `active: false` своего чата.
Обратный вызов Open WebUI (`42<id>[…]`) получает немедленный отказ `owui_link.REFUSAL`, иначе ответ висел бы 60–240 с.
После каждого кадра — сверка рабочего токена: сменился — `user-join` со свежим токеном (Open WebUI перепроверяет
токен сокета каждые 30 с). Обрыв — `link down`, паузы 1, 2, 4 … до `owui_link.RECONNECT_MAX_SEC` (30), на связи —
`link up`; `relogin` — `link relogin`, соединение закрыто. Очередь наблюдателя — до `owui_link.WATCH_MAX` (2000)
событий, отстающий теряет лишнее; кадр — до `owui_link.FRAME_MAX` (16 МиБ).

События Open WebUI переводит `owui_view.normalize`: `list`, `title`, `active`, `delta` (`kind`: `text` | `reasoning`),
`item`, `done` (`error`), `pending`; неизвестное — молча. Пауза 0.13.4 приходит **снимком** `chat:completion {output}`
без `done`, где вызов в статусе из `owui_view.PAUSED`, и затем `chat:active {active: false}`; форма спеки
(`pending_approval: true`) тоже понимается.

## Поток на страницу и push

`GET …/events` — SSE учётки (`claude_code.SSE_HEADERS`): события выше, `queued` и `link {state}`; без событий
`owui.PING_SEC` (20) — `: ping`. Сессию поток сверяет на каждом пинге и на событиях не чаще `owui.CHECK_SEC` (5):
сессия кончилась, заперта для раздела (`lock_policy.locked`), учётку удалили — `closed` и конец; после `link relogin`
поток кончается. Страница держит не больше двух потоков: учётки панели и учётки открытого чата.

Итог, ошибка и пауза ответа на сообщение из Студии — `push.notify_later(…, quiet=True)` вне экрана: слова
`push.CHAT_NOTICES` или `push.DECISION_NOTICE`, заголовок `push.OWUI_TITLE`, ссылка `owui/<id>/<chat>`, без текста
ответа и вопроса. Ответы, начатые в самом Open WebUI, push не дают.

## Страница

`owui.js` — раздел и адреса `#/owui` (последнее место — `localStorage` `studio-owui-place`), `#/owui/<id>` (новый
чат учётки), `#/owui/<id>/<chat>`; `owui-panel.js` — учётки (точка: на связи / нет связи / войдите заново, «⋯»),
окно подключения с шагом сертификата, форма входа заново, поиск и дерево; `owui-chat.js` — лента (разметка
`markdown.js`, рассуждение свёрнуто, инструменты плашками), поток, поле с выбором модели (`picker.js`), вложения,
«Остановить», строка «в очереди»; `owui-pending.js` — карточка паузы: варианты и свой текст / «Разрешить» и
«Отклонить», срок вопроса не отсчитывается. Раздела нет в настройках, в «Поиске», в «Удалить всю историю» и в
разделах подключений — флаги реестра `sections-meta.js` (`history: false`, `settings: false`).

- Нажатие на учётку меняет только панель; лента справа и её поток остаются (второй поток — учётке панели).
- `closed` — обычный обрыв: повтор потока на 423 ждёт отпирания (`api.js`), после отпирания поток учётки снова
  открыт. Обрыв потока — событие страницы `lost`: следующее `link up` перечитывает чат и дерево; `up` новой
  подписки — нет. `relogin` учётки ленты, не показанной в панели, тоже ставит её точку «войдите заново».
- Метка «ждёт решения» снимается только `active: true`: пауза 0.13.4 кончается `active: false`.
- Пароль Open WebUI (подключение и вход заново) — поле как PIN компьютера (`ui.js` `computerPin`: не `password`,
  вне `<form>`), email — без автозаполнения: менеджер паролей не сохраняет его под адресом Студии и не подставляет
  пароль Студии для чужого сервера. Вход заново спрашивает email, если учётка `reenter` или сервер ответил 422
  `owui_email`.
- Разметка, дорисованная после показа чата (длинный ответ — в воркере), докручивает ленту вниз, если вид был у
  конца; пути файлов Open WebUI в тексте ответа (`/api/v1/files/<id>/content`) идут через сервер Студии полным
  адресом. После отпирания `lock.js` перезагружает и сломанные блокировкой картинки `/api/owui/`.

## Журнал и приватность

Журнал — `owui <id учётки>: …`, id учётки Студии, коды HTTP и отказов, числа (байты, число вложений), имена
классов исключений. Ни адреса сервера, ни email, ни текстов, ни имён файлов, ни id чатов и сообщений. Пароль —
только телом запроса входа. Сторожат тесты `caplog` в `tests/test_owui_*.py`.

## Выкладка

Apache: `ProxyPass /api/owui/ … timeout=600 flushpackets=on` и `no-gzip` раньше общего `ProxyPass /` — поток SSE и
вложение, которое служба отдаёт после загрузки и обработки (`owui.UPLOAD_SEC` + `owui.FILE_WAIT_SEC`); тело
вложения проходит общий `LimitRequestBody`. Сверяет `tests/test_deploy.py`.

## Проверки

Быстрые: `tests/test_owui_upstream.py`, `test_owui_tokens.py`, `test_owui_accounts.py`, `test_owui_view.py`,
`test_owui_read.py`, `test_owui_link.py`, `test_owui_send.py` (поддельный Open WebUI — `tests/fake_owui.py`: REST через

удаляются, учётка удаляется (сессия отзывается):

    OWUI_LIVE_URL=https://10.77.1.20:8443 OWUI_LIVE_EMAIL=… OWUI_LIVE_PASSWORD=… \
      .venv/Scripts/python -m pytest -q -n0 -m manual tests/test_owui_live.py

Вопрос модели (`ask_user`) модель задаёт не всегда: тогда эта часть — пропуск.

## Ловушки

- После каждого обновления рабочего токена живой сокет получает `user-join` со свежим токеном — иначе Open WebUI
  отключит сокет на ближайшей проверке (30 с).
- Отзыв сессии «Studio» в Open WebUI сокет не рвёт сам: заметно по REST (`GET /api/v1/auths/`) и по проверке токена
  сокета; поэтому проверка токена — перед каждым сокетом.
- Пауза 0.13.4 — снимок без `done`; продолжение — только через `resolve`. Срок вопроса Open WebUI отсчитывает
  страница собеседника, сервер вопрос не снимает — Студия тоже.
- Обратные вызовы (`execute:python` на `pyodide`, `request:elicitation`, `confirmation` режима `legacy`) Студия не
  выполняет — немедленный отказ.
- Закрытие по простою и сверка токена идут на кадрах сервера (пинг Open WebUI — 25 с), а не таймером: на проде
  соединение закрывается через 60–85 с после последней причины (`owui_link.IDLE_CLOSE_SEC` (60)), запас обновления —
  120 с против пинга 25 с.
- Код неверного пароля — `owui_login`; `login` страница считает концом сессии Студии.
- Образ Open WebUI на плавающей метке может сменить API в любой день: прослойка `owui_view` правится в одном месте,
  живая приёмка ловит поломку.
- Смена `STUDIO_DATA_KEY`: подпись учётки без имени и email (`reenter`), сессия не расшифровывается — учётка в
  `relogin`, «Войти заново» с email и паролем (или «Удалить» и подключить заново).
- Частота `/api/v1/auths/sessions*` в Open WebUI ограничена на IP (30 в минуту), а все учётки Студии выходят с одного
  адреса — продление только по необходимости, без фонового.
