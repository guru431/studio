# Фото, видео, файлы и история

Модули: `images`, `videos`, `media` (файлы на шаре), `forms` (формы фото и роликов: тело с пределом, фото файлом или
из истории), `chains` (цепочка промптов: снимок шагов в `images.chain` / `videos.chain`, у старых строк — по ссылкам; в
ответе — только у одной записи `GET …/<id>`, лента несёт число шагов `steps`), `presets`, `takeout`, `history`.

## Фото и видео

- Поля seed у фото, видео и пресетов нет (спека 2026-10-27-studio-ui-tidy): запросы без seed, студия выбирает
  случайный; seed записи показывается и «Повторить с тем же seed» его шлёт.
- Фото (спека 2026-10-21-studio-photo-presets-compare-series): пресеты — `presets.py` (таблица `presets`, роутер
  `/api/images/presets` подключён раньше `images`; не история — стирание их не трогает, учётка уносит каскадом) и
  `presets.js` (чип «★»); серия — поле `series` у `POST /api/images` (`images.run_series`: строки `queued` по одной в
  слоте пользователя, отмена любой снимает весь остаток; `stop()` и `recover()` переводят `queued` в `error`) и
  `series.js` (чип «×1» и панель в «Изменить»); варианты — `GET /api/images/<id>/variants` (индекс
  `images_user_source`); сравнение — `compare.js` (`#compare`); параметры по модели — `chain.js` (`strengthOf` только
  Lustify, `seedOf` — не у внешнего сервиса; в строку сила пишется только у Lustify).
- Кисть: `images._fit_mask` — маска с соотношением сторон исходника приводится к размеру `normalize_image` (NEAREST)
  и сохраняется уменьшенной; в редакторе `#edit-size-tip` «Фото будет уменьшено до N×M.».
- Фото из истории в формах — до `forms.HISTORY_MAX`/`forms.HISTORY_PIXELS` (= `images.RESULT_MAX`/`RESULT_PIXELS`,
  сверяет тест); `forms._fit_history` уменьшает до рамки `normalize_image`; `forms.history_file(…, limit)`. Фото с
  устройства — в прежних пределах. `image_upload.py` — копия модуля переводчика (CLAUDE.md), не меняется.
- Бомбы распаковки: `images._picture` и `claude_code._image_bytes` принимают `DecompressionBombWarning` за превышение
  (`too_big` / 413 `too_large`); фильтр предупреждений процесса не меняется (`ocr_render` без `warnings.catch_warnings`).
- Видео с seed студии: `videos._send` ставит строку `queued` без `gateway_id` (`detail = videos.SENDING`) **до**
  `POST /slot/videos`; id шлюза пишет `videos._attach`. После перезапуска (`videos.recover` ставит `BOOT`) или старше
  `videos.SEND_STALE_SEC` (900) с наблюдатель ищет задание как при потерянном ответе (`videos._resume`, `videos._pick`):
  нашёл — берёт, нет — `failed` `INTERRUPTED`; шлюз недоступен — ждёт до `videos.RESUME_GIVEUP_SEC`. Отменённый или
  удалённый во время отправки — снимается у шлюза. Стирание истории, отключение и удаление учётки
  (`videos.cancel_user`) отменяют и строки отправки; у оборванной (как выше) принятое ищется по seed студии и
  снимается. С seed пользователя — строка после ответа, как прежде.
- `POST /api/videos/{id}/repeat {count: 1..videos.REPEAT_MAX}` → `{items, message}`; промпт — из шага цепочки
  (`videos._asked_prompt`): придуманный шлюзом не повторяется (шлюз придумает заново). Кнопки «Повторить»/«Ещё
  варианты» — в карточке, плитке, таблице и просмотре; окно 2–4.
- «Создать видео» в просмотре фото открывает `#/video?photo=<image_id>`: раздел получает свою запись фото
  обычным API, ставит её файл исходником без скачивания на устройство, а исходный промпт — в раскрываемое
  редактируемое поле «Описание исходного фото». При отправке описание и движение объединяются с подписями;
  общий предел 4000 знаков проверяется без обрезания. Очистка описания оставляет только движение, выбор
  другого файла убирает прежний контекст. В адресе нет текста; после переноса параметр снимается. Прежние
  ссылки `#/video?source=<media_id>` принимаются без контекста. Полная цепочка фото остаётся в истории ролика.

## Лента и сохранение

Выделение нескольких записей ленты фото и видео (отметки, долгое нажатие, «Скачать» и «Удалить» пачкой) — `select.js`
(действия раздела — `extraActions`: «Сравнить» у фото), групповое сохранение — `save.js` `saveMany` (предел iPhone
`SHARE_MAX` — по Content-Length до чтения и по настоящему размеру после: на заголовок не полагается); файл, собранный
браузером (снимок перевода с наложением), — `saveFile` тем же путём iPhone («Поделиться»).

## Файлы, архивы, выгрузка

- `media` — файлы на шаре; `Range` — один диапазон; несколько диапазонов или другая единица — файл целиком (200), 416 —
  только диапазон вне файла. Архив выделенного — `POST /api/media/archives` списком в теле → токен в памяти на
  `ARCHIVE_TTL_SEC`, `GET /api/media/archives/<токен>` — ZIP без сжатия на лету; CRC и размер — в локальном заголовке
  первым проходом по файлу, без дескриптора данных: запись без сжатия с ним не открывают Archive Utility macOS и
  потоковые читатели; учёт записей — `media.ZipWriter`, общий с выгрузкой.
- `takeout` — выгрузка своей истории: `POST /api/me/export` разделами → токен на `EXPORT_TTL_SEC`, не больше
  `EXPORT_KEEP`; `GET /api/me/export/<токен>` — ZIP асинхронным генератором, одна идущая на пользователя (`RUNNING`,
  вторая — 409 `busy`): база — порциями на цикле событий (диалог, страница раздела по `PAGE`), JSON, CRC и sha256 —
  `asyncio.to_thread` (`_pack`), заголовок и данные записи — разными кусками; файл открывается один раз
  (`media.open_summed`, общий с архивом выделенного: суммы и данные с одного дескриптора); README, диалог — своим
  файлом, разделы — `images/0001.json` …, `files/<media id><расш.>`, `manifest.json` с sha256 последним; без токенов,
  хешей, сессий, passkey. Разделы — `takeout.SECTIONS` (с журналом безопасности `security`).
- Реестр ссылок на файлы — `media.REFERENCES` / `media.NOT_REFERENCES`: единственный источник для `media.referenced`
  (с `chat_share_files`). Новый столбец `*media_id` требует строки в реестре, иначе падает `tests/test_media_orphans.py`.
- `media.sweep_orphans`: раз в `media.ORPHAN_EVERY_SEC` (86400) с (из `_purge_loop`, отметка `settings` `orphans`
  `{at, found}`) строки `media` старше `media.ORPHAN_AGE_SEC` (86400) с без ссылок, до `media.ORPHAN_BATCH` (1000), → очередь
  `purge`; пишущиеся (`SAVING`) пропускаются; в журнал — число. Пропуск (`found: null`), если в базе незнакомый
  `*media_id` или `user_version > db.VERSION` (откат). `GET /api/admin/storage` несёт `orphans` («Файлы без записи»).

- История: база SQLite — `/var/lib/studio/studio.db` (локальный диск); файлы — storage
  `\\storage\dd$\SharedData\studio`, на debian `/mnt/storage/SharedData/studio`. Токены подключений в
  базе зашифрованы `STUDIO_DATA_KEY` (Fernet), пароли — scrypt.
- Путь файла без строки `media` не теряется — очередь удаления `purge` (без FK на `users`, переживает
  удаление учётки): туда идут файлы, которые шара не дала удалить, и файлы, которые пишутся сейчас
  (`save_async`/`save_stream` ставят путь до записи, строка `media` снимает его той же транзакцией, —
  отмена и остановка службы посреди записи не оставят файл без записи; строка не встала — файлы
  убирает тот же проход по одному пути, в потоке). Запись ждут не дольше `media.SAVE_TIMEOUT_SEC`
  (45 с; у `save_stream` — шаг в потоке): зависшая шара — 503 «хранилище не отвечает», а не 502
  Apache через 150 с; поток дописывает сам, путь — в `SAVING`, пока он не кончит (сверяет
  `test_deploy`). Проходит её `media.purge()`:
  при старте и раз в `PURGE_SEC` (`start_purger`), в каждом `delete_async` и в начале стирания
  истории; пишущиеся (`media.SAVING`) пропускает. `DELETE /api/history` и `/api/admin/users/<id>`
  отвечают `{"pending_files": N}` — сколько файлов ещё ждут, страница это говорит.
- Хранилище: `GET /api/me/storage` (`profile`, «Данные» → «Хранилище») — свои файлы по видам
  `media.KINDS` из строк `media` (`media.usage`, шару не обходит) и своя очередь (`media.waiting`:
  число и самый старый `queued`); `GET /api/admin/storage` (`admin`) — проба шары
  (`shutil.disk_usage`) и возраст новейшей копии `backup/<manage.BACKUP_GLOB>` в своём потоке-демоне
  со сроком `admin.PROBE_SEC`, одна проба за раз (`admin.PROBE`: зависшая CIFS держит один поток, а не
  пул `to_thread`), очередь — числом. Чужой истории (и объёмов по пользователям) панель не получает.

## Ловушки

- Отмена задания запрос к шлюзу не обрывает (LiteLLM обрыв дальше не передаёт): задание ждёт
  конца, выбрасывает картинку и само освобождает карту (`release_after_cancel`).
- Аренда модели картинок держит карту 600 с простоя, и другая модель её не вытесняет: без
  release FLUX после Lustify ждал карту 300 с и получал 503 (приёмка 2026-10-20). Поэтому
  `images.generate` перед запросом отпускает другую модель; тесты считают и эти release.
- Освобождение карты после отмены идёт подключением учётки (токен читается из базы): удаление
  учётки ждёт её заданий (`images.settle_user`, до `SETTLE_SEC`), иначе каскад унёс бы токен.
- Список роликов шлюза (`GET /slot/videos`) общий для всех ключей: студия читает его только для
  ролика, ответ на создание которого потерялся, и только если seed выбрала она сама
  (`videos._adopt`: случайный 32-битный seed — единственный признак своего, плюс параметры и
  промпт). Seed пользователя (скрипты и другие учётки ставят те же 42) ничего не доказывает:
  тогда список не читается, ответ — «ролик мог начаться» (`LOST_MANUAL`). Не ослаблять: чужое
  задание студия скачала бы в ленту и сняла у шлюза.

- Наблюдатель роликов не ждёт подключения по очереди: ролики каждого подключения — своей
  задачей (`videos.WATCHING`, не больше `POLL_MAX`), не ответивший по сети шлюз — на паузе
  `PAUSE_SEC`, mp4 целиком — за `FETCH_SEC`. Остановка гасит задачи вместе с `_watch`.

- Имя файла записи едет заголовком `X-Studio-Name`, а не строкой запроса: строку пишет журнал Apache.
- Перевод промпта («EN», `POST /api/images/translations`) идёт маршрутом описания
  `/slot/images/descriptions` — текстом, без картинки, а не чат-ролью `local-gemma-abl`: у этого
  маршрута есть scoped release gemma-abl, и задание вида `translation` проходит путь «Описать» —
  одно задание за раз, release моделей картинок до запроса и gemma-abl после, так что следующий
  Lustify не ждёт карту под арендой gemma-abl. Обрезанный ответ (`finish_reason: length`) —
  ошибка, а не половина промпта в поле.
