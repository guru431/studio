# «Агенты» на сервере

Доступ другому пользователю к выбранному проекту — [совместная работа](project-collaboration.md).

Раздел называется «Агенты» (адреса `#/code` и `/api/code/*` — прежние, модуль — `claude_code.py`). Канал — протокол
[2026-10-28-studio-code-bridge-protocol](../superpowers/specs/2026-10-28-studio-code-bridge-protocol.md); мост —
[agent-bridge.md](agent-bridge.md); страница — [agents-workspace.md](agents-workspace.md).

## Каналы, отказы, фоновые просьбы

- `claude_code.ask` повторно проверяет живую незапертую сессию после ожидания любого ответа моста, включая отказ:
  `409 closed` без приватного результата. PDF повторяет проверку после рендера.
- Фоновые просьбы: заголовок страницы `X-Studio-Passive: 1` → `claude_code.ask(passive=True)` → `req.passive: true`
  (только мосту с `hello.passive_requests`; заголовок может лишь отказаться от продления PIN). `code_activity.all_activity`
  всегда фоновый. Фоновые — опрос меток вкладок и Git в `code.js`, повторы `live` по таймеру и `#code-reload` в
  `code-chat.js`, Git/сводка/лимиты после `done`.
- Компьютер без канала — `409 offline` раньше проверки поддержки нестандартного таймера PIN.
- `claude_code.live` без канала моста — не 409 `offline`, а SSE ожидания: `offline {wait: true}`, пинги, затем
  `online` или `closed` (прежняя страница видит `offline` как конец потока и опрашивает как раньше). `bridge.attach` →
  `bridge._online`: `("online", None)` наблюдателям компьютера, только при подключении без прежнего канала;
  `claude_code._events` завершает им поток; страница по `online` сразу грузит историю и live.
- `claude_code.own_agent`: 404 несёт `computer: true` — страница отличает пропавший компьютер от `not_found` файла.
- `POST /api/code/agents/{aid}/projects/{pid}/seen {items: [{chat, attention}]}` (1–200 элементов;
  `claude_code.project_seen`, модели `claude_code.ProjectSeen` / `claude_code.ChatMark`) — «Отметить прочитанными»
  проекта: проверки как у `chat_seen` (свой компьютер, живой PIN, CSRF), снимаются только переданные ревизии этого
  проекта.
- Вопрос/разрешение субагента: в `ask` и `snapshot.asks` необязательное `subtask` (≤ 200 знаков); сервер поле
  пропускает, страница пишет «Подзадача · <имя>».

  `cc_version`, `projects_root` — из `hello`; id `AUTOINCREMENT` — id отозванного не достаётся новому: им ключуются
  `agent_events` без FK, память службы и адреса push), `agent_events` (история подключений, только добавляется —
  `bridge.record`: `enroll`, `revoke`, `online`, `offline`, `open`, `pin_ok`, `pin_fail`, `session_start`; id и имя
  компьютера без FK, `device` — `bridge.device`), `code_chats` (отметки студии поверх сессий машины: какие чаты
  завела и `open`/`closed`; текста нет), `push_subs` (подписка устройства, каскад от `sessions`). `agents` —
  привязка `POST /api/agent/enroll` без сессии (`auth.OPEN_API`; `auth.check_password` — паузы и общий счёт неудач
  `/login`), ключ — в ответе один раз (с ним `login` учётки — `strip().lower()` введённого), смена пароля его не
  гасит; отзыв — `DELETE /api/agents/<id>` (`bridge.drop`, 4401) или самим мостом `DELETE /api/agent/enroll` (тоже
  `OPEN_API`: ключ — только `Authorization: Bearer`, чужой `Origin` — 403 `origin`, ключ не найден — 401 `key`; учётка
  может быть и отключённой; событие `revoke` с `device` «мост», 204; журнал — «компьютер N: отвязан мостом»); установщик
  моста — `GET /api/agent/download` (сессия; EXE `studio-agent-setup.exe`, кладёт выкладка; нет файла — 404
  `no_agent`), ZIP обновления `agents.AGENT_ZIP` = `<корень кода>/agent/studio-agent.zip` — `GET /api/agent/package`
  (Bearer-ключ действующего устройства, `auth.OPEN_API`); `GET /api/agents` («на связи», модели, усилия — из `bridge.LINKS`), `GET /api/agents/events`. `bridge` —
  канал `/api/agent/link` (WebSocket, `Authorization: Bearer <ключ>`, не строка запроса): `hello` за `HELLO_SEC`,
  кадр до `FRAME_MAX` (16 МиБ; `--ws-max-size` юнита — на 1 КиБ больше, чтобы такой кадр получил 4400, а не 1009
  uvicorn), канал один на компьютер — новый закрывает прежний 4409 и шлёт его наблюдателям `offline`; `welcome` —
  с `login` учётки компьютера; 4400 — протокол, 4401 — ключ, 1012 — остановка службы; кадры снятого канала никуда не
  идут. Закрытие сокета ждёт замок отправки, поэтому прежний канал при замене и снятый `drop` закрываются фоном
  (`bridge.TASKS`, `_close_later`; `stop` ждёт их до `STOP_SEC`); очередь наблюдателя — до `WATCH_MAX` (1000)
  событий, отставшему — `offline`, и он снят. Просьба
  `call` ждёт `res` до `CALL_SEC` (30 с; `Offline`, `BridgeError`, `TimeoutError`); события `ev` — очередям
  `WATCHERS` (`Watch.session` — `tag` сессии); ход на сервере не хранится — источник правды машина. `tag(digest)` —
  признак сессии для моста (производное дайджеста, не токен); `forget` — заперлась или отперлась (`screenlock`:
  `lock/now`, отпирание паролем, PIN, passkey): срок PIN компьютеров сохраняется, потокам этой сессии
  `closed`. `drop_user` — только отключение и удаление учётки (`admin`): смена пароля мосты не рвёт (ключ
  самостоятелен); выход и конец сессий мосту не сообщаются — мёртвая сессия не пришлёт просьб, её запись на мосте
  уйдёт по трёхчасовому сроку. `claude_code` (`/api/code/*`; не `code.py` — «Ловушки») ретранслирует: запрос —
  просьба `bridge.call` от сессии запроса, ответ — `data` моста ASCII-JSON без NaN (`_BridgeJSON`, иначе 502
  `bridge`), отказ — код моста со статусом `STATUS`: `closed` — 409, а не 423 (423 — только экран блокировки от
  `guard`), `pin`/`pin_locked` — 403 (`left`). Чужой компьютер — 404, `pid` не 16 hex и `chat` не UUID — 422 до
  моста. В адресе — только id: имена проектов, пути, PIN и тексты — в теле (чтения — `POST …/files`, `…/read`,
  `…/pdf`). `open` — PIN проверяет мост, итог — `open`/`pin_ok`/`pin_fail`. Чаты — слияние сессий машины с
  `code_chats` (на GET записи нет; строка студии без сессии на машине — только `open`); «Новый чат» заводит UUID без
  моста (не больше `NEW_CHATS_PER_MIN` 10 на компьютер в минуту, дальше 429 `too_many`), без хода `history` —
  пустая, `live` — `idle` (`_new_chat`); PATCH чата без строки спрашивает мост, есть ли сессия (нет — 404, закрыт —
  409), строку не заводит. Ход — `turn` → SSE (`_Watch`; очередь — до просьбы), `live` — `snapshot` идущего хода;
  поток кончается `done`, `offline` (канал пропал или заменён) или `closed` (`forget`, а сам поток на тике
  `PING_SEC` и на событиях не чаще `CHECK_SEC` сверяет сессию `_session_open`: вышли, погасили, истекла, заперта
  по сроку). Пределы — `TEXT_MAX` (100 000 знаков задания), `FILE_MAX` (2 МиБ текста, тело `FILE_BODY_MAX` 3
  МиБ), `RAW_MAX` (10 МиБ PDF), `PATH_MAX`, `claude_code.HISTORY_PAGE` (30; первая страница — `claude_code.HISTORY_TAIL` (12)). Ответы `history`, `files`, `git` — готовым
  `Response` в обход `jsonable_encoder` (глубокая вложенность — 502 `bridge`, не 500); отказ `read_only` моста (файл
  только для чтения) — 409. PDF — раскодирование и подсчёт страниц в одном `to_thread`, рендер `ocr_render` под
  `PDFIUM` не больше `PDF_RENDERS` (2) сразу (`RENDERS`), память `PDFS` одна на пользователя на `PDF_TTL_SEC`
  (просроченные чистит любой запрос раздела, запирание и отпирание — `bridge.FORGET_HOOKS`), ключ — с `tag`; из
  памяти — только после просьбы `projects` (открыт ли компьютер, решает мост). Страница: хода нет и вкладка видна —
  `live` раз в `IDLE_POLL_SEC` (20 с), не дольше `IDLE_POLL_FOR_SEC` (30 мин) после действия владельца в чате (каждый
  `watch` продлевает открытость компьютера, протокол §3); у вопроса агента — «Свой ответ» строкой; `sw.js`
  `pushsubscriptionchange` переподписывает (`POST /api/me/push`), «Настройки» сверяют флажок с `getSubscription()`. Модель и усилие сверяются с `hello`; `null` — прежние модель и усилие чата (страница:
  первый пункт «по умолчанию», умолчания учётки — только в новый чат). `push` — Web
  Push (спека 6.8): ключ VAPID (P-256) в `settings` `vapid` шифром `STUDIO_DATA_KEY` (`vapid_key`), тело — RFC
  8291 aes128gcm одной записью, подпись — JWT ES256, всё на `cryptography`; `GET/POST/DELETE /api/me/push`, флаг
  устройства `studio-push` (`settings.js`); адреса — только `push.HOSTS` («Правила»). Повод — `bridge._push`:
  `ask` и `done`, только если чат никто не смотрит (`bridge.watching`); адресат — начавший ход: ход участника
  совместного проекта (`bridge.initiated` до просьбы `turn`, в памяти) — ему, пока проект ему выдан (отозван —
  никому), иначе владельцу компьютера; страница снимает поток на
  `visibilitychange: hidden` и открывает `live` на `visible`; текст — «<имя компьютера> · <имя проекта>: <повод>»
  (со старым мостом — без проекта), `href`
  `code/<aid>/<pid>/<chat>`, `tag` `code-<chat>`; 404 и 410 службы — подписка снята; `sw.js` — `push` с
  `renotify`. Та же подписка с 2026-10-30 — для успеха и ошибок фото, видео, расшифровки, сканов, перевода и
  озвучки: первое сохранение итога зовёт `push.job_finished`, отмена — тишина; название «Студия», текст только
  повод, адрес `<раздел>?id=<id>`, tag — id записи. `GET /api/jobs` несёт `push` текущей сессии: с подпиской
  `jobs.js` не показывает локальное уведомление. Переключатель — «Push на этом устройстве»; схема базы прежняя.
  Рабочее место (спека 2026-10-29-studio-code-workspace, шаг схемы 20 `db.CODE_20`) — `workspace`:
  `GET /api/code/workspace` — документ `{panel, place {aid, pid, view}, projects [{aid, pid, tabs, active}]}`
  (проекты по убыванию `touched`), `PATCH` — одно действие `{op: open|close|place|panel|move, aid, pid?, chat?, view?,
  index?}` (`move` — `workspace.Action`, `workspace._move`: `index` 0…`TABS_MAX`−1, дальше конца — в конец; активная,
  вид, `touched` и порядок проектов не меняются; вкладки нет — ничего; `code-workspace.js::apply` повторяет то же)
  одной транзакцией к тому, что в базе (не документ целиком: устаревшее устройство не затирает чужие вкладки и не
  возвращает стёртое), ответ — новый документ; таблицы `code_tabs` (вкладки проекта JSON-списком UUID, активная,
  `touched`; каскад от `agents`) и `code_place` (компьютер панели, открытый проект и вид; отзыв компьютера — `NULL`,
  `place` — `null`); пределы `TABS_MAX` (20: лишняя — самая левая) и `PROJECTS_MAX` (100: лишний — открытый раньше

  Стирание истории — `code_chats`, `code_tabs`, `code_place`; выгрузка — `code_chats/` (с `workspace.json`) и
  `agent_events/`, без `key_hash`.

## Визуализации Codex

Визуализации Codex (`visualize` с JSON `path/mode/title`) распознаёт общее inline-расширение
`visualization-markup.js` в `markdown.js` и Worker; блоки кода остаются текстом.
`code-visualizations.js` открывает модальное окно с iframe `sandbox="allow-scripts"`.
`POST …/projects/{pid}/visualization` требует `hello.visualizations`, owner/PIN/CSRF, читает
HTML через op `visualization` и создаёт случайный токен. `GET …/visualization/{token}` сверяет
сессию/компьютер/проект и живой PIN через `projects`, отдаёт документ с отдельной CSP;
общая CSP оболочки остаётся прежней. `code_visualizations.py` держит один HTML ≤2 МиБ на
пользователя в памяти на 5 минут, очищается при `bridge.forget` и по сроку, без диска/журнала.
В iframe нет same-origin, форм, вложенных страниц и сетевых API; разрешены inline-скрипты
и библиотеки из фиксированных CDN. Пути машин не попадают в URL. Проверки:
`test_code_visualizations.py`, `test_ui_visualizations.py`, `agent/tests/test_visualizations.py`.

`code_visualizations`: lucide 1.17.0 (ISC + MIT Feather) — копией `app/static/vendor/lucide.min.js`, подключается только
при упоминании `lucide` во фрагменте; в CSP фрейма `script-src` есть `'self'`. CSP разрешает CDN по хостам (cdnjs,
jsdelivr, esm.sh, unpkg, oaistatic, Google/Bunny Fonts), а не по путям пакетов; внешние запросы делает только сам
фрагмент.

(мост ≥ 0.12.0) `hello.desktop: true` объявляет пульт рабочего стола, `app/desktop.py` и
`code-desktop.js/css`. Разрешение `Config.desktop_enabled` по умолчанию false; только локальный
Checkbutton окна вызывает `Controller.set_desktop_enabled`, атомарно сохраняет bool и применяет без
переподключения. Выбор сохраняется при перезапуске. У HTTP/протокола/CLI нет изменения разрешения.
Все операции требуют своей сессии, обычного PIN и CSRF для POST; токен одного сеанса только в памяти.
`desktop_status/start/frame/input/clipboard/stop` — §14 протокола; отдельные HTTP-запросы с одним
кадром в полёте, без очереди изображений. Сервер фильтрует ответы и повторно проверяет сессию после
ожидания моста; данные не сохраняются. Блокировка шлёт `desktop_close` без сброса обычного PIN.
Мост отзывает управление при локальном выключении/обрыве/10 с без запросов; `desktop_native.py`
в одном рабочем потоке проверяет WTSActive/Default input desktop, захватывает JPEG, посылает SendInput,
обменивается текстом CF_UNICODETEXT; своим окнам ввод запрещает. Активный пульт удерживает обновление.
(мост ≥ 0.13.1) `desktop_status.resolutions` объявляет варианты длинной стороны JPEG 640–2560 px;
`desktop_frame.max_edge` необязателен, по умолчанию 1600. Сервер опускает поле при значении 1600
для старого моста; без списка разрешений UI оставляет только 1600. Окно подключения компактное;
активный `code-desktop` занимает весь экран, кадр вписывается по ширине и высоте свободной области
через ResizeObserver. Масштаб просмотра (−/+/100%/«Вписать») отделён от качества JPEG;
100% соответствует размерам монитора в CSS-пикселях. Увеличенный экран прокручивается по обеим осям,
клавиатура/текст/буфер — отдельная сворачиваемая панель, не уводящая экран за границы окна.
Touch — прямой ввод, Мышь — относительный тачпад,
видимый курсор, ЛКМ/ПКМ, удержание ЛКМ и прокрутка. Смена режима/монитора и отмена жеста
отпускают ввод; старый кадр после смены монитора/качества не показывается.
Проверки: оба `test_desktop.py`, `agent/tests/test_desktop_native.py`, `tests/test_ui_desktop.py`,
`agent/tests/test_window_integration.py`. Настоящие экран/ввод/буфер требуют ручной приёмки после
локального включения владельцем; синтетические и браузерные тесты этого не подтверждают.

(мост ≥ 0.11.0) необязательный `hello.computer_info` объявляет `GET /api/code/agents/<aid>/info` →
op `computer_info`, только свой компьютер с открытым PIN. `agent/studio_agent/computer_info.py`
считывает CIM Windows в потоке (10 с): ОС, память, локальные/съёмные диски, IP интерфейсов;
имя/пользователь и все `Config.projects_roots`, публичный адрес — фиксированный HTTPS api64.ipify.org
(3 с, без redirect и данных компьютера). `app/computer_info.py` фильтрует поля и проверяет числа/IP,
ответ `no-store`, неизвестное — null. `code-computer.js` открывает карточку по явному нажатию
на кнопку ⓘ рядом с именем компьютера в `code-panel.js`, после PIN; имя переключает только список проектов.
Снимок только в DOM окна, закрытие/уход очищают его и отменяют запрос. Старый/offline мост — пояснение без запроса.
Проверки: `test_computer_info.py` обоих наборов и `test_ui_computer_info.py` (320/1280 и WebKit).
При недоступности ipify внешний IP берётся из `link.ip`, только если адрес публичный.

(мост ≥ 0.10.0) `hello.agent_version` сообщает версию самого моста, `hello.agent_update` объявляет обновление.
`GET /api/agents` добавляет `agent_version`, `agent_update`, `latest_version` (последняя — из опубликованного ZIP).
В дереве компьютеров после имени идут версия, круглая кнопка обновления с двумя стрелками, сведения
и подключение к рабочему столу (монитор со стрелкой), без видимой метки PIN и подписи о новой версии.
Кнопка обновления выделена при доступной новой версии, номер — в подсказке; под строкой видны только
этапы и ошибки запрошенного обновления. `POST /api/code/agents/<aid>/update` передаёт только серверные
version/sha256/size. Кнопка запускает обновление доступного совместимого моста; в остальных случаях
скачивает установщик Windows, включая старые/offline/уже актуальные мосты.
`GET` того же адреса — стадия. Обе команды требуют своей сессии, CSRF для POST и открытия PIN.
`GET /api/agent/package` без браузерной сессии проверяет Bearer действующего устройства активной учётки.
`agent/studio_agent/updater.py` скачивает только с настроенного HTTPS-сервера без redirect, проверяет ZIP,
готовит отдельную копию/venv и ждёт `live()` всех Runner и окончания просьб канала. Новые изменения/ходы
блокируются; работающие задания продолжаются. Самостоятельный `update_helper.py` ждёт штатного выхода,
запускает новую копию, сохраняет настройку автозапуска; ранний сбой запуска возвращает прежнюю копию.
Ключи/PIN/переписки не входят в пакет или план. Старые версии требуют однократной ручной установки 0.10.0.
Проверки: `test_agent_update.py`, `test_ui_agent_update.py`, `agent/tests/test_updater.py`.

## Ловушки

- Канал моста — свой `ProxyPass /api/agent/link … upgrade=websocket timeout=300` раньше общего: без
  `upgrade=websocket` `mod_proxy_http` апгрейд не пропустит (нужен Apache ≥ 2.4.47, на debian — 2.4.69). Тишину
  канала рвут штатные пинги uvicorn каждые 20 с, так что живой канал под 300 с не попадает. Поток хода —
  `ProxyPass /api/code/` как у чата (600 с, `flushpackets=on`, `no-gzip`). Сверяет `test_deploy.py`.
- `auth.guard` — HTTP-middleware (`app.middleware("http")`), WebSocket его не проходит: вход канала
  (`bridge.link_socket` — ключ устройства, отключённая учётка) проверяет сам обработчик, и новый WebSocket-маршрут
  без своей проверки был бы анонимным. Ключ — только заголовком: строку запроса пишет журнал Apache.

- Модуль раздела — `claude_code.py`, не `code.py`: каталог службы стоит в `sys.path` первым, и `code.py` заслонил
  бы стандартный модуль `code`, который импортирует `pdb` (pytest падал INTERNALERROR при старте). Маршруты
  `/api/code/*` и `tests/test_code.py` — прежние имена.

- Раздел Claude Code 423 не отдаёт: «компьютер закрыт» — 409 `closed` (страница ведёт к PIN), а 423 ловит экран
  блокировки студии и повторяет запрос после отпирания — тот же код увёл бы в шторку вместо PIN.
