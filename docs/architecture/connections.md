# Подключения и разделы

Модули: `connections` (подключение — адрес с ключом), `sections` (подключения раздела, отмеченные модели,
умолчание; `sections.resolve` — пара запроса), `upstream` (список разрешённых адресов и имён, запросы к ним),
`checks` и `capabilities` (паспорт подключения), `access` (группы доступа к общим API моделей и MCP).

- Подключения: к адресам из списка разрешённых (панель администратора, по умолчанию
  `10.77.1.15:4000`) ходит сервер, токен в браузер не уходит; к остальным — браузер (только чат).
  По адресам вне списка сервер не ходит (с учётом перенаправлений и разрешения имён). Запись
  списка — IP:порт или имя:порт; имя — только https, при каждом запросе все его адреса должны быть
  публичными (`ipaddress.is_global`), соединение — с проверенным адресом (SNI и `Host` — имя,
  `upstream.RESOLVE`). Правило путей `PROXIED_PATHS` — только для IP-записей. Задания держат
  снимок `Connection`: `connections.token` отдаёт ключ, только если владелец, вид и адрес строки
  совпали со снимком, иначе `upstream.ConnectionChanged` (слова — `upstream.refused_words`) — новый
  ключ прежнему адресу не уходит. PATCH подключения проверяет адрес (`check_base_url`), только если
  меняются вид или адрес: убранное из списка (`dropped`) можно переименовать и убрать из разделов,
  новый раздел, кроме чата, — 422 `server`.
- Разделы (`chat`, `photo`, `video`, `transcribe`, `ocr`, `translate`, `speech`, `dictation`) — таблицы `section_links`
  (подключение в разделе и его отмеченные модели) и `section_defaults`; встроенный перечень srvllm —
  `sections.CATALOG`. Строки раздела, которого код не знает (новее его — после отката), `connections`
  не видит (`_from_row` фильтрует `linked` по `SECTIONS`), а `set_sections` не трогает. Старые `connections.sections` и `users.default_*` остаются для отката и
  держатся согласованными (`sections._sync_legacy`) — новая логика их не читает. Ход начатого
  диалога с личным подключением пару не перепроверяет: галочки управляют выбором для новых диалогов.
- «Администрирование» → «Общие API моделей»: OpenAI-совместимое подключение или шлюз Studio из списка
  разрешённых, с ключом только на сервере. Администратор отмечает модели по разделам. Все учётки видят эти
  модели вместе с личными и могут выбрать своё умолчание. В разделе без личных моделей действует первая
  доступная общая модель. Удаление модели из общего списка прекращает новые ходы с ней и в прежних диалогах.
  Общие подключения и их связи имеют `user_id IS NULL` и переживают удаление любой учётки. Их изменение и
  запрос полного каталога доступны через `/api/admin/shared`.
- Группы доступа (`access`, шаг схемы 56, спека 2026-11-20-studio-access-groups-design): администратор заводит группы
  учёток («Администрирование» → «Группы») и у общего подключения кнопкой «Доступ» выбирает «Все пользователи» или
  группы. Нет правила — общее видят все (так остались все общие после выкладки); правило с группами — только их
  участники; правило без групп и правило, все группы которого удалены, — только администраторы: удаление группы
  закрытое не открывает. Администратор видит всё общее без групп. Правила удаляются триггерами вместе с подключением
  или сервером MCP, id которых не повторяются. Состояние — только в базе, без кэша: правка действует со следующего запроса.
  Проверка — в узких местах, где общие строки попадают к учётке: `connections.list_for` и `connections.get`
  (условие `access.shared_filter`; общая строка без доступа — как отсутствующая, тот же отказ, что у удалённой),
  `sections._rows` и всё, что от него (связи, умолчания, `sections.resolve`). Диалог на закрытой модели открывается,
  ход отказывает как у удалённого подключения; умолчание уходит на доступную модель. Управление общим (`uid None`)
  правил не применяет; пути администратора к чужой учётке показывают картину этой учётки — с её доступом.
  Принятое до смены правил доделывается: фоновые пути ищут подключение с `gate=False` — наблюдатель роликов
  `videos._connection`, `ocr.resume_queued`, release карты `ocr.lease_lost`, раннеры очередей озвучки и расшифровки;
  задания держат свой снимок подключения. Известное отступление: очередь перевода при перезапуске
  (`translate.resume_queued`) идёт через фильтр — ждущий перевод на закрытой модели после рестарта получает отказ
  `translate.NO_CONNECTION`. API — `/api/admin/groups` и `/api/admin/shared/{connections,mcp}/{id}/access`; журнал —
  только id и числа, без имён групп и инструментов. Общие MCP и их инструменты — [chat](chat.md#mcp).
- «+ Адрес для раздела» у видов «Шлюз srvllm» и «s06» — галочка «Добавить во все разделы этого шлюза»
  (отмечена, пока у учётки нет подключений; так же в зеркале панели): POST подключения с разделами вида
  `GATEWAY_SECTIONS` (`connection-form.js`; = `connections.KINDS` srvllm и ключи `sections.S06_CATALOG`, сверяет
  `tests/test_connections.py`). API и проверки `sections.check_link` прежние: недоступный раздел — отказ всей формы.
  Cleaner — только разделы `sections.CLEANER`: `check_link` отказывает и связи уже заведённого Cleaner
  с другим разделом (`POST /api/sections/{раздел}/links`). Какие разделы подключение примет по виду (Cleaner, s06,
  `connections.KINDS`), считает один `sections.accepts`: `check_link` отказывает по нему, а `connections.out` отдаёт его
  полем `accepts` — выбор уже заведённых в «+ Адрес для раздела» показывает только подходящие разделу. Связи Cleaner,
  успевшие появиться до запрета (или созданные прежним кодом после отката), убирает при каждом запуске
  `sections.drop_cleaner_strays()` — с `_settle` умолчаний и прежним столбцом `connections.sections`.
- Проверка подключения — `checks.py` (спека 2026-10-21-studio-connection-check-design): паспорт —
  `connections.passport` (JSON: строки `routes` по запросам, модели с возможностями и источником —
  `capabilities.py`, пробы), обнуляется сменой адреса, вида или токена; зеркала панели его убирают.
  Пишется только той строке, что видела проверка (`connections.snapshot`: владелец, вид, адрес,
  ключ шифром; иначе 409 `changed`): проверка ждёт ответа секундами, за это время токен меняют или
  подключение удаляют.
- id подключения — `AUTOINCREMENT` (схема 49): id удалённого не достаётся новому, поэтому `connection_id` истории
  разделов (без FK) после удаления ни на что не указывает — ждущие расшифровки, озвучки, сканы и переводы
  отказывают «подключение удалили», а не уходят другому адресу. `connections.delete` обнуляет `connection_id`
  диалогов учётки: ход такого диалога — 409 `no_connection` («выберите подключение диалога»). На базе до шага 49
  SQLite отдавал id удалённого подключения с наибольшим id следующему созданному.
  Пробы через сервер (`POST …/check`) — только `GET` через `upstream`: srvllm — `/v1/models` и
  `/slot/models`, openai — `models_url` и он же без ключа (`upstream.request(keyless=True)`),
  OpenRouter — `…/key`; ни генерации, ни release, ни `GET /slot/videos` (сторожит `test_checks.py`).
  Прямое проверяет браузер (`passport.js`) → `PUT …/passport` (`source: browser`, пределы формы,
  возможности выводит сервер). «Пробный ответ» (`POST …/probe`) — единственная тратящая проба, у
  srvllm его нет. Адрес, убранный из списка, — `connections.dropped` (не прямое): «Проверить» и
  «Обновить модели» говорят это словами; `UpstreamRefused.reason` различает `unlisted`, `internal`,
  `changed`.
- Отказ сервиса словами — `upstream.gateway_error(response, conn)`: шлюз студии (srvllm, s06) — словами шлюза и
  карты (503 — «карта занята или недоступна»), прочие подключения — «сервис «имя» …» (503 — «временно недоступен»);
  401 у всех называет, где менять ключ (`upstream.KEY_PLACE`), 429 — «слишком много запросов или исчерпан лимит»,
  402 — «закончились средства или лимит оплаты».
- Шлюз s06: вид формы «Шлюз s06», в базе `kind=openai, s06=1` (схема 32), адрес без `/v1`,
  только из списка администратора. Чат и перевод — устойчивые алиасы `qwen-27b` и `qwen-27b-fast`;
  расшифровка и голосовой ввод — `/speech/transcriptions` (WhisperX, `diarize` true/false),
  сканы — `/pages/ocr` с `image` base64 и `model=ocr-ru`, ответ `markdown`. Освобождение слотов
  srvllm не вызывается. Озвучки и координат для перевода снимков нет; прежние умолчания разделов
  при добавлении сохраняются. Флаг профиля входит в снимок подключения и паспорта, смена требует токен.
  Паспорт s06 — профиль `s06` с перечнем `capabilities.S06_CAPS` (WhisperX — с собеседниками); приписку «чего нет
  в сравнении со srvllm» (`passport.js`) получают только профили `openai`, `openrouter`, `compatible` без Cleaner.

## Ловушки

- HTTP-клиент службы (`state.make_http`) один на всех пользователей и cookie ответов не хранит
  (`CookieJar` с политикой без доменов, передан самой банкой: `httpx.Cookies(...)` скопировал бы её
  без политики) — иначе cookie сервиса из запроса одного уходила бы с запросами других к тому же хосту.
