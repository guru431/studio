# Вход через Active Directory

Studio связывает существующую учётку с объектом AD по `objectGUID`. Пользователь вводит логин или подтверждённый
email **в Studio** и доменный пароль. Те же данные подходят для привязки моста и подтверждения действий паролем.
Настроенный второй фактор Studio действует и для LDAP. Доменные пароли проверяются в каталоге, смена и
восстановление пароля выполняются в AD. История, локальные роли и привязки устройств сохраняются.

## Настройка экземпляра

В `/etc/studio/studio.env` на нужном экземпляре задайте следующие переменные. Храните пароль служебной учётки
в vault и передавайте на сервер через stdin по правилам проекта.

| Переменная | Значение |
| --- | --- |
| `STUDIO_LDAP_URL` | `ldaps://dc.example.com` или `ldap://dc.example.com` для обязательного StartTLS. Укажите DNS-имя из сертификата контроллера. |
| `STUDIO_LDAP_BASE_DN` | База поиска пользователей, например `DC=example,DC=com`. |
| `STUDIO_LDAP_GROUP_DN` | DN группы допуска, например `CN=Studio Users,OU=Groups,DC=example,DC=com`. Учитываются прямые и вложенные членства через `memberOf`. |
| `STUDIO_LDAP_BIND_DN` | DN служебной учётки с правом чтения нужных пользователей и членства в группах. |
| `STUDIO_LDAP_BIND_PASSWORD` | Пароль служебной учётки. |
| `STUDIO_LDAP_CA_PEM_B64` | Однострочный Base64 от PEM корпоративного CA, если нужен отдельный центр доверия. При пустом значении используется доверенное хранилище среды Studio. |

После применения настроек откройте **Администрирование → Пользователи → Привязать LDAP**. Укажите UPN или
`sAMAccountName` сотрудника и подтвердите привязку своим паролем администратора. Для нового сотрудника сначала
создайте учётку штатным приглашением. Studio закроет веб-сессии этого пользователя и погасит его одноразовые
ссылки и коды. Последний активный администратор с локальным паролем остаётся доступен для восстановления.

Каталог должен быть доступен с каждого экземпляра, где настроен LDAP. Для этого способа входа контроллер
должен поддерживать LDAP Simple Bind поверх TLS с действующей политикой безопасности. Проверьте вход тестовой учёткой,
повторное подтверждение пароля, привязку моста и отключение при удалении из группы. Синхронизация запускается
при старте и повторяется через 60 секунд после завершения проверки. Подтверждённое отсутствие пользователя,
отключение в AD или потеря членства отключает учётку в Studio, закрывает веб-сессии и каналы мостов. Для
повторного доступа восстановите учётку и членство в AD, затем нажмите **Включить** в Studio.

При ошибке связи или неполном ответе каталога новые проверки доменного пароля отклоняются. Уже выданный доступ
действует до успешной проверки каталога или ручного отключения в Studio. Перед отключением LDAP на экземпляре
или откатом на версию без LDAP отключите связанные учётки в админке.
