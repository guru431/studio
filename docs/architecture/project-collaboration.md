# Совместная работа над проектом

В разделе «Агенты» владелец открывает проект, нажимает «Доступ» между «Файлы» и «Чат» и вводит логин или email существующей
активной учётки Студии. Регистр и пробелы по краям не учитываются. В списке и шапке проекта видна метка «Общий доступ»,
пока у него есть участники; выдача и отзыв обновляют её сразу. Участник видит компьютер с меткой «Совместные» и только выданные ему проекты.
Доступ включает все чаты проекта, чтение и изменение файлов, Git и запуск установленных на компьютере
агентов с настройками и подключениями владельца. Это доверенный соавтор с возможностью запуска кода:
граница проекта ограничивает API Студии, а инструменты CLI работают с правами Windows-пользователя
владельца. Владельцу следует выдавать доступ только пользователям, которым он доверяет эти права.
Участник не управляет компьютером, обновлением, рабочим столом, подпиской или составом участников.
Worktree доступны владельцу; права на другие проекты автоматически не распространяются.

Выдача привязана к id проекта, а он — к имени папки (мост: `agent/studio_agent/projects.py`). Удаление или
переименование папки выдачу не снимает: окно «Доступ» такого проекта уже не открыть (`GET …/members` спрашивает
мост и отвечает 404), а новая папка с тем же именем сразу откроется прежнему участнику. Поэтому все выдачи
компьютеров владельца, и к исчезнувшим папкам, видны и отзываются в «Настройки → Защита → Доступы и ссылки»
(`GET /api/me/access`, `missing` — мост на связи, а папки нет). Отзыв (`project_access.revoke`,
`DELETE /api/me/access/members/<компьютер>/<проект>/<участник>` и прежний `DELETE …/members/<участник>`) моста
не спрашивает, только владельца компьютера. Сами по исчезновению папки выдачи не удаляются: корень проектов
бывает недоступен временно.

`app/project_access.py` хранит в `project_members` только id компьютера, проекта и пользователя, время
выдачи. Сервер проверяет владельца при выдаче и отзыве; перед выдачей мост подтверждает проект и
PIN владельца. При каждом обращении участника сервер проверяет разрешение и активность владельца,
добавляет доверенное поле `shared_projects`. Мост ≥ 0.19.0 объявляет `hello.project_sharing`, проверяет
это поле до исполнения и фильтрует `projects`/`activity`; запросы к компьютеру без проекта не разрешает.
Такая просьба не открывает PIN-сессию и не продлевает срок открытой сессии владельца.
Старые мосты получают обычные просьбы владельца, а совместный доступ требует обновления.

Выдача и отзыв пишутся в журнал безопасности владельца (`project_member_add`/`project_member_remove`, без логина и
проекта) и в историю подключений компьютера (`agent_events` `member_add`/`member_remove`, шаг схемы 39): украденная
сессия не выдаст доступ молча. Аварийный выход снимает все выдачи компьютеров учётки всегда, без галочки отзыва
компьютеров. Ссылку «Поделиться» на чат проекта создаёт и отзывает только владелец компьютера
([sharing-export](sharing-export.md)); отзыв участника (`project_access.drop`) уносит и его ссылки на проект,
записанные прежним кодом.

Чаты проекта общие; отметки `code_chats` принадлежат владельцу компьютера. Вкладки и выбранный вид
личные: у владельца прежняя `code_tabs`, у участников `code_member_tabs` с ключом пользователь/компьютер/
проект. Проверка `/access?project=<pid>` обязательна перед показом сохранённой в памяти истории.
После отзыва сервер отбрасывает запоздавший ответ, закрывает SSE до выдачи следующего события и
убирает вкладки участника. Уже полученный пользователем текст и выполненные изменения отозвать
нельзя; запущенное задание продолжает работу на компьютере владельца.
Push карточек и конца хода адресуется начавшему ход (`bridge.initiated`, в памяти службы): участнику — пока
проект ему выдан, после отзыва — никому; владелец о ходах участников push не получает. Визуализации участнику —
только из самого проекта (мост 0.20.0, `hello.visualization_scope`; старому мосту — только относительный путь).

Схема 38 только добавляет таблицы. Прежний сервер продолжает работать с собственными проектами,
не видит разрешений и не предоставляет совместного доступа. После отката на прежний мост сервер
отвечает участникам `409 unsupported`. Для включения нужны сервер 0.3.0 и мост 0.19.0; действующий
мост обновляется после завершения заданий штатным механизмом обновления.

Проверки: `tests/test_project_access.py`, `tests/test_ui_project_access.py`, `tests/test_ui_account_security.py`,
`agent/tests/test_agent.py`. Общие правила — [agents](agents.md), [agents-workspace](agents-workspace.md).
