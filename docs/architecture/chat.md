# Чат

## Поток и ход

- `chat` — поток SSE. Дата — `chat.with_date` первым системным сообщением каждого запроса (и прямого подключения):
  календарная дата в поясе учётки (`users.timezone`, по умолчанию Москва).
- Предел контекста модели вне `CONTEXT` — `context_length` списка моделей подключения, запомненный в `chat.LIMITS` на
  `CONTEXT_TTL_SEC` (неудача не запоминается).
- Причина отказа ответа словами — `messages.error` (шаг 35, `db.CHAT_35`): `chat._finish(..., error=)`;
  `chat._message_out` отдаёт `error` из столбца, у старых строк — по-прежнему «скан не распознан» из content; если слова
  совпадают с content (скан, «хранилище недоступно»), content отдаётся пустым. Тексты для скана/хранилища пишутся и в
  content (прежний код при откате их видит). После ответа-ошибки страница перечитывает диалог.
- Сверка сессии в потоке: `chat._events` → `chat._session_open` на каждом пинге и на событиях не чаще
  `chat.CHECK_SEC` (1) с: выход, отключение учётки, истечение, блокировка «Чата» (`lock_policy.locked(digest, "chat")`)
  → событие `closed`, поток закрывается, ответ дочитывается и сохраняется; страница перечитывает диалог.
- Ожидание карты: на 503 от шлюза студии (srvllm или s06; `chat.StreamTask._card_gateway`) поток повторяет запрос раз
  в `chat.RETRY_SEC` (15) с до `chat.WAIT_MAX_SEC` (1800) с; пока карту держит своё распознавание (`ocr.holding`), срок не
  идёт; ожидание не съедает `STREAM_TOTAL_SEC`. SSE `wait {seconds}`, по ответу шлюза — `wait {}`; у идущего ответа в
  GET — `message.wait`. `POST /api/chats/{id}/nowait` («Не ждать») — ошибка `chat.GAVE_UP`; ответ уже не ждёт — 409
  `state`. Страница: «жду карту · м:сс» и `.msg-nowait`. 503 других подключений через сервер — сразу ошибка.
- `chat.js`: `acknowledgeTurn` убирает отправленное в любом открытом диалоге; `open()` не сбрасывает идущую отправку.

Отправка обычного чата несёт `request_id` в памяти страницы. Схема 31 хранит подтверждение
`chat_turn_requests` вместе с парой сообщений в одной транзакции; повтор того же запроса возвращает
подтверждение без второго вызова модели. Ключ привязан к диалогу и содержимому, чужая учётка его
не видит; удаление диалога удаляет подтверждения. После замены ответа старый ключ не запускает новый.
При потере ответа POST страница сверяет принятие через `GET /api/chats/<id>/turns/<request_id>`;
после обрыва SSE повторяет только чтение истории, с ограниченными паузами и при возвращении сети/вкладки.
Проверки — `test_chat_delivery.py`, `test_ui_network.py`; данные — `docs/audits/2026-11-04-network-fixes.md`.

## Рассуждение (спека 2026-10-22-studio-chat-tools-badge-reasoning, шаг схемы 15)

Кнопка «Рассуждение» — `chats.thinking`: действует только при `sections.is_local` (`thinking_ok` диалога; иначе
`PATCH {thinking: true}` — 409 `no_thinking`, хранится, но не действует), запрос несёт
`chat_template_kwargs.enable_thinking` в каждом круге, прочим моделям параметра нет; рассуждение —
`delta.reasoning_content`, иначе `delta.reasoning` (`chat.StreamTask._think`): кнопка включена или у модели её нет —
текстом событием SSE `think {text}`, в `messages.reasoning` и секунды `reasoning_sec`, до `REASONING_MAX` знаков
(дальше с кнопкой — остановка `THINK_LONG`, без кнопки — пометка `REASONING_CUT` и ответ дочитывается: облачный
оплачен); выключена — только `think {}` не чаще `THINK_EVERY_SEC`, без хранения, сверх `STRAY_MAX` знаков — «модель
зациклилась»; пределы — на весь ответ, модели рассуждение назад не уходит. В ссылку «Поделиться» рассуждение входит
только по выбору (`chat_shares.ShareIn.reasoning`), в экспорт — всегда (sharing-export.md).

## «Интернет» (спека 2026-10-21-studio-chat-internet, шаг схемы 14) — `web`

Поиск и страницы Exa — `EXA_URL` через `state.HTTP`, не `upstream`; субтитры YouTube — общий `yt-dlp` списком
аргументов только по `https://www.youtube.com/watch?v=<id>` из `web.youtube_id`, одна дорожка `pick_track`, файлы
`<uuid>.*` в `tmp_dir`; запуск — `web.RUN`, тесты подменяют; кнопка — `chats.web` (`PATCH` диалога), инструменты хода —
`web.tools_for` (только `proxied` и только с ключом Exa — без ключа ни одного, YouTube тоже; `PATCH {web: true}` без
ключа — 409 `no_exa_key`, `DELETE /api/me/exa-key` тем же запросом ставит `chats.web = 0` всем диалогам учётки;
страница — по `proxied` диалога и `me.exa_key`: без ключа кнопка выключена с подсказкой, профиль перечитан — событие
`studio-me`), круги — `chat.StreamTask` до `TOOL_ROUNDS`, вызовов за круг — до `CALLS_PER_ROUND` (лишним — шаг-ошибка
со своим `role: tool`), срок ответа — перед каждым вызовом и кругом; `chats.web` читается в транзакции хода и снова
перед каждым вызовом и кругом (выключили — «Интернет выключен», дальше без `tools`); событие SSE `tool`; 400 первого
запроса с `tools`, где тело говорит о `tool`, — `NO_TOOLS`, иное — `gateway_error`; шаги — JSON `messages.tools`
(страница — `web.public`, без текста для модели; выгрузка — целиком), в следующих ходах — блоками `<web>`
`history_block` в сообщении пользователя, без ролей `tool`; ключ — `users.exa_key` шифром, `PUT/DELETE
/api/me/exa-key` в `profile`, `verify-backup` считает `exa_keys`; ход, что даст модели Exa при расшифровке в истории
новее `chats.web_consent`, — 409 `external_web` без `web_ok`; страница — `chat.js`, ключ — «Ввод и интернет» → «Интернет» в
`settings.js`.

Правила адресов Exa и YouTube (исключение из списка разрешённых):

- **Исключение из правила списка разрешённых адресов** («Устройство» → подключения) — только адреса,
  зашитые в `web.py` (`api.exa.ai` и YouTube через yt-dlp) и в `push.py` (службы push, ниже). Первые не выбирают ни пользователь, ни модель:
  адрес страницы уходит в Exa данными, сервер по нему не ходит, и `read_page` берёт только адреса из
  сообщений и документов диалога или из `results[].url` поиска (иначе — шаг-ошибка, в Exa ничего: страница
  или выдача не уведут переписку на чужой сайт краулером Exa; сравнение — `web.norm`, а в Exa уходит адрес, как
  он записан там, без фрагмента — вариант модели не канал наружу); yt-dlp получает только канонический
  адрес из id (у него общий извлекатель — чужой адрес, в том числе внутренний, сервер прочитал бы), и
  только ролика, чей id совпал с id адреса из сообщений и документов диалога или из `results[].url`
  поиска (`web.youtube_id` от адресов `known`, любая форма — watch, youtu.be, shorts, live, embed, music,
  m.; иначе — шаг-ошибка `NOT_KNOWN`, yt-dlp не зовётся: id из 11 знаков, составленный моделью, — тот же
  канал наружу, что и адрес страницы), с урезанным окружением (без `STUDIO_DATA_KEY`) и не больше двух сразу.
  Наружу — только при `chats.web = 1`: иначе в запросе к модели нет `tools`, Exa и yt-dlp не зовутся; в
  Exa — только `query` (до 500 знаков) / `url` (до 2048) из вызова модели, не переписка (сторожат
  `test_chat_web.py`, `test_web.py`). Адреса подписок push — только службы `push.HOSTS` (https, без порта и
  пользователя, до `push.ENDPOINT_MAX`); адрес присылает браузер, сервер шлёт туда лишь зашифрованное (RFC 8291)
  уведомление без содержимого чатов — «<имя компьютера> · <имя проекта>: <повод>» (`push.allowed`, сторожит `test_push.py`).
- **Ключ Exa — свой у учётки**, `users.exa_key` шифром `security.encrypt` (как токены; смена
  `STUDIO_DATA_KEY` — вводят заново, `web.NO_KEY`). В браузер, ответы API, выгрузку и журнал не уходит:
  `GET /api/me` — только `exa_key: true|false`; при сохранении запросом к Exa не проверяется (тратил бы
  баланс). «Удалить всю историю» его не трогает — настройка, как пресеты.

## Документы и сканы в чате

`documents` — вложения чата (PDF, DOCX, TXT, MD до `documents.DOC_MAX`), текст — `documents.extract`; имена загрузок
и тексты приводятся к NFC (`documents.nfc` в `documents.clean_name`, `documents.extract`, `documents.pdf_pages`).
Сообщения и названия чатов не нормализуются (набраны с клавиатуры; NFC задела бы ключ `request_id` и предпросмотр
Cleaner). Скан в чате, ожидание сканов ходом, повтор страниц — [ocr-translate.md](ocr-translate.md#распознавание);
вложение из расшифровки и подтверждение «уйдёт во внешний сервис» — [speech.md](speech.md).

## Cleaner

Cleaner: [docs/cleaner-integration.md](../../docs/cleaner-integration.md), клиент `app/cleaner_client.py`,
схема 26. Флаг подключения `cleaner` — только серверные чат и перевод; ключ провайдера остаётся в Cleaner.
Предпросмотр обязателен для хода чата, квитанция одноразовая; текст SSE заменяется целиком (`replace`).
`STUDIO_CLEANER_CA` — дополнительный доверенный сертификат только клиента Cleaner, TLS не отключать.
Удаление контекстов — через устойчивую очередь `cleaner_deletions`; 401/403/429 откладывают повтор на час.

`cleaner_client.purge`: каждая неудача откладывает строку (`cleaner_client.RETRY_MIN_SEC` (60) …
`cleaner_client.RETRY_MAX_SEC` (3600) с, по возрасту строки); сеть и отказ списка адресов откладывают весь адрес;
`UpstreamRefused` и `InvalidToken` — на `cleaner_client.REFUSED_SEC` (86400) с; 401/403/429 — адрес на час, проход не
прерывается; до `cleaner_client.PURGE_CALLS` (10) запросов на проход. `GET /api/me/storage` несёт
`cleaner_stalled: [{base_url, count}]` — только свои строки с `retry_at > now`. Подробно —
[docs/cleaner-integration.md](../cleaner-integration.md).
