# Почта учётной записи

`email_accounts.py` отвечает за приглашения, подтверждение почты, восстановление пароля и дополнительные
коды входа; `account_mail.py` отправляет письма. Формы — `static/account.html`, `static/account.js`,
настройка кодов — `static/js/email-settings.js`, приглашения — `static/js/admin.js`.

## Поведение

- У каждой учётной записи уникальный email без учёта регистра. Новую учётку создаёт получатель приглашения:
  администратор указывает email, комментарий и при необходимости права администратора. Одноразовая ссылка
  действует 48 часов. Получатель сам выбирает логин и пароль; email берётся только из приглашения.
- В панели сохраняются email, комментарий и статус приглашения. Комментарий виден только администраторам.
  Можно изменить комментарий, отправить новую ссылку и отозвать старую. Успешная повторная отправка заменяет
  ссылку; отказ почты сохраняет прежнюю действующую. Новое неотправленное приглашение видно со статусом ошибки.
- Вход принимает логин или email. Оба имени учётки делят счёт неверных паролей и паузу.
- «Настройки → Защита → Электронная почта»: коды входа выключены по умолчанию. Изменение опции требует
  текущего пароля. Включённая опция добавляет шестизначный код после пароля: срок 10 минут, не больше пяти
  попыток. Привязка Windows-моста также требует код; работающие ключи компьютеров продолжают действовать.
- «Забыли пароль?» принимает логин или email и всегда отвечает нейтрально. Письмо со ссылкой на 30 минут
  уходит после отправки HTTP-ответа. Ссылка позволяет задать новый пароль и закрывает все веб-сеансы;
  опция кодов и самостоятельные ключи компьютеров сохраняются. При отказе почты токен удаляется.
- Почта меняется с текущим паролем и ссылкой на новый адрес. До подтверждения действует прежний адрес.
  Подтверждение требует сеанс той же учётки: ссылка открывается в браузере, где запрошена. При успехе
  остальные веб-сеансы и все прежние почтовые токены этой учётки отзываются.

## Миграция и защита

Шаг 40 (`db.EMAIL_40`) добавляет поля `users.email`, `users.email_codes`, таблицы `invitations`,
`email_tokens`, `email_limits`. Существующие учётки получают NULL email и выключенные коды. После входа
они должны подтвердить почту на `/account/email`; `/` перенаправляет туда, API отвечает 428
`email_required`, кроме получения профиля и действий подтверждения. История, пароли и работающие
компьютеры не меняются. Пути блокировки тоже доступны: если сеанс заперся во время чтения письма,
страница подтверждения предлагает открыть его паролем, не ослабляя проверку защищённых API. Первый администратор
создаётся с `STUDIO_ADMIN_EMAIL`; существующая учётка
командой `create-admin` не получает другой email автоматически.

Публичные входы — страницы `/account/{screen}` и JSON POST `/account/invite/check`, `/account/invite/accept`,
`/account/forgot`, `/account/reset`, `/account/code`. Чужой Origin запрещён, тело не больше
`auth.LOGIN_BODY_MAX`. Ответы не кешируются, Referrer-Policy — no-referrer. Секрет ссылки — во фрагменте
адреса, браузер убирает его сразу и передаёт только телом JSON. В базе — хеши токенов и кодов.
Код браузерного входа дополнительно связан со случайной Secure HttpOnly cookie `__Host-studio_email`.
Код моста проверяется только после пароля; его хеш защищён ключом данных сервера. Паузы отправки и ввода
хранятся в SQLite и переживают перезапуск. Смена пароля, почты или отключение учётки делают выданные токены
недействительными; повторная проверка происходит после вычисления хеша и ожидания SMTP.

В журнале нет email, комментариев, кодов, токенов и текста SMTP-ошибки. В журнал безопасности учётки
попадают события смены почты, включения/выключения кодов и восстановления пароля.

Общие правила восстановления сверены с [OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html).
Отправка использует [smtplib](https://docs.python.org/3/library/smtplib.html) из стандартной библиотеки.

## Настройка почты и выпуск

В `/etc/studio/studio.env` (0600, только потоком stdin) задаются:

```dotenv
STUDIO_SMTP_HOST=smtp.example.com
STUDIO_SMTP_PORT=587
STUDIO_SMTP_TLS=starttls
STUDIO_MAIL_FROM=studio@example.com
STUDIO_SMTP_USER=studio@example.com
STUDIO_SMTP_PASSWORD=<password>
```

Допустим также `STUDIO_SMTP_TLS=ssl` (обычно порт 465). Проверка сертификата обязательна.
SMTP с отдельным внутренним адресом может использовать `STUDIO_SMTP_CONNECT_IP=10.77.1.20`: TCP идёт
на этот IP, а SNI и проверка сертификата используют прежний `STUDIO_SMTP_HOST`. Без параметра используется
обычное разрешение имени. Для доверенного relay без авторизации не задаётся `STUDIO_SMTP_USER`;
TLS всё равно обязателен. При ненастроенной
почте или ошибке доставки приглашение/код/подтверждение возвращают 503 и не дают войти без кода.
Проверять нужно фактическое получение письма, затем регистрацию, восстановление и вход с кодом.

Для привязки подтверждённого владельцем адреса к существующей учётке без сброса пароля:
`python manage.py set-email` читает `STUDIO_ACCOUNT_LOGIN` и `STUDIO_ACCOUNT_EMAIL` из stdin. Команда
отказывается заменять уже заданный другой адрес, выводит только id и итог. Перед изменением рабочей базы
делается согласованная копия. Для новой установки `STUDIO_ADMIN_EMAIL` можно передать из vault или
игнорируемого `deploy/local-profile.sh` вместе с `--create-admin`; в Git — только примеры.

Откат к коду схемы 39 совместим с добавленными столбцами и таблицами, но отключает почтовые ограничения
и возвращает прежнее создание учёток. Это граница безопасности отката; удалять данные шага 40 не нужно.

`tests/test_ui_email_accounts.py` (HTTPS; Chromium, Firefox, WebKit; 320/390/1280 px), тесты привязки и настройки моста.
