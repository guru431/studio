# «Сканы» и «Перевод»

## Распознавание

- Распознавание (спека 2026-10-27-studio-ocr-design, шаг схемы 16 `db.OCR_16`): раздел `ocr`
  «Распознавание», вкладка рельса «Сканы» (`ocr.js`, `#/ocr`). Документ — `scans` (`queued`, `working`,
  `cancelling`, `done`, `error`, `cancelled`; `origin` — `section`/`chat`, `attachment_id` без FK; `text` —
  весь текст по готовности, для поиска триггерами `search_scans_*`), страницы — `scan_pages` (n с 1, свой
  `user_id` — для `media.referenced`; `waiting`, `done`, `failed`, `layer`, `blank`). Шаг 16 связал каждое
  подключение srvllm с `ocr` (`hunyuan-ocr`, умолчание — наименьшее). API `/api/ocr` (`ocr.router`):
  загрузка — один PDF (все страницы, слой не читается) или 1…`PAGES_MAX` (50) фото PNG, JPEG, WebP одним
  документом, до `documents.DOC_MAX` на всё; лента, документ (`pages` — список страниц, в ленте и с
  `?brief=1` — число),
  `cancel`, `DELETE`, `export?format=txt|md|docx`, `attachments` — «<имя>.md» в чат. Очередь — один раннер
  на пользователя (`ocr.RUNNERS`, `kick`), ждущих до `QUEUE_MAX` (5, дальше 409 `busy`). Страница —
  `POST <адрес>/pages/ocr`, модель `tencent/HunyuanOCR` (в студии — `hunyuan-ocr`), `PROMPT` — дословно
  cleaner `_OCR_PROMPT`; обрезанный, пустой ответ, карта блоков `layout_type` и страница, которую не
  нарисовать (`ScanError` рендера, обрезанное фото — `ocr.UNREADABLE`), — отказ страницы (`failed` со
  словами), прочие отказы шлюза — документа; 503 — повтор раз в `RETRY_SEC` до `WAIT_MAX_SEC`.
  Рендер — `ocr_render`: pypdfium2 только под замком `PDFIUM` (PDFium не потокобезопасен и на разных
  документах), 300 DPI, длинная сторона ≤ `MAX_SIDE` 2200, фото — поворот по EXIF; пустая страница
  (`is_blank`, разброс яркости < `BLANK_STDDEV`) шлюза не зовёт. Скан в чате (только подключение через
  сервер): PDF, где у страницы нет текста слоя или он короче `LAYER_MIN_CHARS` (40 непробельных) и в
  ресурсах есть картинка (`needs_ocr`; битые ресурсы — картинка), с подключением раздела `ocr` —
  вложение без текста и документ `origin=chat` (ответ загрузки — `ocr {id, pages}`), без подключения —
  `chat.NO_OCR`, а сканы части страниц (`ocr_render.is_scan`, `pdf_layer_pages`, как у переводчика) — 422 `scan`
  `chat.SOME_SCANS`. Ход создаётся сразу, `StreamTask._await_scans` ждёт сканы хода и истории диалога
  (`ocr.pending`) раз в `SCAN_POLL_SEC`, событие SSE `ocr {page, pages}`, у сообщения в GET — `ocr`, у
  вложения без текста с идущим сканом — `ocr {id}`;
  затем ждёт `ocr.idle` и только тогда `compose` и предел контекста, срок ответа — от готовности.
  Ошибка документа — «скан не распознан: …» без модели, слова — в `content` ответа-ошибки (`compose` его не
  берёт), в GET — `error` при пустом `content`; «Остановить» отменяет только сканы, ещё стоящие в очереди (ниже). Прямое
  подключение — 409 `not_ready`: страница опрашивает `GET /api/ocr/<id>?brief=1` сканов поля и вложений
  диалога и повторяет ход; правка поля или вложений снимает ожидание обычного хода, но не «Ответить
  заново». Подключение раздела есть, но адрес убран из списка — слова
  `sections.unlisted`. Текст вложения — `ocr.attachment_text` («Страница N», не длиннее
  `documents.TEXT_MAX_CHARS` — дальше обрезка с пометкой); дописанный после хода — в поиске чата
  (триггер `search_attachments_text`). Файлы — исходный PDF и PNG страниц в `media`;
  «Хранилище» считает их по MIME.

Дополнения к устройству выше:

- **«Остановить» ответа чата** отменяет только сканы, ещё стоящие в очереди; идущий дорабатывает, «Ответить заново»
  берёт его текст (прежнее «Остановить отменяет документ» снято).
- `POST /api/ocr/{id}/retry {page?}` (`ocr.retry`): с `page` — «Повторить страницу» (только `failed`), без — «Распознать
  заново» (все `failed` и `waiting`); только для кончившегося документа; 409 `running`/`nothing`/`no_connection`/`busy`.
  PNG страницы PDF берётся прежний. У документа из чата текст вложения до нового итога пуст (ход его ждёт), итог
  пересобирает `ocr.attachment_text`. `POST /api/attachments/{id}/ocr` — то же для вложения чата; в GET диалога такое
  вложение — `rescan: true`.
- `ocr.release(conn, busy)` прекращает повторы после 409, как только `busy()` (новый документ) истинна; `_settle`
  передаёт `_scanning`.
- NFC: `ocr.recognize` (сканы и снимки перевода) приводит текст к NFC.
- Выгрузка TXT/DOCX: `exports.md_plain` снимает только `exports.HTML_TAG` (именованные элементы HTML в пределах одной
  строки); `<`/`>` сравнений и формул остаются.

## Перевод

- Перевод (спека 2026-10-28-studio-translator-design, шаг схемы 18 `db.TRANSLATE_18`): раздел `translate`
  «Перевод», вкладка рельса после «Сканов» (`translate.js`, `#/translate`); только через сервер, оба вида
  подключений, модели — чат-модели подключения (без `CATALOG`; новая связь srvllm — `CHAT_INITIAL`). Связи
  чата через сервер с их моделями и умолчанием раздел получил при старте `sections.adopt("translate", "chat")`
  — один раз на базу (флаг `settings` `adopted:translate`), дальше разделы порознь. `translate_text` — языки
  `LANGS` и `redirect` (исходник совпал с целевым — на английский, английский — на русский), определение языка
  моделью (`detect`), `normalize` (`\r\n` → `\n`) до `split`: куски до `CHUNK_CHARS` (3000) по абзацам, затем
  предложениям, пробелам, жёстко, склейка с разделителями — исходник байт в байт; указание `PROMPT` — текст
  данные, не просьбы, только перевод; кусок — поток `chat/completions` подключения; `temperature`, `max_tokens`
  и `chat_template_kwargs.enable_thinking: False` — только `sections.is_local`, облачным ничего из этого (модели
  рассуждений OpenAI — 400); `finish_reason` не `stop` — ошибка, `length` — кусок пополам (обрезка половинки —
  ошибка). `translate_spot` — разбор ответа HunyuanOCR с координатами (`parse`, доли 0…1000) и сборка строк в
  блоки (`group`). `translate` — записи `translations` (`text`, `file`, `photo`), куски `translation_parts`
  (`waiting`, `done`, `failed`; у снимка — блок с `box`), API `/api/translate`; две полосы на пользователя
  (`text` — поле, `file` — файлы и снимки; в полосе одно идёт, ждущих до `QUEUE_MAX` 5, дальше 409 `busy`).
  Текст — до `TEXT_MAX` (300 000) знаков после `normalize`; отказ куска — `failed` со словами, запись — «кусок
  n из N: …», готовое видно; 503 — повтор раз в `RETRY_SEC` до `WAIT_MAX_SEC`; локальной модели — release
  моделей картинок раз на задание. «Остановить» бросает поток куска на следующей дельте, `recover` — «прервано»;
  «Продолжить» (`resume`) — та же модель и язык, только непереведённые куски (подключения нет — 409
  `no_connection`); «Перевести» у записи-файла и снимка — `…/repeat`, новая запись из исходника (снимок — те
  же блоки, скан — текст готового скана) без загрузки и распознавания. Файл — PDF, DOCX, TXT, MD
  (`documents.extract`, до `DOC_MAX`), исходник — в `media` (`source_media_id` знает `media.referenced`). PDF
  со страницами без слоя при подключении `ocr` через сервер — документ «Сканов» `origin=section` с тем же
  файлом (`ocr.plan_pages`), запись — со `scan_id` без исходника; задание ждёт скан, берёт
  `ocr.attachment_text` и зовёт модель после `ocr.idle`; скан удалён, отменён или без текста — «скан не
  распознан: …». Без такого подключения PDF со страницами `ocr_render.is_scan` (слоя мало и есть картинка;
  `pdf_layer_pages`) — 422 `scan`, и когда сканы — часть страниц; пустая страница без картинки — не скан,
  пропускается. Снимок (PNG, JPEG, WebP; только с `ocr` через сервер, иначе 409 `no_ocr`) — на шару PNG
  `ocr_render.photo_png` (EXIF, ≤ 2200), те же байты распознаются и показываются: один `/pages/ocr` с
  `translate_spot.PROMPT` под `ocr.borrowed` (`free_card` до, `_settle` после, учёт в `ocr.EXTERNAL`, на время
`_settle` — `ocr.RELEASING`: пока он стоит, `ocr.idle` ложна; распознавание дольше `FREED_FRESH_SEC` (15 с) —
release моделей картинок заново перед переводом); срок ожидания карты (`WAIT_MAX_SEC`) не идёт, пока её держит своё
распознавание пользователя (`ocr.holding`); пустой
  ответ (`ocr.EMPTY`) — «готово» со словами «текст на снимке не найден», без модели; текст без координат —
  ошибка `NO_BOXES`; блоки — пачками до `CHUNK_CHARS` нумерованным запросом (`numbered`, `parse_numbered`),
  вернулись не все номера — по одному; модель — после `ocr.idle`. Поиск — триггеры `search_translations_*`
  (имя, исходник и перевод по `INDEX_CHARS`; `text` пишется по готовности, остановке и ошибке); выгрузка —
  `translations/` с файлами, тексты кусков — только у снимков (рамки); скачивание — `…/export?format=txt|docx`
  (Markdown в docx — только у перевода скана). Лента берёт начало исходника и перевода из куска n = 1 (у снимка —
  из всех блоков по порядку, `_photo_heads`: кусок — одна надпись), опрос
  `?from=k` (k > 0) не шлёт `source` ждущих кусков (кроме снимка). Удаление записи уносит её скан (`ocr.remove` —
  тот же путь, что удаление в «Сканах»), если на него не ссылается другая запись (повтор); скан ещё
  останавливается — 409. Лента и `GET` записи несут `scan_shared` (есть другая запись с тем же `scan_id`) — по нему
  окно удаления говорит, останется ли скан. Журнал — id, коды и числа: текст, имя файла и языки исходника — нет. Наложение —
  `translate-photo.js` (`photoView`, `savePng` — PNG рисует canvas); страница опрашивает идущую запись
  `?from=k` — только новые куски.

Дополнения:

- Контекст: `translate_text.CONTEXT`, `translate_text.CONTEXT_CHARS` (300), `translate_text.CONTEXT_SENTENCES` (2),
  `translate_text.tail`, `translate_text.repeats`, `translate_text._without_echo`; `translate_text.system_prompt(...,
  context=)`, `translate_text.chunk(..., context=)`; `translate._context`. 1–2 последних предложения перевода
  предыдущего куска — в рамке `<previous_translation>` с пометкой «данные: не переводить, не повторять, не
  продолжать»; теги рамки внутри контекста вырезаются; ответ, начинающийся полным повтором контекста, — повтор
  снимается; кусок-«припев» (`repeats`), Cleaner и блоки снимка контекста не получают; «Продолжить» берёт контекст из
  готового куска в базе. Глоссария нет.
- NFC: `translate_text.normalize`, итог `translate_text.chunk`, путь Cleaner `translate._attempt`.

## Ловушки

- Слот `ocr` (6656 МиБ) не помещается рядом ни с gemma-abl, ни с comfy и держит карту арендой 900 с:
  перед первой страницей документа — `speech.free_card`, после каждого документа (готово, ошибка, отмена —
  звал он шлюз или нет) и после отмены ждущего — `ocr._settle`: `POST <адрес>/pages/ocr-release {}` каждому
  шлюзу из `ocr.LEASED` (`ocr.release`; 409 `slot_busy` — повтор через `RETRY_SEC` до `RELEASE_RETRIES`),
  если в студии не идёт и не ждёт другое распознавание. Решает студия, а не документ: последним может
  кончиться документ, что шлюз не звал (пустые страницы, отмена до первой страницы). Запись `LEASED`
  снимает только удачный release, и только если она та же и новый документ не начался; неудачный оставляет
  её концу следующего документа. Без release
  Lustify и gemma-abl ждали бы 15 минут. Отмена идущего документа запрос страницы не обрывает: раннер
  дожидается ответа, выбрасывает его и только потом освобождает карту (`stop_user` обрывает сразу, release —
  фоном: шлюз ещё считает оборванную страницу, 409 и повтор). Из обработчиков HTTP (отмена ждущего,
  `stop_user`) release — фоном, `ocr.settle_later` (`ocr.SETTLING`, гасит `ocr.stop`): ответ шлюза не ждёт.
  Ход чата со сканом зовёт модель только после `ocr.idle` — раннер уже освободил слот и release фоном нет:
  итог документа пишется раньше release, и gemma-abl иначе ждала бы карту под арендой `ocr`. Перевод — так
  же; снимок перевода распознаётся вне раннера, под `ocr.borrowed`: пока он идёт, он в `ocr.EXTERNAL`, и
  release другого распознавания его не оборвёт.
