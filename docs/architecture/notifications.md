# «В работе», Web Push, ntfy

## «В работе» (`jobs`)

`jobs` — свои идущие и готовые за час задания всех разделов: только база и память модулей, к шлюзу не ходит.
Страница — `jobs.js`: значок и панель, опрос `GET /api/jobs` и уведомления (локальный запасной вариант через
`showNotification`, флаг устройства `studio-notify`); нажатие на уведомление — `notificationclick` в `sw.js`; разделы
переходят к записи по `?id=` и зовут `jobs.js::kick` после запуска. У идущих строк — `cancel` (`jobs.CANCEL`; у чата —
`/api/chats/<id>/stop`), в панели «Отменить» (адрес проверяется регуляркой); закрытый раздел — 423.

## Web Push (`push`)

Ключ VAPID (P-256) — `settings` `vapid` шифром `STUDIO_DATA_KEY`, тело — RFC 8291 aes128gcm, подпись JWT ES256;
`GET/POST/DELETE /api/me/push`, флаг устройства `studio-push`; адреса — только `push.HOSTS`. Поводы «Агентов» —
`bridge._push` (подробно — [agents.md](agents.md)); задания разделов — `push.job_finished` (первое сохранение итога,
отмена — тишина; название «Студия», текст — только повод, адрес `<раздел>?id=<id>`). Web Push выбирает только живые
сессии активной учётки и перепроверяет получателя перед каждой отправкой.

- У сессии одна подписка: новый `POST` удаляет прежние адреса этой сессии. `GET /api/me/push.endpoint` — первые 16 hex
  SHA-256 адреса подписки.
- `sw.js`: на 423 подписка остаётся, окнам — `{push:'resync'}`; `push-sync.js` (зовёт `app.js::enter`) сверяет признак
  с подпиской браузера и досылает через `api.js` (под замком ждёт отпирания); `pushsubscriptionchange` переподписывает.
- Ссылка «Поделиться», отключённая после `chat_shares.FAILS_MAX` неверных PIN, — push и ntfy владельцу без содержимого.

## ntfy

Прямые уведомления ntfy — `app/ntfy.py`, схема 30: `ntfy_devices` привязаны к digest сессии,
каскад от `sessions` и учётки. Прежние `ntfy_settings` — только шаблон параметров, без отправки.
Миграция сохраняет сервер/токен, назначает разные темы и выключает ntfy у всех устройств;
новая сессия тоже всегда начинает с выключенным ntfy. Общая тема не назначается новому устройству.
«Настройки → Прочее → ntfy» (`ntfy-settings.js`): HTTPS-сервер из административного allowlist,
тема, необязательный токен, включение, сохранение/проверка/сброс. `GET/PUT/DELETE /api/me/ntfy`,
`POST /api/me/ntfy/test` — только текущая сессия, CSRF и блокировка по общим правилам; сброс
меняет только её настройки, тест шлёт только её теме. Токен шифром
`security.encrypt`, наружу только `has_token`; отсутствующий токен сохраняется лишь у прежнего
сервера, пустой удаляется. Доставка — JSON POST в корень ntfy через `upstream.request` (DNS pinning,
публичные адреса имени, TLS, без redirect, 10 с), без переписки, с `click` на свой origin.
`push.notify_later` отправляет Web Push и ntfy независимо; события мостов и заданий общие.
`GET /api/jobs.push` учитывает ntfy только текущей сессии, чтобы её локальные уведомления не дублировались.
Доставка — включённым непросроченным сессиям активной учётки, с дедупликацией server/topic и
независимой обработкой отказов устройств. Выход/истечение сессии прекращают её доставку.
Клиенты ntfy получают всё из своей темы: для физического разделения доставки темы должны отличаться.
Ссылка `ntfy://` в настройках открывает подписку на сохранённую тему этого устройства. Тесты: `tests/test_ntfy.py`,
`tests/test_ui_ntfy.py` (integration, 320/1280).
`ntfy` не импортирует `upstream` при загрузке: цепочка main → bridge → push → ntfy иначе
замыкает connections/upstream до объявления `UpstreamRefused`. На Debian Python 3.13 аннотация
`connections.refused` вычисляется сразу, а локальный Python 3.14 скрывал этот сбой. Проверка
холодного импорта — `test_ntfy_import_does_not_start_the_connections_cycle`; после изменения
цепочки импорта дополнительно проверить `import main` на Python хоста до перезапуска службы.
Проверка холодного импорта запускает отдельный процесс и относится к `integration`.

## Ловушки

- Ключ VAPID — в базе (`settings` `vapid`) шифром `STUDIO_DATA_KEY`, не в vault: сменили ключ данных — служба
  заводит новый ключ VAPID и стирает все `push_subs` (браузеры подписаны на прежний открытый ключ), push на
  устройствах включают заново.
