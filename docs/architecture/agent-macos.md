# Мост macOS

С Studio 0.22.0 и Studio Agent 0.29.0 общий мост работает на Windows и macOS Intel/Apple Silicon.
Протокол v1, PIN, исходящий WebSocket, ограничения доступа и запрет записи личных данных в журнал
совпадают с [общим мостом](agent-bridge.md). Совместимость старых Windows-мостов сохраняется.

`GET /api/agent/download?platform=macos` отдаёт вошедшему пользователю один автономный
`studio-agent-setup.pkg` (с Studio 0.23.0 / Agent 0.30.0). Штатный установщик macOS запускается
двойным щелчком. ZIP исходников остаётся форматом автообновления. Прежний URL
без параметра отдаёт Windows EXE. Секреты устройства по-прежнему передаются только в заголовке.
Необязательное поле `hello.platform` (`darwin`/`win32`) помогает выбрать установщик машины на связи.

## Установка и системные границы

- PKG для macOS 13+ содержит native runtime Python с Tk и закреплённые wheels Intel/Apple Silicon;
  установка проходит без сети, sudo, Homebrew и системного Python. Git и CLI настраиваются отдельно.
  LaunchAgent добавляет обычные пути Homebrew,
  `~/.local/bin`, `~/.cargo/bin`, `~/.opencode/bin`; команды запускаются списками аргументов без shell.
  OpenCode также обнаруживается внутри `/Applications/OpenCode.app` и `~/Applications/OpenCode.app`:
  используется вложенный CLI `Contents/Resources/opencode-cli`.
  Сведения о дисках включают корневой и подключённые локальные тома `/Volumes/`; сетевые ФС и служебные
  APFS-тома исключены. Сбор ограничен таймаутом внешней команды, при отказе остаются сведения о корневом диске.
- Настройки: `~/Library/Application Support/Studio Agent`. Приложение:
  `~/Applications/Studio Agent.app`. Выпуски: `app/releases/release-*` внутри каталога настроек;
  приложение открывает `app/current`. Среды venv создаются сразу по окончательному пути.
- Python установщика хранится отдельно в `app/runtimes/<sha256>`: уборка старых выпусков не удаляет
  интерпретатор, на который ссылаются venv автообновлений. Повторная установка использует тот же runtime.
- Ключ Fernet лежит в Keychain под сервисом `com.studio.agent.secrets.v1`, запись привязана к
  настоящему пути каталога настроек. `key.bin` и `pin.bin` содержат только аутентифицированный
  шифротекст. Ошибка или блокировка Keychain не создаёт замену существующего ключа. Пароль Studio
  не сохраняется. Перенос конфигурации на другую машину требует новой привязки и задания PIN.
- Один экземпляр на каталог настроек: `flock`, автоматически снимаемый ОС. Установщик использует
  тот же замок и отказывает при работающем мосте. Автозапуск — пользовательский Aqua LaunchAgent
  `~/Library/LaunchAgents/com.studio.agent.plist`, без `KeepAlive` и остановки текущего процесса.
- Tk и значок строки меню используют главный цикл macOS (`pystray.run_detached`).
- Codex/OpenCode и установщики CLI получают отдельную POSIX-группу процессов; закрытие клиента
  завершает также его дочерние процессы. Claude Code сохраняет штатный жизненный цикл SDK.
- С Agent 0.32.0 удалённый рабочий стол доступен и на Mac: экран, мышь, клавиатура (включая Cmd/Option)
  и текстовый буфер обмена. `desktop_enabled` по умолчанию выключен; выбор сохраняется и меняется только
  в локальном окне агента. Там же кнопки «Запись экрана…» и «Управление вводом…» запрашивают системные
  разрешения и открывают соответствующие страницы конфиденциальности macOS для **Studio Agent**.
  С Agent 0.33.0 приложение содержит нативный launcher `com.studio.agent`, который загружает Python
  в свой процесс. Приложение, автозапуск и обновлятор используют эту идентичность. Переход со старого
  Python-launcher выполняется до запуска GUI и заданий, включая первый запуск старым обновлятором.
  Прежние разрешения Python не переносятся: macOS требует один раз выдать их Studio Agent локально.
  Обновления кода моста сохраняют тот же launcher; изменение самого launcher может потребовать повторной выдачи прав.
  В локальном окне показаны отдельные статусы записи экрана, управления вводом и графического сеанса;
  они перечитываются раз в пять секунд и при возврате из системных настроек, без повторного запроса прав.
  Обновление и первый переход из Python открывают приложение через Launch Services, сохраняя настройки
  и подтверждение запуска. После запуска из SSH вне Aqua мост нужно один раз открыть из «Приложений»;
  такой сеанс не считается готовым к удалённому рабочему столу даже при выданных правах Python.
  После выдачи доступа к экрану macOS может потребовать штатный перезапуск агента после окончания заданий.
  Запросы из Studio сами разрешений не запрашивают. Блокировка, смена активного пользователя, отзыв
  разрешений, обрыв канала и выключение локального доступа завершают управление и отпускают ввод.
  Собственное окно/меню агента недоступны для удалённого ввода. Экран входа и заблокированный Mac не обслуживаются.
- `desktop_macos.py` использует Quartz/AppKit и ScreenCaptureKit на macOS 14+ (на 13 — Core Graphics).
  Retina захватывается с учётом масштаба, координаты мыши — в логических границах монитора, включая отрицательные.
  Изображения и буфер остаются в памяти; `screencapture`, временные PNG и AppleScript не используются.
- Intel использует `cryptography==48.0.1` с готовым universal2-пакетом; Windows и Apple Silicon —
  основную версию из `constraints.txt`. Зависимости Cocoa/Quartz также закреплены.

Обновление проверяет размер и SHA-256, готовит отдельную среду, ждёт простоя и штатного выхода.
Хелпер stdlib ждёт прежний PID, запускает новую копию и переключает прежний LaunchAgent и `current`
лишь после подтверждения готовности. При раннем падении новой копии запускается прежняя.

Проверка паритета 2026-11-17: проекты, файлы/Git, PIN, чаты и ходы трёх CLI, MCP, Keychain,
строка меню, LaunchAgent и автообновление моста имеют пути macOS. Оставшиеся ограничения:
снимок компьютера пока показывает только корневой том; нативные Claude Code/Codex (в том числе
Homebrew) обновляются вручную, из Studio поддержаны npm/VS Code и штатный upgrade OpenCode.
CLI устанавливаются и авторизуются отдельно; блокировка экрана и системные разрешения macOS
сохраняют действие независимо от разрешения рабочего стола в агенте.

## Проверки

`deploy/build-agent-macos.py --archive <studio-agent.zip> --output <studio-agent-setup.pkg>` работает
на Mac либо через SSH (`STUDIO_MACOS_BUILD_*` в [локальном профиле](../publication.md)). Он проверяет
SHA-256 обоих runtime из `deploy/macos-runtime.json`, скачивает закреплённые wheels для обеих архитектур,
проверяет настоящую установку без сети во временный HOME и собирает пользовательский PKG через
`pkgbuild`/`productbuild`. Все промежуточные файлы и кэши находятся рядом с ZIP в `.tmp`.
Вся удалённая сборка ждёт до 60 минут; отдельные команды и передачи сохраняют предел 15 минут.
PKG содержит скрипт общего установщика, не запускается от root и не меняет системный Python.
Без Developer ID Installer пакет не подписан; macOS может потребовать «Всё равно открыть».

Windows: команды наборов `main` и `agent` из корневого `CLAUDE.md` и `agent/CLAUDE.md`.
На macOS команды выполняются из `agent/`; временные каталоги и кэш задаются внутри `.tmp/<task>/`.

Быстрый переносимый набор (Python на Mac):

```sh
.venv/bin/python -m pytest tests/test_macos.py tests/test_desktop_macos.py tests/test_desktop.py tests/test_store.py tests/test_pin.py tests/test_link.py tests/test_files.py tests/test_file_operations.py tests/test_gitinfo.py tests/test_cli.py tests/test_constraints.py tests/test_codex_rpc.py tests/test_opencode_rpc.py -q
```

Системная приёмка без LLM-квоты:

```sh
.venv/bin/python -m pytest tests/test_macos_integration.py tests/test_macos.py -q -m integration
```

Для теста автономного PKG распакуйте его `pkgutil --expand-full` в `.tmp/<task>/expanded`
и задайте `STUDIO_AGENT_MACOS_PAYLOAD` путём `expanded/bridge.pkg/Scripts`. Проверяются отсутствие
сети, повторная установка, сохранение ключа и независимость runtime от выпуска исходного кода.

Keychain проверяется отдельной временной связкой, которая удаляется в `finally`; окно и строка меню
проверяются в графическом сеансе. Отдельная проверка реальной генерации требует авторизованных CLI
и выполняется только по согласованию владельца.
