## 1. Зачем

После серии генераций владелец снова и снова набирает одни и те же модель, формат, силу и
начало промпта; чтобы понять, лучше ли правка исходника, листает две картинки туда-обратно; чтобы
подобрать силу правки или удачный seed, запускает генерации по одной и ждёт каждую. Цепочка
промптов показывает путь к картинке, но не показывает другие варианты, сделанные из того же шага.

## 2. Критерий успеха

1. Чип «★» → «Сохранить как пресет…» → имя «Портрет студия» → пресет в меню; на другом устройстве
   он тот же; нажатие ставит модель, формат, силу, seed (если сохранён) и промпт.
2. В просмотре правки — «Сравнить с исходником»: две картинки друг над другом, вертикальная
   граница тянется пальцем или мышью; на компьютере и телефоне.
3. В режиме выделения отмечены ровно две картинки с файлом — «Сравнить» открывает то же сравнение.
4. Чип серии «×3 · seed» → «Создать» → в ленте три карточки: первая генерирует, две — «в очереди
   серии»; готовые встают по одной; «Отменить» у любой снимает её и остальные невыполненные.
5. С исходным фото у Lustify — серия по силе «от 0.25 до 0.75, 3 варианта»: перед запуском видно
   значения 0.25 · 0.50 · 0.75; три картинки с этими силами.
6. В просмотре картинки — «Варианты»: миниатюры других картинок из того же исходника и картинок,
   сделанных из этой; нажатие открывает вариант (его цепочка — своя ветвь).
7. Параметры, которые модель не принимает, не показываются и не обещаются: у FLUX нет силы (и в
   цепочке нет «сила 0.65»), у внешнего сервиса нет seed.

## 3. Не цели

- Пресеты видео, чата, речи; общие пресеты между пользователями; импорт и экспорт пресетов.
- Сравнение больше двух картинок, разница пикселей, сравнение роликов.
- Серия больше `SERIES_MAX` (4), серия из нескольких моделей, серия по промптам, серия правок
  кистью (маска — только одиночная правка), серия у видео.
- Дерево ветвей целиком на одном экране; переименование ветвей.
- Побитовое повторение между версиями модели (seed повторяет картинку только той же модели и
  версии шлюза — так и пишем).

## 4. Анти-цели

- Пресет, вариант или сравнение показывают чужую картинку (любой чужой id — 404).
- Серия занимает карту в обход шлюза или держит больше одного запроса к шлюзу на пользователя
  одновременно (одно задание картинки на пользователя остаётся: серия — по одной).
- Отмена серии оставила карту занятой моделью (освобождение после отмены — как у одиночной).
- Промпты пресетов или серии попали в журнал.
- Откат `install.sh` на прежний код ломается на новой базе.

## 5. Пресеты

**Схема — следующий свободный шаг `db.STEPS`** (в работе — 10; окончательный номер — при слиянии в
`main`, план: 10 расшифровки, 11 фото, 12 подключения):

    CREATE TABLE presets(id TEXT PRIMARY KEY, user_id INTEGER NOT NULL REFERENCES users ON DELETE CASCADE,
          section TEXT NOT NULL, name TEXT NOT NULL, params TEXT NOT NULL, created REAL NOT NULL);
    CREATE INDEX presets_user ON presets(user_id, section);
    CREATE INDEX images_user_source ON images(user_id, source_media_id);

- `section` — пока только `photo` (на будущее, без новых таблиц). `params` — JSON
  `{model, connection_id, size, seed, strength, prompt}`: `model` и `connection_id` — пара выбора
  (как у чипа модели), `seed` и `strength` — число или null, `prompt` — строка или null.
- Пресеты — настройки, а не история: «Удалить всю историю» их не трогает, удаление учётки — каскадом.
  README так и говорит.
- Пределы: имя 1…60 знаков, промпт — как у задания (24 000), не больше `PRESETS_MAX` (50) на
  пользователя (409 `presets` «не больше 50 пресетов — удалите ненужные»). То же имя — замена
  прежнего пресета (подтверждение — на странице).

**API** (объявить раньше `GET /api/images/{image_id}`):
`GET /api/images/presets` → `{items: [{id, name, params, created}]}` (новые сверху);
`POST /api/images/presets` `{name, params}` → 201 (замена по имени — тот же ответ);
`DELETE /api/images/presets/<id>` → 204. Только свои; чужой id — 404.

**Страница.** Чип «★» в ряду чипов: меню — пресеты (нажатие — применить, «×» — удалить с
подтверждением), внизу «Сохранить как пресет…» (окно: имя, галочки «промпт» — по умолчанию да, если
поле не пусто, и «seed» — по умолчанию да, если seed задан). Применение: модель — если пара есть
среди отмеченных моделей раздела (иначе остаётся текущая и строка «модели «FLUX» нет в разделе —
выбрана текущая»), формат, seed, сила (видна только у Lustify с исходником, ставится всегда);
промпт — если в поле пусто; если не пусто — окно «Заменить промпт пресетом?» («Заменить» / «Оставить
свой» — тогда ставится всё, кроме промпта).

## 6. Сравнение

**Окно `#compare`** (`dialog` через `showModal()`, как просмотр): две картинки в одной рамке
(`object-fit: contain`, одинаковая область), правая обрезана по вертикальной границе
(`clip-path`); граница — ползунок (`input type=range`, клавиши ←/→) и перетаскивание пальцем или
мышью по рамке. Подписи слева и справа — шаг цепочки или модель · seed · сила. «Поменять местами»,
крестик и Escape закрывают. Картинки — оригиналы (`/api/media/<id>`), не миниатюры.

**Откуда.** В просмотре картинки, у которой есть исходник с файлом (у предыдущего шага цепочки
есть `media_id`: удалённая строка исходника файл не уносит, пока на него ссылается правка, — шаг
«удалена», а сравнить можно), — «Сравнить с исходником» (исходник слева). В режиме выделения «Фото»: ровно
две отмеченные с файлом — действие «Сравнить» (в шапке и в панели телефона), иначе его нет. Режим
выделения при этом не закрывается. `select.js` получает необязательный список действий раздела
(`extraActions`) — видео им не пользуется.

## 7. Серии

**Запрос.** `POST /api/images` получает необязательное поле `series`:
`{"count": 2…4, "vary": "seed"}` или `{"count": 2…4, "vary": "strength", "strength_to": 0.05…1}`.
- `vary=seed`: seed задан — `seed, seed+1, …` (по модулю 2³²); пуст — случайные разные.
- `vary=strength` — только Lustify на srvllm с исходником (иначе 422 `series` словами): силы —
  `count` значений поровну от `strength` до `strength_to` включительно, округлённые до 0.05, без
  повторов (повторы — 422 «слишком узкий диапазон для N вариантов»).
- Внешний сервис — только `vary=seed`, и seed ему не уходит (N независимых картинок; README:
  «каждая — отдельный платный запрос»).
- Маска с серией — 422 (`series`).

**Задания.** Серия — `count` строк `images` сразу: первая `working`, остальные — новое состояние
`queued` («в очереди серии · 2 из 3») со своими seed и силой, общим `series_id` в памяти задания
(колонка не нужна: связь живёт, пока серия идёт). Одно задание картинки на пользователя
сохраняется: серия держит слот до последней; `ensure_idle` видит `queued` как занятость. Серия идёт
одной задачей: следующая строка стартует после конца предыдущей тем же путём `run_job` (освобождение
другой модели перед запросом, сохранение, `_store`). Ошибка одной — следующая всё равно идёт.
«Отменить» у любой строки серии снимает весь её остаток: идущая — как одиночная отмена
(`cancelling`, ожидание конца запроса, `release_after_cancel` — карта освобождается), все `queued`
серии — сразу `cancelled` («отменено»); готовые остаются. Серия, дошедшая до конца без отмены, карту
не освобождает (как одиночная: аренда модели держится 600 с — следующая картинка той же модели не
ждёт загрузки). `recover()` при старте переводит `queued` в `error` («прервано перезапуском
студии»), как `working`; `stop()` при остановке службы переводит `queued` в `error` сам — иначе после
отката `install.sh` на прежний код (его `recover()` о `queued` не знает) строки остались бы
неудаляемыми. Отключение и удаление учётки — как у задания (`forget_user`, `settle_user`) и для
`queued`.
`DELETE` строки `queued` — 409 «сначала отмените», как у идущей. Ответ `POST` — `{id, seed, ids}`
(`ids` — все строки серии по порядку; `id` — первая).

**Страница.** Чип серии «×1» (меню: 1, 2, 3, 4; при 2+ — «меняется: seed / сила»; «сила» видна
только у Lustify с исходником и показывает второй ползунок «до» и строку значений). Сброс серии в
«×1» — после запуска. То же — в окне «Изменить» (`editor.js`): правку картинки истории подбирают
как раз серией по силе; поле `series` уходит в multipart строкой JSON, ответ `ids` редактор отдаёт
разделу вместе с `id` (кистью серии нет — с маской выбор серии скрыт). Лента получает все строки серии сразу (`adopt` по `ids`), карточка `queued` —
как идущая, но без таймера, с «Отменить». `RUNNING` страницы включает `queued`.

## 8. Ветви

`GET /api/images/<id>/variants` → `{siblings: […], children: […]}`: только свои готовые с файлом;
`siblings` — с тем же `source_media_id` (кроме самой; у генерации без исходника — пусто),
`children` — с `source_media_id` = `media_id` этой. Поля — как у ленты (`_out` без цепочки), не
больше 24 в каждом, новые сверху. В просмотре под цепочкой — «Варианты» (миниатюры двумя рядами
«из того же исходника» и «из этой»), нажатие открывает вариант в том же просмотре. Нет вариантов —
блока нет. Индекс `images_user_source` — шаг 11.

## 9. Параметры по модели

- Сила хранится и показывается только у Lustify на srvllm: `images.create_job` пишет `strength`,
  только если модель — `lustify` (сейчас FLUX-правка пишет 0.65, которую FLUX не получает); старые
  строки и снимки цепочки FLUX с силой — карточка, цепочка (`chain.js` `meta`) и сравнение её не
  показывают (по модели шага).
- Внешний сервис seed не получает: чип seed у модели внешнего подключения скрыт, у его картинок seed
  не показывается (карточка, таблица, цепочка), «Повторить с тем же seed» называется «Повторить».
  Внешняя — модель не из `images.MODELS` (у строк нет `connection_id`). В базе случайный seed такой
  строки остаётся, как сейчас (`images.seed NOT NULL`, а шаги схемы только добавляют), — он лишь не
  показывается.

## 11. Решения проектировщика (не владельца) — проверить при чтении

1. Пресеты — в учётке (таблица), только «Фото»; не история.
2. Серия — до 4, по seed или по силе, по одной через шлюз в одном слоте пользователя, и в поле
   промпта, и в «Изменить»; ошибка одной не останавливает остальные, «Отменить» снимает весь
   остаток (идущую — с освобождением карты).
3. Сравнение — из просмотра (с исходником) и из выделения двух.
4. Ветви — «Варианты» (соседи по исходнику и потомки), без дерева целиком.
5. FLUX без силы (новые записи и показ); внешний сервис — seed не показывается (в базе остаётся).
