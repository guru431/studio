Дата: 2026-10-21. Статус: решения владельца — из обсуждения 2026-10-21 (раздел 5, решение 11 —
поправка того же дня); решения
проектировщика помечены **«(решение проектировщика)»**. Проект: `studio` (репозиторий приватный).
Основа — [2026-10-19-studio-pwa-design.md](2026-10-19-studio-pwa-design.md) (приватность журналов,
«пользователь видит только своё», CSRF) и устройство чата в `app/chat.py`: всё, что здесь не сказано
иначе, остаётся как там. Вторая часть того же обсуждения — распознавание текста (OCR) — отдельная
спека.

## 1. Зачем

Модели студии ничего не знают о том, что случилось после их обучения, и не знают сегодняшней даты.
Чтобы спросить о свежем, прочитать статью или обсудить ролик YouTube, сейчас текст ищут и копируют в
чат руками. Нужен выход в интернет из самого чата — но так, чтобы без явного включения ничего не
уходило наружу и всё оставалось бесплатным.

## 2. Критерий успеха

1. В диалоге включаю «Интернет», спрашиваю «что нового вышло у X на этой неделе» — модель сама ищет в
   Exa и отвечает по найденному; под ответом — что искала и источники ссылками.
2. При включённом «Интернет» на вопрос, где поиск не нужен («переведи эту фразу»), модель отвечает без
   поиска — в Exa ничего не ушло.
3. Вставляю ссылку на статью и пишу «перескажи» — модель читает страницу и пересказывает.
4. Вставляю ссылку на ролик YouTube и пишу «о чём ролик» — модель читает субтитры (yt-dlp на сервере)
   и отвечает; под ответом — название ролика ссылкой.
5. Следующим сообщением спрашиваю о прочитанном — модель помнит найденное, не ищет заново.
6. «Интернет» выключен (по умолчанию) — ни Exa, ни YouTube не получают ни одного запроса, что бы ни
   было в сообщении.
7. Модель на вопрос «какое сегодня число» отвечает верно — в любом диалоге, с «Интернет» и без.
8. Пользователь без ключа Exa: «Интернет» не включается — кнопка выключена, и студия говорит, где
   ввести ключ (решение 11; прежде ролики YouTube читались и без ключа).

## 3. Не цели

- «Интернет» у прямых подключений (ход читает браузер, `via = browser`) — кнопки там нет
  (решение проектировщика: цикл инструментов пришлось бы вести в браузере).
- Платные функции Exa: `/answer`, deep search, research, agent, monitors.
- Расшифровка звука ролика без субтитров (WhisperX умеет, но это карта и минуты) — «у ролика нет
  субтитров».
- Плейлисты, каналы, поиск по YouTube; другие видеосайты.
- Свой метапоиск (SearXNG и подобное), свой загрузчик страниц.
- Общий ключ Exa на всю студию, учёт расходов Exa в студии, включение «Интернет» администратором.
- Индексация найденного поиском по истории (`search.py`) — ищется только текст сообщений, как сейчас
  (решение проектировщика).

## 4. Анти-цели — провал, даже если всё «работает»

- При выключенном «Интернет» хоть один запрос ушёл в Exa или YouTube; в запросе к модели есть `tools`.
- В Exa ушла переписка, а не поисковый запрос или адрес страницы, составленные моделью.
- Поисковый запрос, адрес, название страницы или ролика, текст найденного или ключ Exa попали в
  журнал службы.
- Ключ Exa ушёл в браузер (в `GET /api/me`, в выгрузку истории, в ответ любого API).
- yt-dlp получил адрес не YouTube (у yt-dlp есть общий извлекатель — сервер сходил бы на любой сайт,
  в том числе во внутреннюю сеть).
- В диалоге с расшифровкой поиск или чтение страницы ушли в Exa без подтверждения пользователя
  (раздел 6.10).
- Пользователь тратит чужой ключ Exa или видит чужие найденные материалы.
- Откат `install.sh` на прежний код ломается на новой базе.

## 5. Решения владельца

1. Поиск — Exa. Кнопка «Интернет» в каждом чате, **по умолчанию выключена**.
2. Ищет модель **по необходимости** или когда пользователь прямо просит — не перед каждым ответом и
   только при включённой кнопке.
3. **Ключ Exa — в настройках каждого пользователя**, у каждого свой.
4. Модель может **прочитать страницу целиком**: вставленную ссылкой или одну из найденных.
5. Модель может **прочитать ролик YouTube по субтитрам**; субтитры берёт **yt-dlp на сервере**.
6. **Всё бесплатно.** Exa — на бесплатном тарифе каждого пользователя: $10 в месяц, сброс 1-го числа,
   без карты (exa.ai/docs/admin/pricing, проверено 2026-10-21). Без карты перерасход невозможен:
   кончился баланс — Exa отказывает до 1-го. Ориентиры цены: поиск `auto` — $0,007 (около 1400 в
   месяц), страница `/contents` — $0,001. yt-dlp бесплатен.
7. **Текущая дата — в каждом запросе к модели**, во всех диалогах.
8. Картинка из чата — не делать (`IDEAS-archive.md`); поиск по истории — сделан отдельно.
9. **Exa с debian — маршрутом в сети**, а не прокси в студии: выход debian (Финляндия) Exa блокирует
   (раздел 7); маршрут — отдельная задача проекта `network` (его `FINDINGS.md`, 2026-10-21).
10. **Диалог с расшифровкой и «Интернет» — подтверждение, как для внешней модели** (раздел 6.10).
11. **Без ключа Exa «Интернет» не включается** (2026-10-21) — и ролики YouTube тоже только с ключом.
    `PATCH {web: true}` без ключа — 409 `no_exa_key` («сначала задайте ключ Exa в Настройках → Прочее →
    Интернет»), выключить можно всегда; «Убрать» ключ выключает «Интернет» во всех диалогах учётки,
    сохранение ключа ничего не включает (решения проектировщика).

## 6. Как устроено

### 6.1 Данные

**Схема — следующий свободный шаг `db.STEPS`** (сейчас `VERSION = 13`; только добавляет; новая база —
сразу в `SCHEMA`):

    ALTER TABLE chats ADD COLUMN web INTEGER NOT NULL DEFAULT 0;
    ALTER TABLE users ADD COLUMN exa_key BLOB;
    ALTER TABLE messages ADD COLUMN tools TEXT;
    ALTER TABLE chats ADD COLUMN web_consent REAL;

- `chats.web` — кнопка «Интернет» этого диалога (0/1).
- `chats.web_consent` — время подтверждения «расшифровка и Exa» (раздел 6.10); NULL — не было.
- `users.exa_key` — ключ Exa шифром `security.encrypt` (как токены подключений); NULL — ключа нет.
- `messages.tools` — у ответа ассистента: NULL или JSON-список шагов по порядку, например
  `{"kind": "search", "query": …, "results": [{"title", "url", "published"}], "text": …}`,
  `{"kind": "page", "url", "title", "text"}`, `{"kind": "youtube", "id", "title", "channel",
  "duration", "lang", "text"}`; у неудачного шага — `"error": "<слова>"`. `text` — ровно то, что
  получила модель (с пределом, раздел 6.4). Точная форма — на усмотрение исполнителя.
- Удаление диалога, «Удалить всю историю», удаление учётки уносят всё каскадом, как сейчас.

### 6.2 Ключ Exa

- `PUT /api/me/exa-key` `{key}` — сохранить (шифром), `DELETE /api/me/exa-key` — убрать и тем же
  запросом выключить `chats.web` во всех диалогах учётки (решение 11).
  `GET /api/me` отдаёт только `"exa_key": true|false`. Ключ не возвращается никогда.
- При сохранении ключ не проверяется запросом к Exa (решение проектировщика: проверка тратила бы
  баланс); неверный ключ скажет первый поиск (раздел 6.7).
- Смена `STUDIO_DATA_KEY` делает ключ нерасшифровываемым — как токены подключений: «ключ Exa не
  читается — введите заново». `manage.py verify-backup` проверяет расшифровку и этих ключей.
- Выгрузка истории (`takeout`) ключа не несёт; «Удалить всю историю» его не трогает (это настройка,
  а не история — как пресеты).

### 6.3 Ход с «Интернет»

Только путь через сервер (`StreamTask`, `conn.proxied`). У прямого подключения `chats.web`
игнорируется, ход идёт как сейчас.

- `web = 0` — запрос к модели как сейчас, **без `tools`**.
- `web = 1` и у пользователя есть ключ Exa — запрос несёт `tools` (OpenAI function calling,
  `tool_choice: auto`): `web_search`, `read_page`, `youtube_subtitles`. Ключа нет (`web` остался 1 у
  ключа, убранного мимо `DELETE`) — запрос как при `web = 0`, без `tools` (решение 11). Описания
  инструментов говорят модели искать, только когда нужны свежие или внешние данные или пользователь
  просит; системное сообщение запроса с `tools` несёт ещё строку о доступе в интернет (без неё gemma-abl
  отвечает по памяти — раздел 8, проверка 2026-10-21).
- Цикл: модель потоком отвечает текстом или вызовами инструментов (`delta.tool_calls`,
  `finish_reason: tool_calls`); студия исполняет вызовы, добавляет в запрос ответ ассистента с
  `tool_calls` и сообщения `role: tool` с результатом и зовёт модель снова. Не больше `TOOL_ROUNDS`
  кругов на ответ (решение проектировщика: 5); после предела — последний запрос без `tools`, чтобы
  модель ответила по уже найденному.
- Весь цикл — внутри прежних пределов ответа: `STREAM_TOTAL_SEC`, `ANSWER_MAX`, `USER_STREAMS`.
  «Стоп» и остановка службы отменяют идущий запрос к Exa и убивают процесс yt-dlp; `recover()` после
  перезапуска помечает ответ, как сейчас. Шаги, выполненные до остановки, сохраняются в
  `messages.tools`.
- Поток SSE получает новое событие (например `tool` — `{kind, label}`: запрос, адрес или «субтитры»),
  чтобы страница показала «Ищу: …» / «Читаю: …»; текст ответа — прежними `delta`.
- Модель или сервер, не принимающие `tools` (ошибка 400 на первый запрос с `tools`, и её тело говорит о
  `tool`), — ответ-ошибка словами «эта модель не умеет пользоваться интернетом — выключите „Интернет“ в
  этом диалоге» (решение проектировщика); иной 400 (контекст, картинка) — словами шлюза (ревью M3).
- Повтор ответа (`regenerate`) ищет заново; прежние шаги уходят вместе с прежним ответом.
- Подтверждение расшифровки для внешней модели (`_needs_consent`) не меняется.

### 6.4 Инструменты

Ходят наружу **сервер студии к постоянным адресам**, не из списка разрешённых подключений: это
исключение из правила «сервер не ходит по адресам вне списка» — адреса зашиты в код, пользователь
и модель их не выбирают (адрес страницы идёт в Exa как данные, сервер по нему не ходит). Адрес
страницы модель берёт только из переписки (сообщения пользователя, вложенные документы диалога) или из
найденного поиском (`results[].url` этого ответа и прежних), как в решении владельца 5.4 («вставленную
ссылкой или одну из найденных»): незнакомый адрес Exa обходит сам, и адрес, составленный моделью по
подсказке текста страницы, унёс бы переписку на чужой сайт. Сравнение — без пробелов по краям, фрагмента
и одного «/» в конце; другой адрес — шаг-ошибка «читаю только ссылки из переписки или найденные
поиском», в Exa ничего не уходит (ревью 2026-10-21, I1). С 2026-10-22 регистр схемы и хоста и %-коды
при сравнении не важны, а в Exa уходит адрес, как он записан в переписке или выдаче, без фрагмента: вариант
модели (фрагмент, регистр, кодировка) — не канал наружу (FINDINGS N1).

**`web_search(query)`** → `POST https://api.exa.ai/search` с ключом пользователя (`x-api-key`): только
`query`, составленный моделью; `type: auto`, до 10 результатов (базовая цена), выдержки
(`highlights`), а не полный текст страниц. Модели — заголовок, адрес, дата и выдержки каждого
результата.

**`read_page(url)`** → `POST https://api.exa.ai/contents` с `urls: [url]` и текстом страницы с
пределом `maxCharacters`. Только `http(s)` адреса. Ошибка конкретного адреса — из `statuses` ответа
(`CRAWL_NOT_FOUND` и т. п.) — словами модели и пользователю.

**`youtube_subtitles(url)`** → yt-dlp на debian.
- Адрес разбирается в студии: хосты `youtube.com`, `www.`, `m.`, `music.youtube.com`, `youtu.be`;
  формы `watch?v=`, `youtu.be/<id>`, `shorts/<id>`, `live/<id>`, `embed/<id>`; id — ровно 11 знаков
  `[A-Za-z0-9_-]`. yt-dlp получает **только собранный из id адрес**
  `https://www.youtube.com/watch?v=<id>`; что не разобралось — отказ без вызова yt-dlp.
- Вызов — список аргументов без оболочки: `--ignore-config --no-playlist --no-cache-dir
  --skip-download`, вывод — в свой каталог внутри `config.tmp_dir`, удаляется после чтения.
- **Одна дорожка субтитров** — на языке оригинала (своя или автоматическая); автопереводы не брать:
  проба 2026-10-21 на debian — русские автосубтитры полуторачасового ролика за ~1 с, а третий
  подряд запрос дорожки (английский автоперевод) получил от YouTube `429 Too Many Requests`.
- VTT → текст: без разметки и повторов «бегущих» строк автосубтитров, с отметками времени `[м:сс]`
  по абзацам, чтобы модель могла сослаться на место (решение проектировщика).
- Модели — название, канал, длительность, язык и текст.

**Пределы** (числа — исполнителю, с обоснованием): текст одной страницы и одних субтитров (ориентир:
субтитры 1,5 ч — ~94 тыс. знаков, контекст gemma-abl — 131 072 токена, `CONTEXT`), срок запроса к Exa
и к yt-dlp, обрезанное — с пометкой для модели.

### 6.5 Найденное в следующих ходах

Найденное сохраняется в `messages.tools` ответа и уходит модели в следующих ходах — модель помнит
прочитанное. В текущем ходе — родные сообщения `tool_calls`/`role: tool`. Для прежних ходов `compose`
собирает найденное без ролей `tool` (решение проектировщика: шаблоны Gemma требуют чередования ролей,
см. `_merge`), например блоками `<web …>…</web>` перед текстом ответа ассистента или в сообщении
пользователя, как документы. Оценка токенов (`estimate_tokens`) учитывает и эти блоки: не помещается —
прежний 413 «не помещается в контекст».

### 6.6 Дата

Каждый запрос к модели — через сервер и прямой (сообщения браузеру собирает сервер) — начинается
строкой с сегодняшней датой и днём недели, например «Сегодня среда, 21 октября 2026 года (Москва)».
Время — `clock.NOW()`, пояс — фиксированный UTC+3 (решение проектировщика: в Москве нет перехода на
летнее время, а `zoneinfo` на Windows требует пакета `tzdata`). Форма — системное сообщение; если
шаблон модели его не принимает — первой строкой последнего сообщения пользователя (проверить на
gemma-abl, раздел 8). В базу дата не пишется.

### 6.7 Ошибки словами

Неверный ключ Exa (401) — «ключ Exa не подходит — проверьте в Настройках»; кончился бесплатный баланс
или превышен предел Exa (402/429, коды проверить по документации Exa) — «Exa: лимит исчерпан, баланс
обновится 1-го числа» / «Exa: слишком часто, попробуйте позже»; YouTube 429 — «YouTube временно
ограничил запросы, попробуйте позже»; нет субтитров, ролик закрыт или с ограничением по возрасту —
так и сказать; на сервере нет yt-dlp — «чтение YouTube на сервере недоступно»; Exa ответил не JSON
(403 HTML Cloudflare — блок выхода сервера, раздел 7) — «Exa недоступен с сервера студии». Ошибка инструмента —
не ошибка ответа: модель получает слова ошибки результатом инструмента и отвечает с ними — с припиской
`web.NOTHING` («из интернета ничего не получено — не выдумывай данные…»): без неё gemma-abl после
«Exa недоступен» писала курс доллара «из интернета» в 12 прогонах из 12 (2026-10-22).

### 6.8 Страница

- В диалоге — переключатель «Интернет» (рядом с полем ввода), состояние — `PATCH /api/chats/<id>`
  `{web}`, хранится у диалога. У прямого подключения — скрыт. Без ключа Exa — виден, но выключен и
  не нажат, с подсказкой «Задайте ключ Exa в Настройках → Прочее → Интернет» (title и строка под
  полем), и у нового диалога тоже; ключ задан — кнопка оживает при возвращении в чат (оболочка
  перечитывает профиль). 409 `no_exa_key` (ключ убрали в другой вкладке) — его слова, кнопка выключена
  (решение 11).
- Пока идёт инструмент — строка «Ищу: …», «Читаю: …», «Субтитры: …».
- Под ответом — сворачиваемый список: что искала модель, источники ссылками, ролик ссылкой с
  названием. Ссылки — новая вкладка, `rel="noopener noreferrer"`: сайты не узнают адрес студии.
- Настройки («Прочее» → «Интернет»): поле ключа Exa (скрытый ввод), «Сохранить», «Убрать»; показан
  только признак «ключ задан»; ссылка на dashboard.exa.ai с пояснением про бесплатные $10 в месяц и
  про то, что поисковые запросы и адреса страниц видит Exa.

### 6.9 Приватность и журнал

- Журнал — только события с id: «чат X: ответ Y — шаг search/page/youtube: ok/ошибка (код)». Ни
  запросов, ни адресов, ни названий, ни ключа. Сторожат тесты журналов.
- Наружу уходит: в Exa — поисковые запросы и адреса страниц, составленные моделью; в YouTube — id
  ролика с адреса debian. Больше ничего. Это — в README.
- Выгрузка истории (`takeout`) несёт `tools` сообщений (найденное — часть истории пользователя;
  решение проектировщика), без ключа.

### 6.10 Расшифровка в диалоге и Exa

Модель составляет поисковый запрос и адрес из всей истории диалога — значит, имена и факты из
вложенной расшифровки могут уйти в Exa. Поэтому, как для внешней модели (`_needs_consent`, 409
`external`):
- Ход и повтор, в которых модели будут даны `web_search`/`read_page` (`web = 1`, путь через сервер,
  ключ Exa есть), а в истории, что уйдёт модели, есть вложение с `source_transcript_id`, — 409 с
  новым кодом (например `external_web`) и словами «Запросы, составленные из расшифровки, могут уйти в
  Exa — подтвердите», пока пользователь не подтвердит (`TurnIn` — новое поле вроде `web_ok`).
- След подтверждения — новый: подтверждение покрывает расшифровки, уже бывшие в диалоге, когда его
  дали; расшифровка, вложенная позже, спрашивает снова (решение проектировщика). Например
  `chats.web_consent REAL` — время подтверждения в том же шаге схемы; нужно подтверждение, если есть
  сообщение с расшифровкой новее него. Прежний след (`messages.model`/`via`) для этого не годится.
- Без ключа Exa инструментов нет вовсе (решение 11) — и подтверждения не нужно.
- Окно на странице — как у подтверждения внешней модели; оба подтверждения в одном ходе — по очереди
  или одним окном (исполнителю).

## 7. Хост и выкладка

- yt-dlp на debian уже стоит общий: `/usr/local/bin/yt-dlp` (системный `python3`), root обновляет его
  каждую ночь — `/etc/crontab`: `0 1 * * * root /usr/bin/pip3 install -U yt-dlp
  --break-system-packages` (на 2026-10-21 — 2026.8.19, последняя на PyPI). Студия зовёт его, а не
  свою копию в `.venv` (решение проектировщика: копия устаревала бы между выкладками, а YouTube ломает
  старые версии). Крон — не часть этого репозитория.
- `install.sh` проверяет наличие yt-dlp и предупреждает, но выкладку не останавливает.
- Юнит: `ProtectSystem=strict`, `ProtectHome=yes`, `PrivateTmp=yes` — yt-dlp пишет только в
  `config.tmp_dir` (`/var/lib/studio/tmp`, чистится при старте), кэш выключен (`--no-cache-dir`).
  Процесс входит в `MemoryMax=2G` службы.
- YouTube с debian доступен (проверено 2026-10-21: 200 за 0,6 с).
- **api.exa.ai с debian заблокирован** (2026-10-21): Cloudflare Exa отвечает 403 HTML-страницей
  «Sorry, you have been blocked»; выход debian — Финляндия (`loc=FI`), а с рабочей машины (`loc=SE`)
  Exa отвечает. Решение владельца — маршрут в сети (задача `network/FINDINGS.md` 2026-10-21), код
  студии под это не меняется. Пока маршрута нет, ответ HTML вместо JSON (403 Cloudflare) — слова
  «Exa недоступен с сервера студии» (раздел 6.7). Живая проверка поиска на проде — после маршрута.

## 8. Риски — проверить вживую первым шагом плана

1. **Вызов инструментов gemma-abl через шлюз потоком.** vLLM запущен с `--enable-auto-tool-choice
   --tool-call-parser gemma4` (`llm_routers/srvllm/deploy/services/gemma-abl.conf`), но цепочка
   LiteLLM → slot-gate → vLLM с `tools` и `stream: true` вживую не проверялась: приходят ли
   `delta.tool_calls`, принимает ли шаблон `role: tool` и системное сообщение (дата), не выбрасывает
   ли LiteLLM `tools` молча (`drop_params`: ошибки нет, а модель никогда не зовёт инструмент).
   **Допустимые обходы без возврата к владельцу** (решение проектировщика) — те, что не меняют
   видимого пользователю: круги с инструментами без потока (потоком идёт только последний ответ);
   результат инструмента текстом в сообщении пользователя вместо `role: tool` (как найденное прежних
   ходов, раздел 6.5); дата — первой строкой сообщения пользователя. Модель не зовёт инструменты
   вовсе — остановиться и вернуться к владельцу до UI.

   **Проверено 2026-10-21** (`local-gemma-abl` через шлюз, ключ `owner-images`, `stream: true`):
   системное сообщение с датой принято; `tools` доходят; вызов приходит потоком — куски
   `delta.tool_calls` (`index`, `id`, `function.name`, затем `function.arguments`), конец
   `finish_reason: tool_calls`; второй запрос с `assistant.tool_calls` и `role: tool` — ответ текстом по
   результату. **Обходы не нужны.** Но без подсказки модель на «найди в интернете» отвечает по памяти:
   нужна строка в системном сообщении, пока «Интернет» включён, — «У тебя есть доступ к интернету через
   инструменты…; если просят найти в интернете, прочитать ссылку или ролик или нужны свежие данные —
   вызывай инструмент, а не отвечай по памяти» (с ней — вызов в 1 из 1). `tool_choice` с именем функции
   и `required` модель игнорирует — студии они не нужны.
   **2026-10-22, живой диалог:** модель, отвечавшая по памяти, потом уверяла, что «сходила в интернет»; на
   таком диалоге «какой курс доллара» — вызов в 5 из 12, выдумка в остальных. Фраза `WEB_NOTE` «говори, что
   нашёл в интернете, только если инструмент в этом ответе вернул результат…» — вызов в 10 из 12. До нуля
   промпт не доводит (temperature 1.0 из `generation_config` модели).
2. Форма ответа Exa `/search` и `/contents` и коды ошибок (401/402/429) — по документации Exa
   (Context7 или exa.ai/docs), не по памяти.
3. Выбор дорожки «язык оригинала» у yt-dlp (`<lang>-orig` у автосубтитров) — на нескольких роликах
   (русский, английский, без субтитров, закрытый).

## 9. Тесты

Быстрый набор: Exa — `httpx.MockTransport` (`tests/fakes.py`), yt-dlp — подменяемый запуск (как
`clock.SLEEP`). Обязательно:
- `web = 0` — в запросе к модели нет `tools`, Exa и yt-dlp не вызваны (сторож анти-цели 1);
- в Exa уходит только `query`/`url` из вызова модели;
- адрес не YouTube (и YouTube с чужим хостом, лишними частями, id не 11 знаков) до yt-dlp не доходит;
  yt-dlp получает канонический адрес;
- VTT автосубтитров → текст без повторов;
- без ключа — `tools` нет, `PATCH {web: true}` — 409, «Убрать» ключ выключает `web` своих диалогов;
  ключ не виден в `GET /api/me`, выгрузке, журнале;
- журнал без запросов, адресов и названий;
- предел кругов, «Стоп» посреди инструмента, найденное — в `compose` следующего хода;
- дата в запросе при подменённых часах; у прямого подключения — дата есть, `tools` нет;
- диалог с расшифровкой, `web = 1`, ключ есть — 409 без подтверждения, Exa не вызван; после
  подтверждения — идёт; расшифровка, вложенная позже, — снова 409; без ключа — без 409;
- шаг схемы и откат: прежний код читает новую базу.
`test_deploy` — проверка yt-dlp в `install.sh`. Живая приёмка (`-m manual`) — по возможности ход с
поиском на gemma-abl.
