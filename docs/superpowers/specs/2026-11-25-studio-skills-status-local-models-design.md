# Навыки, строка состояния «Чата» и работа с локальными моделями

Дата: 2026-11-25. Статус: список из 43 изменений утверждён владельцем целиком («делаются все и сразу, одним
планом»); порядок пунктов — не приоритет. План — [2026-11-25-studio-skills-status-local-models](../plans/2026-11-25-studio-skills-status-local-models.md).

## Зачем

1. **Локальная модель не тянет большую задачу одним куском.** Контекст раздувается, модель уходит не туда, ход
   кончается отказом. Рабочий приём (его публично показывает автор стороннего продукта Wormsoft Harness; код продукта
   закрыт и не используется — взята только идея процесса): задачу сначала готовят и делят на части, каждую часть
   исполняют отдельно с чистым контекстом, итог принимают отдельным шагом. Весь процесс держится на **навыках** —
   именованных текстах-инструкциях, которые человек вызывает по имени.
2. **«Чат» отстал от «Агентов».** В «Агентах» есть строка состояния с контекстом, кэшем, изменёнными файлами,
   подзадачами, очередь, ветки, черновик на чат, стрелки по сообщениям. У «Чата» — три элемента в шапке, сервер не
   хранит ни токенов, ни длительности ответа.
3. **«Чат» расточителен к окну локальной модели**: результаты инструментов прошлых ответов вставляются целиком на
   каждом ходе, пересказ истории не хранится и может отбрасываться, окно считается по знакам, а не по токенам.

## Цели, не-цели, анти-цели

**Цели** — 43 пункта раздела «Изменения». Один выпуск Studio 0.55.0, один шаг схемы 82, мост 0.48.0.

**Не-цели** (решено в обсуждении, не добавлять):

- отдельный вид «Задачи» проекта и запуск очереди задач мостом — сначала навыки;
- выбор навыка самой моделью (каталог навыков в системном сообщении) — навык вызывает только человек;
- прогрев локальной модели заранее: он выгрузил бы тёплые модели других разделов с общей карты, а умеет ли шлюз
  загрузку без генерации, из этого репозитория не проверить;
- коллекции и теги (из отложенной идеи берётся только закрепление диалога);
- серверные черновики; снятие блока PIN из Студии; логин и IP участника; пять отклонённых пунктов аудита
  2026-11-12; прежние предложения по «Агентам» (конвейер по `FINDINGS.md`/`IDEAS.md`, модели Studio для помощников по
  ключу устройства, подсветка опасных команд, «Объяснить» на карточке).

**Анти-цели** — что делает работу провалом, даже если она «работает»:

- текст навыка, пересказа, цитаты, имени файла или промпта в журнале (журнал — id, коды, числа);
- обход защищённого источника: ветка, «Новый диалог с итогом», часть (`run_part`) и окно HTML не должны давать
  данным защищённого диалога путь в сеть;
- запрос подключения через Cleaner мимо `cleaner_route`;
- окно HTML/SVG, которое ходит в сеть или видит страницу и учётку Studio;
- шаг схемы, после которого прежний код (`previous`) не работает на новой базе;
- новая возможность «Агентов» без объявления в `hello` моста: старый мост не должен получать незнакомые просьбы.

## Ограничения

- **Приватность** — контракт CLAUDE.md. Тексты агентских чатов в базу не пишутся (кроме снимка ссылки шифром).
  Навыки — настройки, как роли: «Удалить всю историю» их не трогает, удаление учётки уносит каскадом, выгрузка
  (`takeout`) их содержит. Администратор чужие навыки не видит.
- **Схема** — только добавление, один шаг 82; строка отката в CLAUDE.md. Новых столбцов `*media_id` нет.
- **Мост** — протокол v1 не меняется: новые просьбы и поля — по capability в `hello`; страница скрывает то, чего
  мост не объявил. Работающий мост не перезапускать из его же задания.
- **Сеть** — сервер ходит только по списку разрешённых адресов; новых внешних адресов нет ни у сервера, ни у моста.
- **Страница** — без сборки; подписи через `tr` и `static/en.js`; значки только из `icons.js`; меню — `menu.js`;
  цвета — `light-dark()`; `:hover` — в `@media (hover: hover)`; имена разделов — `sections-meta.js`.
- **Тесты** — быстрый набор ≤ 60 с, без реального времени (`clock.NOW`, `clock.SLEEP`), шлюз — `tests/fakes.py`,
  мост — `tests/fake_bridge.py`; дольше 1 с и браузер — `integration` (320 и 1280 px).
- **Контракт шлюзов** (`llm_routers`) не меняется: всё, что требует нового поля или маршрута шлюза, делается
  только если шлюз это уже умеет (см. пункты 31 и 36).
- **Публикация** — в отслеживаемых файлах только примеры адресов и имён.

## Подходы

| Вопрос | Рассмотрено | Выбрано и почему |
|---|---|---|
| Где живут навыки | (а) библиотека учётки на сервере; (б) файлы `SKILL.md` в проекте; (в) оба | (в): библиотека работает в «Чате» и со всеми помощниками одинаково, файлы проекта едут с репозиторием. Навык в обоих случаях — текст, который Studio подставляет в сообщение |
| Кто вызывает навык | человек через «/»; модель по каталогу в системном сообщении | человек: каталог стоит локальной модели токенов и даёт ложные срабатывания |
| Разбиение в «Чате» | только текст навыка; режим под управлением сервера; навык + один инструмент | навык + инструмент `run_part`: без инструмента все части идут в одном контексте, а отдельный режим дублировал бы навыки |
| Статистика «Чата» | оценка по знакам; `usage` из ответа модели | `usage`: оценка по знакам занижает кириллицу и JSON; где шлюз `usage` не даёт — поля пустые, а не выдуманные |
| Результаты инструментов в истории | целиком; выжимка только у старых; выжимка сразу | выжимка сразу со следующего хода: начало запроса не меняется задним числом, кэш модели работает |
| Вкладки и очередь «Чата» | на сервере, как в «Агентах»; на устройстве | на устройстве: это состояние окна, а не истории; шаг схемы не нужен |

## Решения автора спеки (владелец может отменить любое)

1. Навык вызывается только человеком; модель сама навыки не выбирает.
2. Текст навыка подставляется в сообщение пользователя и хранится в нём: навык действует весь диалог и не ломает
   кэш. Лента показывает такое сообщение свёрнуто: «Навык: имя» и то, что дописал человек.
3. Инструмент `run_part` модель получает только в диалоге, где вызван навык с отметкой «по частям».
4. Выжимки результатов инструментов — у всех серверных диалогов, не только у локальных моделей.
5. Диалог через Cleaner не ветвится (контексты замен привязаны к диалогу) — отказ словами.
6. Окно HTML/SVG не ходит в сеть вообще.
7. Звук по умолчанию выключен.
8. Вкладки диалогов и очередь «После ответа» хранятся на устройстве.
9. В «Агентах» — до 12 изображений и до 12 вложений всего; пределы размера прежние.
10. Папки навыков проекта — `.agents/skills` и `.claude/skills`.
11. «Поделиться» Open WebUI — снимком шифром, как у «Агентов».
12. Прогрева модели нет (см. не-цели); из п. 36 остаётся показ уже существующего ожидания карты в строке состояния.
13. Вызов инструмента, написанный моделью текстом (`<tool_call>`), разбирается только у локальной модели
    (`sections.is_local`) и никогда — у подключения через Cleaner: там замены получают только структурные вызовы.
14. Текст последнего вызванного в диалоге навыка в пересказ не входит и остаётся в запросе дословно; более ранние
    навыки пересказываются. `run_part` предлагается, пока у последнего вызванного навыка есть отметка «по частям».
15. Ответ по частям живёт до 2 часов (обычный — 30 минут, как сейчас); срок одной части — срок обычного ответа;
    ожидание карты в сроки не входит, как сейчас. За один круг исполняется одна часть.
16. «Положить набор в проект» пишет в одну папку по выбору владельца (по умолчанию `.agents/skills`); имя навыка в
    файле — латинский ключ, в заголовке файла — `disable-model-invocation: true`, чтобы помощник не запускал такой
    навык сам. Родные навыки помощника, которые владелец завёл без Studio, Studio не ограничивает.
17. В защищённом диалоге кнопки «Открыть» у блоков HTML и SVG нет: песочница закрывает не все сетевые пути скрипта.
18. В ссылку «Поделиться» и экспорт текст навыка не входит — только «Навык: имя» и то, что дописал человек; в
    выгрузку своих данных (`takeout`) сообщение входит целиком.
19. У прямого подключения `usage` и время ответа сообщает страница при сохранении ответа; сервер принимает их как
    числа в разумных пределах. Иначе статистика молча теряла бы такие диалоги.
20. Пределы навыка равны прежним пределам быстрого действия (имя 80, текст 100 000 знаков): перенос без потерь.

## Данные: шаг схемы 82

Точные типы и имена ограничений выбирает исполнитель по образцу соседних шагов `db.py`; состав — такой:

- `skill_defaults` — типовой набор администратора: ключ встроенного, язык (`ru`/`en`), имя, описание, текст, где
  доступен (`chat`/`agents`/`both`), «кнопкой в пустом чате», «по частям», порядок. Образец — `role_defaults`.
- `skills` — библиотека учётки: те же поля, `user_id` с каскадом, `origin` (из какого умолчания), время правки.
  Образец — `chat_roles`. `users.skills_seeded` — отметка посева.
- `messages.skill` — JSON `{name, chars, parts}`: имя навыка, длина его текста в начале сообщения, отметка «по частям».
- `messages.usage` — JSON `{in, out, cached, reasoning}` (чего шлюз не сообщил — нет ключа); `messages.gen_ms` —
  время генерации (от первого фрагмента до конца, по всем кругам); `messages.total_ms` — весь ход.
- `chats.summary`, `chats.summary_upto` (id последнего сообщения, вошедшего в пересказ), `chats.summary_at`.
- `chats.pinned`, `chats.seen` (когда диалог последний раз открыт), `chats.effort` (уровень рассуждения).
- `connection_profiles.model_params` — JSON «модель → параметры».
- `model_facts` — на пару (подключение, модель): число знаков на токен по наблюдениям, окно контекста, время.
- Ссылки «Поделиться» новых видов — чат «Озвучки» и переписка Open WebUI — строками `chat_shares` со своим
  `item_kind` у обоих; чат «Озвучки» — это группа записей по `speeches.chat_id`, ссылку уносит удаление последней
  записи группы (триггер).

**Откат на прежний код.** Навыков нет, быстрые действия «Агентов» — прежние (`users.code_quick_actions` новый код
не стирает); сообщение с навыком видно целиком; токены, пересказ, закрепление, «не прочитано», уровень рассуждения и
параметры на модель не читаются (пересказ считается заново, параметры — с подключения). Ссылки новых видов прежний
код считает недоступными (его `chat_shares.LIVE` не знает их `item_kind`) — обход не нужен; именно поэтому у
ссылки Open WebUI свой `item_kind`, а не вид «как у Агентов».

## Изменения

Номера — те же, что в утверждённом списке. «Приёмка» — что должно наблюдаться; тесты — в плане.

### А. Навыки и разбиение задачи на части

**1. Библиотека навыков учётки.** Модуль `skills` по образцу `roles`: умолчания ведёт администратор в панели,
библиотека учётки засевается умолчаниями языка страницы при первом чтении, «Добавить умолчания» возвращает
недостающие. API `/api/skills` (свои; чужой id — 404) и `/api/admin/skills` (умолчания). Страница — «Настройки →
Навыки»: список, правка, порядок, «где доступен», «кнопкой в пустом чате», «по частям».
*Приёмка:* навык, созданный в настройках, виден в «/» «Чата» и «Агентов» по своему `scope`; администратор не
видит навыки учёток.

**2. Меню «/».** Общий модуль страницы. Открывается, когда поле ввода начинается с «/»; фильтр по набранному;
стрелки, Enter, Esc; строка — имя, тип («навык», «проект», «команда»), описание. Выбор навыка ставит над полем чип
«Навык: имя» (снимается крестиком), текст поля остаётся уточнением. При отправке уходит `текст навыка + пустая
строка + уточнение`. В «Агентах» меню показывает ещё навыки проекта (п. 3) и команды помощника; список «Команды
OpenCode» переезжает в него.
*Приёмка:* навык вызывается в середине диалога, а не только в пустом чате; 320 px — меню не выходит за экран.

**3. Навыки из папки проекта («Агенты»).** Мост объявляет `hello.skills` и принимает две просьбы: список навыков
проекта (имя и описание из начала `SKILL.md`, без текста) и текст одного навыка. Читаются только `.agents/skills`
и `.claude/skills` проекта; путь, который после разрешения ссылок выходит за проект, отвергается — как при чтении
файлов (`files.resolve`). Участник совместного проекта видит навыки проекта. «Положить набор в проект» (только
владелец): страница записывает типовые навыки `scope` ≠ `chat` файлами `<папка>/<ключ>/SKILL.md` через
существующую запись файлов — по решению 16; существующий файл не перезаписывается. Навык проекта с тем же ключом,
что у навыка библиотеки, в «/» показывается один раз — проектный.
*Приёмка:* навык из папки проекта виден в «/» с пометкой «проект» и вызывается; мост без `hello.skills` — раздел
работает как раньше, пометки «проект» нет.

**4. Типовые навыки по методу подготовки и разбиения.** Тексты пишет исполнитель на русском и английском; состав
обязателен:

- «Подготовить ТЗ» — изучить проект; написать файл(ы) задач в `tasks/todo/`; спросить только то, что нельзя решить
  самому, каждым вопросом с вариантами и рекомендацией; проверить «руками» доступы, нужные для проверки результата;
  задачи остаются в разделе `NeedInfo` файла `tasks/index.md`, пока человек не скажет «финализируй», затем — `Todo`.
- «Разбить на задачи» — разделить ТЗ на задачи, у каждой: цель, «владение» (каталоги и файлы, без пересечений с
  другими задачами), зависимости, критерии приёмки, команда проверки, ограничения; порядок и то, что можно делать
  параллельно; последняя задача — приёмка.
- «Выполнить очередь» — головной чат не пишет код: по одной задаче из `Todo` отдаёт подзадаче помощника с чистым
  контекстом; после каждой — проверка, один коммит с точечным `git add`, перенос файла в `tasks/done/`, строка в
  `Done`; неясно — задача в `NeedInfo` с вопросами, код откатить; не вышло — в `Errors` с причиной. Если у
  помощника подзадач нет (DeepSeek Harness) — выполнять по одной задаче и после каждой просить человека начать
  новый чат.
- «Приёмка» — сверить сделанное с критериями всех задач, прогнать проверки, отчёт «прошло / не прошло / неприменимо».

Формат очереди: `tasks/index.md` с разделами `Todo`, `NeedInfo`, `Errors`, `Done`; строка — ссылка на файл задачи и
одна фраза.

**5. Быстрые действия становятся навыками.** Три встроенных (`code_actions.DEFAULTS`) — в типовой набор с
отметкой «кнопкой в пустом чате», `scope` `agents`. Свои быстрые действия учётки переносятся в её библиотеку при
посеве (один раз). Кнопки пустого чата «Агентов» берутся из навыков с отметкой; страница «Быстрые действия»
настроек заменяется «Навыками».
*Приёмка:* у учётки со своими быстрыми действиями после обновления те же кнопки в пустом чате.

**6. Типовые навыки «Чата».** «Разобрать по частям» (отметка «по частям»): составить план до 7 частей через
`todo_write`, спросить подтверждение через `ask_user`, каждую часть выполнить вызовом `run_part`, собрать общий
ответ. «Протокол встречи»: из расшифровки в диалоге — решения, поручения с ответственными и сроками, открытые
вопросы.

**7. Инструмент «Чата» `run_part`.** Встроенный инструмент серверного хода, предлагается модели только в диалоге
с навыком «по частям» (`messages.skill.parts`). Аргументы: название части и задание. Сервер делает **отдельный
запрос** той же модели тем же путём, что и ход (в том числе через Cleaner): системное сообщение диалога, задание
части, краткие итоги прежних частей этого ответа; история диалога в запрос не входит. Внутри части доступны
инструменты диалога, кроме `run_part`, `todo_write`, `ask_user` и требующих подтверждения. Модель получает итог
части (≤ 4000 знаков). Шаг виден под ответом: название, «идёт / готово / ошибка», длительность, раскрываемый текст
итога. «Остановить» прерывает и часть. Защищённый источник, сработавший внутри части, помечает диалог как обычно.
Пределы — по решению 15: `run_part` в общий счёт кругов и вызовов хода не входит, у него свой счёт (10 на ответ,
один за круг; второй `run_part` того же круга — отказ инструменту словами). Известная граница: в диалоге, где
инструменты ведёт не сервер (прямое подключение, Cleaner с предпросмотром), `run_part` нет — навык «по частям»
сработает как обычный текст, и части пойдут в одном контексте.
*Приёмка:* запрос части не содержит прежних сообщений диалога; одиннадцатая часть ответа — отказ инструменту
словами, ход продолжается; ответ с частями не обрывается на 1800-й секунде.

### Б. «Агенты»

**8. Время работы и скорость** в окне «Сессия и контекст»: время последнего хода и всех ходов сессии, принятых
через Studio (мост меряет сам), и скорость «выходные токены ÷ время хода» там, где помощник сообщает токены. Нет
данных — «нет данных», не ноль.

**9. Поиск по тексту открытого чата.** Строка поиска над лентой (Ctrl+F в разделе, лупа в строке состояния):
совпадения в загруженной ленте, «предыдущее / следующее», счётчик; «Искать в более ранней части» догружает
историю страницами до совпадения или начала. Тексты на сервер не уходят.

**10. Из «Чата»:** «Копировать» ответ целиком и модель под ответом — когда помощник её сообщает. «Прочитать» в
«Агентах» **не делается**: озвучка создаёт запись «Озвучки», то есть текст ответа помощника попал бы в базу, а
тексты агентских чатов в базе не хранятся. Добавить можно только отдельным решением владельца об оговорке к этому
инварианту.

**11. «Проверить другим помощником».** Пункт меню «Ветки и рабочие копии»: выбор помощника → новая вкладка этого
помощника в том же проекте, в поле — навык «Приёмка» и список изменённых файлов последнего ответа. Отправляет
человек.

### В. «Чат»: строка состояния

**12. Строка состояния над полем** — общий с «Агентами» каркас (`code-status-bar.js` переносится в общий модуль):
слева стадия хода («жду карту · N», «загружаю модель», «жду ответа», «пишет», «инструмент X») с временем стадии
и «последнее событие N с назад» после 10 с тишины; справа кнопки пунктов 13–16, лишние уходят в «⋯».

**13. Окно «Диалог и контекст».** Кольцо контекста становится кнопкой. В окне: модель, подключение, роль, число
сообщений; занято и предел; токены последнего ответа и диалога (ввод, вывод, из кэша); время и скорость
последнего ответа; кнопки «Сжать сейчас» (п. 30) и «Новый диалог с итогом» (п. 27). Сервер просит у шлюза `usage`
в потоке и хранит его у ответа вместе с длительностью. Шлюз отказал из-за незнакомого параметра — запрос
повторяется без него, подключение запоминается до перезапуска службы. Под ответом рядом с моделью — скорость.
У прямого подключения числа присылает страница (решение 19).
*Приёмка:* шлюз без `usage` — ход работает, в окне «нет данных».

**14. «Статистика» учётки.** Ответы, токены ввода и вывода, время генерации — по дням (пояс учётки) и моделям за
31 день, по сохранённой истории своих диалогов. Кнопка в строке состояния и в «Настройках».

**15. «Файлы диалога (N)».** Вложения, медиа диалога и файлы результатов MCP одним списком: имя, вид, размер,
«Открыть» или «Скачать» существующими маршрутами. Правила защищённого источника для файлов MCP — прежние.

**16. Счётчик вызовов инструментов** идущего хода; по нажатию — шаги текущего ответа.

**17. Название диалога в шапке** вместо слова «Чат»; рядом — «Действия с диалогом» (переименовать, удалить,
скопировать адрес — п. 41) теми же окнами, что в меню списка.

### Г. «Чат»: перенос из «Агентов»

**18. «Продолжить иначе».** У своего сообщения: новый диалог с историей до него (выбранные варианты ответов,
вложения — ссылками на те же файлы), текст сообщения — в поле. Наследует подключение, модель, роль, MCP, знания
и отметку защищённого источника. Диалог через Cleaner — отказ словами.

**19. Стрелки по своим сообщениям и «развернуть все»** — код из `code-chat.js` выносится в общий модуль.

**20. Push и напоминание, когда ход ждёт ответа** (подтверждение инструмента, вопрос, предложение памяти): вид
`ask`, без содержимого; тихие часы и интервал напоминания — из «О чём уведомлять» устройства, как у «Агентов».

**21. Черновик на каждый диалог** — как `code-drafts.js`: текст в хранилище сессии по id диалога, отметка
черновика в списке; вложения — только в памяти страницы.

**22. Отправка во время ответа.** «После ответа»: сообщение встаёт в очередь (до 5) и уходит само по окончании
хода; ждущую карточку очередь не обходит. Очередь — в памяти страницы, вид — `queueView`; закрытие страницы
возвращает неотправленное в черновик.

**23. Список диалогов.** Метки «идёт ответ» и «не прочитано» (ответ кончился, пока диалог не был открыт),
звёздочка «Закрепить» (закреплённые сверху), поиск по названиям.

**24. Вставка файлов из буфера и перетаскиванием** в поле «Чата» — тем же путём, что скрепка.

**25. HTML и SVG из ответа.** У блока кода `html` или `svg` — «Открыть»: окно с `iframe sandbox` без
`allow-same-origin`, с политикой содержимого, запрещающей любую сеть (скрипты и стили — только встроенные,
картинки — `data:`). Политику задаёт заголовок ответа сервера, который отдаёт содержимое окна своей учётке по
короткоживущему адресу (не `srcdoc`: унаследованная политика страницы сломала бы скрипты блока); текст блока в
журнал не пишется. Блок больше 2 МиБ — без кнопки. В защищённом диалоге кнопки нет (решение 17).

**26. Вкладки диалогов.** Ряд вкладок над лентой (до 12): открыть диалог во вкладке, закрыть, метки «идёт
ответ» и черновика. Состав — на устройстве, при выходе из учётки стирается.

**27. «Новый диалог с итогом»** (возврат идеи, отклонённой 2026-11-21). Кнопка в окне п. 13 и в отказе по длине:
модель пишет итог диалога (механизм пересказа п. 30), открывается новый диалог с теми же подключением, моделью,
ролью, MCP и знаниями, итог — в поле ввода, человек дописывает вопрос и отправляет. Новый диалог наследует отметку
защищённого источника.

**28. Источники «Знаний» под ответом** (вторая половина идеи от 2026-11-16): шаг «Знания» под ответом перечисляет
документ и номер куска; по нажатию — текст куска. И для автоматического блока знаний, и для `knowledge_search`.

### Д. Локальные модели

**29. Выжимки результатов инструментов.** В запросах следующих ходов результат инструмента прошлого ответа —
первые 1500 знаков и пометка, что остальное можно получить повторным вызовом. В ходе, где инструмент вызван,
модель видит результат целиком, как сейчас.

**30. Хранимый пересказ и «Сжать сейчас».** Пересказ ранней части хранится у диалога и переиспользуется; новое
сжатие строится из прежнего пересказа и сообщений после него. Правка или удаление сообщения внутри пересказанной
части пересказ сбрасывает. Просьба и предел согласованы (500 слов, 2048 токенов); оборванный по длине пересказ
принимается. В ленте — отметка «ранняя часть свёрнута в пересказ» с «Показать». В ссылку и экспорт пересказ не
входит. Текст последнего вызванного навыка сжатие не трогает (решение 14). Закрывает находку `FINDINGS.md`
2026-11-25 о пересказе.

**31. Точный счёт окна.** (а) Число знаков на токен — по `usage` прошлых ответов пары «подключение, модель»
(`model_facts`); без наблюдений — прежняя оценка. (б) Предел окна: ручное значение в параметрах модели (п. 35),
иначе сообщённое шлюзом в списке моделей, если шлюз его сообщает, иначе прежняя таблица. (в) В оценку входят
описания инструментов запроса. (г) Отказ шлюза по длине контекста — один повтор со сжатием, потом отказ словами.

**32. Меньше и понятнее инструменты.** Имя инструмента MCP для модели — из имени сервера и инструмента, одно и то
же от хода к ходу (сейчас в имени порядковый номер). Локальной модели по умолчанию — до 32 инструментов MCP и
описание до 1000 знаков; `max_tools` профиля по-прежнему сильнее.

**33. Терпимость к слабому вызову инструментов.** Вызов, пришедший структурой, исполняется при любом признаке
конца ответа — у всех серверных ходов. Вызов, написанный текстом в `<tool_call>{…}</tool_call>` при предложенных
инструментах, разбирается только у локальной модели и не у подключения через Cleaner (решение 13). Неразобранные
аргументы — отказ инструмента словами модели, а не ошибка хода.

**34. Неизменное начало запроса.** Запрос следующего хода повторяет запрос прошлого до конца предпоследнего
сообщения: системное сообщение в пределах суток то же, имена и порядок инструментов те же, выдержки большого
документа в старом сообщении не зависят от нового вопроса (найденное по новому вопросу добавляется к новому
сообщению), пересказ и выжимки не меняются.
*Приёмка:* тест сравнивает два соседних запроса побайтно до этой границы.

**35. Один признак «локальная модель» и параметры на модель.** `sections.is_local` — единственный источник
(роли `local-*` srvllm и шлюз s06); `card._local` и остальные места зовут его. Профиль подключения получает
параметры на модель (температура и прочее из `profiles.Params`, окно контекста), они сильнее параметров
подключения. Закрывает находку `FINDINGS.md` 2026-11-25 о двух понятиях локальности.

**36. Карта.** Ожидание карты с повтором, место в очереди и оценка уже есть на сервере и под ответом; сервер не
меняется. Новое — только показ: эти же сведения переезжают в строку состояния (п. 12). Прогрева нет (не-цели).

### Е. Все разделы

**37. Звук.** Три коротких сигнала (готово, ждёт решения, ошибка), синтезом в браузере, без файлов. Настройка
устройства «Звук», по умолчанию выключена; играет только на видимой странице.

**38. «Цитировать» и меню сообщения.** Выделение в сообщении → «Цитировать»: чип над полем, при отправке —
`> …` в начале (≤ 4000 знаков). Меню сообщения (правая кнопка, долгое нажатие): «Копировать», «Цитировать» и
действия, что уже есть у сообщения. «Чат», «Агенты», Open WebUI.

**39. Картинки из результатов MCP — модели.** Картинка в результате инструмента передаётся модели, принимающей
изображения, в пределах `max_images` и показывается под ответом. Через Cleaner не передаётся.

**40. Уровень рассуждения** у подключений, чей профиль провайдера его принимает: «Рассуждение» получает выбор
`low` / `medium` / `high`, хранится у диалога.

**41. Ширина ленты** (настройка «Оформление»), **поле ввода** растёт до половины экрана со «Свернуть»,
**«Скопировать адрес чата»**.

**42. «Поделиться».** Чат «Озвучки» (тексты и звук всех записей с одним `speeches.chat_id`) — новый вид записи
ссылки. Open WebUI — снимок переписки шифром со своим `item_kind` и экспорт PDF/Markdown; «Копировать» ответ.

**43. Вложения «Агентов».** Изображений — до 12, вложений всего — до 12. Мост объявляет пределы числом в
`hello`; страница и сервер берут их оттуда, у старого моста — прежние 4 и 8. Слова отказов называют действующее
число.
*Приёмка:* 10 скриншотов вставляются одним сообщением у моста 0.48.0; у моста 0.47 — отказ «до 4 изображений» до
отправки.

## Что остаётся исполнителю

Имена функций и маршрутов, точные типы столбцов, разметка и стили, тексты типовых навыков, слова отказов,
разбиение на модули страницы — по образцу соседнего кода. Обязательны числа, состав данных, границы безопасности
и поведение из «Изменений».
