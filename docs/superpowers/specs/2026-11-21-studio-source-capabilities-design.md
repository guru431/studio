# Возможности источников: всё, что умеет Open WebUI на Spark, — универсально в Studio

Дата: 2026-11-21. Статус: решения владельца собраны поштучно (каждое изменение — отдельный вопрос с объяснением),
технический дизайн по каждому пункту — следующий шаг; реализация — после утверждения.

## Зачем

На хосте Spark работает Open WebUI с собственными доработками (инструменты aitools, правила модели, файлы,
речь, чувствительный бизнес-API). Studio работает **параллельно** с ним (не замена — такого решения нет) и должна
уметь всё, что умеет он. Главное правило владельца: **Studio не работает «на Spark»**. Она универсальна; Spark —
образец требований будущих систем, по нему закладываются универсальные масштабируемые функции. Источник (API
моделей или MCP) сам приносит свои требования, и они действуют только там, где этот источник участвует.
Open WebUI и панель на Spark не меняются; доработки Spark — в обёртке aitools (вне репозитория).

## Решения владельца (не пересматривать)

- Администратор не видит чужие файлы — инвариант приватности Studio сохраняется (на Spark админ видит).
- Голоса — личные, как сейчас, плюс общие голоса Spark в «Озвучке».
- Оформление Studio не меняется (тема и баннер Spark не переносятся). Панель Spark не меняется.
- Изменения не группируются: каждое ниже утверждено отдельно.

## Утверждённые изменения

1. **Требования источника.** MCP-сервер отдаёт правила работы со своими инструментами и подсказки стандартными
   средствами MCP — `instructions` (знакомство) и `prompts`; для Spark — обёртка из своего файла, который ведёт
   администратор Spark (из правил Open WebUI — то, что про инструменты). У API-подключения в Studio — профиль:
   дополнительный текст к системному сообщению, параметры генерации (temperature, top_p, top_k, presence_penalty,
   max_tokens), подсказки. Системное сообщение собирается из кусков участников: дата + профиль подключения
   выбранной модели + `instructions` включённых в диалоге MCP. Одного общего текста нет.
2. **Подсказки на пустом экране чата** — из профиля подключения выбранной модели и `prompts` доступных MCP.
3. **Общие MCP включены в чате по умолчанию** (с учётом групп доступа), в диалоге выключаются. MCP — агрегатор
   услуг сервера: по разделам распределяется как сейчас, в чате доступен посреди переписки.
4. **Файлы между чатом и инструментами.** Вложения диалога при включённом MCP загружаются в личную папку на
   сервере MCP (контракт `artifact_upload`), модель получает ссылку на файл; файлы результатов инструментов —
   под ответом для скачивания (картинки и видео — встраиваются).
5. **Подтверждение долгих задач.** Инструмент, помеченный сервером как требующий подтверждения, в чате
   запускается только после «Запустить» (кнопки с параметрами вызова); отказ возвращается модели.
6. **Круги инструментов**: предел задаёт администратор, умолчание 15 (было 5); одинаковый повторный вызов с теми
   же аргументами в одном ответе не выполняется.
7. **Веб-инструменты MCP подчиняются «Интернету»**: инструменты со стандартной пометкой MCP `openWorldHint`
   доступны модели только при включённом «Интернете»; обёртка Spark помечает свои веб-инструменты.
8. **«Мои файлы»**: просмотр файлов пользователя на сервере MCP — папки, скачивание, ZIP с докачкой, загрузка
   кусками, удаление, личная ссылка на файл на сутки. Каждый видит только своё.
9. **Корзина на 14 дней для всего удаляемого в Studio** (чаты, записи всех разделов, файлы MCP); вернуть может
   владелец записи, не администратор.
10. **Пределы форм разделов из схемы инструмента MCP** (`minimum`, `maximum`, `enum`, `default`) вместо зашитых
    чисел; ролик Spark — до 600 с.
11. **Протокол встречи файлами** в «Расшифровке»: флажок «Протокол» и «Разделить по говорящим» — по схеме
    инструмента; файлы .txt, .srt, .md, .docx скачиваются из результата.
12. **«Прочитать» у ответа чата** — источником, выбранным по умолчанию в «Озвучке»; слушать и скачать.
13. **Режим «Разговор»** в диалоге: голосовой ввод → модель диалога → озвучка ответа, по кругу; конец фразы — по
    паузе; всё остаётся в истории текстом.
14. **«Защищённый источник»** у MCP: после срабатывания его инструмента в диалоге выключаются «Интернет» и
    веб-инструменты, аргументы со ссылками отклоняются. На Spark — MCP чувствительного бизнес-API с двумя
    наборами инструментов (обычный — со скрытыми идентификаторами SIM, администраторский); доступ — группами по
    инструментам (0.39.0). Подключение к живым ключам — только после проверки владельцем.
15. **Поиск по большим вложениям и базы знаний** на эмбеддингах и переранжировании подключённого источника;
    базы знаний — наборы документов с доступом по группам.
16. **«Справка»** в Studio: руководство Studio и руководства, которые публикуют MCP-серверы (ресурсы MCP).
17. **Вопросы кнопками в чате**: встроенный инструмент «спросить пользователя» для любой модели через сервер.
18. **Список задач и память** в чате: видимый план многошаговой работы; память — личная, шифром, включается и
    очищается в настройках.
19. **Общие голоса Spark в «Озвучке»** рядом с личными (через схему инструмента озвучки обёртки).
20. **Cookies YouTube** — отдельной формой в настройках, файл уходит в личную папку на сервере MCP и модели не
    передаётся (инструмент `youtube_cookies` в обёртке остаётся закрытым).

## Из проекта video (решения владельца 2026-11-21)

21. **Записка автору aitools** с правилами скачивания из video (по умолчанию mp4 avc1+m4a для Safari/iOS, звук в
    каждой альтернативе формата, `--extract-audio` для «только звук», `--` перед адресом, код 101 — штатная
    остановка, путь результата из `after_move`); код aitools не правим — записка рядом с обёрткой на Spark.
22. **JS-рантайм YouTube в образе Studio**: deno и `yt-dlp[default]` (yt-dlp-ejs) и записанный регламент
    поднятия закреплённой версии yt-dlp при поломках YouTube.
23. **Длинные записи в «Расшифровке»** частями по живым пределам источника (`/speech/limits` и аналоги):
    резать, расшифровывать по очереди, склеивать с верными метками времени; метки собеседников в разных частях
    независимы — это отмечается в тексте.
24. **Быстрое действие «Агентов» «Скачать ролик»** на подключённом компьютере скриптами video (свой адрес и
    cookies браузера пользователя, файл остаётся у него); код моста не меняется, действие с запросом разрешения.

Не берём из video: GUI WinForms и EXE, бинарники (ffmpeg-сборка GPL, deno, vot-cli-live), неофициальный API
Яндекса для перевода, скачивание и обход каналов на сервере Studio, таблицы itag, самообновление yt-dlp.
