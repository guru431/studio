# Мост Claude Code: скачивание из студии, окно и трей в стиле студии, отвязка — спека

Дата: 2026-10-28. Проекты: студия (`C:/work/projects/studio`) и мост (`C:/work/projects/studio-agent`).
Основа — [2026-10-28-studio-claude-code-design.md](2026-10-28-studio-claude-code-design.md) и протокол
[2026-10-28-studio-code-bridge-protocol.md](2026-10-28-studio-code-bridge-protocol.md) (версия 1).

## 1. Зачем

Владелец ставит мост на компьютер и не находит, откуда его взять: студия говорит «поставьте мост», но ссылки нет,
а репозиторий приватный. Окно моста после установки остаётся формой привязки (логин, пароль, PIN): по нему не
видно, подключён ли компьютер, под какой учёткой, и как отключиться. Значок в трее — цветной кружок без подписи.

Успех: человек с учёткой студии скачивает мост из студии, ставит его двойным щелчком, входит; дальше окно и трей
с первого взгляда говорят «на связи · <логин>», а «Отключиться» возвращает компьютер в исходное состояние.

## 2. Решения владельца (2026-10-28)

- **«Отключиться» — отвязать компьютер**: мост просит студию отозвать себя (компьютер уходит из списка), стирает
  ключ устройства и PIN, окно снова показывает форму входа. Студия недоступна — ключ стирается всё равно, мост
  говорит, что компьютер остался в списке студии и его нужно отозвать там.
- **Скачивание — архив из студии**: выкладка студии собирает ZIP из закоммиченного HEAD `studio-agent` и кладёт
  рядом с кодом; отдаёт его `GET /api/agent/download` только вошедшим (любая учётка студии; секретов в мосте нет).
- После готовности и зелёных тестов — push обоих репозиториев, выкладка студии, мост этого компьютера —
  перезапуск новой версией.

## 3. Цели и не-цели

Цели:
- Ссылка «Скачать мост для Windows» в «Настройках» (блок «Компьютеры (Claude Code)» — всегда) и в разделе
  «Claude Code» (пустой список компьютеров — вместо текста-заглушки).
- Установка из архива двойным щелчком (`install.cmd`), обновление — тем же архивом поверх.
- Окно моста: до привязки — форма входа; после — состояние подключения, логин, компьютер, «Отключиться», папка
  проектов, автозапуск, PIN кнопками «Задать / Изменить / Убрать PIN», «Снять блок».
- Трей: значок студии с точкой состояния, первая строка меню — состояние и логин, подсказка с логином,
  уведомление Windows о подключении после привязки и об отзыве.
- Вид окна — палитра и типографика студии («Бумага» / «Графит» по теме Windows).

Не-цели: установщик `.exe`/MSI и подпись кода; переименование компьютера без новой привязки; пауза связи без
отвязки; проверка обновлений мостом; несколько учёток в одном мосте.

Анти-цели: пароль студии остаётся на диске или в журнале; ключ устройства уходит строкой запроса; «Отключиться»
молча оставляет компьютер в студии без слов об этом; архив моста отдаётся без входа.

## 4. Студия

### 4.1 Скачивание

- `GET /api/agent/download` (`agents.py`, через `auth.guard` — сессия; CSRF у GET нет): файл
  `<корень кода>/agent/studio-agent.zip` (рядом с `app/`; путь — константа модуля, тесты подменяют),
  `FileResponse`, `media_type="application/zip"`, имя `studio-agent.zip`, `Cache-Control: private, no-cache`.
  Нет файла — 404 `{"code": "no_agent", "message": "архива моста нет на сервере — его кладёт выкладка студии"}`.
  Журнал — `пользователь N: скачан мост`.
- `deploy/deploy.sh`: репозиторий моста — `STUDIO_AGENT_REPO` (по умолчанию `$D/../studio-agent`); нет
  каталога или незакоммиченные изменения — отказ, как у студии. `git -C <мост> -c core.autocrlf=false archive
  --format=zip --prefix=studio-agent/ HEAD` → `.incoming/agent/studio-agent.zip` на хосте (тем же `ssh`), строка
  `==> мост <короткий хеш> → agent/studio-agent.zip`.
- `deploy/install.sh`: `agent` — в `SWAP` вместе с кодом (откат `.previous` возвращает прежний архив); права —
  как у кода (`root`, читается всеми). `test_deploy.py` сверяет: deploy собирает архив моста, install переносит
  `agent`.
- Что попадает в архив, решает мост `.gitattributes` `export-ignore` (§5.1).

### 4.2 Ссылка на странице

Один источник текста и элемента — функция в общем модуле (например, `ui.js` `agentDownload()` или экспорт
`code.js`), её берут оба места:

- Ссылка `<a href="/api/agent/download" download>` «Скачать мост для Windows», рядом — «ZIP, нужны Python 3.11+
  и Claude Code».
- Шаги: «Распакуйте архив и запустите install.cmd. В окне моста войдите логином и паролем студии — компьютер
  появится здесь.»
- «Настройки» → «Прочее» → «Компьютеры (Claude Code)»: под заголовком, всегда (второй компьютер ставят тем же
  архивом); строка пустого списка — без прежнего «Поставьте мост…».
- «Claude Code», пустой список (`#code-empty`): значок, «Компьютеров пока нет.», ссылка и шаги вместо `EMPTY`.

### 4.3 Протокол: логин и отвязка мостом (версия остаётся 1)

Добавки совместимы в обе стороны: мост v1 лишние поля пропускает, новый мост без них показывает «—».

- §1 привязка: ответ 201 — ещё `"login"` (логин учётки как в студии: `strip().lower()`).
- §2 `welcome` — ещё `"login"` (учётки компьютера).
- §1 отвязка: `DELETE /api/agent/enroll`, ключ — заголовком `Authorization: Bearer <ключ>` (как канал), тела нет.
  Анонимен для `guard` (путь уже в `auth.OPEN_API`); чужой `Origin` — 403 `origin`; ключ не найден — 401 `key`.
  Найден — строка `agents` удаляется (как `DELETE /api/agents/<id>`, учётка может быть и отключённой), событие
  `revoke` с `device` «мост», канал на связи — `bridge.drop` (4401), ответ 204. Журнал — `компьютер N: отвязан
  мостом`. Прежняя студия ответит 405 — мост считает это «студия недоступна».
- Текст протокола и раздел «Устройство» CLAUDE.md студии — дописать.

## 5. Мост

### 5.1 Архив и установка

- `.gitattributes`: `export-ignore` для `tests/`, `.claude/`, `CLAUDE.md`, `AGENTS.md`, `FINDINGS*.md`,
  `IDEAS*.md`, `pytest.ini`, `requirements-dev.txt`, `.gitignore`, `.gitattributes`.
- `install.cmd` (ASCII, CRLF; `.gitattributes` `*.cmd text eol=crlf` последним): `powershell -NoProfile
  -ExecutionPolicy Bypass -File "%~dp0install.ps1" %*`; код не 0 — `pause`, чтобы окно не закрылось молча.
- `install.ps1`: запущен не из git-копии (нет `.git` рядом) — ставит в `%LOCALAPPDATA%\Programs\studio-agent`:
  останавливает работающий оттуда мост (процесс `pythonw.exe` этой `.venv`), копирует файлы архива поверх (среда
  `.venv` остаётся), снимает «Mark of the Web» (`Unblock-File`), дальше — как сейчас (среда, пакеты, запуск).
  Из git-копии — на месте, как сейчас (разработка). Автозапуск указывает на установленную копию.
- README: установка из студии — первой; `git clone` — для разработки.
- `VERSION` — `0.2.0`.

### 5.2 Ядро (`app.Controller`, `store`, `enroll`)

- `Config.login: str = ""` — из ответа привязки (иначе введённый, `strip().lower()`) и из `welcome` (сменился —
  записать). `Link` отдаёт `welcome` наружу (колбэк или поле), `Controller` пишет `login` и `name`.
- `Controller.unenroll()` (блокирует — не из потока Tk) → `(ok: bool, words: str)`: ходы — `runner.close()`, канал —
  `_drop_link()`; `enroll.unenroll(url, key)` (`DELETE`, `urllib`, без перенаправлений, 15 с); 204 или 401 — студия
  забыла компьютер; иначе — «Студия недоступна — компьютер остался в её списке: отзовите его в «Настройки» →
  «Компьютеры»». В обоих случаях стираются `key.bin` и `pin.bin`, из `config.json` — `agent_id` и `login`
  (адрес, имя, папка, автозапуск остаются), состояние — `setup`.
- `Controller.set_pin(pin | None)` → `PinStore.set_pin` и `restart_link()` (студия узнаёт `has_pin` в новом
  `hello`; открытые сессии сбрасываются — как сейчас «Сохранить»). `set_folder(path)`, `set_autostart(bool)` —
  запись и `restart_link()` (папка) / реестр (автозапуск).
- `Controller.has_pin` — `PinStore` есть (нечитаемый — «задан», как `hello`).
- Состояние для окна и трея — прежние `WORDS`; подписчики получают его через очередь Tk, как сейчас.

### 5.3 Окно «Studio Agent»

Одно окно (`window.open_setup` → `open_main`), заголовок «Studio Agent». Перерисовывается по состоянию: привязан
(есть ключ) — вид «Подключение», нет — «Вход». Состояние ядра окно получает той же очередью, что трей.

Вид «Вход» (не привязан):
- шапка: значок студии, «Studio Agent», плашка «Не подключён»;
- поля: Адрес студии, Логин, Пароль (под ним — «Пароль нужен один раз и на компьютере не хранится»), Имя
  компьютера, Папка проектов [Обзор…], PIN (по желанию, 4–8 цифр) и «PIN ещё раз», ☐ Запускать при входе в Windows;
- кнопка «Подключить» (акцентная), ошибки — под формой; привязка — в своём потоке, как сейчас; пароль стирается
  из поля сразу после нажатия.

Вид «Подключение» (привязан):
- карточка состояния: крупная точка и слова — «На связи» (зелёная), «Подключается…» (серая), «Нет связи —
  переподключаюсь» (жёлтая), «Компьютер отозван в студии» / «Ключ используется другим мостом» (красная);
  строки «Студия» (хост адреса), «Вход» (логин или «—»), «Компьютер» (имя); кнопка «Отключиться» (опасная,
  контурная). Отозван или заменён — кнопка «Войти заново» (та же отвязка без запроса к студии: стереть ключ, PIN,
  к виду «Вход»);
- «Отключиться» — окно подтверждения «Отключить компьютер от студии? Студия забудет этот компьютер, идущие ходы
  прервутся. Чаты Claude Code останутся на компьютере.» [Отключить] [Отмена]; итог — вид «Вход», слова отказа
  студии — над формой;
- карточка «Настройки»: Папка проектов (путь, [Изменить…] — выбор папки, сразу сохранить); ☐ Запускать при входе
  в Windows (сразу); PIN — строка состояния и кнопки: не задан — «PIN не задан» [Задать PIN]; задан — «PIN задан»
  [Изменить PIN] [Убрать PIN]; заблокирован — «PIN заблокирован после 5 ошибок» [Снять блок] [Изменить PIN];
- «Задать / Изменить PIN» — окно: «Новый PIN» и «Ещё раз» (скрытый ввод), [Сохранить] [Отмена], слова ошибок
  `setup.pin_errors`; «Убрать PIN» — подтверждение. Старый PIN не спрашивается (на машине — владелец учётки
  Windows, ему доступен и `pin.bin`).
- Escape и крестик — закрыть окно (мост работает дальше в трее).

Вид — палитра студии (`app/static/css/app.css`): светлая «Бумага» — фон `#fbfaf7`, панель `#ffffff`, текст
`#1f1d1a`, приглушённый `#7b766d`, граница `#e3dfd6`, акцент `#c96442` (текст на нём белый), «на связи»
`#2f9e6f`, опасное `#b42318`; тёмная «Графит» — фон `#1b1b1b`, панель `#262626`, текст `#ececec`, приглушённый
`#8f8f8f`, граница `#2a2a2a`, акцент `#ececec` (текст `#111111`), «на связи» `#3ecf8e`, опасное `#f87171`.
Тема — по Windows (`HKCU\…\Themes\Personalize\AppsUseLightTheme`), тёмная — и тёмный заголовок окна
(`DwmSetWindowAttribute` 20); шрифт Segoe UI (Variable), заголовки — полужирные; карточки — панель с границей,
отступы 16–20 px; ttk на теме `clam` со своими стилями (кнопки: акцентная, обычная, опасная контурная). Палитра
и стили — один модуль (`theme.py`), окна берут их оттуда.

### 5.4 Трей

- Значок — рисунок `icons/icon.svg` студии (скруглённый квадрат с градиентом, облачко, звезда) Pillow-ом в 64 px
  и точка состояния в правом нижнем углу с обводкой: зелёная `online`, серая `connecting`/`setup`, жёлтая
  `offline`, красная `revoked`/`replaced`.
- Подсказка — «Studio Agent — на связи · example-user» (без логина — без хвоста; не длиннее 127 знаков).
- Меню: первая строка — неактивная «● На связи — example-user» (состояние и логин); «Открыть Studio Agent» (по
  умолчанию, щелчок по значку); «Снять блок PIN» (активна при блоке); «Открыть журнал»; «Выход».
- Уведомление Windows (`icon.notify`): первый `online` после привязки — «Компьютер подключён к студии»;
  `revoked` — «Компьютер отозван в студии»; `replaced` — «Ключ используется другим мостом». На переходы
  `offline`/`connecting` — нет (обрывы сети шумят).

### 5.5 Журнал

Без изменений правил: ни логина, ни имени компьютера, ни путей. Новые строки — `отвязка: <код>` (204, 401, тип
ошибки), `PIN: задан` / `убран`, `папка проектов сменена`.
