# Студия: рабочее место «Claude Code» — панель проектов и вкладки сессий — дизайн

Дата: 2026-10-29. Статус: **одобрен владельцем 2026-10-29.** Проект: `studio` (репозиторий приватный).

Переделка интерфейса раздела «Claude Code» (`#/code`) поверх уже работающего сервера и моста — спека
[2026-10-28-studio-claude-code-design.md](2026-10-28-studio-claude-code-design.md) (дальше — «спека CC»),
протокол [2026-10-28-studio-code-bridge-protocol.md](2026-10-28-studio-code-bridge-protocol.md). Протокол моста
и сам мост (`studio-agent`) не меняются.

## 1. Зачем

Владелец работает с Claude Code в VS Code. Ему нравятся вкладки, но не нравится, что для каждого проекта
нужно открывать новое окно. Сейчас в студии раздел устроен лестницей уровней «компьютеры → проекты → проект →
чат» (`code.js`): каждый шаг — переход по ссылке, назад — по строке пути, видна одна сессия за раз, а строка пути
на узком экране переносится на несколько строк (скриншот владельца: «Компьютеры › WORKSTATION › local-config › База
типичных проблем code review» занимает отдельную широкую полосу).

Нужно одно окно на все проекты всех компьютеров: слева всегда видны компьютеры и их проекты, справа —
вкладки открытых сессий выбранного проекта, путь — одной короткой плашкой. И чтобы при следующем входе всё
открылось, как было.

## 2. Критерий успеха

1. Владелец открывает «Код» на компьютере. Слева — имена всех его компьютеров строками, под ними — проекты
   выбранного компьютера; справа — вкладки сессий проекта, открытого в прошлый раз, и активной из них — чат.
2. Нажал имя другого компьютера — под именами его проекты (компьютер с PIN — сначала поле PIN прямо в
   панели). Имена компьютеров при прокрутке длинного списка проектов остаются на месте.
3. Нажал проект — справа его вкладки; вернулся в прежний проект — его вкладки на месте.
4. «+» — меню: «Новый чат» и остальные сессии проекта (в том числе начатые в VS Code и терминале); выбранная
   открывается новой вкладкой. «×» убирает вкладку, сессия на компьютере остаётся.
5. Над лентой — одна строка: плашка `WORKSTATION / local-config` и переключатели «Чат · Файлы · Git».
6. Владелец закрыл браузер, открыл студию на телефоне — те же проекты и вкладки. На телефоне панель выезжает
   слева по кнопке ☰ и прячется после выбора проекта; вкладки — полосой, которую листают вбок.
7. Ссылка из push (`#/code/<aid>/<pid>/<chat>`) открывает тот проект и ту сессию вкладкой.
8. Откат `install.sh` на прежний код с новой базой работает (прежний код видит старый интерфейс).

## 3. Не цели

- Не показывать две сессии рядом (разделение экрана) — только вкладки, одна видимая за раз.
- Не перетаскивать вкладки и не закреплять их: порядок — порядок открытия.
- Не синхронизировать вкладки между устройствами вживую: другое устройство видит изменения при следующем
  входе в раздел.
- Не показывать «идёт ход / ждёт ответа» у проектов, которые сейчас не открыты (для этого — push, спека CC
  §6.8).
- Не менять протокол моста, мост, PIN и правила открытости компьютера (спека CC §6.3).
- Не трогать другие разделы студии: панель есть только в «Коде».

## 4. Анти-цели — провал, даже если всё «работает»

- **Студия без конца держит компьютер открытым.** Любая просьба к мосту продлевает открытость сессии на 30
  минут (протокол §3). Фоновый опрос (метки вкладок, список проектов) без предела — и забытая вкладка браузера
  держит компьютер открытым вечно. Предел — тот же, что у чата сейчас: опрос идёт, только пока страница видна, и
  не дольше `IDLE_POLL_FOR_SEC` (30 мин) после последнего действия владельца в разделе.
- **Push перестал приходить.** Сервер шлёт push, только если чат никто не смотрит (`bridge.watching`). Поток
  `live`/`turn` держит только видимая вкладка; фоновые вкладки потоков не держат.
- В запомненном рабочем месте на сервере — имена компьютеров, проектов, названия сессий, пути или тексты. Там
  только номера: id компьютера, `pid`, UUID сессии.
- PIN попал в адрес, хранилище браузера или рабочее место (сейчас этого нет — не сломать при переносе панели
  PIN в боковую панель).
- Несохранённая правка во «Файлах» теряется при смене вкладки или проекта (сейчас её сторожат `hold()` и
  `files.leave`).
- Имена компьютеров уезжают вместе со списком проектов при прокрутке.

## 5. Решения владельца (разговор 2026-10-29)

1. Слева всегда видны компьютеры и проекты, «как Explorer и расширения в VS Code», без нового окна на каждый
   проект.
2. Имена компьютеров — **строками, одно под другим, над списком проектов**; отдельного столбца для них нет (из
   макетов отвергнуты: сворачиваемые заголовки-гармошка и узкий столбец значков, как у Telegram). Нажатие на имя
   показывает проекты этого компьютера; список проектов прокручивается, имена — нет.
3. Справа — вкладки сессий **проекта**, как вкладки VS Code: у каждого проекта свой набор; «×» только убирает
   вкладку; «+» в конце ряда.
4. Путь — одна компактная плашка `<компьютер> / <проект>` над лентой; в том же ряду справа «Чат · Файлы · Git».
   Название сессии — на вкладке, в пути его нет.
5. Компьютер с PIN — поле PIN прямо в панели вместо списка проектов; не на связи — вместо проектов строка «не
   на связи» (предложено, принято).
6. Телефон: панель выезжает слева по ☰ рядом с плашкой пути и прячется после выбора; вкладки — полоса с
   прокруткой вбок (предложено, принято).
7. «+» — меню: сверху «Новый чат», ниже остальные сессии проекта, новые первыми, с пометками «VS Code или
   терминал», «идёт ход», «ждёт ответа»; выбранная — новой вкладкой (предложено, принято).
8. Запоминаются компьютер, проект и все вкладки каждого проекта — **в учётке** (все устройства видят одно и то
   же), только номерами, без имён и текстов (предложено, принято).

## 6. Как устроено

### 6.1 Раскладка (широкий экран, > 760 px)

```
рельс │ ПАНЕЛЬ (≈220 px)          │ [вкладка ×][вкладка ×][+]          ← ряд вкладок
      │ ● WORKSTATION          PIN    │ [WORKSTATION / local-config]   Чат Файлы Git   ← строка пути
      │ ● BUILD-HOST                 │
      │ ○ HOME-PC   не на связи   │  лента чата (прокрутка)
      │───────────────────────────│
      │ local-config               2     │
      │ studio              1     │  поле задания (прилипает к низу)
      │ llm_routers               │
      │ …  (прокрутка)            │
```

- Панель — колонка на всю высоту раздела, рядом с лентой (как список диалогов `.chats` в чате). Верх панели —
  блок компьютеров без прокрутки; низ — список проектов выбранного компьютера, прокручивается только он. Лента
  справа прокручивается отдельно от панели.
- Ряд вкладок и строка пути прилипают к верху правой части; поле задания — к низу, как сейчас
  (`.code-composer`).
- Строка компьютера: точка «на связи» (цвет) или серая «не на связи», имя, справа — «PIN», если задан. Версия
  Claude Code — подсказкой (`title`). Порядок — как отдаёт `GET /api/agents`. Выбранный компьютер подсвечен.
- Строка проекта: имя; справа — число открытых у него вкладок (берётся из рабочего места, без запросов к
  мосту). Открытый проект подсвечен.
- Компьютеров нет — в панели «Компьютеров пока нет.» и «Скачать мост» (`ui.js agentDownload`), справа пусто.

### 6.2 Телефон (≤ 760 px)

- Панель прячется и выезжает слева по кнопке ☰, стоящей перед плашкой пути, с затемнением фона — тем же
  приёмом, что список диалогов чата (`.chats`, `panel-open`, `.chats-backdrop`). Закрывается после выбора
  проекта, выбора в меню «+», нажатия на фон, Escape.
- Выбор компьютера панель не закрывает (дальше выбирают проект или вводят PIN).
- Ряд вкладок — одна строка с прокруткой вбок; активная вкладка прокручивается в видимую часть.

### 6.3 Компьютеры и проекты в панели

- Нажатие на имя компьютера — как нажатие на строку сейчас (`code.js` `choose`): не на связи — вместо списка
  проектов строка «Компьютер не на связи — включите его и запустите мост», запросов нет; на связи — `POST
  …/open {pin: null}`; 204 — `GET …/projects` и список; 409 `pin_needed` — поле PIN на месте списка проектов
  (тот же элемент `#code-pin`: не `<form>`, не `password`, Enter и «Открыть»; `pin`, `pin_locked`, `offline` —
  те же слова).
- Выбранный в панели компьютер и открытый справа проект независимы: можно смотреть проекты BUILD-HOST, пока
  справа открыт `local-config` на WORKSTATION. Нажатие на имя компьютера не меняет ни адрес, ни правую часть — только
  панель (и запоминается в рабочем месте). Плашка пути всегда говорит про проект справа.
- Отказ `closed` в любом месте (вкладка, «Файлы», «Git», «+») — панель выбирает этот компьютер и показывает
  его поле PIN; после верного PIN — туда, где застал отказ (вкладка, «Файлы» с файлом и правкой — как
  `returnTo` сейчас). PIN — только в поле и переменной обработчика, как сейчас.
- Компьютер ушёл со связи, пока открыт его проект — вкладки и лента ведут себя, как сейчас чат
  («Компьютер пропал со связи — жду его»); строка в панели сереет при следующем чтении `GET /api/agents`.

### 6.4 Вкладки

- Вкладка — сессия проекта: название сессии (`title` из `GET …/chats`, иначе «Новый чат»), обрезка многоточием,
  полное — подсказкой; «×». В конце ряда — «+». Мост отдаёт в списке не больше 200 новейших сессий (протокол
  §4, `CHATS_MAX`): вкладка старой сессии, не попавшей в список, показывается с названием «Сессия» и без меток —
  это не повод её убирать.
- Активная вкладка — `chatView` (`code-chat.js`) как сейчас. Только она держит поток `live`/`turn`; при уходе
  с вкладки поток снимается, при возврате — история и `live` заново (снимок догонит идущий ход). Черновик поля
  переживает переключение (`drafts` уже в памяти модуля по чату).
- Метки вкладок открытого проекта: «идёт ход» и «ждёт ответа» — по `running`/`asking` из `GET …/chats`; этот
  список читается при открытии проекта и затем раз в `IDLE_POLL_SEC` (20 с), пока страница видна и не дольше
  `IDLE_POLL_FOR_SEC` после последнего действия владельца в разделе (§4). Метка «ждёт ответа» заметнее
  (акцентный цвет).
- Новая вкладка встаёт в конец ряда и становится активной. Вкладок в проекте — не больше `TABS_MAX` (20): при
  открытии 21-й (из «+», «Новым чатом», ссылкой push или «В работе» — любым путём) молча уходит самая левая
  неактивная, как при пределе вкладок VS Code. Отказа нет — ссылка из push открывает сессию всегда.
- «×» активной — активной становится соседняя справа, иначе слева. Закрыта последняя — справа список сессий
  проекта (§6.5). «×» сессию не закрывает и ход не останавливает: идущий ход продолжается на машине, и раз чат
  больше никто не смотрит, придёт push.
- «Закрыть чат» над лентой (`#code-close-chat`, `PATCH {state: "closed"}`) остаётся и вдобавок убирает вкладку
  (дальше — как «×»).
- Вкладка убирается сама только по ответу 404 `not_found` на чтение её истории (`GET …/chats/<chat>` при
  показе): сессии на машине нет и студия её не заводила. Отсутствие в списке `GET …/chats` вкладку не убирает
  (предел 200 выше; новый чат студии без хода в списке есть, пока открыт).

### 6.5 Меню «+» и список сессий проекта

- «+» открывает меню: сверху «Новый чат» (как кнопка сейчас: `POST …/chats` → UUID, вкладка, выбор модели
  устройства — `freshChat`), ниже — сессии проекта из `GET …/chats`, которых нет во вкладках, в порядке сервера
  (открытые, затем закрытые, новые первыми), с пометками «VS Code или терминал», «закрыт», «идёт ход», «ждёт
  ответа» и временем. Выбор — новая вкладка; закрытая сессия при выборе сначала открывается снова (`PATCH
  {state: "open"}`), затем вкладкой. Отдельных кнопок «Закрыть» / «Открыть снова» у строк нет: закрывают из
  самого чата («Закрыть чат», §6.4).
- У проекта без вкладок справа вместо ленты — тот же список во всю ширину, с «Новым чатом» сверху. Это и
  первое знакомство с проектом.

### 6.6 Строка пути, «Файлы» и «Git»

- Плашка `<компьютер> / <проект>` — одна строка, мелким моноширинным шрифтом на подложке; не влезает — сначала
  обрезается имя компьютера, потом проекта (многоточие), перенос строки запрещён. Это не ссылка.
- «Чат · Файлы · Git» — переключатели вида правой части для открытого проекта. «Файлы» и «Git» — те же
  `filesView`/`gitView` (`code-files.js`), один экземпляр на проект; ряд вкладок при них остаётся, а
  активная вкладка теряет подсветку. Нажатие на вкладку — снова «Чат» с этой сессией.
- «Открыть файл» шага ленты — «Файлы» этого проекта и файл, как сейчас (`wantFile`).

### 6.7 Адреса и история браузера

- Адреса остаются прежними — на них опираются push (`href` `code/<aid>/<pid>/<chat>`), `hold()` и тесты:
  `#/code/<aid>/<pid>/<chat>` — проект и активная вкладка; `#/code/<aid>/<pid>?tab=files|git` — проект и вид;
  `#/code/<aid>/<pid>` — проект с активной вкладкой из рабочего места или списком сессий; `#/code` — открытый
  проект и активная вкладка из рабочего места (`location.replace` на их адрес), их нет — справа «Выберите проект
  слева», в панели — запомненный компьютер, иначе первый. `#/code/<aid>` — только входная ссылка (старые закладки,
  возврат к PIN): выбирает компьютер в панели, правая часть — как у `#/code`. Нажатие на компьютер в панели адрес
  не меняет (§6.3).
- Адрес с сессией, которой нет во вкладках, добавляет её вкладкой (push, ссылка из «В работе»).
- Смена проекта — новая запись истории; смена вкладки — тоже смена адреса, но заменой записи
  (`location.replace`), чтобы «Назад» не листал вкладки (решение автора, §9). Обе идут через роутер `app.js`,
  поэтому `hold()` (несохранённая правка) срабатывает и на них. Раздел, меняя адрес своей записи, сохраняет
  метку `entry` (`history.replaceState(history.state, …)`, «Ловушки» CLAUDE.md).

### 6.8 Рабочее место на сервере

- Документ рабочего места учётки: выбранный в панели компьютер; открытый проект (`aid`, `pid`) и вид
  (`chat`/`files`/`git`); по каждому проекту с вкладками — упорядоченный список UUID сессий и активная. Только
  id, никаких имён и названий.
- `GET /api/code/workspace` — документ (нет — пустой). Запись — **не документом целиком, а действиями**, каждое
  сервер применяет атомарно к тому, что лежит в базе: открыть вкладку (добавить в конец, если её нет, сделать
  активной и открытым проектом; предел — §6.4), убрать вкладку, сделать активной, открыть проект и вид, выбрать
  компьютер панели. Ответ — новый документ. Сервер проверяет поля (`aid` — свой компьютер учётки, `pid` — 16 hex,
  сессия — UUID; чужой и несуществующий компьютер — 404, как у остальных `/api/code/*`), держит пределы
  (`TABS_MAX` на проект, проектов с вкладками — до 100: сверх — уходит проект, открытый раньше всех) и к мосту не
  ходит. Под `auth.guard` (сессия и CSRF), как всё `/api/code/*`; не в `SCREEN_LOCK_PATHS`.
- Зачем действия: телефон с PWA висит в фоне со вчерашним документом; запись целиком первым же нажатием стёрла бы
  вкладки, открытые сегодня на компьютере, а после «Удалить всю историю» вернула бы стёртые номера. Действие
  меняет только своё — устаревшее устройство не затирает чужое.
- Страница читает документ при входе в раздел и при возвращении на экран (`visibilitychange: visible`): обновляет
  панель и ряд вкладок, но **не переключает** проект и активную вкладку, которые сейчас на экране этого
  устройства (под руками ничего не прыгает, несохранённая правка не задета); показанная здесь вкладка, убранная
  на другом устройстве, остаётся на экране, пока с неё не уйдут. Живой синхронизации нет (§3).
- Отзыв компьютера (`DELETE /api/agents/<id>`, отвязка мостом) и удаление учётки уносят его часть рабочего
  места. «Удалить всю историю» стирает рабочее место целиком (в нём номера сессий — это история, как
  `code_chats`). Выгрузка (`takeout`) кладёт его в `code_chats/` (решение автора).
- Журнал — ничего сверх обычного (никаких id сессий и проектов в строках журнала на каждое сохранение).

### 6.9 Схема и откат (шаг 20)

- Новый шаг `db.STEPS` — только добавление (таблица или столбец — на выбор исполнителя, §10); прежний код его
  не читает.
- Откат на код до шага 20: прежний интерфейс (лестница уровней), рабочее место не видно и не мешает; «Удалить
  всю историю» прежнего кода его не стирает — вернувшись вперёд, вкладки тех, кто стирал историю, снова
  видны (абзац отката в CLAUDE.md, как у шагов 18 и 19). Отзыв компьютера прежним кодом невозможен (нет
  вкладки) — ничего нового.

## 7. Приватность

Без изменений по смыслу: на сервере — только номера (§6.8), в журнал — ничего, тексты и имена — только
`textContent`. Хранилище браузера: прежний выбор модели `studio-code-choice:<aid>` и ничего нового (рабочее
место — в учётке, не в `localStorage`).

## 8. Тесты

- Сервер: `GET /api/code/workspace` и действия записи — проверка полей, пределы (21-я вкладка вытесняет самую
  левую неактивную), чужой и несуществующий компьютер, два устройства (действие устаревшего не затирает чужие
  вкладки; после «Удалить всю историю» действие не возвращает стёртое), каскад отзыва и удаления учётки,
  выгрузка; к мосту не ходит (подставной мост не получает просьб).
- Браузер (`tests/test_ui_browser.py`, подставной мост): панель с несколькими компьютерами (имена не уезжают
  при прокрутке проектов; нажатие на компьютер не меняет адрес), PIN в панели и возврат после PIN, вкладки
  (открыть из «+», «Новый чат», закрытая сессия из «+» открывается снова, «×», «Закрыть чат», соседняя активная,
  предел 20, 404 `not_found` убирает вкладку, сессия вне списка — «Сессия»), восстановление после перезагрузки
  страницы, возвращение на экран не переключает открытое, ссылка push добавляет вкладку,
  несохранённая правка во «Файлах» спрашивает при смене вкладки и проекта, фоновая вкладка не держит поток
  (push уходит), опрос меток прекращается после `IDLE_POLL_FOR_SEC`, телефон — ☰, панель прячется после
  выбора, полоса вкладок листается.
- Существующие браузерные сценарии раздела (`#code-agents`, `#code-projects`, `#code-chats`, `code-tab-*`,
  строка пути) переписываются под новую раскладку, а не выбрасываются: то, что они сторожат (PIN, `hold()`,
  открытие файла из шага, `?pin=`-возврат), должно остаться под тестом.

## 9. Решения автора (не владельца — проверить при чтении)

1. Число у проекта в панели — сколько у него открытых вкладок; «идёт ход / ждёт ответа» — только на вкладках
   открытого проекта (у остальных проектов это стоило бы опроса моста на каждый проект — анти-цель §4).
2. Поток держит только активная вкладка; переключение перечитывает историю с моста (небольшая задержка при
   переходе — цена работающего push).
3. Порядок вкладок — порядок открытия, новая — в конец; при 20 вкладках новая вытесняет самую левую
   неактивную (как VS Code), отказа нет — ссылка push открывается всегда.
4. «Назад» браузера не листает вкладки (смена вкладки заменяет запись), а переходит к прежнему проекту.
5. «Удалить всю историю» стирает и вкладки; выгрузка их несёт.
6. Проект без вкладок показывает список сессий во всю ширину вместо пустого экрана.
7. «Файлы» и «Git» — вид правой части проекта, а не отдельные вкладки в ряду сессий.
8. Рабочее место пишется действиями, а не документом целиком; другое устройство при возвращении на экран
   обновляет панель и ряд вкладок, но не перескакивает на чужой открытый проект.
9. Нажатие на компьютер в панели меняет только панель, не адрес и не правую часть.
10. Вкладка убирается сама только по 404 `not_found` истории; старая сессия вне 200 новейших остаётся вкладкой
    с названием «Сессия».
11. «Закрыть чат» в чате убирает и вкладку; выбор закрытой сессии в «+» открывает её снова; кнопок
    «Закрыть» / «Открыть снова» в списке больше нет.

- Ширина панели, отступы, значки, вид меню «+»; контейнер прокрутки ленты (сейчас `#view`) под новую раскладку.
- Разбиение `code.js` на модули (панель, вкладки).
