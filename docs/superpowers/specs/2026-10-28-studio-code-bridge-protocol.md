# Студия ↔ мост Claude Code: протокол канала, версия 1

Дата: 2026-10-28. Контракт между сервером студии (план
[2026-10-28-studio-claude-code-server](../plans/2026-10-28-studio-claude-code-server.md)) и мостом
`studio-agent` (второй план). Основа — спека
[2026-10-28-studio-claude-code-design](2026-10-28-studio-claude-code-design.md). Меняется только новой
версией (`v` в `hello`); сервер версии 1 отвечает мосту другой версии закрытием 4400.
Добавки v1 объявляются необязательными полями `hello` (capability); оглавление «capability → версия моста →
раздел» — [docs/architecture/agent-bridge.md](../../architecture/agent-bridge.md#capability-и-версии-моста).

## 1. Привязка

`POST https://studio.example.com/api/agent/enroll`, тело JSON `{"login", "password", "name"}` (не больше 4096
байт; `name` — 1–64 знака без управляющих). Ответ 201 `{"agent_id": int, "device_key": str, "login": str}` —
ключ выдаётся один раз, сервер хранит только его sha256; `login` — логин учётки, как его проверила студия
(введённый `strip().lower()`). Отказы — JSON `{"detail": {"code", "message"}}`:
401 `login` (неверный логин или пароль), 429 `locked` (пауза входа — та же, что у `/login`), 413
`too_long`, 422 `name`, 403 `origin` (запрос с заголовком `Origin` чужого сайта; мост `Origin` не шлёт).
Мост хранит ключ зашифрованным DPAPI; пароль не хранит.

Отвязка самим мостом («Отключиться»): `DELETE https://studio.example.com/api/agent/enroll`, ключ — заголовком
`Authorization: Bearer <device_key>` (как у канала, не строкой запроса), тела нет. Ответ 204 — компьютер
забыт: строки компьютера в студии нет (учётка может быть и отключённой), в истории подключений — событие
`revoke` с устройством «мост», канал на связи закрыт 4401. Отказы: 401 `key` (ключ не принят — компьютер уже
отозван или ключ чужой: для моста это тоже «забыт»), 403 `origin`. Студия до этой добавки отвечает 405 — мост
считает это «студия недоступна».

Добавки `login` и отвязки — в пределах версии 1: мост, который их не знает, лишние поля пропускает, а новый
мост без них показывает логин как «—».

## 2. Канал

Добавка studio-agent 0.10.0 в пределах v1: необязательные `hello.agent_version` (`major.minor.patch`)
и `hello.agent_update: true`. Без них версия неизвестна и автоматическое обновление недоступно.
Студия берёт последнюю версию, SHA-256 и размер из опубликованного `studio-agent.zip`, а не из браузера.
После открытия PIN обычная просьба `agent_update {version, sha256, size}` сразу отвечает
`{state: preparing|waiting|restarting|idle|failed, version}`. Повтор во время обновления возвращает
текущую стадию; `agent_update_status {}` читает её. Более старая/равная версия не устанавливается.
С моста 0.20.0 (`hello.agent_update_cancel: true`) `agent_update_cancel {}` в `preparing`/`waiting` возвращает
`idle` (новые задания снова принимаются; подготовленная копия удаляется), в `restarting` — поздно, ответ — текущая
стадия; права — как у `agent_update` (открытый PIN владельца, участнику — `closed`). В `waiting` статус несёт
`holds {tasks, asking, requests, desktop}` — что держит ожидание, только числа и признак рабочего стола.
Сервер: `DELETE /api/code/agents/<aid>/update`; мосту без capability — 409 `unsupported`.
Агент скачивает `GET /api/agent/package` с настроенного HTTPS-сервера, без перенаправлений,
`Authorization: Bearer <device_key>`; сервер проверяет существование устройства и активность учётки.
ZIP ограничен 16 МиБ, распакованный размер — 64 МиБ, 3000 записей; запрещены обход корня, ссылки,
небезопасные Windows-имена и дубликаты. Версия внутри ZIP должна совпадать с запрошенной.
Новая копия и её venv готовятся рядом с прежней; ходы всех трёх Runner и просьбы канала должны
завершиться до штатного выхода и запуска новой копии независимым помощником. Пока идёт обновление,
`turn/save/file_operation/worktree_create/chat_fork` получают `busy`; очередь/ответы текущего хода остаются.
Перезапуск сбрасывает открытые PIN-сессии, но сохраняет локальные ключи, PIN, настройки и историю.

`wss://studio.example.com/api/agent/link`, заголовок `Authorization: Bearer <device_key>`. Кадры — текстовые
сообщения WebSocket, в каждом один объект JSON (UTF-8), не больше `FRAME_MAX` = 16 МиБ. Поле `t` — тип
кадра. Пинги — штатные WebSocket (сервер шлёт каждые 20 с); кадров «ping» в протоколе нет.

Закрытие сервером:

| код | когда | мост |
|---|---|---|
| 4401 | ключ неизвестен, компьютер отозван, учётка отключена или удалена | не переподключается; показывает «компьютер отозван» |
| 4409 | тот же компьютер подключился заново (новый канал заменил этот) | не переподключается; «ключ используется другим мостом» |
| 4400 | нарушение протокола: нет `hello` за 10 с, неверный `hello`, неизвестный `t`, кадр больше `FRAME_MAX` | переподключается через паузу |
| 1012, 1001, обрыв сети | перезапуск студии, сбой | переподключается: 1, 2, 4 … 60 с |
| отказ рукопожатия (любой ответ HTTP, кроме 101), сеть недоступна | — | переподключается с той же паузой; «отозван» — только по закрытию 4401 |

Ответ, который не влез бы в `FRAME_MAX`, мост заменяет отказом `too_large`. Кадр больше `FRAME_MAX` + 1 КиБ
сервер WebSocket рвёт сам кодом 1009, не дойдя до студии (мост переподключается, как после обрыва).

### 2.1 Знакомство

Первый кадр моста — `hello`:

```json
{"t": "hello", "v": 1, "cc_version": "2.3.1", "projects_root": "C:\\work\\projects", "has_pin": true,
 "models": [{"id": "claude-opus-5-5", "label": "Opus 5.5"}], "efforts": ["low", "medium", "high"]}
```

`cc_version` — до 64 знаков; `projects_root` — до 1024 (только для показа владельцу); `models` — до 50,
`id` по `^[A-Za-z0-9._:\[\]-]{1,100}$`, `label` до 100 знаков; `efforts` — подмножество
`low, medium, high, xhigh, max`. Ответ сервера — `{"t": "welcome", "agent_id": 7, "name": "Рабочий ПК",
"login": "example-user", "studio_version": "0.1.0"}` (`login` — логин учётки компьютера; добавка версии 1, см. §1).
`studio_version` — версия работающего сервера Studio, независимая от версии моста и `v` протокола.
Поле необязательно для совместимости со старой студией; мост ≥ 0.18.0 показывает его только у текущего
соединения. Новый `welcome` без версии сбрасывает прежнее значение; разрыв канала тоже сбрасывает его.
Необязательное `welcome.completions: true` — студия принимает кадр досланных завершений (§18).

### 2.2 Просьбы студии и ответы моста

Добавка v1 от 2026-10-31 (studio-agent 0.6.0): boolean `hello.chat_control` объявляет
`steer {project, chat, text, images?}` → `{mode: steer|queue, id}` и
`claim {project, chat, fork?: bool}` → `{available?: bool, external?: bool, forked?: bool}`.
Просьбы чата могут нести `window` — 32 hex, случайный id страницы (HTTP-заголовок `X-Studio-Window`).
`turn` запоминает владельца, `steer/answer/stop` чужого окна получают `owned` (HTTP 409);
`claim` явно передаёт управление, не прерывая работу. Нет активного хода — у обычных движков claim пустой;
у Codex — проверка внешнего writer без генерации, либо при явном `fork: true` копия полной истории
и новый alias этого чата. Исходный внешний процесс не останавливается.
Codex передаёт уточнение в [turn/steer](https://learn.chatgpt.com/docs/app-server#steer-an-active-turn)
с обязательным expectedTurnId; Claude — SDK query, OpenCode ACP — очередь до конца текущего prompt.
Мост не принимает новые model/effort/access в steer. До 20 уточнений и до 2 МиБ ASCII-JSON текстов
на ход; очередь base64-картинок OpenCode — до 8 МиБ. Старому мосту эти просьбы не идут (409 unsupported).
`input_accepted` подтверждает, что CLI принял исходное задание; при отказе до отправки turn/start `done.not_started: true`
возвращает непринятый черновик, `done.code: writer_active` показывает ожидание/копию.
`followup {id, text, mode, sent?}`, `followup_sent {id}` и `ownership {owner}` идут всем наблюдателям.
С 0.15.3 необязательное `followup.position: {text, steps}` фиксирует позицию уточнения:
число уже переданных UTF-16 символов текста и начатых шагов. Та же позиция приходит в `snapshot.followups`;
страница ставит сообщение между ними, разделяя при необходимости текстовый сегмент.
Если снимок урезан, позиции опускаются. Старый мост без позиции вставляет уточнение в конец текущей ленты.
`snapshot` дополнен owner/accepted/followups; оригиналы картинок уже переданы CLI либо находятся в ограниченной
очереди моста. С 0.19.1 `followup` и `snapshot.followups[]` дополнены необязательными
`images: [{index, name}]` и `image_message_id`: изображение читается штатным `history_image` с этим id.
LRU в памяти движка ограничен 32 МиБ base64, ключ включает проект/чат/id/index; байтов в событии нет.
Старый мост оставляет только текстовый счётчик изображений. `done.unsent: [{id,text}]` возвращает очередь, снятую остановкой/ошибкой;
страница возвращает тексты и сохранённые в памяти вложения в поле. Тексты и картинки не журналируются.

Добавка v1 от 2026-10-30 (studio-agent 0.5.0): необязательный `hello.opencode` —
`{version, models, efforts, defaults?}` третьего помощника. До 500 моделей, id —
`[A-Za-z0-9._:\[\]/@+-]{1,300}`, label до 100 знаков; версия до 64 знаков. До 100 вариантов
effort — `[A-Za-z0-9._-]{1,64}`, включая `default`. Каталог приходит из локального OpenCode ACP,
без генерации. `defaults` содержит модель/усилие/доступ корня проектов.
`engine: opencode` выбирает его в `chats.items` и просьбах чата (включая `state`); без поля — Claude.
Сессии OpenCode `ses_*` связаны на машине с UUID студии, наружу идут только UUID.
`access: default` сохраняет правила OpenCode, `auto` отвечает `allow_once` на запрашиваемые
разрешения, сохраняя запреты CLI; null сохраняет прежний выбор. Старому мосту без каталога сервер
не шлёт такие просьбы: HTTP 409 `unsupported`.

Добавка той же версии: событие `activity {state, tool?}` и необязательное `snapshot.activity`
хранят стадию `thinking|tool|responding|waiting`. `tool` — только имя текущего инструмента,
без текста рассуждений. Открытые карточки имеют приоритет `waiting`; итог хода — прежний `done`.
Студия показывает текущую стадию и явный итог; старые мосты по-прежнему дают `text/step/result/ask/done`.

Добавка v1 от 2026-10-30 (studio-agent 0.4.0): `hello.chat_state: true` объявляет `state`
с полями `project, chat, model, effort, access` (три последних могут быть null). Ответ —
`{settings: {model, effort, access, approval?}, context: {used, limit, percent} | null}` без генерации.
Необязательные `hello.defaults` и `hello.codex.defaults` несут конкретные настройки корня проектов.
`turn.access` — необязательный режим: Claude `default|auto|acceptEdits|plan|bypassPermissions|dontAsk`,
Codex `read-only|workspace-write|danger-full-access`. Null сохраняет прежний выбор сессии/CLI;
явный выбор действует со следующего хода. Без chat_state студия отказывает в выборе access (409 unsupported).
События `settings` и `context` несут соответствующие поля, те же поля могут быть в snapshot.
Токены — последний отчёт CLI, не накопленный расход; статистика и настройки хранятся на машине.

Добавка v1 от 2026-10-31 (studio-agent 0.7.4): необязательный `context.usage` — накопленный расход
главной сессии: `{total?, input?, output?, cached?, cache_write?, reasoning?}`. Все значения — целые
неотрицательные токены, неизвестные поля отсутствуют. `used/limit/percent` по-прежнему описывают
текущее окно, а не накопленный расход. Codex передаёт total CLI, Claude агрегирует SDK-историю без
дублирования блоков одного API message.id; кэш у Claude входит в total, у Codex cached — часть input.
Ответ `git` без upstream может дополнительно нести `unpushed: int | null` по локальным remote refs.
UI использует эти данные для цветов; четыре кнопки Git — обычные turn текущего чата, без новых операций протокола.

Добавка v1 от 2026-11-08 (studio-agent 0.15.2): необязательный `context.cache` —
`{updated_at?: Unix seconds, model, ttl_seconds?: 300 | 3600 | null, message_id?: string}`.
Это метаданные последней обработки контекста, а не подтверждённое состояние серверного кэша.
Codex сообщает время изменения счётчиков; UI оценивает 30 минут только для GPT-5.6 и новее.
Claude сообщает срок по `usage.cache_creation`: 5 минут или час, при смешанном кэше — короткий;
чистое чтение сохраняет ранее известный срок той же модели. Время начала ответа SDK сохраняется
только для соответствующего API message.id; внешняя история без этой отметки времени неизвестна.
Повторные отчёты и чтение `state` отметку не продлевают. При неизвестных данных UI показывает «—».
Все таймеры приблизительные («≈»); ноль не означает гарантированного удаления кэша.

Добавка v1 от 2026-10-30 (studio-agent 0.3.3): необязательный boolean `hello.images` объявляет
картинки в ходах обоих помощников. Без поля или при `false` студия не отправляет картинки
(409 `unsupported`), текстовые задания работают как прежде. `turn.images` — необязательный список
до 4 объектов `{mime, data}`: `mime` — `image/png`, `image/jpeg`, `image/webp` или `image/gif`, `data` —
строгий base64 байтов картинки; имён файлов, URL и путей нет. До 5 МиБ раскодированных байтов на файл,
до 8 МиБ всего; HTTP-тело до 13 МиБ, кадр по-прежнему до 16 МиБ. Мост повторно проверяет пределы,
base64 и сигнатуру картинки до старта хода; неверное — `invalid`, превышение размера — `too_large`.
Пустой `text` допустим, если есть картинки. Студия их только ретранслирует, не пишет на диск и в журнал.
Claude Agent SDK получает image/source base64, Codex app-server — image с data URL; временных файлов нет.
История машины возвращает текстовый маркер `[изображение]`, без данных картинки в ответе студии.

Добавка v1 от 2026-10-31: `hello.attachments: true` объявляет произвольные файлы в `turn` и `steer`.
`attachments` — необязательный список `{name, mime, data}`: имя до 200 знаков (только метаданные),
MIME до 200 знаков (неизвестный — `application/octet-stream`), строгий base64 содержимого.
Разрешены любые типы и пустые файлы; URL и локальные пути вместо содержимого не принимаются.
До 8 файлов вместе с `images`, по 5 МиБ на файл, 8 МиБ раскодированных байтов всего; прежние
ограничения четырёх изображений и HTTP/WS сохраняются. Без capability сервер отвечает 409 `unsupported`.
Пустой текст допустим при любом вложении. Обе стороны проверяют содержимое и общий размер.
Имя очищается от частей пути и управляющих символов; реальный путь строится из сгенерированного
имени в приватном временном каталоге пользователя моста. Claude, Codex и OpenCode получают пути
и исходные имена как JSON-метаданные текстового ввода. Файлы доступны до завершения хода,
включая уточнения и очередь OpenCode, затем удаляются после отключения клиента, также при ошибке
или остановке. Сервер файлы не хранит и не журналирует. В снимке уточнения остаётся только число
вложений; временные пути и base64 туда не попадают.
Если локальная подготовка вложений или запуск клиента завершились до попытки отправить ввод,
`done.not_started: true` возвращает черновик страницы; после попытки запуска генерации эта метка
не ставится, поскольку отказ канала не доказывает, что CLI не принял задание.

Добавка v1 от 2026-10-30 (studio-agent 0.3.0): `hello` может нести `codex` — объект
`{version, models, efforts}`. Пределы версии и моделей как у Claude; усилия Codex — подмножество
`none, minimal, low, medium, high, xhigh, max, ultra`, только объявленные установленным Codex.
Без поля мост поддерживает только Claude Code. Элементы `chats.items` могут нести `engine: codex`
(без поля — `claude`). Просьбы `history`, `turn`, `watch`, `answer`, `stop` могут нести `engine: codex`;
без поля — Claude. Неподдерживаемый помощник — `unsupported`. Формы событий, снимков и ответов прежние;
общий предел одновременных ходов задаётся на машине в окне агента (с 0.9.1 по умолчанию 8,
`Config.max_turns`, целое число > 0; старые мосты ограничены двумя). Изменение применяется без
переподключения и не прерывает идущие задания. Студия хранит помощника в отметке чата (шаг схемы 21),
UUID чатов разных помощников не смешивает. Мост хранит соответствие UUID студии → thread Codex и проект
только локально, поскольку UUID новой сессии Codex задаёт app-server. Каталог и история читаются через
app-server, ходы продолжают сессии Codex; авторизация, sandbox и правила — настройки Codex компьютера.
Документация транспорта: [Codex app-server](https://learn.chatgpt.com/docs/app-server).

```json
{"t": "req", "id": "9f2c4a…", "op": "chats", "session": "3b1e…", "project": "a1b2c3d4e5f60718"}
{"t": "res", "id": "9f2c4a…", "ok": true, "data": {"items": […]}}
{"t": "res", "id": "9f2c4a…", "ok": false, "code": "closed", "message": "компьютер закрыт"}
```

`id` — 16 знаков hex, ответ — с тем же `id`. `session` — признак сессии студии (32 знака hex: sha256 от
`"studio-code\0" + дайджест сессии`), мосту непрозрачен. `message` — слова для человека (до 300 знаков;
сервер длиннее обрезает), может быть пустым. Мост отвечает на каждую просьбу; сервер ждёт ответа 30 с,
затем говорит владельцу «компьютер не ответил».

Общие отказы любой просьбы, кроме `open`: `closed` — сессия не открыта (§3); `invalid` — неверные поля;
`not_found` — нет такого проекта, чата или файла; `error` — сбой моста при исполнении (сервер отвечает 502
`bridge`).

### 2.3 Уведомление о закрытии сессии

`{"t": "close", "session": "3b1e…"}` — без ответа. Мост убирает сессию из открытых (§3).

### 2.4 События хода

```json
{"t": "ev", "project": "a1b2c3d4e5f60718", "chat": "<uuid>", "turn": "t-17", "e": {"k": "text", "text": "При"}}
```

Мост шлёт их сам, пока идёт ход, и в ответ на `watch`. Пока канала нет, события не копятся: вернувшись,
браузер просит `watch` и получает `snapshot`.

## 3. Открытые сессии и PIN (обязанности моста)

- PIN — 4–8 цифр ASCII, на машине хранится хешем scrypt; счёт неверных подряд хранится на диске и
  переживает перезапуск моста; после 5 неверных PIN не принимается, пока его не разблокируют за самой
  машиной (окно моста).
- `open` с верным PIN (или любой `open`, если PIN не задан) добавляет `session` в открытые с отметкой
  времени. Любая другая принятая просьба этой сессии продлевает отметку (кроме фоновой `passive: true`, §16);
  просьба сессии, которой нет в открытых или чья отметка старше `idle_sec` (по умолчанию `OPEN_IDLE_SEC` =
  10 800), — отказ `closed`. Мост с `passive_requests` продлевает только после проверки `op` и полей:
  неизвестная или отклонённая `invalid` просьба срок не продлевает.
- `open` с `pin: null` сессии, что уже открыта и не просрочена, — `{}` и продление: страница зовёт `open` с
  `null` при каждом входе в компьютер.
- Открытые сессии живут только в памяти моста и пропадают при `close`, перезапуске моста и явном изменении
  его настроек/PIN. С моста 0.7.1 новый канал после обрыва, перезапуска студии или обновления каталога моделей
  сохраняет отметки без продления срока. Проверка PIN, начавшаяся на прежнем канале, завершается `closed`.
  Блокировка экрана студии закрывает потоки и кэши сессии, сохраняя срок PIN компьютеров; `auth.guard`
  не пропускает запросы запертой, истёкшей или удалённой сессии к мосту.
- `has_pin` в `hello` — задан ли PIN сейчас.

## 4. Просьбы

Обозначения: `project` — id проекта `pid` (16 hex, §5); `chat` — UUID сессии Claude Code в каноническом
виде (строчные, 8-4-4-4-12); `path` — путь внутри проекта (§6).

| `op` | поля | `data` при успехе | свои отказы |
|---|---|---|---|
| `open` | `pin`: строка или `null` | `{}` | `pin` (`"left": n` — сколько попыток осталось), `pin_locked`, `pin_needed` (PIN задан, а пришёл `null`) |
| `projects` | — | `{"items": [{"pid", "name"}]}` — подпапки корня, по имени | — |
| `chats` | `project` | `{"items": [{"chat", "title", "created", "modified", "tag", "running", "asking"}]}` | — |
| `history` | `project`, `chat`, `before` (int или `null`), `limit` (1–100) | `{"items": [сообщение], "start": int, "total": int}` | — |
| `turn` | `project`, `chat`, `text`, `model` (id или `null`), `effort` (или `null`) | `{"turn": str}` | `running` (в чате уже идёт ход), `busy` (идёт предел ходов машины) |
| `watch` | `project`, `chat` | `{"running": bool}`; если ход идёт — сразу за ответом событие `snapshot` | — |
| `answer` | `project`, `chat`, `request_id`, `decision` (`allow`, `always`, `deny`), `message` (строка или `null` — только при `deny`), `answers` (объект «вопрос → ответ» или `null` — только для вопроса) | `{}` | `gone` (такого запроса уже нет) |
| `stop` | `project`, `chat` | `{}` | `idle` (хода нет) |
| `files` | `project`, `path` | `{"items": [{"name", "dir", "size", "modified"}]}` — папки сначала, затем файлы, по имени | `outside` |
| `read` | `project`, `path` | `{"text", "version"}` | `outside`, `too_large` (больше 2 МиБ), `binary` |
| `raw` | `project`, `path` | `{"data": base64, "size", "version"}` | `outside`, `too_large` (больше 10 МиБ) |
| `visualization` (0.16.0, `hello.visualizations`) | `project`, `source` | `{"text", "version"}` | `outside`, `invalid`, `not_found`, `too_large` (2 МиБ), `binary`, `closed` |
| `save` | `project`, `path`, `text`, `version` | `{"version"}` | `outside`, `conflict` (`"version"` — нынешний), `too_large`, `binary`, `read_only` (файл только для чтения; сервер — 409) |
| `file_operation` (0.8.1, `hello.file_operations`) | `project`, `operation`, `path`, `destination` (путь или `null`) | `{}` | `outside`, `invalid`, `not_found`, `exists` (409), `read_only` (409), `busy` (409) |
| `git` | `project` | `{"branch", "upstream", "ahead", "behind", "files": [{"path", "status"}]}` | `not_git` |

`visualization.source` — UTF-8 `.html` внутри выбранного проекта (относительный либо абсолютный
путь) или абсолютный путь внутри `$CODEX_HOME/visualizations` (умолчание `~/.codex/visualizations`).
Windows `\\` принимается как разделитель только здесь. `..`, ADS и выход из корней запрещены;
каталог визуализаций и вложенные пути не могут быть junction/symlink. Требуется открытая
PIN-сессия, повторная проверка после чтения. Это не расширяет допустимые пути `read/raw/save`.

- `chats`: `title` — `custom_title`, иначе `summary`, иначе начало `first_prompt` (до 120 знаков);
  `created`, `modified` — секунды Unix; `tag` — метка SDK (`studio` у начатых студией) или `null`;
  `running` — идёт ли ход; `asking` — ждёт ли ход ответа на запрос. По `modified` — новые сверху; не
  больше 200 новых.
- `history`: сообщения нормализованы: `{"id", "role": "user"|"assistant", "text", "steps": [шаг], "time"}`,
  шаг — `{"id", "tool", "input", "text", "error"}`; результаты инструментов приложены к шагам ответа, а
  сообщения пользователя, несущие только результаты, не выдаются. `before` — номер сообщения, до которого
  отдать (`null` — до конца), выдаются последние `limit` перед ним; `start` — номер первого выданного.
  Мост может выдать меньше `limit`, чтобы страница не превысила 512 КиБ (снимок `watch` — до 8 МиБ); `start` — номер первого выданного,
  страница листает от него; `time` — секунды Unix или `null`.
- `files`: не больше 5000 записей, иначе первые 5000 и `"truncated": true`.
  Добавка v1 с studio-agent 0.7.5: необязательный `items[].created` — дата создания в секундах Unix или
  `null`, если файловая система её не сообщает. `modified` — секунды Unix, `size` — байты файла (у папки 0,
  без подсчёта её содержимого). Старый мост может не присылать `created`.
- Добавка v1 с studio-agent 0.7.6: `hello.file_stats: true` объявляет op `file_stats {project,path}`
  (`POST …/files/stats`, обычные сессия/CSRF/PIN). Ответ: `items[{path,size,files,folders,complete}]`, `complete`,
  `skipped_links`, `checked_at` (секунды Unix). Пути относительно проекта, корневая строка — запрошенный `path`;
  размеры в байтах, счётчики включают всё вложенное содержимое. Ссылки исключены; недоступные записи,
  20 секунд обхода, 5000 папок или бюджет около 4 МиБ JSON помечают затронутые строки и общий итог `complete:false`.
  Одновременно один подсчёт на мост (`busy`); обычный `files` по-прежнему не запускает рекурсивного обхода.
  Кадры `ev` с `ask`/`done` необязательно несут `project_name` — имя папки проекта (не путь, до 255 знаков).
  Push шифром несёт «компьютер · проект: повод»; старый/некорректный кадр — прежнее «компьютер: повод».
- `watch`: хода нет — `{"running": false}` без проверки чата.
- `turn`: сессии с таким `chat` в папке проекта нет — мост начинает её с `session_id = chat` и после первой
  записи ставит метку `studio` (`tag_session`); есть — продолжает (`resume`). Клиент SDK поднимается на
  каждый ход (`session_id` — у новой сессии, `resume` — у существующей), `model` и `effort` — его опции;
  `null` — выбор, запомненный мостом для чата, иначе модель последнего ответа сессии и усилие по умолчанию.
- `answer`: `allow` — разрешить с исходным вводом; `always` — разрешить и записать предложенные Claude
  Code правила в `localSettings` (`updated_permissions`); `deny` — отказать со словами `message` (пусто —
  «Пользователь отказал»). Ответ на вопрос (`AskUserQuestion`) — `decision: "allow"` и `answers`.
  У Codex/OpenCode ключ — стабильный `questions[].id`; прежний текст вопроса принимается только если он
  уникален в карточке. У Claude ключ остаётся текстом вопроса Agent SDK.
  Варианты OpenCode с `options[].id` объявляют поддержку выбора по идентификаторам в этой карточке:
  `answers[question.id]` — массив ID, в том числе одноэлементный при `multi: false`. Подпись варианта
  служит только для отображения; запятые и одинаковые подписи не меняют выбранные значения.
  Свободный ввод — строка, даже если она совпала с ID варианта; он не распознаётся как ID.
  Массив содержит 1–100 уникальных ID; одиночный выбор — ровно один. Пустые/неизвестные ID отклоняются.
  Старый мост без `options[].id` получает прежнюю строку; новый мост принимает старые строки подписей
  лишь при однозначном сопоставлении (одинаковые подписи или неоднозначная склейка не подменяют выбор).
- `stop`: `interrupt()`; открытые запросы хода получают отказ и событие `asked`; ход кончается `done`
  со `status: "stopped"`.
- `version` файла — sha256 его байтов (hex). `save` пишет, только если `version` совпал с нынешним, байты
  — UTF-8 текста как есть (без смены концов строк).
- Добавка v1 с 0.8.1: `hello.file_operations: true` объявляет `file_operation` через
  `POST /api/code/agents/{aid}/projects/{pid}/files/operate` (успех HTTP 204).
  `operation` — `create_file`, `create_dir`, `move` (включая переименование), `delete`.
  `path` непустой, `destination` непустой только для `move`, в остальных случаях `null`/отсутствует.
  Все пути относительны проекту и передаются только в теле; PIN, владелец и CSRF обязательны как у `save`.
  Создание требует существующего родителя; перенос не перезаписывает назначение, допускает смену регистра.
  Корень, пути через ссылки/reparse-point и перенос папки внутрь себя запрещены.
  `delete` удаляет папку рекурсивно без обхода вложенных junction; интерфейс заранее подтверждает необратимость.
  При ошибке удаления часть записей могла быть удалена: интерфейс обновляет дерево.
  `save` и операции сериализованы на машине. Успех сбрасывает кэш PDF сессии, статистику дерева и обновляет Git.
  Старый мост без capability — HTTP 409 `unsupported`, интерфейс скрывает операции.

## 5. Проект

Проект — подпапка `projects_root` первого уровня. `pid` — первые 16 знаков hex sha256 имени папки (UTF-8,
как его отдаёт ОС). Сервер `pid` не вычисляет и проверяет только вид `^[0-9a-f]{16}$`; имя проекта знает
только мост и ответ `projects`. Скрытые и системные папки — по усмотрению моста.

## 6. Пути (обязанности моста)

`path` — относительный путь через `/`, `""` — корень проекта; без начального `/`, без `\`, без частей `.`
и `..`, до 1024 знаков (сервер отбивает иное сам, 422). Мост сверяет **настоящий** путь (с раскрытыми
символьными ссылками и junction) с настоящим путём проекта: вне него — `outside`, в том числе для записи
списка, ведущей наружу. Текст — файл до 2 МиБ, читающийся как UTF-8 без байтов NUL; иначе `binary`.

## 7. События (`e.k`)

| `k` | поля | смысл |
|---|---|---|
| `text` | `text` | кусок текста ответа |
| `activity` | `state: thinking|tool|responding|waiting`, `tool?` | текущая стадия; в snapshot — `activity` без k |
| `step` | `id`, `tool`, `input` (объект) | вызов инструмента начат |
| `result` | `id`, `text`, `error` (bool) | итог инструмента |
| `step_update` | `id`, `text?`, `output_truncated?`, `process_id?`, `progress_message?` | обновление уже известного шага, без его завершения; `text` заменяет текущий вывод (с моста 0.20.0 — не чаще раза в 250 мс на шаг, последнее состояние; `result` — сразу) |
| `progress` | `changes?`, `plan?`, `agents?` | обновление переданных полей сводки активного хода |
| `ask` | `request_id`, `kind: "permission"`, `tool`, `input`, `always` (bool: есть ли что запомнить) | запрос разрешения |
| `ask` | `request_id`, `kind: "question"`, `questions`: `[{"id"?, "question", "header", "multi", "options": [{"id"?, "label", "description"}]}]` | вопрос агента; ID варианта OpenCode стабилен до закрытия карточки, включая snapshot |
| `asked` | `request_id` | запрос закрыт (ответили, остановили) |
| `snapshot` | `text`, `steps` (как в `history`), `asks` (открытые `ask` без `k`) | всё состояние идущего хода — вместо прежнего |
| `done` | `status`: `done`, `stopped`, `error`; `message` (при `error`) | ход кончился |

Оба вида `ask` (и в `snapshot.asks`) необязательно (мост ≥ 0.17.0) несут `subtask` — имя субагента (строка до 200 знаков),
чей запрос это: Codex — поток, порождённый ходом (`collabAgentToolCall.receiverThreadIds` потока хода или
известного субагента, `thread/started` с `parentThreadId` из них же); OpenCode — дочерняя сессия инструмента
`task` (`metadata.sessionId` с `parentSessionId` сессии хода). Ответ — обычный `answer` с тем же `request_id`:
мост отвечает CLI на исходный запрос субагента. Запросы прочих потоков/сессий мост по-прежнему отклоняет
без карточки. Без поля — запрос самого хода; страница прежней версии поле не показывает. Ход субагентов Codex
виден только статусом в `progress.agents` (`running`, `completed`, `interrupted`, `errored`), их шаги и текст
в ленту хода не попадают. Сервер поле не фильтрует.

С моста 0.15.0 сообщения истории и `snapshot` могут нести `timeline` (до 2000 записей):
`{kind: "text", start, end, block?, phase?}` ссылается на `[start,end)` единственного `text`
в единицах UTF-16; `{kind: "step", id}` — на шаг из `steps`. `block` — id текстового элемента CLI,
`phase` — `commentary|partial_answer|final_answer`, когда известен. `text`-события могут включать
те же `block`/`phase`. Порядок совпадает с событиями; результаты обновляют существующий шаг.
При урезке сообщения позиции удаляются; отсутствие/некорректность `timeline` означает прежний
показ списка шагов и текста. Полный снимок заменяет прежнее состояние, включая сводку.

Необязательные поля шага/`result`: `status: running|completed|failed`, `duration_ms`, `exit_code`,
`process_id`, `output_truncated`, `agents`. Неизвестные длительности/коды отсутствуют.
Ненулевой exit_code означает failed. Потоковый вывод ограничен хвостом 20 000 знаков, с пометкой;
конечный результат CLI остаётся главным. PTY id — информационное поле, без нового управления процессами.

`progress.changes` — `{diff, files: [{path, added, removed}], truncated}`: последний общий diff CLI,
до 120 000 знаков и 200 файлов; счётчики вычислены до обрезки текста. `progress.plan` — до 100
`{step,status: pending|inProgress|completed}`. `progress.agents` — до 50
`{id,title,status,task?}`; переход к истории ребёнка повторяет штатную проверку принадлежности чату.
`snapshot.progress` содержит полную накопленную сводку. Всё живёт в памяти моста/страницы;
завершённая история восстанавливает только данные, сохранённые самим CLI. Новая база и журнал текстов
не создаются. Старый мост работает с прежними событиями; новые сервер и мост обновляются вместе.

`request_id`, `turn` — до 64 знаков `[A-Za-z0-9_-]`. Строки в `input`, `text` шагов и `result` мост
обрезает до 20 000 знаков (пометка `…` в конце): кадр события не должен приближаться к `FRAME_MAX`.
Терминальный статус Codex `completed` даёт `done`, `interrupted` — `stopped`, `failed` и неизвестный
статус — `error`. Очередь запускается только после `completed`; при остановке/ошибке непереданные
сообщения остаются в `done.unsent`. Прерывание закрывает карточки `asked`, как и локальный `stop`.

## 8. Приватность

Сервер пишет в журнал только id компьютера и пользователя, коды и числа — ни ключа, ни PIN, ни имён
проектов и файлов, ни текстов. Мост — так же в свой журнал.

## 9. Лимиты и статистика подписок

Необязательное `hello.subscription_usage: true` объявляет просьбу `usage` с `engine: claude|codex|opencode`
и необязательным `refresh: bool`. Она не требует проекта или чата, но требует открытую PIN-сессию,
как остальные просьбы. HTTP: `GET /api/code/agents/<aid>/usage?engine=codex&refresh=false`;
владелец компьютера и экранная блокировка проверяются обычными защитами сервера.

Ответ: `{engine, available, source, checked_at, cache_ttl: 60, plan, windows, statistics, links, message?}`.
`checked_at` и `windows[].resets_at` — Unix seconds; `windows[]` содержит
`{id, label, available, used_percent, remaining_percent, window_minutes, resets_at, reason?}`.
Периоды `five_hour`, `seven_day`, `monthly` присутствуют всегда. Непереданный провайдером лимит имеет
`available: false` и `null` вместо процентов; неизвестный месячный лимит не вычисляется из недельного.
Дополнительные корзины провайдера идут отдельными строками. Claude `extra_monthly` — дополнительное
использование, оно не заменяет месячный лимит подписки.

`statistics`: `{available, source, summary, daily: [{date: YYYY-MM-DD, tokens}], reason?}`.
Поля summary Codex: `lifetime_tokens`, `peak_daily_tokens`, `longest_running_turn_sec`,
`current_streak_days`, `longest_streak_days` — только переданные сервисом числа.
С моста 0.14.2 необязательное `available_resets` — неотрицательное целое из
`account/rateLimits/read.rateLimitResetCredits.availableCount`. Ноль — отсутствие доступных сбросов;
отсутствующее поле/null — неизвестно. Счётчик не вычисляется по длине `credits`: список может быть
неполным. Он доступен независимо от статистики токенов; интерфейс показывает его только для Codex.
С моста 0.14.3 необязательное `statistics.reset_credits` содержит до 100 `{expires_at: Unix seconds|null}`
из `rateLimitResetCredits.credits` для `resetType: codexRateLimits`, `status: available`,
по возрастанию срока (неизвестные — в конце). Остальные поля credits не передаются.
Отсутствующее поле/null означает, что подробности не получены, `[]` — пустой список доступных подробностей.
Список не заменяет авторитетный `available_resets`; при неполном списке UI указывает число показанных сроков.
Даты показываются в поясе учётки, null — «Не сообщается», без предположения о бессрочности.
Локальный агрегат Claude Code может содержать `total_sessions` и `total_messages`; его источник явно
обозначен как локальная история CLI, а не полная статистика аккаунта.

Codex читает [account RPC app-server](https://learn.chatgpt.com/docs/app-server): `account/read`,
`account/rateLimits/read`, `account/usage/read`. Ни thread, ни ход для этого не создаются; отказ старого CLI
от usage не скрывает доступные лимиты. Общий бюджет чтения 24 секунды, метаданные используют существующий
app-server моста. Claude читает `GET https://api.anthropic.com/api/oauth/usage` с локальными OAuth-данными
CLI (`CLAUDE_CONFIG_DIR`, иначе `~/.claude/.credentials.json`; явный `CLAUDE_CODE_OAUTH_TOKEN` имеет
приоритет). Этот API недокументирован; при истечении входа или отказе сервисов возвращается объяснение.
Мост не обновляет и не переписывает credentials, не следует HTTP redirects и не отправляет токен студии.
Статистика Claude — необязательный локальный `stats-cache.json`. У OpenCode нет общего API подписок:
ответ честно сообщает недоступность и даёт ссылку на провайдеров.

Только нормализованные числа, безопасные подписи и заранее заданные ссылки уходят в студию.
Мост кэширует результат по помощнику 60 секунд в памяти, одновременно пришедшие просьбы объединяются.
`refresh: true` обходит готовый кэш, сохраняя объединение уже идущей проверки. Повторное открытие панели
не создаёт новый CLI-процесс и не вызывает модель.

## 10. Статусы проектов

`hello.project_activity: true` объявляет `activity` без project/chat/engine. Просьба требует
открытую PIN-сессию. HTTP: `GET /api/code/agents/<aid>/activity`, только владелец компьютера.
Ответ `{items: [{project, chat, engine, running: true, asking: bool}]}` включает все текущие ходы
Claude, Codex и OpenCode, запущенные этим мостом; названий, текстов и истории в нём нет.
Пустой список означает отсутствие текущих ходов моста, не отсутствие активности внешнего CLI.
Студия показывает отдельно работающие ходы и ожидающие ответ. Открытый чат обновляет свои метки
по событиям, все проекты выбранного компьютера сверяются каждые 20 секунд, пока страница видна
и с последнего действия прошло не больше 30 минут. Опрос не запускает CLI и не расходует квоту.

### 10.1. Сводка файлов проекта и Git (studio-agent 0.7.3)

`hello.project_summary: true` объявляет просьбу `project_summary {project}`. Требуется открытая PIN-сессия;
HTTP — `GET /api/code/agents/<aid>/projects/<pid>/summary`, только владелец. Старому мосту — 409 `unsupported`.
Ответ: `{findings, ideas, changed, unpushed, modified, checked_at, git}`. Счётчики — целые неотрицательные
или `null` (нет достоверных сведений); даты — Unix seconds. `git` — `ok|not_git|error`.
`findings`/`ideas` — записи уровня `##` в корневых `FINDINGS.md`/`IDEAS.md` со статусом `open`/`proposed`,
без HTML-комментариев и блоков кода; отсутствующий файл — 0, недоступный/не UTF-8/больше 2 МиБ — `null`.
`changed` — все изменённые и новые файлы из porcelain v2, без лимита списка файлов обычного `git`.
`unpushed` — ahead от upstream, при его отсутствии число `HEAD --not --remotes`; пустой репозиторий — 0.
Сравнение только с локальными refs, без fetch. `modified` — максимум даты последнего коммита и mtime
изменённых файлов (при удалении — родительской папки), без Git — mtime папки проекта.
Содержимое журналов и имена файлов в ответ не входят. Команды Git ограничены пятью секундами каждая.
Страница читает до четырёх проектов одновременно при показе списка и по кнопке. Сортировка, кнопка
и дата полного обновления закреплены вне прокрутки; ошибка сохраняет прежние значения с отметкой.
Сводка живёт только в памяти панели и не записывается на сервере или в хранилище браузера.

С 0.9.2 необязательное поле `github`: `null` (нет публичной копии) либо
`{state: current|behind|ahead|diverged|missing|unknown, behind: int|null, ahead: int|null}`.
Счётчики показывают отставание/опережение GitHub относительно текущей локальной ветки и HEAD.
`missing` — текущая ветка не опубликована; `unknown` — сеть/неизвестный объект/shallow/detached HEAD;
для обоих счётчики `null`. Прежние мосты поле не присылают, индикатор скрыт.
Мост читает remote `github` либо GitHub `origin`, проверяет публичность анонимным smart-HTTP discovery
на `https://github.com/<owner>/<repo>.git/info/refs?service=git-upload-pack` (5 с, до 2 МиБ),
без ключей, cookie, Git credentials, fetch и обновления refs. HTTP 401/404 скрывают репозиторий;
остальные ошибки — `unknown`. Редиректы только внутри HTTPS github.com. Разница считается локально,
команды Git ограничены 3 с. В ответе нет URL, веток, hash, содержимого и путей.

С 0.10.1 необязательное поле `remotes`: список `{name: string, state, behind, ahead}` настроенных
Git remote. Состояния и смысл счётчиков — как у `github`, но источник только локальный:
сравнение `refs/remotes/<name>/<branch>` с текущим HEAD, без сети, credentials, fetch и изменения refs.
Состояние сервера после последнего fetch/push может отличаться. Неизвестная/не загруженная ветка,
shallow/detached/пустая история и ошибки дают `unknown`, сохраняя имя; отсутствие локального ref
не означает `missing` на сервере. Общий бюджет 5 с, команда до 3 с. API пропускает до 64 уникальных
имён по 1–128 знаков без управляющих и только проверенные счётчики/состояние, остальные поля удаляет.
Прежние мосты поле не присылают. Страница показывает дополнительные remote рядом с Git/GitHub,
не дублирует основной `origin` и живой `github`; подсказка явно сообщает о локальном источнике.

## 11. Инструменты рабочего места (studio-agent 0.8.0)

Возможности `hello.file_suggestions`, `chat_search`, `queue_edit`, `chat_fork`, `subagents`, `worktrees` —
необязательные boolean. HTTP всегда проверяет владельца, открытую сессию и соответствующую возможность;
старому мосту — 409 `unsupported`. Версия протокола остаётся 1. Тексты, имена и результаты не записываются
в серверную БД, журналы или browser storage. Новые файлы не требуют зависимостей в серверной среде.

| Просьба мосту | HTTP относительно `/api/code/agents/<aid>/projects/<pid>` | Ответ |
|---|---|---|
| `file_suggestions {project, query}` | `POST /files/suggest {query}` | `{items: [relativePath], complete, more}` |
| `chat_search {project, query}` | `POST /search {query}` | `{items: [{chat, engine, title, snippets: [{text, role}]}], complete}` |
| `queue_edit {project, chat, request_id, version, text}` | `POST /chats/<chat>/queue` с теми же полями без project/chat | `{items, paused}` |
| `queue_pause {project, chat, paused}` | `POST /chats/<chat>/queue/pause {paused}` | `{items, paused}` |
| `chat_fork {project, chat, message_id?}` | `POST /chats/<chat>/fork {message_id?}` | `{chat: newChat, engine, draft}` |
| `subagents {project, chat}` | `GET /chats/<chat>/subagents` | `{items: [{id, title, status}]}` |
| `subagent_history {project, chat, request_id}` | `POST /chats/<chat>/subagent {request_id}` | `{items: messages, complete}` |
| `worktrees {project}` | `GET /worktrees` | `{items: [{pid, name, branch, current}]}` |
| `worktree_create {project, query}` | `POST /worktrees {name}` | `{pid, name, branch}` |

**Подсказки и поиск.** `query` — до 200 знаков без управляющих, всегда в теле запроса. Подсказки читают
имена, исключают служебные каталоги, известные файлы секретов, symlink/reparse points; пределы 3 секунды,
1000 каталогов, 5000 файлов и 50 результатов. `complete=false` означает неполный обход, `more=true` —
нужен более узкий запрос. До восьми индексов имён кэшируются в памяти моста на 30 секунд;
одновременные запросы используют один обход. Поиск использует существующие адаптеры истории, без постоянного индекса:
до 60 последних чатов, 1500 сообщений, трёх фрагментов на чат и общего бюджета около 15 секунд.
Ошибка одного доступного помощника не скрывает результаты остальных, но делает результат неполным.
Один поиск одновременно на мост; второй — `busy`.

**Правки.** Шаг истории и событие `result` могут содержать `changes: [{path, before?, after?, patch?, truncated?}]`.
`before/after` — предоставленные CLI фрагменты или текст, `patch` — готовый Codex diff. Только `after`
означает новое содержимое с неизвестным старым; на диске старый файл не читается. Вывод ограничен восемью
файлами и 12000 знаками каждого поля до общей урезки событий; UI показывает до 240 строк и пометку части.
Неизвестные инструменты и ошибки продолжают отображаться обычным текстом.

**Очередь.** `steer` дополнительно принимает `mode: steer|queue` (прежнее поведение — `steer`).
`queue` хранится в памяти моста и доставляется после результата текущей работы. OpenCode по-прежнему
отправляет уточнения последовательно. До 20 уточнений на ход; изображения ограничены общим бюджетом очереди.
Редактирование/пауза требуют владельца хода (`window`); чужому окну — `owned`. `text:null` удаляет ожидающее
сообщение, строка меняет только его текст, сохраняя вложения. `version` — целое от 1, после правки возрастает;
несовпадение — `conflict`, уже переданное сообщение — `gone`.
Редактор сначала вызывает `queue_pause {paused:true}`. Текущий прогон доходит до результата,
доставка ждёт вне `input_lock`; сохранение/отмена вызывают `paused:false`. Пока пауза действует, новые
уточнения не принимаются. Stop/close будят ожидание; удаление последнего сообщения не удерживает пустой ход.

Новые события: `queue {items, paused}`, `followup_removed {id}`. Элементы очереди несут прежние поля
followup плюс `version` и `input_text` без служебных пометок вложений. `followup_sent` снимает элемент
с редактирования. Снимок содержит `queue` и необязательный `queue_paused:true`. Пауза переживает закрытие
страницы, но не рестарт моста; несохранённые правки редактора принадлежат конкретной странице.

**Ветки.** Claude использует SDK `fork_session`, Codex — штатный `thread/fork` из
[app-server API](https://learn.chatgpt.com/docs/app-server). `message_id` обозначает пользовательское
сообщение; в новый чат копируется история строго до него, его текст возвращается как `draft` только в память
браузера. Без точки копируется вся переписка. Для Codex передаётся предыдущий `lastTurnId` и проверяется
количество реально скопированных ходов: старый CLI, проигнорировавший отсечение, получает `unsupported`.
Уточнение внутри того же хода не является точкой ветвления Codex: история помечает его `forkable:false`,
а прямая просьба получает `unsupported` вместо молчаливой потери предшествующей части хода.
Подписка на созданного потомка снимается в finally. Первое сообщение создаёт пустой чат с новым UUID.
Исходный работающий чат — `running`; его writer и файлы не меняются. Сохранённые модель/усилие/права
наследуются на компьютере; сервер хранит только новую собственную строку `code_chats`, как у обычного создания.
Вложения выбранного сообщения автоматически в поле не переносятся. OpenCode ACP — `unsupported`.

**Подзадачи и рабочие копии.** Историю дочернего агента можно читать только после подтверждения его связи
с родителем через SDK Claude или collab-вызовы Codex; произвольный ID не открывается. Данные ограничены
50 дочерними сессиями и обычным бюджетом истории; неизвестный статус — `unknown`. Управления чужим прогоном
и нового координатора агентов нет. OpenCode ACP эту поверхность не предоставляет.
Рабочая копия создаётся только из HEAD в новой ветке `studio/<name>-<random>` и папке первого уровня
настроенного корня проектов, с проверкой отсутствия папки. `name` — 1–31 строчная латинская буква/цифра/дефис,
первый символ — буква или цифра. В списке только разрешённые проекты корня; наружные worktree не показываются.
История, dirty-правки, секреты и зависимости не переносятся; stash, merge, force и удаление не выполняются.

## 12. Настраиваемый таймер PIN и несколько папок (агент 0.9.0)

Необязательный `hello.pin_timeout: true` объявляет поддержку `req.idle_sec` — целого числа
60–604800 секунд. Поле передаётся сервером с каждым запросом, включая `open`, из отдельной настройки
учётки `computer_pin_timeout`. Без поля действует прежний `OPEN_IDLE_SEC = 10800`.
Неверный тип или диапазон — `invalid` до проверки PIN и исполнения. Истёкшая сессия — `closed`,
а `open` без PIN после истечения — `pin_needed`; запросы после истечения доступ не восстанавливают.
Старому мосту сервер не посылает поле: нестандартная настройка требует обновления (`unsupported`).

Несколько папок настраиваются только на машине, в `config.projects_roots`. `projects_root` в `hello`
остаётся первой папкой для совместимости. `projects` объединяет разрешённые подпапки всех корней;
`project` по-прежнему 16 hex. Прежняя папка хранится как `projects_legacy_root`: её id не меняются,
у дополнительных папок id зависит от настоящего корня и имени. Удаление первой папки не меняет id
оставшихся проектов. Одинаковые имена различаются подписью родителя и суффиксом id, полный путь не
добавляется к строке проекта. Рабочие копии создаются внутри корня своего исходного проекта.

## 13. Сведения компьютера (агент 0.11.0)

Необязательный `hello.computer_info: true` объявляет op `computer_info` без дополнительных полей.
Как и другие чтения, требует открытой PIN-сессии. HTTP — `GET /api/code/agents/<aid>/info`;
чужой компьютер — 404, старый мост — 409 `unsupported`, закрытый — 409 `closed`, offline — 409 `offline`.
Ответ с `Cache-Control: no-store`:

```json
{"hostname":"WORKSTATION","username":"worker","os":"Windows 11 Pro 10.0.26100",
 "external_ip":"8.8.8.8","internal_ips":["10.77.1.8"],
 "memory":{"total":17179869184,"used":12884901888,"available":4294967296},
 "disks":[{"path":"C:\\","total":536870912000,"free":107374182400}],
 "projects_roots":["C:\\work\\projects","D:\\projects"],"checked_at":1800000000}
```

Память и диски — байты, время — Unix seconds. Недоступные значения — null; списки — пустые,
свободные 0 байт остаются нулём. Диски — локальные и съёмные, без сетевых шар; IP — активные
адреса интерфейсов без loopback, link-local и multicast. Внешний IP — публичный адрес выхода
машины к фиксированному `https://api64.ipify.org` (IPv4 или IPv6), включая её VPN/прокси; timeout/не-IP/непубличный
адрес — null. Запрос не передаёт имя, пользователя, пути или секреты. CIM имеет предел 10 с,
HTTPS — 3 с, redirect не допускается. Чтение в потоке, без сохранения или журналирования снимка.
Сервер разрешает только объявленные поля, валидирует числа/IP и не сохраняет их в базе.
Карточка открывается по явному нажатию на компьютер; при необходимости продолжает после PIN,
обновляется вручную и очищается при закрытии/уходе со страницы.
При недоступности внешнего сервиса сервер может подставить публичный адрес действующего
соединения моста (`link.ip`); локальный адрес соединения внешним не считается.

## 14. Рабочий стол (studio-agent 0.12.0)

`hello.desktop: true` — поддержка операций, а не разрешение на управление. Локальный
`Config.desktop_enabled` по умолчанию false, сохраняется при перезапуске и обновлениях;
меняет его только человек в окне агента. У протокола нет операции изменения разрешения.
Лишние поля desktop-просьбы отвергаются, в частности `enabled`. Все операции требуют открытой
PIN-сессии и обычного `session`, без project/chat/engine/window. В Студии — только свой компьютер,
сессия и CSRF. Старый мост — `unsupported`, выключенный — `desktop_disabled`, закрытая PIN-сессия — `closed`.

HTTP-префикс `/api/code/agents/<aid>/desktop`; в ответах только `Cache-Control: no-store`.

| HTTP | op | Поля | Ответ |
| --- | --- | --- | --- |
| GET префикса | `desktop_status` | — | `{enabled:bool,active:bool,resolutions?:[int]}` |
| POST `/start` | `desktop_start` | `{}` | `{control:32hex,monitors:[{id,width,height,primary}],monitor}` |
| POST `/frame` | `desktop_frame` | `{control,monitor,max_edge?:int}` | `{image:base64JPEG,width,height,screen_width,screen_height,monitor}` |
| POST `/input` | `desktop_input` | `{control,events}` | `{}` / HTTP 204 |
| POST `/clipboard` | `desktop_clipboard` | `{control,text:string|null}` | `{text:string}` |
| POST `/stop` | `desktop_stop` | `{control}` | `{}` / HTTP 204 |

Токен случайный, один активный на компьютер, привязан к `session`; второе подключение — `busy`,
чужой/старый токен — `owned`/`gone`. Мониторы нумеруются агентом; абсолютные координаты не передаются.
С 0.13.1 `resolutions` объявляет варианты длинной стороны 640, 800, 1024, 1280, 1600, 1920, 2560 px.
`max_edge` — целое 640–2560, по умолчанию 1600; физическое разрешение монитора не меняется.
Без `resolutions` сервер сообщает браузеру только 1600; при 1600 поле `max_edge` мосту не отправляется,
чтобы прежние версии принимали запрос. Кадр — ≤`max_edge` по длинной стороне и ≤700 КиБ строки base64;
при превышении объёма JPEG разрешение дополнительно уменьшается. Клиент запрашивает следующий после
окончания предыдущего, с паузой 250 мс; данные не попадают в историю, БД, журналы и browser storage.
Буфер только по кнопкам: null читает, строка пишет (пустая очищает), ≤65 536 UTF-16 единиц.

`events` — 1–32 объектов с точным набором полей:

- `{type:"move",monitor:int,x:number,y:number}`: x/y в [0,1] внутри показанного монитора;
- `{type:"button",button:"left"|"right"|"middle",down:bool}`;
- `{type:"wheel",dx:int,dy:int}`: [−1200,1200], положительный dy — вниз;
- `{type:"key",code:DOM_KeyboardEvent_code,down:bool}`: конечный список Win32-клавиш агента;
- `{type:"text",text:string}`: 1–4096 UTF-16 единиц, Unicode через SendInput.

Нативные действия последовательны в одном потоке с ограниченной очередью; потерявший актуальность
кадр отбрасывается после захвата. Локальное выключение, close, обрыв канала, перезапуск и 10 с
без запросов отзывают токен и отпускают наши клавиши/кнопки. Блокировка Студии шлёт только мосту
с capability `desktop` кадр `{"t":"desktop_close","session":"32hex"}`: отзывает рабочий стол,
не сбрасывает срок PIN. Закрытие/фон/pagehide пульта завершает управление; задания помощников продолжаются.
Автообновление ждёт закрытия пульта. Отзыв управления не меняет сохранённый локальный выключатель.

Только WTSActive и рабочий стол Default. Экран входа/защищённый desktop — `desktop_unavailable`,
повышенные окна могут отклонять ввод. Собственные окна агента удалённый ввод не принимают.
Проверки: два `test_desktop.py`, `test_desktop_native.py` и `test_ui_desktop.py`.

## 15. Снимки метаданных (0.13.0, необязательно)

`hello.metadata_cache: true` объявляет общие снимки в памяти компьютера. `projects`, `chats` и
`project_summary` принимают необязательный `refresh: bool` (по умолчанию false). PIN проверяется
до чтения любого снимка; идентификатор проекта заново проверяется на принадлежность разрешённому
корню и отсутствие reparse points. Операции и done инвалидируют относящиеся к проекту значения.

`chats` собирает каталоги параллельно с отдельным бюджетом 8 с. Ответ содержит `items` и
`complete: bool`; false сохраняет доступные движки и обозначает неполноту, а не отсутствие сессии.
Флаги running/asking всегда берутся из текущих Runner, не из кэша. TTL каталога и локальной сводки
20 с; для каталога папок — до 5 с с проверкой изменения корней.

`project_summary` возвращает локальный Git и журналы до сетевой проверки GitHub. Дополнения:
`github_pending: bool`, `github_checked_at: number | null`. При `remote: true` запрос дожидается
GitHub; его результат хранится 300 с независимо от локальной даты checked_at. Принудительное
обновление и ожидающие его читатели используют один новый запрос. Внутренние данные репозитория
и пути не передаются в ответе. История ограничена 512 КиБ на страницу; старые мосты продолжают
работать с прежними необязательными полями.

HTTP-сервер поддерживает `?refresh=true`, для списка сессий также заголовок
`x-studio-refresh: true` (явное «+», Git и повторные проверки). `GET /api/code/agents/<aid>/access`
сначала проверяет владельца и открытую PIN-сессию через короткий activity/projects и отвечает 204;
браузер использует его перед показом кэшированного текста. Списки, истории и снимки не сохраняются
в постоянном хранилище браузера или в файлах сервера Studio.

## 16. Фоновые просьбы (необязательно, мост ≥ 0.17.0)

`hello.passive_requests: true` объявляет необязательное поле просьбы `passive: bool` (по умолчанию false).
Фоновая просьба — опрос по таймеру или чтение после события, а не действие владельца: значок «Агентов»
(`GET /api/code/activity` — всегда), метки вкладок и Git открытого проекта, повтор `watch` по таймеру,
сводка проекта, Git и лимиты после `done`. Мост проверяет открытость и срок `idle_sec` как обычно
(истёкшая — `closed`, `open` с `pin: null` — `{}` или `pin_needed`), но отметку не продлевает. Поле не того
вида — `invalid` до исполнения. Срок PIN компьютера отсчитывается от последней принятой просьбы владельца.

Страница помечает такие запросы HTTP-заголовком `X-Studio-Passive: 1`; сервер передаёт `passive: true`
только мосту с объявленной возможностью — старый мост поля не получает и продлевает срок, как прежде.
Заголовок может лишь отказаться от продления, поэтому сервер ему доверяет без дополнительной проверки.
Компьютер не на связи (`LINKS` без канала) — `offline` до проверки поддержки таймера: страница ждёт
возвращения моста, а не просит его обновить.

## 17. Совместный проект (studio-agent 0.19.0)

`hello.project_sharing: true` объявляет доверенное поле просьбы `shared_projects`: непустой список
до 1000 id проектов (16 hex). Его задаёт только сервер по разрешениям владельца компьютера из
`project_members`; из HTTP-тела или заголовков пользователя поле не принимается. Сервер проверяет
разрешение до отправки и после ответа, включая активность учётки владельца. Без capability
совместная просьба получает HTTP 409 `unsupported`, а просьбы владельца не меняются.

При наличии поля мост не требует открытой PIN-сессии и не открывает/продлевает её. Допустимы только
операции из явного списка `agent.SHARED_OPS`: `projects`, `activity`, `project_summary`, `chats`,
`history`, `history_image`, `state`, `turn`, `steer`, `queue_edit`, `queue_pause`, `claim`, `watch`,
`answer`, `stop`, `files`, `file_stats`, `file_operation`, `file_suggestions`, `chat_search`,
`chat_fork`, `subagents`, `subagent_history`, `read`, `raw`, `visualization`, `save`, `git`.
У операций, кроме `projects`/`activity`, `project` обязательно входит в выданный список.
`projects` и `activity` возвращают только его элементы. Некорректный список — `invalid`, операция
или проект вне разрешения — `closed`. Сведения о компьютере, его PIN, рабочий стол, обновление,
подписка и worktree участнику недоступны даже с открытой PIN-сессией.

`visualization` участника читает только файлы проекта: общий каталог визуализаций Codex
(`$CODEX_HOME/visualizations`) хранит HTML тредов всех проектов владельца. Мост 0.20.0 объявляет это
`hello.visualization_scope: true`; мосту без него сервер передаёт от участника только относительный `source`
(абсолютный, начиная с буквы диска, `/` или `\` — HTTP 409 `unsupported`). Владелец читает оба корня, как прежде.

Все просьбы несут собственный `session` участника; SSE, очереди и управление ходом сохраняют
обычный протокол. Сервер закрывает поток при отзыве до следующего события; выполняемое задание
при этом продолжает работу. Граница проекта защищает API, но не ограничивает права CLI в ОС:
участник — доверенный соавтор с возможностью запуска кода от владельца компьютера.

## 18. Досланные завершения ходов (studio-agent 0.20.0)

Ход, кончившийся без канала (выкладка с 1012 и паузой переподключения, обрыв сети), раньше не давал ни
отметки «непрочитано», ни push: их ставит только живой `done`. Мост держит в памяти не больше
`limits.COMPLETIONS_MAX` (50) таких концов — по одному на чат, последний итог; кадры `done`, не отправленные
писателем умершего канала, тоже возвращаются туда. Кадр, уже переданный сокету, может пропасть.

`hello.completions: true` — мост досылает; `welcome.completions: true` — студия принимает. Только при обоих
мост сразу после `welcome`, первым кадром канала, шлёт

    {"t": "completions", "items": [{"project": "<16 hex>", "chat": "<uuid>", "status": "done|stopped|error",
                                    "project_name": "<имя папки, необязательно>", "ago": <целое ≥ 0, с>}]}

и забывает их; кадр, не ушедший до обрыва, возвращается к следующему каналу. `ago` — давность конца хода по
монотонным часам моста. Прежней студии мост кадр не шлёт и ждёт новой. Студия ставит отметку
`code_attention` (время конца — сейчас минус `ago`, не старше `bridge.COMPLETION_AGE_MAX`) и шлёт push, если
чат никто не смотрит, — как для живого `done`; строки — только этого компьютера. Кадр без capability — 4400;
неверный (больше `bridge.COMPLETIONS_MAX` записей, поле не того вида) — пропускается с записью в журнал.
