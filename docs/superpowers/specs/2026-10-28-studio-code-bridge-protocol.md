# Студия ↔ мост Claude Code: протокол канала, версия 1

Дата: 2026-10-28. Контракт между сервером студии (план
[2026-10-28-studio-claude-code-server](../plans/2026-10-28-studio-claude-code-server.md)) и мостом
`studio-agent` (второй план). Основа — спека
[2026-10-28-studio-claude-code-design](2026-10-28-studio-claude-code-design.md). Меняется только новой
версией (`v` в `hello`); сервер версии 1 отвечает мосту другой версии закрытием 4400.

## 1. Привязка

`POST https://studio.example.com/api/agent/enroll`, тело JSON `{"login", "password", "name"}` (не больше 4096
байт; `name` — 1–64 знака без управляющих). Ответ 201 `{"agent_id": int, "device_key": str}` — ключ
выдаётся один раз, сервер хранит только его sha256. Отказы — JSON `{"detail": {"code", "message"}}`:
401 `login` (неверный логин или пароль), 429 `locked` (пауза входа — та же, что у `/login`), 413
`too_long`, 422 `name`, 403 `origin` (запрос с заголовком `Origin` чужого сайта; мост `Origin` не шлёт).
Мост хранит ключ зашифрованным DPAPI; пароль не хранит.

## 2. Канал

`wss://studio.example.com/api/agent/link`, заголовок `Authorization: Bearer <device_key>`. Кадры — текстовые
сообщения WebSocket, в каждом один объект JSON (UTF-8), не больше `FRAME_MAX` = 16 МиБ. Поле `t` — тип
кадра. Пинги — штатные WebSocket (сервер шлёт каждые 20 с); кадров «ping» в протоколе нет.

Закрытие сервером:

| код | когда | мост |
|---|---|---|
| 4401 | ключ неизвестен, компьютер отозван, учётка отключена или удалена | не переподключается; показывает «компьютер отозван» |
| 4409 | тот же компьютер подключился заново (новый канал заменил этот) | не переподключается; «ключ используется другим мостом» |
| 4400 | нарушение протокола: нет `hello` за 10 с, неверный `hello`, неизвестный `t`, кадр больше `FRAME_MAX` | переподключается через паузу |
| 1012, 1001, обрыв сети | перезапуск студии, сбой | переподключается: 1, 2, 4 … 60 с |

### 2.1 Знакомство

Первый кадр моста — `hello`:

```json
{"t": "hello", "v": 1, "cc_version": "2.3.1", "projects_root": "C:\\work\\projects", "has_pin": true,
 "models": [{"id": "claude-opus-5-5", "label": "Opus 5.5"}], "efforts": ["low", "medium", "high"]}
```

`cc_version` — до 64 знаков; `projects_root` — до 1024 (только для показа владельцу); `models` — до 50,
`id` по `^[A-Za-z0-9._:\[\]-]{1,100}$`, `label` до 100 знаков; `efforts` — подмножество
`low, medium, high, xhigh, max`. Ответ сервера — `{"t": "welcome", "agent_id": 7, "name": "Рабочий ПК"}`.

### 2.2 Просьбы студии и ответы моста

```json
{"t": "req", "id": "9f2c4a…", "op": "chats", "session": "3b1e…", "project": "a1b2c3d4e5f60718"}
{"t": "res", "id": "9f2c4a…", "ok": true, "data": {"items": […]}}
{"t": "res", "id": "9f2c4a…", "ok": false, "code": "closed", "message": "компьютер закрыт"}
```

`id` — 16 знаков hex, ответ — с тем же `id`. `session` — признак сессии студии (32 знака hex: sha256 от
`"studio-code\0" + дайджест сессии`), мосту непрозрачен. `message` — слова для человека (до 300 знаков;
сервер длиннее обрезает), может быть пустым. Мост отвечает на каждую просьбу; сервер ждёт ответа 30 с,
затем говорит владельцу «компьютер не ответил».

Общие отказы любой просьбы, кроме `open`: `closed` — сессия не открыта (§3); `invalid` — неверные поля;
`not_found` — нет такого проекта, чата или файла.

### 2.3 Уведомление о закрытии сессии

`{"t": "close", "session": "3b1e…"}` — без ответа. Мост убирает сессию из открытых (§3).

### 2.4 События хода

```json
{"t": "ev", "project": "a1b2c3d4e5f60718", "chat": "<uuid>", "turn": "t-17", "e": {"k": "text", "text": "При"}}
```

Мост шлёт их сам, пока идёт ход, и в ответ на `watch`. Пока канала нет, события не копятся: вернувшись,
браузер просит `watch` и получает `snapshot`.

## 3. Открытые сессии и PIN (обязанности моста)

- PIN — 4–8 цифр ASCII, на машине хранится хешем scrypt; счёт неверных подряд хранится на диске и
  переживает перезапуск моста; после 5 неверных PIN не принимается, пока его не разблокируют за самой
  машиной (окно моста).
- `open` с верным PIN (или любой `open`, если PIN не задан) добавляет `session` в открытые с отметкой
  времени. Любая другая просьба этой сессии продлевает отметку; просьба сессии, которой нет в открытых
  или чья отметка старше 30 минут (`OPEN_IDLE_SEC` = 1800), — отказ `closed`.
- Открытые сессии живут только в памяти моста и пропадают: при `close`, при перезапуске моста и при
  **любом** новом канале (после обрыва и после перезапуска студии — вводить PIN снова).
- `has_pin` в `hello` — задан ли PIN сейчас.

## 4. Просьбы

Обозначения: `project` — id проекта `pid` (16 hex, §5); `chat` — UUID сессии Claude Code в каноническом
виде (строчные, 8-4-4-4-12); `path` — путь внутри проекта (§6).

| `op` | поля | `data` при успехе | свои отказы |
|---|---|---|---|
| `open` | `pin`: строка или `null` | `{}` | `pin` (`"left": n` — сколько попыток осталось), `pin_locked`, `pin_needed` (PIN задан, а пришёл `null`) |
| `projects` | — | `{"items": [{"pid", "name"}]}` — подпапки корня, по имени | — |
| `chats` | `project` | `{"items": [{"chat", "title", "created", "modified", "tag", "running", "asking"}]}` | — |
| `history` | `project`, `chat`, `before` (int или `null`), `limit` (1–100) | `{"items": [сообщение], "start": int, "total": int}` | — |
| `turn` | `project`, `chat`, `text`, `model` (id или `null`), `effort` (или `null`) | `{"turn": str}` | `running` (в чате уже идёт ход), `busy` (идёт предел ходов машины) |
| `watch` | `project`, `chat` | `{"running": bool}`; если ход идёт — сразу за ответом событие `snapshot` | — |
| `answer` | `project`, `chat`, `request_id`, `decision` (`allow`, `always`, `deny`), `message` (строка или `null` — только при `deny`), `answers` (объект «вопрос → ответ» или `null` — только для вопроса) | `{}` | `gone` (такого запроса уже нет) |
| `stop` | `project`, `chat` | `{}` | `idle` (хода нет) |
| `files` | `project`, `path` | `{"items": [{"name", "dir", "size", "modified"}]}` — папки сначала, затем файлы, по имени | `outside` |
| `read` | `project`, `path` | `{"text", "version"}` | `outside`, `too_large` (больше 2 МиБ), `binary` |
| `raw` | `project`, `path` | `{"data": base64, "size", "version"}` | `outside`, `too_large` (больше 10 МиБ) |
| `save` | `project`, `path`, `text`, `version` | `{"version"}` | `outside`, `conflict` (`"version"` — нынешний), `too_large`, `binary` |
| `git` | `project` | `{"branch", "upstream", "ahead", "behind", "files": [{"path", "status"}]}` | `not_git` |

- `chats`: `title` — `custom_title`, иначе `summary`, иначе начало `first_prompt` (до 120 знаков);
  `created`, `modified` — секунды Unix; `tag` — метка SDK (`studio` у начатых студией) или `null`;
  `running` — идёт ли ход; `asking` — ждёт ли ход ответа на запрос. По `modified` — новые сверху.
- `history`: сообщения нормализованы: `{"id", "role": "user"|"assistant", "text", "steps": [шаг], "time"}`,
  шаг — `{"id", "tool", "input", "text", "error"}`; результаты инструментов приложены к шагам ответа, а
  сообщения пользователя, несущие только результаты, не выдаются. `before` — номер сообщения, до которого
  отдать (`null` — до конца), выдаются последние `limit` перед ним; `start` — номер первого выданного.
- `turn`: сессии с таким `chat` в папке проекта нет — мост начинает её с `session_id = chat` и после первой
  записи ставит метку `studio` (`tag_session`); есть — продолжает (`resume`). `model` — `set_model`;
  `effort` сменился — клиент SDK поднимается заново с `resume`. `null` — прежние модель и усилие чата.
- `answer`: `allow` — разрешить с исходным вводом; `always` — разрешить и записать предложенные Claude
  Code правила в `localSettings` (`updated_permissions`); `deny` — отказать со словами `message` (пусто —
  «Пользователь отказал»). Ответ на вопрос (`AskUserQuestion`) — `decision: "allow"` и `answers`.
- `stop`: `interrupt()`; открытые запросы хода получают отказ и событие `asked`; ход кончается `done`
  со `status: "stopped"`.
- `version` файла — sha256 его байтов (hex). `save` пишет, только если `version` совпал с нынешним, байты
  — UTF-8 текста как есть (без смены концов строк).

## 5. Проект

Проект — подпапка `projects_root` первого уровня. `pid` — первые 16 знаков hex sha256 имени папки (UTF-8,
как его отдаёт ОС). Сервер `pid` не вычисляет и проверяет только вид `^[0-9a-f]{16}$`; имя проекта знает
только мост и ответ `projects`. Скрытые и системные папки — по усмотрению моста.

## 6. Пути (обязанности моста)

`path` — относительный путь через `/`, `""` — корень проекта; без начального `/`, без `\`, без частей `.`
и `..`, до 1024 знаков (сервер отбивает иное сам, 422). Мост сверяет **настоящий** путь (с раскрытыми
символьными ссылками и junction) с настоящим путём проекта: вне него — `outside`, в том числе для записи
списка, ведущей наружу. Текст — файл до 2 МиБ, читающийся как UTF-8 без байтов NUL; иначе `binary`.

## 7. События (`e.k`)

| `k` | поля | смысл |
|---|---|---|
| `text` | `text` | кусок текста ответа |
| `step` | `id`, `tool`, `input` (объект) | вызов инструмента начат |
| `result` | `id`, `text`, `error` (bool) | итог инструмента |
| `ask` | `request_id`, `kind: "permission"`, `tool`, `input`, `always` (bool: есть ли что запомнить) | запрос разрешения |
| `ask` | `request_id`, `kind: "question"`, `questions`: `[{"question", "header", "multi", "options": [{"label", "description"}]}]` | вопрос агента |
| `asked` | `request_id` | запрос закрыт (ответили, остановили) |
| `snapshot` | `text`, `steps` (как в `history`), `asks` (открытые `ask` без `k`) | всё состояние идущего хода — вместо прежнего |
| `done` | `status`: `done`, `stopped`, `error`; `message` (при `error`) | ход кончился |

`request_id`, `turn` — до 64 знаков `[A-Za-z0-9_-]`. Строки в `input`, `text` шагов и `result` мост
обрезает до 20 000 знаков (пометка `…` в конце): кадр события не должен приближаться к `FRAME_MAX`.

## 8. Приватность

Сервер пишет в журнал только id компьютера и пользователя, коды и числа — ни ключа, ни PIN, ни имён
проектов и файлов, ни текстов. Мост — так же в свой журнал.
