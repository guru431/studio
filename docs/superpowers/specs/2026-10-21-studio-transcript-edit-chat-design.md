# Студия: правка расшифровки и расшифровка в чат — дизайн

Дата: 2026-10-21. Статус: по IDEAS.md 2026-10-21 («Правка расшифровки, имена собеседников и переход
к месту записи», «Передать расшифровку в чат без ручного копирования»); владелец поручил разобрать
IDEAS.md целиком, решения ниже — проектировщика (раздел 10). Проект: `studio` (репозиторий
приватный). Основа — [2026-10-20-studio-sections-voice-design.md](2026-10-20-studio-sections-voice-design.md)
(речь, расшифровка, выгрузки) и [2026-10-19-studio-pwa-design.md](2026-10-19-studio-pwa-design.md)
(приватность журналов, «пользователь видит только своё», CSRF): всё, что здесь не сказано иначе,
остаётся как там. Правка расшифровки в спеке речи была не-целью; эта спека её вводит.

## 1. Зачем

Расшифровка встречи или звонка почти всегда с ошибками: распознавание путает слова и фамилии,
собеседники — «Собеседник 1», «Собеседник 2». Сейчас исправить это можно только выгрузив TXT и
правя у себя; выгрузка по-прежнему без исправлений. Нажатием на реплику нельзя послушать, что там
на самом деле сказано. И чтобы обсудить запись с моделью, текст копируют в чат руками.

## 2. Критерий успеха

1. В открытой расшифровке «Править» → исправил текст двух реплик → «Сохранить»; «Имена» →
   «Собеседник 1 → Иван» → везде в расшифровке «Иван»; TXT, DOCX и SRT — с исправлениями и
   именами, без повторного распознавания; «Копировать» — тоже.
2. Нажатие на реплику ставит плеер записи на её начало и играет; играющая реплика подсвечена.
3. «Сбросить правки» возвращает исходное распознавание целиком; у одной исправленной реплики —
   «вернуть» её исходный текст.
4. SRT новой расшифровки — короткими сегментами распознавания со своим временем; ни один субтитр
   не длиннее `SRT_MAX_SEC` (7 с) и `SRT_MAX_CHARS` (84 знака) — и у старых расшифровок тоже.
5. «В чат ▾» → «Составить итоги» → открывается новый диалог: вложение «<имя записи>.txt» с
   числом знаков (нажатие показывает весь передаваемый текст), в поле — готовый вопрос; ничего не
   отправлено. Модель — локальная по умолчанию раздела «Чат»; если локальной нет — модель не выбрана,
   «Отправить» закрыто, пока пользователь сам не выберет.
6. В отправленном сообщении у вложения — ссылка «к записи», открывающая эту расшифровку (если её
   не удалили).

## 3. Не цели

- Правка времени реплик, деление и склейка реплик, слияние собеседников.
- Правка сразу в нескольких вкладках с согласованием (последнее сохранение побеждает, раздел 6).
- Повторное распознавание и выбор слов из вариантов распознавания.
- Автоматическая отправка в чат, итоги без открытия чата, расшифровка в чат из браузерного
  подключения без явного выбора модели.
- Слова со временем (word-level) — сервис их отдаёт, студия их не хранит и сейчас не начнёт.

## 4. Анти-цели — провал, даже если всё «работает»

- Правка затёрла исходное распознавание: «Сбросить правки» не вернуло исходный текст.
- Текст реплик, имена собеседников или текст вложения попали в журнал службы.
- Чужая расшифровка правится, выгружается или уходит вложением (любой id чужой записи — 404).
- Расшифровка ушла во внешний сервис (подключение не из списка разрешённых или облачное) без
  явного выбора модели пользователем.
- Сообщение с расшифровкой отправилось само.
- Откат `install.sh` на прежний код ломает чтение новых расшифровок или базы.

## 5. Данные

**Схема — следующий свободный шаг `db.STEPS`** (только добавляет; в работе — 10, окончательный
номер — при слиянии в `main`; новая база — сразу в `SCHEMA`):

    ALTER TABLE transcripts ADD COLUMN edits TEXT;
    ALTER TABLE attachments ADD COLUMN source_transcript_id TEXT;

- `transcripts.edits` — NULL (правок нет) или JSON
  `{"texts": {"<номер реплики>": "текст"}, "names": {"<исходная метка>": "имя"}}`. Номер — индекс
  в `segments` файла итога (с 0), метка — исходная «Собеседник N». Исходное распознавание не
  меняется: файл итога на шаре остаётся как есть.
- `attachments.source_transcript_id` — id расшифровки, из которой сделано вложение; без ссылки на
  `transcripts` (запись могут удалить, вложение остаётся в диалоге).
- **Файл итога** новых расшифровок получает рядом с `segments` ключ `raw` — сегменты распознавания до
  склейки по собеседникам: `{start, end, speaker, text, turn}`, метка «Собеседник N» той же нумерации,
  `turn` — номер реплики `segments`, в которую сегмент склеен (`speech.speakers` знает это при склейке;
  по времени не сопоставлять: у WhisperX конец реплики и начало следующей совпадают). `segments_of`
  читает только `segments`, так что прежний код (откат) новый файл читает. У старых расшифровок `raw`
  нет — их исходные короткие сегменты потеряны при сохранении; для них SRT делится по тексту
  (раздел 7).

## 6. Сервер: правка

**`GET /api/transcripts/<id>`** готовой расшифровки — как сейчас, но `segments` — с правками:
каждая реплика `{start, end, speaker, label, text, edited}`: `speaker` — показываемое имя (правка
`names` или исходная метка), `label` — исходная метка (для окна «Имена»), `edited` — текст изменён;
у изменённой ещё `original` — исходный текст (для «вернуть»). Плюс `names` — словарь правок имён,
`edited` — есть ли правки вообще. `speakers` в ответе — число разных показываемых имён (два
собеседника, названные одинаково, — один).

**`PATCH /api/transcripts/<id>`** `{"texts": {"3": "текст" | null}, "names": {"Собеседник 1": "Иван" | null}}`
— сливает с `edits`: `null` или значение, равное исходному, снимает правку. Проверки (422 `input`
словами): номер — в пределах `segments`; текст после обрезки пробелов — 1…`EDIT_TEXT_MAX` (20 000)
знаков; метка — одна из исходных меток расшифровки; имя — 1…`NAME_EDIT_MAX` (60) знаков без
управляющих. Только `done` (иначе 409 `running`/`state`); чужая — 404 `gone`. Ответ — как у GET.
Запись — одним `UPDATE … SET edits = ?` (последнее сохранение побеждает). Журнал — «transcript
<id>: правка» без текста и имён.

**`DELETE /api/transcripts/<id>/edits`** → `edits = NULL`, ответ как у GET.

**Выгрузки** (`GET …/export`) и «Копировать» — по репликам с правками (тот же код, что у GET:
одна функция `transcripts.view(row, result)` собирает показываемые реплики). TXT и DOCX — как сейчас,
с показываемыми именами.

## 7. SRT

Субтитр — не длиннее `SRT_MAX_SEC` (7 с) и `SRT_MAX_CHARS` (84 знака, две строки по 42).

- Реплика **без правки текста** и есть `raw` — субтитры по её сегментам `raw` (поле `turn`);
  сегмент длиннее пределов делится как ниже.
- Иначе (правленая реплика, старая расшифровка, внешний сервис без `raw`) — текст реплики делится
  на куски не длиннее `SRT_MAX_CHARS`: по концам предложений, затем по словам; время реплики
  делится между кусками пропорционально их длине.
- Каждый субтитр — не длиннее 7 с (длиннее — обрезается по концу, между субтитрами бывают паузы:
  «Да.» на 20 с реплики — один субтитр 7 с); субтитр без длительности (у внешнего сервиса времени
  может не быть) — 1 с, но не дальше начала следующего. Субтитры не перекрываются, время не убывает.
- Имя собеседника — префиксом «Иван: » только у первого субтитра реплики.

## 8. Сервер: вложение из расшифровки

**`POST /api/transcripts/<id>/attachments`** (за `auth.guard`, CSRF) — только `done`, только своя:
- Текст — заголовок «Расшифровка «<имя записи>» · <длительность>» и реплики с правками в формате
  TXT-выгрузки. Больше `documents.TEXT_MAX_CHARS` — 413 `too_big` словами.
- Файл — `media.save_async(uid, текст UTF-8, "text/plain", "<имя без расширения>.txt")`; строка
  `attachments` — `kind='document'`, `message_id NULL`, `name` = то же имя, `text`, `chars`,
  `source_transcript_id`. Дальше это обычное неотправленное вложение: крестик в чате удаляет его
  с файлом (`DELETE /api/attachments/<id>`), забытое убирает уборка через сутки
  (`chat.sweep_attachments`), отправка привязывает его к сообщению, предел контекста проверяет
  отправка (`chat._too_big`, 413 `context` — как у документа).
- Ответ 201 — `{id, kind, name, chars, media_id, text, tokens}`: `text` — для просмотра на странице
  до отправки, `tokens` — `chat.estimate_tokens` по этому тексту.
- `chat._message_out` у вложения с `source_transcript_id` добавляет `source: {"transcript_id": …,
  "exists": bool}` (есть ли ещё своя расшифровка с этим id).

**Локальная модель** — модель, которая работает на карте srvllm: подключение вида `srvllm` (идёт
через сервер) и имя модели с приставкой `local-` (соглашение шлюза `llm_routers`: `local-chat`,
`local-vision`, `local-gemma-abl` — на srvllm; остальные роли того же шлюза — облачные: `chat`,
`claude-*`, `gpt-*` и т. п.). Ни подключение, ни IP-адрес локальности не доказывают: шлюз
`10.77.1.15:4000` отдаёт и облачные модели, а запись списка по IP может быть публичной. Признак —
функция `sections.is_local(conn, model)`; `GET /api/sections` отдаёт его у моделей ссылок раздела
«Чат» (`local_models` у ссылки).

**Запрет на сервере.** `chat.create_turn` принимает новое поле `TurnIn.external_ok` (по умолчанию
false): ход, который привязывает вложение с `source_transcript_id`, к нелокальной модели диалога без
`external_ok` — 409 `external` «Расшифровка уйдёт во внешний сервис «<подключение>» — подтвердите».
Так правило держится и в уже открытом диалоге с облачной моделью, и после ухода и возврата.

## 9. Страница

**Расшифровка (`transcribe.js`).**
- Реплика — `div.tr-turn[data-index]` с временем начала. Вне правки нажатие по реплике (если в
  этот момент не выделен текст) ставит плеер на её начало и запускает; играющая реплика —
  `aria-current="true"` по `timeupdate`. Плеер — один `audio.tr-audio` вида, на него держится ссылка.
- «Править» в `.tr-acts`: тексты реплик становятся полями (растут по содержимому), внизу вида —
  «Сохранить» и «Отмена»; у изменённой реплики — пометка «изменено» и «вернуть». «Сохранить» шлёт
  `PATCH` только изменённых номеров; ошибка — словами, правка не теряется.
- «Имена» — окно со строкой на исходную метку: «Собеседник 1 → [поле]»; «Сохранить» — `PATCH names`.
  Если собеседников нет (`speakers` 0) — кнопки нет.
- «Сбросить правки» — в окне подтверждения; видна, когда `edited`.
- Пока идёт правка, опрос списка вид не перерисовывает (`createPicker.refresh` и так перерисовывает
  только при смене состояния; правка не должна теряться и от `select` того же id).
- «В чат ▾» — меню из трёх: «Обсудить в чате», «Составить итоги», «Выделить решения и задачи» →
  `ctx.navigate('chat?transcript=<id>&ask=discuss|summary|tasks')`.
- Открытие по ссылке: `#/transcribe?id=<id>` — раздел выбирает эту запись после загрузки списка
  (своей нет — список как обычно).

**Чат (`chat.js`).** Начинает читать `ctx.query` в `mount` и `update`:
- `transcript` и `ask` → новый диалог (как «Новый диалог», в том числе если он уже открыт), `POST
  /api/transcripts/<id>/attachments`, вложение встаёт в поле как уже загруженное (у элемента `atts`
  есть `meta`, файла нет — `upload` его пропускает, `paintAtts` берёт имя и вид из `meta`), в поле —
  вопрос по `ask` (`discuss` — пусто;
  `summary` — «Составь краткие итоги этой записи: о чём говорили и к чему пришли.»; `tasks` —
  «Выдели из записи принятые решения и задачи: что сделать, кто отвечает, сроки, если названы.»),
  затем адрес заменяется на `#/chat` без записи в историю (перезагрузка не делает второе вложение).
  Ошибка создания — словами в строке ошибки чата.
- Чип вложения показывает число знаков; нажатие — окно с передаваемым текстом (только чтение,
  прокрутка) и «~N тыс. токенов».
- Модель: умолчание раздела «Чат», если оно локальное; иначе первая отмеченная локальная модель;
  иначе модель не выбрана — подсказка «Запись уйдёт во внешний сервис — выберите модель» у чипа
  модели, «Отправить» закрыто до явного выбора. Это правило — только для диалога из расшифровки;
  обычный новый диалог — как сейчас.
- Отправка с вложением из расшифровки к нелокальной модели (выбранной сейчас или моделью уже
  открытого диалога) — сначала окно «Расшифровка уйдёт во внешний сервис «<подключение>» —
  отправить?»; «Отправить» — ход с `external_ok: true`. Ответ 409 `external` (вкладка не знала) —
  то же окно.
- Ничего не отправляется само.
- Вложение отправленного сообщения с `source.exists` — ссылка «к записи» → `#/transcribe?id=<id>`.

## 10. Решения проектировщика (не владельца) — проверить при чтении

1. Правки — отдельным JSON в базе, исходник — файл итога без изменений; «последнее сохранение
   побеждает» без согласования вкладок.
2. Новые расшифровки хранят ещё и сегменты до склейки (`raw`) — для SRT; старые делятся по тексту.
3. Пределы SRT — 7 с и 84 знака; имя — у первого субтитра реплики.
4. Вложение из расшифровки — обычный документ (`kind='document'`, свой txt-файл), а не ссылка на
   файл итога: удаление записи не ломает диалог, удаление вложения не трогает запись.
5. «Локальная» модель — `local-*` подключения srvllm; к остальным расшифровка уходит только с
   подтверждением, и это держит сервер (`external_ok`).
6. Нажатие по реплике перематывает (кроме момента, когда выделен текст); подсветка играющей.
7. Имена — правка меток для показа; число собеседников — по показываемым именам.
8. Тексты трёх вопросов — раздел 9.
