# DeepSeek Harness — четвёртый помощник «Агентов»

Дата: 2026-11-22. Статус: согласован владельцем 2026-11-22.

## 1. Зачем

Студией пользуются разные люди, у каждого свой компьютер и свой мост. У кого-то DeepSeek Harness (дальше DSH)
уже основной помощник: в нём его чаты, память, модели, ключи и MCP. Студия должна управлять **этой самой
установкой**, а не заводить рядом отдельную: показывать прежние чаты DSH, продолжать их и начинать новые с той же
памятью и настройками, на Windows, macOS и Linux — так же, как сейчас она управляет Claude Code, Codex и OpenCode.
Работа, начатая в студии, должна быть видна потом в самом DSH.

## 2. Цели, не-цели, анти-цели

**Цели**

- `engine: deepseek` («DeepSeek Harness») рядом с `claude`, `codex`, `opencode`: чаты проекта, история, новый чат,
  ход с потоком, карточки разрешений, остановка, очередь уточнений, выбор модели и усилия, права чата, контекст,
  умолчания в настройках учётки, MCP агентов, версия и обновление в «Компьютере», баланс в панели лимитов,
  вложения-картинки, экспорт и ссылка «Поделиться», совместные проекты — везде, где эти функции есть у OpenCode
  и DSH это позволяет (§4.3).
- Чаты, созданные в DSH Web, Desktop или консоли, видны в студии и продолжаются из неё; чаты студии видны в DSH.
- Ходы студии идут с моделями, провайдерами, MCP и памятью из профиля DSH человека (решение владельца А, §5).
- Мосты Windows x64, macOS (Intel и Apple Silicon), Linux x64/arm64.

**Не-цели**

- Ставить DSH с нуля: как и для остальных помощников, студия только обнаруживает установленный и обновляет его.
- Править настройки DSH из студии (модели, провайдеры, память) — студия их только читает.
- Встраивать интерфейс DSH Web, запускать его сервер.
- То, чего нет в ACP DSH (§4.3): ветвление, дерево подагентов, удаление сессий, режимы, slash-команды, уточнение
  внутрь идущего ответа. Кнопки скрыты, а не изображают работу.

**Анти-цели** (провал, даже если «работает»)

- Студия меняет файлы DSH человека: настройки, профили, сессии; оставляет в его списке чатов пустые служебные сессии.
- Ключ DeepSeek уходит куда-либо, кроме `api.deepseek.com`, или попадает в студию, журнал, argv.
- Тексты, пути, имена проектов, вывод DSH — в журнале моста или сервера.
- Регрессия OpenCode после выделения общей основы ACP.
- Молча неполные настройки: если что-то из профиля DSH не применилось, человек этого не видит.

## 3. Что известно о DSH (проверено 2026-11-22)

Источник — официальный репозиторий `github.com/deepseek-ai/deepseek-harness` (MIT, «developer preview», авторы
предупреждают о несовместимых изменениях): `apps/cli/reference/README.md`, `packages/acp/acp/README.md`,
`packages/bundle/base/cordis.patch.yml`, `packages/settings/settings/README.md`,
`packages/session/session-persistence-jsonl/README.md`, `packages/interaction/permission-presets/README.md`.
Живьём DSH не запускался — отсюда шаг 0 (§8).

- **Установка.** npm `@deepseek-ai/dsh`, на 2026-11-22 тег `latest` — `0.2.2-rc.5` (предварительный выпуск),
  `engines.node >=24.9.0`; master — `0.2.3-alpha.2`, `^24.22.3 || >=26.13.1`. `bin.dsh` → `lib/bin.js` (скрипт Node,
  своего exe нет). Есть Python-пакет `deepseek-harness-sdk` (тоже даёт `dsh`) и Desktop (`apps/desktop`): оболочка
  Electron вокруг полного DSH Web, профиль `desktop`, своя среда (Electron RunAsNode, встроенный pnpm); команды `dsh`
  в системе нет, пока человек не выберет в меню «Manage dsh Command… → Install» (macOS — `/usr/local/bin/dsh`,
  Windows — PATH пользователя); версия этой команды следует выпуску Desktop. На Linux имя `dsh` занято
  distributed shell.
- **Профили.** `web` = base + web-app, `acp` = base + acp-app, `headless`, `sdk`, `sdk-minimal` (без base).
  Слои по возрастанию силы: бандлы профиля → `cordis.patch.yml` профиля (`$DSH_HOME/profiles/<имя>/`) →
  `$DSH_HOME/cordis.patch.yml` (общий для всех профилей) → `--patch` из командной строки. Патч заменяет `config`
  строки целиком, без слияния. Формы DSH Web пишут в патч **своего** профиля: модели, MCP и память, настроенные в
  Web, профиль `acp` не видит. Общие для base-профилей: хранилище сессий `$DSH_HOME/sessions`, `storages`,
  `$DSH_HOME/.credentials.yaml` (ключ DeepSeek). `DSH_HOME` по умолчанию `~/.dsh` (для Windows не проверено).
  Старый `settings.yaml` однажды импортируется и переименовывается в `settings.yaml.imported`.
- **ACP** (`dsh --profile acp`, stdio, ACP v1): `initialize` (+ `session/list`, `session/resume`, `session/close`,
  Streamable HTTP MCP), `authenticate` (сразу успех), `session/new` (абсолютный cwd, stdio/HTTP MCP),
  `session/list` (новые первыми, фильтр `cwd`, страница 100, подагенты исключены), `session/resume` (без replay),
  `session/close`, `session/set_config_option` (только `model` и `reasoning_effort`), `session/prompt` (текст,
  `resource_link`, картинки — если маршрут модели их принимает; один prompt на сессию), `session/cancel`,
  `session/update` (сообщения, мысли, жизненный цикл инструментов, конфиг, контекст), запрос клиенту
  `session/request_permission` (разовое allow/reject). **Нет:** `session/load` и replay истории, удаление, fork,
  дополнительные каталоги, SSE-MCP, режимы, команды, планы, терминалы, fs-вызовы клиента, elicitation.
  Названия чатов в acp — детерминированные, без генерации моделью.
- **Сессии.** `<root>/--<нормализованный cwd>--/<id>/session.v3.jsonl.zstd` (или `.jsonl` без сжатия); формат
  менялся v0→v3, в master уже миграция V3→V4. Одна запись на сессию: блокировка ядра (`flock` / именованный
  семафор Windows) — чат, открытый в DSH Web, нельзя продолжить из другого процесса. Сессия, созданная без
  материализующей записи, следа на диске не оставляет.
- **Права.** base: режим песочницы `DSH_PERMISSION_MODE` (`read-only` | `workspace-write` | `danger-full-access`,
  по умолчанию `workspace-write`), одобрение `ask` (при `danger-full-access` — `never`). Пресет новой сессии —
  `permission.defaultPreset` настроек, закрепляется при создании; ACP пресет не меняет.
- **Ключ и модели.** `DEEPSEEK_API_KEY`, `DEEPSEEK_BASE_URL`; провайдер по умолчанию `deepseek-official`,
  модели вида `deepseek-v4-flash`, `deepseek-v4-pro`; свои OpenAI-совместимые провайдеры.
- **Баланс.** `GET https://api.deepseek.com/user/balance` (Bearer-ключ): `is_available`,
  `balance_infos[{currency, total_balance, granted_balance, topped_up_balance}]`.

## 4. Подходы

1. **Общая основа ACP для OpenCode и DSH — выбран владельцем.** Из `opencode.py` выделяется общая часть (процесс
   ACP, ход, поток, карточки разрешений, остановка, очередь, параметры модели и усилия, контекст), DSH — тонкий
   модуль поверх неё. Через проверенный код, исправления протокола — один раз. Цена — правка работающего OpenCode,
   её страхуют его тесты до и после.
2. Отдельный модуль DSH копией `opencode.py`. OpenCode не трогается, но ~800 строк дублируются и каждое
   исправление ACP — дважды.
3. Скрытый `dsh --profile web` и API его интерфейса на loopback. Настройки и история точно как в Web, но API
   внутренний и меняется, второй экземпляр конфликтует с открытым у человека DSH Web, на компьютере слушающий порт.

Отброшены: Python SDK (только полный доступ, без карточек, без настроек человека), `headless` (одно задание без
продолжения), JSON-RPC `--profile sdk` (методы не описаны, сверх ACP ничего не даёт).

## 5. Решения владельца (2026-11-22)

- **Настройки — вариант А, «подхватывать сами».** При каждом запуске DSH мост берёт из профиля человека модели,
  провайдеров, MCP и память и передаёт их процессу `acp` наложением `--patch`; файлы DSH не меняет. Что не удалось
  применить — студия показывает списком. Отклонены: Б (перенос по кнопке — надо нажимать после каждой правки в Web),
  В (настройки в студии — теряются память и MCP из Web).
- **Лимиты — вариант А, баланс DeepSeek.** Мост читает остаток с `api.deepseek.com` ключом из настроек DSH; рядом —
  токены и контекст из самого DSH. Новый адрес — в `limits.HOSTS` и перечни обоих CLAUDE.md. Отклонён Б (без
  обращения наружу).
- **Подход — 1** (§4).
- **DSH Desktop — вариант А, «мост находит сам».** Человеку с одним Desktop ничего включать не нужно; мост
  использует встроенную среду приложения. Отклонён Б (один раз нажать «Manage dsh Command… → Install» по подсказке).
- **Провайдеры.** Ключ DeepSeek у владельца есть, но без баланса; DSH подключает сторонние OpenAI-совместимые API —
  у пользователей студии это обычный случай, баланс тогда не показывается (§6.1), остальное работает.

## 6. Устройство

### 6.1. Мост (`agent/studio_agent/`)

**Общая основа ACP.** Новый модуль (имя — на усмотрение исполнителя, например `acp.py`): `AcpRunner(Runner)` с
тем, что сейчас в `OpenCodeRunner` не зависит от OpenCode, — `_run`, `_notification`, `_request`/`_request_card`,
`answer`, `_deny_all`, `_configure`, `state`, очередь, `Aliases`, `normalize`/`step_of`, учёт контекста. Точки
расширения: аргументы запуска и окружение, файл соответствий и `choices`, открытие существующей сессии
(`session/load` у OpenCode, `session/resume` у DSH), источник истории (replay у OpenCode, файлы у DSH),
набор возможностей (fork, дети, режимы, команды, дополнительные каталоги — только OpenCode). OpenCode-only
остаётся в `opencode.py`, `opencode_native.py`, `opencode_events.py`, `opencode_usage.py`. `opencode_rpc.Client`
обобщается аргументами команды (сейчас зашито `"acp"`). Поведение OpenCode не меняется: его тесты проходят до и
после выделения, без правки ожиданий.

**`deepseek_rpc.py` — поиск CLI.**
- Windows: `@deepseek-ai/dsh/lib/bin.js` в глобальном npm (`%APPDATA%\npm\node_modules`, также префикс из
  `npm config`), запуск `node.exe bin.js --profile acp` — настоящий `node.exe` из PATH, обёртки `dsh.cmd`/`dsh.ps1`
  через shell не исполняются (как `opencode_rpc.find_cli`).
- macOS/Linux: `host.find_tool("dsh")` с разрешением ссылки; принимается только файл внутри пакета
  `@deepseek-ai/dsh` (или `dsh` Python-пакета `deepseek-harness-sdk`) — чужой `dsh` (distributed shell) не запускается.
- **DSH Desktop** (решение владельца, §5): мост сам находит установленное приложение на Windows, macOS и Linux и
  запускает его встроенную среду так же, как это делает команда, которую регистрирует пункт Desktop «Manage dsh
  Command…»: Electron в режиме RunAsNode и CLI из ресурсов приложения (README `apps/desktop`, «Bundled command
  runtime»). Регистрация команды человеком не нужна; зарегистрированный лаунчер Desktop (`/usr/local/bin/dsh`,
  запись в PATH пользователя Windows) мост распознаёт как Desktop. Места установки и точная команда — по шагу 0
  (Windows — установкой на машине разработки, macOS/Linux — по конфигурации сборки `apps/desktop`). Версия
  показывается, обновляет сам Desktop (как OpenCode.app на macOS: «обновляется приложением»).
- Если найдены и npm/Python-CLI, и Desktop, ходы идут средой того приложения, чей профиль — источник настроек
  (`desktop` → Desktop, `web` → CLI): более новая версия DSH при записи переводит файлы сессии в новый формат
  (README `session-persistence-jsonl`: запись публикует перенесённую версию), и старшее приложение человека
  перестало бы открывать свои чаты.
- Версия Node проверяется по `engines` установленного пакета; не подходит — DSH «не готов» с понятной причиной.
- Версия DSH — `dsh --version`; процесс ACP — в Job Object (`jobs.attach`), stderr отбрасывается, без окна консоли.
- Окружение: `DSH_HOME` пользователя сохраняется; `DSH_PERMISSION_MODE` задаёт мост по правам чата (ниже).

**`deepseek_settings.py` — наложение настроек (решение А).**
- Источник — патч профиля, которым человек пользуется: из `profiles/web` и `profiles/desktop` — тот, что менялся
  последним (см. §9). Пользователь только консоли (нет ни одного) — наложения нет: профиль `acp` сам читает общий
  `$DSH_HOME/cordis.patch.yml` и `.credentials.yaml`, их мост не трогает и не копирует.
- Из патча берутся только строки известных видов: провайдеры и каталог LLM, MCP, память, пресет прав по умолчанию.
  Строки интерфейса web-app, HMR, порты и всё незнакомое не переносится и попадает в список «не применено» (по
  имени строки/плагина, без значений). Строки, которые человек сам задал в `profiles/acp/cordis.patch.yml`
  (пользуется DSH из редактора по ACP), наложение не перекрывает: `--patch` сильнее, поэтому такие строки из
  источника пропускаются.
- Если на шаге 0 наложение не работает целиком (строки Web зависят от плагинов web-app, память привязана к профилю
  Web, `--patch` ведёт себя иначе) — реализация останавливается до решения владельца: это суть решения А.
  Частичная неудача — штатный список «не применено».
- Наложение пишется во временный файл в `host.private_dir` (как `mcp/runtime-*`), передаётся `--patch`, удаляется
  после disconnect; остатки после падения стирает sweep при старте ядра. Секреты в argv не попадают.
- Как получить строки — разбором YAML патча или выводом самого DSH (`--dump-config` профиля): выбирает исполнитель
  по итогам шага 0, предпочтительнее путь самого DSH. Новая зависимость моста (например, PyYAML) допустима, если
  без неё нельзя; тогда она попадает в `requirements.txt` и колёса установщика macOS (включая Intel).
- Итог наложения (`profile`, `applied`, `skipped` — только имена) — в каталоге `hello.deepseek` и `state`.
- Ключи сторонних провайдеров, введённые в DSH Web/Desktop, лежат в общем `.credentials.yaml` и работают. Провайдер,
  который берёт ключ из переменной окружения (`apiKeyEnv`), получает её только если она есть у процесса моста:
  LaunchAgent macOS не видит переменных из профиля оболочки. Такой провайдер попадает в «не применено» с причиной
  «ключ из переменной окружения недоступен мосту» (имя переменной не передаётся).

**`deepseek.py` — `DeepSeekRunner(AcpRunner)`.**
- Каталог моделей и усилий — `configOptions` пробной `session/new` + `session/close` без prompt. Проверить на шаге 0,
  что такая сессия не оставляет следа в `session/list` и на диске; если оставляет — каталог берётся иначе
  (по итогам пробы), но мусора в чатах человека нет.
- Чаты проекта — `session/list` с `cwd` проекта, UUID студии ↔ id DSH в `deepseek-chats.json` (только id, проект,
  происхождение), настройки чатов — `deepseek/choices.json`. Чаты, созданные вне студии, — `origin: other`.
- Продолжение — `session/resume`. Сессия занята другим процессом (открыта в DSH Web) — отказ `writer_active` со
  словами «Чат открыт в DeepSeek Harness на компьютере — закройте его там и повторите»; копии и ветки нет.
  Если шаг 0 покажет, что Web/Desktop держат блокировку до выхода из приложения, слова говорят «закройте
  DeepSeek Harness». Защиту от двух писателей даёт сам DSH: без своего системного модуля блокировки он отказывает
  в записи (README `session-persistence-jsonl`), мост показывает этот отказ и сам в файлы сессий не пишет.
- История — чтение файлов сессии мостом (ACP replay нет): `.jsonl` и `.jsonl.zstd` поддерживаемых версий формата,
  с пределами страниц и бюджета, как у прочих историй (`limits.HISTORY_BUDGET`), через индекс историй с ревизией
  файла. Незнакомая версия формата или повреждённый файл — чат открывается и продолжается, вместо истории — пояснение
  «Историю этой версии DeepSeek Harness студия пока не читает». Если на шаге 0 найдётся официальный способ прочитать
  переписку (команда экспорта, метод `sdk`) — он предпочтительнее разбора файлов. Распаковка zstd: `compression.zstd`
  на Python 3.14, иначе зависимость (`zstandard`) — по тем же правилам, что выше.
- Ход — `session/prompt`, уточнения во время ответа — очередь до конца ответа (как OpenCode), картинки — блоками
  ACP; отказ маршрута без картинок — понятное сообщение, а не тело ошибки провайдера.
- Права чата (`access`): `default` — пресет из настроек DSH, `DSH_PERMISSION_MODE` не задаётся; `read-only`,
  `workspace-write`, `danger-full-access` — задаются этой переменной процессу хода. На шаге 0 проверить, действует ли
  переменная на возобновлённую сессию с закреплённым пресетом; если нет — выбор прав доступен только новому чату,
  у существующего показывается «как при создании». Карточки `session/request_permission` — обычные карточки студии.
- Контекст — из `session/update` (заполненность окна и накопленные токены завершённых ходов студии).
- MCP агентов студии (проект + движок) — `mcpServers` в `session/new`/`session/resume`; только stdio и HTTP
  (SSE DSH не принимает) — проверка в `mcp.validate` для `deepseek`. MCP из профиля человека приходят наложением.

**`deepseek_usage.py` — баланс.** Ключ — `DEEPSEEK_API_KEY` окружения моста или `.credentials.yaml` из
`DSH_HOME`; запрос только если у текущей модели провайдер `deepseek-official` и `DEEPSEEK_BASE_URL` не задан или
равен официальному адресу (иначе ключ может принадлежать другому сервису — баланса нет, причина в ответе).
`GET https://api.deepseek.com/user/balance`, без перенаправлений, предел тела и времени как у `opencode_usage`,
кэш 60 с. В студию — только числа, валюты и признак доступности; ключ не покидает компьютер кроме этого запроса.
`limits.HOSTS["deepseek"] = "api.deepseek.com"`.

**Прочее моста.** `software.py`: `deepseek` → npm `@deepseek-ai/dsh`; «последняя версия» допускает предварительный
выпуск, если npm `latest` указывает на него (сейчас так); обновление — `npm install --global` установленного
префикса, как у остальных npm-пакетов. `agent.py`: четвёртый бэкенд везде, где перебираются три. Окно, трей, меню
Linux и консоль — статус четвёртого помощника, подписи через `i18n.tr` с переводом в `i18n.EN`.
Журнал — только id, коды, числа.

### 6.2. Протокол (добавка v1, спецификация `2026-10-28-studio-code-bridge-protocol`)

- `hello.deepseek`: `{version, models, efforts, defaults?, settings: {profile, applied[], skipped[]}}` — пределы и
  форматы как у `hello.opencode`; `engine: deepseek` в `chats`, `history`, `turn`, `state`, `answer`, `stop`,
  `mcp_get`/`mcp_save`, `usage`, `software_update`.
- `hello.deepseek_models` — обновление каталога без смены канала (как `opencode_models`, §22).
- `usage` для `deepseek`: окна `five_hour`/`seven_day`/`monthly` — `available: false`; новое необязательное
  `balance: {available, items: [{currency, total, granted, topped_up}], reason?}`.
- Без `hello.deepseek` сервер такие просьбы не шлёт (409 `unsupported`), страница помощника не показывает.
- Новая строка в таблице «capability → версия моста» `docs/architecture/agent-bridge.md`.

## 7. Что увидит пользователь как ограничение DSH

- Чат, открытый сейчас в DSH Web/Desktop, из студии не продолжить, пока его не закрыть там.

## 8. Проверка

**Шаг 0 — проба (до кода).** Установить на машине разработки npm-DSH и DSH Desktop (Windows), всё — в отдельный
`DSH_HOME`, настройки и чаты владельца не трогаются. Node здесь 26.7.0: подходит выпуску `latest` (`>=24.9.0`), но не
master — пробовать выпуск `latest`. Модель — сторонний OpenAI-совместимый провайдер DSH: шлюз srvllm, его ключ — из
vault потоком в окружение процесса, не в argv и не в вывод; модель с вызовом инструментов (не умеет — вернуться к
владельцу). Ключ DeepSeek без баланса для ходов не годится; живой запрос баланса — только если владелец положит его в
`~/.claude/.env` как `DEEPSEEK_API_KEY` (нулевой остаток для проверки показа подходит), иначе — подменой HTTP.
Снять и сохранить как фикстуры
(без ключей и личных путей): ответ `initialize` (`agentCapabilities`), `session/new` (`configOptions`), страницу
`session/list`, поток `session/update` короткого хода с инструментом и `session/request_permission`, файл сессии
(raw и zstd). Проверить: след пробной сессии без prompt; отказ `session/resume` занятой сессии (код ошибки);
действие `DSH_PERMISSION_MODE` на возобновлённую сессию; `--patch` поверх `acp` со строками из патча `web`
(провайдер, MCP); путь `DSH_HOME` на Windows; поведение `node-addon-system` на доступных платформах. Итоги —
в отчёт `docs/reports/`, решения §6 уточняются по ним до плана реализации.

**Тесты** (политика проекта: быстрые без сети и реального времени, `integration` — дольше секунды):
- мост: подставной ACP-процесс DSH на фикстурах шага 0 (каталог, чаты, resume, `writer_active`, ход, карточка,
  остановка, очередь, права и переменная окружения, MCP), разбор истории raw/zstd и незнакомой версии, наложение
  настроек (известные/неизвестные строки, временный файл и sweep), поиск CLI (npm Windows, ссылка на POSIX,
  чужой `dsh`, старый Node), баланс (подмена HTTP, нет ключа, чужой `DEEPSEEK_BASE_URL`), `software`;
- выделение основы ACP: весь набор OpenCode без изменения ожиданий — до и после;
- сервер: `hello`, маршруты с `engine=deepseek`, шаг 63 на копии базы шага 62, умолчания, лимиты, MCP;
- браузер (`integration`, 320 и 1280 px): новый чат DSH, ход с карточкой, плашка «не применено», баланс, скрытые

## 9. Решения, принятые без владельца (проверить при чтении)

- Источник настроек — из профилей `web` и `desktop` тот, что менялся последним; студия показывает, какой применён.
  Собственные строки человека в профиле `acp` наложение не перекрывает.
- Шаг 0 — первый этап плана реализации с проверкой «идти дальше»: план пишется после согласования этого проекта,
  ветви §6 закрываются итогами пробы до кода; провал решения А целиком — возврат к владельцу.
- Права чата — три пресета DSH плюс «по настройкам DSH» по умолчанию.
- Студия не ставит DSH с нуля, только обновляет установленный через npm; Python-установка и Desktop
  обнаруживаются, но обновляются самим человеком (Desktop — своим обновлением).
- При двух установках ходы идут средой приложения, чей профиль — источник настроек (защита формата чатов, §6.1).
- Проба и живой тест — через шлюз srvllm как сторонний провайдер DSH.
- Новые зависимости моста (YAML, zstd) — только если шаг 0 не даст пути без них.
- Имя движка в протоколе и базе — `deepseek`.
