# Студия: поиск по истории и фильтры — дизайн

Дата: 2026-10-21. Статус: решение владельца 2026-10-21 — делать поиск и фильтры (идея IDEAS.md
«Поиск по истории и личные коллекции»; коллекции и избранное — в IDEAS-archive.md, deferred).
Остальное — решения проектировщика (раздел 10). Проект: `studio` (репозиторий приватный). Основа —
[2026-10-19-studio-pwa-design.md](2026-10-19-studio-pwa-design.md) (там «поиск по истории» был не

## 1. Зачем

После сотен генераций, диалогов и записей найти старое можно только листая ленты по дням и помня
начало текста. Владелец хочет найти результат по словам промпта, сообщения, названия или текста
записи, модели и периоду — и открыть его, даже если модель уже не отмечена в разделе.

## 2. Критерий успеха

1. Значок поиска (лупа) в полосе (на телефоне — вверху справа) → экран «Поиск»: поле и фильтры
   «раздел», «модель», «с … по …». «кошк» находит картинку с промптом «Кошка на крыше» и диалог, где
   в ответе модели было «кошки»; «елка» находит «Ёлку».
2. Результаты — новые сверху: значок раздела, кусок текста с найденным выделенным, модель, дата;
   нажатие открывает запись в её разделе (фото и видео — просмотр, расшифровка и озвучка — запись,
   диалог — диалог), даже если модель раздела снята.
3. Только фильтры без слов («Видео», «за октябрь») — тоже список.
4. Слова поиска не попадают ни в журнал службы, ни в журнал Apache (строка запроса).
5. «Удалить всю историю», удаление записи или учётки убирают её и из поиска сразу.

## 3. Не цели

Коллекции, теги, избранное (deferred); поиск по смыслу (RAG, LLM, эмбеддинги); морфология («кот» не
находит «коту» — только начало слова: «кот» находит «коты», «котик»); поиск внутри картинок и
роликов; поиск по чужой истории в панели администратора; голоса (образцы) и подключения;
подсветка найденного внутри раздела после перехода (раздел открывает запись, как «Открыть» в
«В работе»).

## 4. Анти-цели

- В выдаче — чужая запись или кусок чужого текста.
- Слова поиска — в журнале службы или в строке запроса (журнал Apache).
- Индекс отстаёт: удалённое находится, новое — нет (после «Готово»).
- Откат `install.sh` на прежний код ломает базу или чат (запись в таблицы истории должна работать и
  со старым кодом, а индекс — оставаться верным).
- Поиск тормозит службу: ответ — за доли секунды на десятках тысяч записей.

## 5. Индекс

**Схема — шаг `db.STEPS[13]`** (`db.VERSION = 13`; новая база — сразу в `SCHEMA`):

- Виртуальная таблица FTS5 `search(body, section UNINDEXED, item UNINDEXED, part UNINDEXED,
  user_id UNINDEXED, model UNINDEXED, created UNINDEXED, tokenize='unicode61 remove_diacritics 2')`.
  Проверено на SQLite 3.46 (прод) и 3.50 (workstation): кириллица сворачивается по регистру, начало слова
  (`кош*`) работает, но «ё» ≠ «е» — поэтому текст в индекс и слова запроса проходят замену «ё»→«е»,
  «Ё»→«Е».
- `transcripts.text` (новый столбец, TEXT) — текст расшифровки для поиска (реплики с правками одной
  строкой): пишет `transcripts` при «готово» и при правке/сбросе; у старых расшифровок — фоновое
  заполнение при старте службы (`transcripts.backfill_text`: читает файлы итога своих `done` без
  `text` по одной, в потоке, не держит старт; шара недоступна — следующий старт).
- **Триггеры** (в том же шаге) держат индекс в лад с таблицами — и при прежнем коде после отката:
  - `images`: строка — промпт (раздел `photo`, `item` = id, `model`), на вставку; удаление — убрать.
  - `videos`: промпт (`video`, модель — `wan`), вставка и смена промпта (`prompt_source` — промпт
    придумал шлюз); удаление.
  - `chats`: название (`chat`, `item` = chat id, `part` = `title`), вставка и смена названия; удаление
    диалога — все строки `chat` этого `item`.
  - `messages`: содержимое (`chat`, `item` = chat_id, `part` = message id, `user_id` и `model` — из
    `chats`/сообщения) — только когда `status != 'streaming'` (ход пишет текст каждые `SAVE_SEC`, пока
    идёт ответ; индекс — по готовому); удаление — убрать.
  - `attachments` документов с `message_id` (привязанные): текст документа (`chat`, `part` = id
    вложения) — при привязке; удаление — убрать. Неотправленные не ищутся.
  - `transcripts`: имя записи + `text` (`transcribe`, `model`), вставка и смена `name`/`text`;
    удаление.
  - `speeches`: текст (`speech`, `model`, голос в тело не входит), вставка; удаление.
  - `users`: удаление учётки — все её строки (каскады по таблицам тоже дёрнут свои триггеры —
    этот — страховка).
  Замена «ё» — в триггерах (`replace`).
- **Заполнение** — тем же шагом `INSERT … SELECT` из таблиц (кроме текста старых расшифровок — его
  заполняет фон, раздел выше).

## 6. Сервер

**`POST /api/search`** (за `auth.guard`, CSRF; тело, а не строка запроса — строку пишет журнал
Apache) `{q?, section?, model?, since?, until?, before?, limit?}`:
- `q` — до 200 знаков; слова (буквы и цифры Unicode, остальное — разделитель), до 8 слов, каждое —
  `"слово"*` (кавычки FTS5 экранированы), через AND. Пусто — только фильтры; ни слов, ни фильтров —
  400 `input`.
- `section` — один из `chat|photo|video|transcribe|speech`; `model` — точное имя; `since`/`until` —
  дни `ГГГГ-ММ-ДД` (по часам хоста, `until` включительно).
- Порядок — новые сверху (`created` по убыванию, затем `item`, `part`); `limit` до 50 (по умолчанию
  30); `before` — курсор `{created, item, part}` последней строки страницы («Показать ещё»).
- Диалог в выдаче — один раз (лучшее совпадение — последнее по времени сообщение или название).
- Ответ `{items: [{section, id, title, snippet, model, created, href}], more}`: `title` — название
  диалога / промпт (до 80 знаков) / имя записи / начало текста озвучки; `snippet` — `snippet()` FTS5
  с маркерами `\u0002…\u0003` вокруг найденного и `…` (страница строит выделение узлами, не HTML);
  без слов — `snippet` пуст; `href` — как у «В работе» (`photo?id=…`, `video?id=…`,
  `transcribe?id=…`, `speech?id=…`, `chat/<id>`).
- **`GET /api/search/models`** — разные модели своей истории по разделам (для фильтра).
- Только `user_id` сессии; журнал — «search: N» (число найденного), без слов и фильтров.

## 7. Страница

- Раздел `search` в `app.js` (`#/search`), значок-лупа в полосе над «В работе» (на телефоне — вверху
  справа рядом с ним); не вкладка нижней панели.
- Поле поиска (ввод с паузой 300 мс, Enter — сразу), чипы фильтров: раздел (Все, Чат, Фото, Видео,
  Расшифровка, Озвучка), модель (из `GET /api/search/models` выбранного раздела), период (две даты
  `input type=date`, «сбросить»). Состояние поиска — только в памяти раздела (не в адресе: адрес видно
  в истории браузера и на экране; не в localStorage).
- Результаты по дням (как ленты), «Показать ещё»; пусто — «Ничего не нашлось». Нажатие —
  `ctx.navigate(href)`.
- Голосовой ввод в поле — как у промптов (`attachMic`).

## 8. Тесты

- Быстрые (`tests/test_search.py`): каждый раздел находится по слову и началу слова, регистр и «ё»;
  чужое не находится (две учётки с одинаковыми словами); фильтры раздела, модели, дат; курсор
  страниц; диалог — один раз; ответ чата индексируется после «готово», а не во время потока;
  удаление записи/диалога/учётки и «Удалить всю историю» убирают из выдачи; правка расшифровки
  меняет найденное; FTS-спецсимволы и кавычки в запросе не ломают (`"`, `*`, `NEAR`, `OR`);
  400 пустого; 401 без сессии, CSRF; журнал без слов; `GET /api/search/models`; заполнение шагом
  схемы и фон `backfill_text` (файл есть / шара недоступна); миграция — `test_foundation.py`
  (`DROP_V13`, снимать первой в цепочках). Скорость: 20 000 строк — поиск быстрее 0,2 с (тест не
  должен быть дольше 1 с — иначе в integration).
- Браузерный: лупа → поиск по слову → результат → открывается запись раздела; фильтр раздела.
- README — раздел «Поиск»; CLAUDE.md — индекс `search`, триггеры, `transcripts.text`, `POST` вместо
  строки запроса.

## 10. Решения проектировщика (не владельца) — проверить при чтении

1. FTS5 по тексту SQLite с триггерами (а не LIKE по таблицам): регистр кириллицы, начало слова и
   скорость; индекс держат триггеры — верен и после отката кода.
2. Текст расшифровок — в базе (`transcripts.text`): иначе их не найти (итог — файлом на шаре).
3. Слова — только «начало слова», без морфологии; «ё» = «е».
4. Запрос — `POST` телом; состояние поиска не в адресе и не на устройстве.
5. Новые сверху, а не по «похожести».
6. Поиск — отдельный экран со значком, не вкладка.
