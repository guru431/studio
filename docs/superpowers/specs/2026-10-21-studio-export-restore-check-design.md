# Студия: выгрузка своей истории и проверка копии базы — дизайн

Дата: 2026-10-21. Статус: по IDEAS.md 2026-10-21 («Экспорт личного проекта и проверяемое
восстановление»); владелец поручил разобрать IDEAS.md целиком, решения ниже — проектировщика
(раздел 10). Выгрузка «выбранной коллекции» ждёт коллекций (идея поиска и коллекций — вопрос
владельцу); здесь — вся своя история с выбором разделов. Проект: `studio` (репозиторий
приватный). Основа — [2026-10-19-studio-pwa-design.md](2026-10-19-studio-pwa-design.md) (хранение,
копия базы, приватность) и [2026-10-21-studio-feed-selection-design.md](2026-10-21-studio-feed-selection-design.md)
(потоковый ZIP по токену): всё, что здесь не сказано иначе, остаётся как там.

## 1. Зачем

Скачать можно отдельные картинки, ролики (и выделенное архивом) и расшифровку. Забрать свою
историю целиком — с промптами, цепочками, диалогами и файлами, в виде, который можно прочесть без
студии, — нельзя. Копия базы делается каждую ночь, но никто не проверял, что из неё действительно
поднимется студия: схема, ключ шифрования токенов, файлы на шаре.

## 2. Критерий успеха

1. «Настройки» → «Прочее» → «Хранилище» → «Выгрузить мою историю» (галочки разделов, по умолчанию
   все) → «Подготовить» → «Скачать: 1 234 файла, 5,6 ГБ» → загрузка `studio-export-ГГГГ-ММ-ДД.zip`
   начинается сразу.
2. Внутри: `README.txt`, `manifest.json` (что внутри, sha256 каждого файла), `chats/<id>.json`,
   `images.json`, `videos.json`, `transcripts.json`, `speeches.json`, `voices.json`,
   `settings.json`, `files/<media id>.<расширение>`; распаковывается Проводником, macOS и 7-Zip,
   `sha256sum`-проверка по манифесту сходится.
3. В выгрузке нет токенов подключений, хеша пароля, сессий, ключей passkey, CSRF.
4. Администратор: «Панель» → «Хранилище» → «Проверить копию» → через минуты «Копия 21.10 04:30 —
   поднимается: схема 9 → 12, целостность в порядке, токены расшифрованы 3 из 3, файлов нет на шаре
   0 из 4 512». Рабочая база не тронута. То же — `manage.py verify-backup` на хосте.
5. README и CLAUDE.md говорят, где лежит запасной `STUDIO_DATA_KEY` и что копия базы не
   возвращает уже удалённые с шары файлы.

## 3. Не цели

- Импорт выгрузки обратно в студию (формат — для чтения и хранения).
- Выгрузка «выбранного» по коллекциям (коллекций нет), по датам, по поиску.
- Восстановление рабочей базы из панели (только проверка копии; восстановление — как в CLAUDE.md,
  руками на хосте).
- Проверка по расписанию и тревога о неудачной проверке (можно позже — таймером, как копия).
- Копии вне storage.

## 4. Анти-цели

- В выгрузку попал чужой файл или чужая строка; в выгрузке — токен, хеш пароля, сессия, passkey.
- Выгрузка собирается целиком в памяти или на диске debian (только поток, как архив выделенного).
- Проверка копии тронула рабочую базу, шару (кроме чтения `stat`) или оставила копию базы во
  временном каталоге.
- Панель администратора узнала из проверки чужую историю: в итоге — только числа, без путей, имён,
  логинов.
- Имена файлов, промпты или пути — в журнале.

## 5. Выгрузка: сервер

**`POST /api/me/export`** `{"sections": ["chat","photo","video","transcribe","speech","voices"]}`
(подмножество, пусто — 400) → `{id, files, bytes}`: токен в памяти службы (как `media.ARCHIVES`:
`EXPORT_TTL_SEC` 1 ч — большая выгрузка дольше 10 минут; не больше 2 живых на пользователя),
`files` и `bytes` — по строкам `media` выбранных разделов (оценка до загрузки). Шара не отвечает —
503 `storage`, как у архива.

**`GET /api/me/export/<токен>`** — `application/zip`, `Content-Disposition: attachment;
filename="studio-export-ГГГГ-ММ-ДД.zip"`, `Cache-Control: no-store`, `nosniff`, без
`Content-Length`. Чужой, неизвестный, просроченный токен — 404 `gone`. Всё — своё (`user_id`
сессии). Шара проверяется, как у архива (`stat` каталога шары → 503), но выгрузка без файлов
(только диалоги) — законна: `media._archive_ready` с его 404 «нет строк» сюда не годится.

**Чтение базы.** База — одна `state.DB`, и трогают её только из цикла событий. Поэтому выгрузка —
асинхронный генератор (`StreamingResponse` его принимает): в начале — id строк выбранных разделов
(небольшой список), затем по одной: диалог со всеми сообщениями и вложениями читается из базы в
цикле событий, превращается в JSON и отдаётся; файлы читаются блоками через `asyncio.to_thread`
(первый проход — CRC-32 и sha256, второй — данные). Это не мгновенный снимок: строка, удалённая во
время выгрузки, пропускается (её файл — в `missing`, если строка уже ушла). Память — один диалог и
один блок файла.

**Порядок записей:** `README.txt`, затем JSON разделов, затем файлы, последним — `manifest.json`
(в нём суммы уже записанного).
- `chats/<chat id>.json` — диалог: `{id, title, model, created, updated, messages: [{id, role,
  content, status, model, created, attachments: [{id, kind, name, chars, text, file}]}]}` — по одному
  файлу на диалог (память — на один диалог, а не на все).
- `images.json` — `[{id, kind, model, prompt, size, seed, strength, state, detail, created,
  finished, chain, file, source_file, mask_file}]`; `videos.json`, `transcripts.json` (с правками,
  если они есть в базе), `speeches.json`, `voices.json` — так же, файлы — ссылками `files/…`.
- `settings.json` — профиль (логин, имя, тема, виды лент), подключения `{id, name, kind, base_url}`
  без токенов, разделы (`section_links`, `section_defaults`), пресеты (если таблица есть).
- `files/<media id><расширение>` — все строки `media` пользователя, на которые ссылаются выбранные
  разделы (`media.EXT` по mime), без миниатюр. Файла нет на шаре — пропуск и запись в
  `manifest.missing`.
- `manifest.json` — `{format: "studio-export", version: 1, created, schema: db.VERSION, user:
  {login, name}, sections, counts, files: [{path, media_id, mime, size, sha256, download_name,
  created}], entries: [{path, sha256}] (JSON-файлы и README), missing: [media id]}`.

**Поток.** Запись ZIP — общая с архивом выделенного: из `media.py` выделяется писатель
(заголовок записи по CRC, размеру и времени; учёт смещений и центрального каталога; конец архива),
которым пользуются и синхронный `_zip` архива, и асинхронная выгрузка. Запись — файл или байты
(JSON, README). Первый проход по файлу считает и CRC-32, и sha256 (одно чтение), второй — отдаёт;
суммы копятся для манифеста. Остальное — как у архива: ZIP_STORED, CRC и размеры в локальном
заголовке, ZIP64, обрыв чтения шары — обрыв ответа. Журнал — «export: N файлов» и
предупреждение на сбой.

**Страница.** «Хранилище» в «Прочем»: «Выгрузить мою историю» → окно с галочками разделов →
«Подготовить» (`POST`) → «Скачать: N файлов, X ГБ» (ссылка на токен, как `save.js` `download`);
на iPhone — та же ссылка (уйдёт в «Файлы»). Ошибка — словами в окне.

## 6. Проверка копии: сервер

**`manage.py verify-backup [ПУТЬ]`** — без пути: новейшая `backup/<BACKUP_GLOB>` на шаре. Итог —
JSON в stdout, код 0 (поднимается) или 1 (нет) или 2 (копий нет / неверный вызов). Та же функция —
`manage.verify_backup(path=None) -> dict`.

Шаги (рабочую базу не открывает):
1. Скопировать копию в `tmp_dir` (`/var/lib/studio/tmp`, локальный диск, файл
   `verify-<случайное>.db`, не каталог: `audio.clean_tmp` при старте удаляет файлы, а каталог
   уронил бы старт) — в `finally` удалить (и `-wal`, `-shm`).
2. `PRAGMA integrity_check` — `ok`.
3. Версия схемы копии — от 1 до `db.VERSION` (0 — пустой или чужой файл: `migrate` налил бы в него
   свежую схему и «прошёл» — это провал «копия пуста»); `db.migrate` на временной копии — проходит
   (шаги применимы); итог — «схема A → B». Копия без единой учётки — тоже провал.
4. Токены: каждый `connections.token_enc` расшифровывается текущим `STUDIO_DATA_KEY` — числа
   «расшифровано / нет» (значения не держатся и не печатаются).
5. Файлы: `stat` каждого `media.rel_path` на шаре — числа «есть / нет» (без путей); шара не
   отвечает — «шара недоступна», проверка файлов пропущена; общий срок `VERIFY_FILES_SEC`
   (600 с) — дальше «проверено N из M».
6. Итог: `{backup: имя, at, size, integrity, schema_from, schema_to, users, tokens: {ok, failed},
   files: {present, missing, checked, total}, ok: bool, took}`; `ok` — целостность в порядке, схема
   применилась, все токены расшифрованы, шара отвечает.

**Панель.** `POST /api/admin/backup-check` запускает проверку потоком-демоном (одна за раз, как
`admin.PROBE`; идёт — 409 `running`), `GET /api/admin/backup-check` — `{state: idle|running|done,
result?}`; итог живёт в памяти службы до следующей проверки. В «Хранилище» панели — строка
«Проверка копии» с кнопкой «Проверить копию» и итогом словами (`ok` — зелёным, иначе — что не
так). Журнал — «backup-check: ok/fail» без чисел пользователей.

## 7. Документы

- README «Где хранится история»: выгрузка (что внутри, без чего) и проверка копии; что копия базы
  возвращает строки, но не файлы, удалённые с шары после её даты (их строки — 404).
- CLAUDE.md «Хост»: восстановление (как сейчас) + сначала `manage.py verify-backup`; запасной
  `STUDIO_DATA_KEY` — vault `local-config/secrets/vault.env` `STUDIO_DATA_KEY` (тот же, что на хосте в
  `/etc/studio/studio.env`); без него токены подключений из копии не расшифровать — их вводят заново.

## 8. Тесты

- Быстрые (`tests/test_export.py`): выгрузка открывается `zipfile`, состав по разделам, sha256 в
  манифесте сходятся с байтами, чужое не попало (две учётки), секретов нет (поиск хеша пароля,
  токена, csrf, digest в байтах архива), пропавший файл — в `missing`, токен чужой/просроченный —
  404, 400 пустого списка, 503 шары, журнал без имён; один диалог — один JSON; поток не держит весь
  архив (генератор отдаёт куски до конца файлов). `test_storage.py` или `test_deploy.py` —
  `verify_backup`: целая копия (`ok`), испорченная (integrity), старая схема (переход), чужой ключ
  (токены не расшифрованы), файл пропал (числа), рабочая база не изменилась (хеш файла), временная
  копия удалена; `manage.py verify-backup` коды; маршруты панели (только администратор, одна за раз).
- Браузерные: «Выгрузить мою историю» — окно, «Подготовить», ссылка на токен; панель — «Проверить
  копию» и итог.

## 9. Модули

`app/exports.py` уже занят выгрузками расшифровки — выгрузка истории в новом `app/takeout.py`
(роутер `/api/me/export`), запись ZIP — общая с `media.py`. Проверка — `manage.py`
(`verify_backup`), маршруты панели — `admin.py`.

## 10. Решения проектировщика (не владельца) — проверить при чтении

1. Формат — ZIP с JSON по разделам (диалог — свой файл), файлы — `files/<media id>`, манифест с
   sha256 последним; без импорта.
2. Подключения в выгрузке — с адресами, без токенов; пресеты и разделы — в `settings.json`.
3. Токен выгрузки живёт 1 ч, не больше двух на пользователя.
4. Проверка копии — по кнопке в панели и командой, без расписания; итог — только числа.
5. Временная копия — файлом в `tmp_dir`, удаляется в `finally`.
