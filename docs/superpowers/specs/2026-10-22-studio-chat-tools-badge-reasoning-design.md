# Чат: плашка «Интернет» над ответом и кнопка «Рассуждение»

Дата: 2026-10-22. Проект: studio (`https://studio.example.com`). Состояние до работы — коммит `6155c9d`.

## 1. Зачем

Разбор живого диалога 2026-10-22 (`local-gemma-abl`, «Интернет» включён после первого вопроса):

- ответы, где модель ходила в Exa, внешне не отличались от ответов по памяти. Единственный след — свёрнутое
  «Источники (0)» внизу (число считает ссылки, у неудачного поиска их ноль). Модель же уверяла, что «сходила
  в интернет», когда не вызывала ничего;
- ход «какой курс доллара» минуту шёл почти пустым: gemma-abl зациклилась, ~2700 токенов «thoughtthought…»
  ушли в `delta.reasoning_content`, а студия читает только `content`. Без «Стопа» такой ответ идёт до
  `STREAM_TOTAL_SEC` (30 мин) и держит карту srvllm (запись `FINDINGS.md` 2026-10-22 «Зациклившаяся модель…»).

Владелец хочет: **явно видеть, что для ответа модель вызывала Exa** (и чем кончилось), и **кнопку
включения и выключения рассуждения**, «как во многих подобных программах». Из вариантов для петель он выбрал
«показывать „думает…“».

## 2. Цели, не-цели, анти-цели

Цели:
1. Над каждым ответом, где были вызовы инструментов, — не свёрнутая плашка: какие вызовы и удались ли.
2. Кнопка «💭 Рассуждение» в диалоге: включает рассуждение модели там, где студия умеет его включать.
3. Рассуждение видно: пока идёт — «Думает… N с» с бегущим текстом, после — свёрнутое «Рассуждала N с ▸».
4. Петля в рассуждении не держит ответ полчаса.

Не-цели: пометка ответов, данных при выключенном «Интернете» (студия не хранит, был ли он включён в момент
хода, — владелец согласился без неё); выбор «силы» рассуждения (effort, бюджет токенов); кнопка у
подключений, кроме ролей `local-*` srvllm через сервер (OpenRouter, OpenAI, «совместимые», облачные роли
шлюза); путь через браузер (прямые подключения) — без изменений; передача рассуждения модели — ни в
следующих ходах, ни в кругах инструментов того же ответа.

Анти-цели (провал, даже если «работает»): рассуждение или его куски в журнале службы; кнопка, которая
ничего не меняет (видна там, где параметр не доходит); ответ с выключенным рассуждением, обрезанный «петлёй»,
хотя модель рассуждала законно; старые ответы и откат `install.sh` ломаются от новой схемы.

## 3. Плашка «Интернет» (вариант A, выбран владельцем по макету)

Только страница (`app/static/js/chat.js`, стили — по месту); сервер уже отдаёт шаги ответа (`tools` у
сообщения — `web.public`) и событие SSE `tool` (`{kind, label}`).

- **Где.** Над текстом ответа ассистента, выше строки рассуждения (раздел 4). Не свёрнута. Есть, только
  если у ответа есть шаги (`message.tools` не пуст). Ответ без шагов — без плашки (это и значит «по памяти»).
- **Текст** (моё решение, принято владельцем): виды по порядку, числа с `plural` из `ui.js`.
  Поиск и страница — Exa: «🌐 Интернет (Exa): 2 поиска, 1 страница»; YouTube идёт не через Exa — своей
  частью через « · »: «▶ YouTube: 1 ролик». Шаг вида `unknown` (модель позвала несуществующий инструмент
  или с битыми аргументами) — «1 неверный вызов». Есть ошибки — в конце « — 1 ошибка» / « — 2 ошибки».
- **Цвет.** Все шаги без `error` — зелёная; хоть одна ошибка — красная. Цвета — токенами темы студии
  (светлая и тёмная), как прочие пометки ошибок.
- **Нажатие** раскрывает блок «Источники» этого ответа и прокручивает к нему (там тексты ошибок). Плашка —
  кнопка с понятной подписью для чтения с экрана.
- **Пока идёт ответ.** Первое событие `tool` ставит плашку на место нынешней строки «Ищу: запрос»
  (`toolLine`, слова те же), с крутилкой: «🌐 Ищу: курс доллара…», «🌐 Читаю: …», «▶ Субтитры: …». По концу
  ответа страница, как и сейчас (`job.tooled`), перечитывает диалог, и плашка становится итоговой.
- **Старые ответы** с шагами получают плашку сами (строится из сохранённых шагов).
- Блок «Источники (N)» внизу остаётся как есть.

## 4. Кнопка «Рассуждение»

### 4.1 Где работает

Кнопка — только у модели, которую студия проверила: подключение через сервер (`conn.proxied`) и роль карты
srvllm (`sections.is_local(conn, model)`, `local-*`). Решение — функция сервера от подключения и модели
(как `web.tools_for`). Запрос несёт `chat_template_kwargs: {"enable_thinking": true}` при включённой кнопке и
`{"enable_thinking": false}` при выключенной. Прочим моделям (облачные роли шлюза за LiteLLM, другие
подключения) параметр не уходит вовсе: LiteLLM мог бы передать его облачному провайдеру и получить 400 —
сломались бы и диалоги с выключенной кнопкой.

Проверено 2026-10-22 через шлюз srvllm (`local-gemma-abl`, ключ `owner-images`): с `enable_thinking: true`
ход мысли идёт потоком в `delta.reasoning_content` с первых 0,1 с, ответ — через 11 с; с `false` — ответ
сразу, рассуждения нет. Круг после вызова инструмента без рассуждения первого круга — 200, ответ по
результату: рассуждение модели назад не передаётся и внутри ответа. На проде 2026-10-22 одно подключение —
srvllm; OpenRouter (`reasoning: {enabled}` / `{exclude}`, `delta.reasoning_details`) — когда появится.

**С рассуждением gemma-abl реже ищет:** свежий диалог «какой курс доллара к рублю?», `WEB_NOTE` прода, по 10
прогонов — поиск в 10 из 10 без рассуждения и в 5 из 10 с ним (остальные — курс «по памяти»).

### 4.2 Состояние и API

- Схема — шаг 15 (`db.VERSION = 15`, `db.STEPS[15]`, новая база — в `SCHEMA`; только добавление):
  `chats.thinking INTEGER NOT NULL DEFAULT 0`, `messages.reasoning TEXT`, `messages.reasoning_sec REAL`.
- `PATCH /api/chats/<id>` принимает `thinking: bool | null` (null — не трогать), как `web`. Включить у
  модели без поддержки — 409 `no_thinking` словами «эта модель не умеет рассуждать по кнопке». Смена
  подключения или модели диалога `thinking` не сбрасывает (как `web`): у модели без поддержки оно хранится,
  но не действует.
- Диалог в ответах API (GET, POST, PATCH одного диалога) несёт `thinking` (кнопка) и `thinking_ok`
  (поддерживает ли модель диалога). Сообщение — `reasoning` и `reasoning_sec` (null, если нет).
- Новый диалог — выключено. Кнопку можно нажать до создания диалога — в памяти страницы и тем же PATCH после
  создания, как черновик «Интернета» (`draftWeb`, `chat.js` ~1000).
- Ход берёт значение кнопки так же, как `web`: в транзакции хода (`create_turn`). «Ответить заново» — по
  нынешнему значению. Смена кнопки посреди ответа на этот ответ не влияет.

### 4.3 Поток

Рассуждение в дельте (только сервер — `StreamTask._round`): строка `delta.reasoning_content` (vLLM через
LiteLLM), иначе строка `delta.reasoning`.

Два режима показа (моё решение):
- **«Рассуждение видно»** — кнопка включена или модель без кнопки (рассуждение такой модели законно, раз
  студия его не выключала). Текст идёт на страницу, копится в
  `messages.reasoning` (сохраняется вместе с `content` каждые `SAVE_SEC` и в конце), длительность —
  `reasoning_sec`: от первого куска рассуждения до первого куска `content` после него (или до конца). В
  ответе с кругами инструментов — рассуждения кругов подряд через пустую строку, секунды — суммой.
- **«Только думает…»** — кнопка выключена у модели с кнопкой (студия послала `enable_thinking: false`). Текст на
  страницу не идёт и не хранится — только признак «модель думает». Это случай петель gemma-abl:
  в нормальных ответах она изредка роняет в reasoning 7–14 знаков «thought».

Сервер → страница: событие SSE `think` — `{text}` в первом режиме, `{}` во втором (не чаще раза в секунду).

Пределы (моё решение):
- `REASONING_MAX = 60_000` знаков рассуждения в первом режиме: больше — ответ остановлен с ошибкой
  «рассуждение слишком длинное — ответ остановлен», прочитанное (и `content`, и `reasoning`) сохранено.
- `STRAY_MAX = 2_000` знаков во втором режиме: больше — ошибка «модель зациклилась — ответ остановлен».
  В петлях повтора 2026-10-22 — 3–4,5 тыс. знаков за 75 с, в нормальных ответах — до 14.
- Известный предел: петля при **включённом** рассуждении идёт до `REASONING_MAX` (~60 знаков/с — около
  17 мин), но на экране видна («thoughtthought…» в блоке) и останавливается «Стопом».

`STRAY_MAX` и `REASONING_MAX` — на весь ответ (все круги вместе).

### 4.4 Страница

По макету (`.superpowers/brainstorm/…/reasoning.html`, одобрен):
- Кнопка «💭 Рассуждение» — чип рядом с «🌐 Интернет», `aria-pressed`, видна при `thinking_ok`.
- Пока идёт рассуждение — над текстом ответа (ниже плашки интернета) строка с крутилкой «Думает… 8 с»
  (секунды — счётчик страницы от первого `think`). В первом режиме под ней бегущий текст бледным курсивом,
  свёрнутый до нескольких строк, раскрывается нажатием; во втором — только строка.
- Готовый ответ с `reasoning` — свёрнутое «💭 Рассуждала 11 с ▸» (`reasoning_sec`, округлённо), раскрывается
  в полный текст (как обычный текст, без разметки Markdown — моё решение: рассуждение моделей часто
  с битой разметкой). Без `reasoning` — строки нет.
- «Копировать» копирует только ответ.

### 4.5 Что ещё касается

- `compose` рассуждение модели не передаёт (только `content`).
- Поиск (`search_docs`): не индексируется — триггеры не трогать.
- Выгрузка (`takeout`): сообщение несёт `reasoning` и `reasoning_sec` (это история пользователя).
- Журнал: только события с id, как сейчас; текста рассуждения — никогда (остановка по пределу — событием
  «ответ X — рассуждение сверх предела»). Сторожат тесты журналов чата.
- `chat.recover()` при старте: недописанный ответ с рассуждением помечается как прежде, `reasoning` остаётся.

«Думает…» и свёрнутое «Рассуждала N с».

## 6. Решения

Владелец: вариант A плашки; кнопка «как в подобных программах» по макету; «думает…» для петель; описание
разделов 3 и 4 (пересказ в чате 2026-10-22) — «ок».

Мои (владелец видел в пересказе): тексты плашки и YouTube отдельно от Exa; выключено по умолчанию; хранить
рассуждение, не отдавать модели; два режима показа; `REASONING_MAX`, `STRAY_MAX`; рассуждение без Markdown;
выгрузка с рассуждением, поиск без. После проверки спеки (владелец не видел в пересказе): кнопка только у
`local-*` srvllm через сервер — без OpenRouter (на проде его нет) и без пути через браузер; параметр
облачным ролям не уходит.

Исполнителю: вёрстка и стили в рамках макетов; троттлинг `think`; где именно держать функцию поддержки
(`chat.py` или новый модуль); имена констант и слов ошибок в духе `chat.py`.
