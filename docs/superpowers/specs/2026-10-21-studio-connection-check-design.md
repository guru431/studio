## 1. Зачем

Сейчас «Обновить модели» отвечает одним из двух: список или «нет связи с подключением». Что именно
не так — адрес не отвечает, ключ не принят, адрес убран из списка администратора, имя разрешается во
внутренний адрес, сервис не пускает браузер (CORS) — студия не различает, а отказ списка
разрешённых и вовсе называет «нет связи». Наличие модели в `/models` и галочка пользователя не
говорят, умеет ли она смотреть на фото, рисовать, принимать кисть и seed, делить речь по
собеседникам: внешние ветки проверялись на подменах, а о поддержке пользователь узнаёт по отказу
задания.

## 2. Критерий успеха

1. В «Настройках» раздела у карточки подключения — «Проверить». Через секунды под ней паспорт:
   «Адрес — отвечает, 45 мс», «Ключ — принят», «Модели — 14», возможности моделей раздела
   («lustify: генерация, правка, кисть, сила, seed — встроенный перечень srvllm»), «Проверено
   21.10 17:40».
2. Неверный токен — «Ключ — не принят (401): введите токен заново»; адрес не отвечает — «Адрес — не
   отвечает: …»; адрес убран из списка администратора — так и сказано, а не «нет связи».
3. Облачное подключение из браузера — та же проверка браузером; сбой сети и CORS неразличимы —
   «нет ответа: сервис недоступен или не разрешает запросы из браузера (CORS)».
4. Проверка ничего не генерирует и не тратит платный лимит. Пробный ответ модели чата — отдельной
   кнопкой «Пробный ответ» с предупреждением, по одной модели.
5. Паспорт сохраняется в подключении: вернулся в настройки — видно, когда и что проверено.
6. Ни история пользователя, ни его промпты при проверке никуда не уходят.

## 3. Не цели

- Проверка по расписанию, уведомления о «сломавшемся» подключении.
- Пробы, которые рисуют, озвучивают или распознают (картинка, ролик, речь) — их нет вовсе.
- Пробный ответ модели, смотрящей на фото (vision) — только текстовый.
- Автоматическое снятие галочек моделей, которых нет в списке (сейчас — пометка «не найдена»,
  так и остаётся).
- Проверка подключений другого пользователя из панели администратора (панель паспорт не
  показывает и «Проверить» не даёт).

## 4. Анти-цели

- Токен подключения через сервер ушёл в браузер (в паспорте, ответе проверки или журнале).
- Сервер сходил по адресу вне списка разрешённых (проверка — тем же `upstream`, со всеми его
  правилами: точное совпадение, публичность имени, без перенаправлений).
- Проверка что-то сгенерировала, освободила карту (`release`) или прочла общий список роликов шлюза
  (`GET /slot/videos` — чужие задания).
- Паспорт браузерной проверки подделал возможности «проверенными сервером» (источник — честный).

## 5. Пробы

**Через сервер** (`POST /api/connections/<id>/check`, только своё; не через сервер — 409 `direct`
«проверяет браузер»):

| Подключение | Запросы (все `GET`, таймаут `CHECK_TIMEOUT_SEC` 10 с) |
|---|---|
| srvllm | `{base}/v1/models` (ключ и модели чата LiteLLM), `{base}/slot/models` (модели картинок и ролика; slot-gate отвечает сам, карту не трогает) |
| openai | `models_url(conn)` |

Каждый запрос — отдельной строкой паспорта `routes: [{path, ms, status, reach, key}]` (у srvllm их
две: чат может отвечать, а `/slot/*` ключу закрыт — разделы показывают каждый свою строку: «Чат» —
`/v1/models`, «Фото» и «Видео» — `/slot/models`; у речи (`/speech/*`) проб без распознавания нет —
«не проверяется: проба занимала бы карту», возможности — только из перечня). Из каждого ответа:
- **Адрес** (`reach`): ответил (любой HTTP-ответ) — `ok` и время в мс; `httpx.ConnectError`/таймаут —
  «не отвечает: <класс ошибки словами>»; отказ `upstream` — его словами: «убран из списка
  администратора» и «имя разрешается во внутренний адрес» — разные (в `upstream.UpstreamRefused`
  появляется признак причины, `refused_words` говорит каждую своими словами); `ConnectionChanged` —
  «изменено — откройте заново».
- **Ключ** (`key`): 200 — `accepted`; 401 — `refused`; 403 — `limited` («ключ принят, маршрут
  закрыт»); иное — `unknown` с кодом. У openai-подключения 200 на `/models` ещё не доказывает ключ
  (у OpenRouter и многих своих серверов список открыт): тогда тот же `GET` без заголовка
  `Authorization` (у `upstream.request` — признак «без ключа»); ответил 200 и он — `key` =
  `unverified` («сервис отдаёт список без ключа — ключ проверит первый запрос или «Пробный ответ»»).
  У профиля OpenRouter ключ проверяет `GET {base}/key` (401 — `refused`, 200 — `accepted`; бесплатно,
  ничего не создаёт).
- **Модели**: список id из `data` (с `context_length`, если есть, и метаданными, раздел 6). У srvllm
  ответ `/slot/models` — id шлюза: в найденные модели раздела они идут после перевода в короткие
  имена перечня (`images.MODELS`, `videos.VIDEO_MODEL`), остальные — только в паспорт.

**Подключение, ушедшее из списка разрешённых.** `proxied` считается при чтении подключения, поэтому
подключение srvllm или с `server_only`, чей адрес администратор убрал, — не «прямое»: `/check`
отвечает паспортом «адрес убран из списка администратора» без запроса (а не 409 `direct`). Так же
`connections.fetch_models` («Обновить модели»): сейчас этот случай — 409 `direct` или «токен не
выдаётся», станет — эти слова. 409 `direct` «проверяет браузер» — только у настоящего прямого
(openai, не `server_only`).

**Из браузера** (прямое подключение): страница берёт токен (`GET /api/connections/<id>/token`,
как сейчас), сама делает `GET models_url` (и без ключа — как выше) и отправляет итог
`PUT /api/connections/<id>/passport` `{routes, models, probes?}`; сервер проверяет форму (пределы:
4 строки `routes`, 500 моделей, id ≤ 200 знаков, слова ≤ 300), ставит своё время и `source:
"browser"`; всё присланное страницей помечено «по словам браузера» (и пробный ответ тоже —
`probe` с `source: browser`), возможности сервер выводит сам (раздел 6). `TypeError` fetch — «нет
ответа: сервис недоступен или не разрешает запросы из браузера (CORS)».

**Пробный ответ** — `POST /api/connections/<id>/probe` `{model}` (через сервер) или браузером
(прямое; итог — в `PUT …/passport` полем `probes`): `chat/completions` с `messages: [{"role":
"user", "content": "Ответь одним словом: ok"}]`, `max_tokens: 16`, `stream: false`, таймаут
`PROBE_TIMEOUT_SEC` 60 с; ответ 400 со словом `max_tokens` (модели рассуждений OpenAI) — один повтор
с `max_completion_tokens: 16`. Любой 200 — «ответила за N мс» (пустой текст — тоже ответ); иначе —
слова отказа. В паспорт — `chat` этой модели с источником `probe`. Кнопка — только у моделей
раздела «Чат» **не-srvllm** подключений, под предупреждением «отправит одно короткое сообщение; у
платного сервиса это расход». У srvllm пробного ответа нет совсем: «ping» роли `local-gemma-abl`
занял бы карту арендой gemma-abl, и следующая картинка ждала бы её (ловушка CLAUDE.md), а release
проверка не делает.

## 6. Возможности и профили

Паспорт — по моделям, у каждой возможности — источник:
- `catalog` — встроенный перечень srvllm (`sections.CATALOG` и то, что студия знает о шлюзе):
  lustify — генерация, правка, кисть, сила, seed; flux — генерация, правка, кисть, seed; wan —
  ролик из картинки; whisperx — расшифровка с собеседниками, голосовой ввод; gigaam — голосовой
  ввод (только русский); qwen3-tts — озвучка своими образцами; «Описать» и «EN» — когда
  `/slot/models` ответил 200 (маршруты `/slot/*` ключу открыты). Модель картинок или ролика из
  перечня, чьего id шлюза (`images.MODELS`, `videos.VIDEO_MODEL`) нет в `/slot/models`, — «нет у
  шлюза»; модели речи по спискам не сверяются (их там нет) — только перечень.
- `metadata` — из ответа `/models`: OpenRouter-подобное `architecture.input_modalities` /
  `output_modalities` (`image` на входе — смотрит фото, на выходе — рисует), `context_length`.
- `name` — догадка по имени (помечается «по названию, не проверено»): `gpt-image-*`, `dall-e-*` —
  генерация и правка (без кисти, без seed); `whisper-*`, `*-transcribe*` — расшифровка без
  собеседников и голосовой ввод; `tts-*`, `*-tts*` — озвучка голосом по имени; `gpt-4o*`, `gpt-4.1*`,
  `gpt-5*`, `o3*`, `o4*`, `claude-*`, `gemini-*` — смотрит фото. Таблица шаблонов — одна, в
  `connections` (или новом модуле `capabilities.py`), с тестом на каждую строку.
- `probe` — пробный ответ прошёл.

Профиль подключения — строка паспорта: «шлюз srvllm», «OpenAI» (`api.openai.com`), «OpenRouter»
(`openrouter.ai`), иначе «OpenAI-совместимый» — плюс что из этого следует: у не-srvllm нет кисти,
силы, seed, «Описать», «EN», роликов и образцов голоса; расшифровка — без собеседников.

## 7. Данные

**Схема — следующий свободный шаг `db.STEPS`** (в работе — 10; соседние работы тоже берут
следующий свободный, окончательные номера — при слиянии в `main`, план: 10 расшифровки, 11 фото,
12 подключения):

    ALTER TABLE connections ADD COLUMN passport TEXT;

JSON: `{checked, source: "server"|"browser", profile, routes: [{path, ms, status, reach: {ok, words},
key: {state, code, words}}], models: [{id, context_length?, caps: [{name, source}]}], probes:
{<model>: {ok, ms, words, at, source}}}`. Смена адреса, вида или токена (`connections.patch`) паспорт
обнуляет. Ответ `GET /api/connections` и `sections` (`connection` в ссылке раздела) несёт
`passport` как есть — токена в нём нет; зеркала панели администратора
(`/api/admin/users/<id>/…`) его убирают.
Журнал — «connection <id>: проверка <итог одним словом>», без адреса, моделей и слов сервиса.

## 8. Страница

`settings.js`, карточка подключения в разделе: «Проверить» рядом с «Обновить модели»; под шапкой —
блок паспорта (свёрнут до одной строки «Проверено 21.10 17:40 · адрес отвечает · ключ принят»,
раскрывается): адрес, ключ, профиль, число моделей и возможности **моделей этого раздела** (у
каждой — слова возможностей и источник). Ошибки проверки — в блоке паспорта, а не в общей строке
раздела. В карточке раздела «Чат» у отмеченной модели — «Пробный ответ» (окно-предупреждение,
затем итог в паспорте). Проверка браузером — тот же вид; в панели администратора блока и кнопок нет.
Найденные проверкой модели заодно встают в список найденных (как после «Обновить модели»).

## 9. Тесты

- Быстрые (`test_connections.py`, FakeGateway): srvllm — оба запроса, паспорт с `catalog`-возможностями
  и пометкой «нет у шлюза»; 401 → `refused`; 403 → `limited`; `down` → «не отвечает»; адрес убран из
  списка → `refused_words`, запроса нет; имя во внутренний адрес → отказ до запроса; openai —
  `metadata` из `architecture`, `name`-догадки по таблице; `PUT …/passport` — форма, пределы,
  `source: browser`, время сервера; пробный ответ — тело (`ping`, `max_tokens: 1`), итог в паспорте,
  чужое подключение — 404; `patch` адреса/токена обнуляет паспорт; журнал без адреса и моделей;
  `fetch_models` различает отказ списка; FakeGateway получает `GET /slot/models`.
  `test_foundation.py` — шаг 12.
- Браузерные: «Проверить» у srvllm показывает паспорт; облако (FakeCloud) — проверка браузером,
  закрытый порт — слова про CORS; «Пробный ответ» с предупреждением.
- README — «Подключения и разделы»; CLAUDE.md — паспорт и пробы в «Устройство».

## 10. Решения проектировщика (не владельца) — проверить при чтении

1. Пробы — только чтение `models` (и `/slot/models` у шлюза); единственная тратящая проба — пробный
   ответ «ping» одной модели чата по отдельной кнопке.
2. Возможности — из перечня srvllm, метаданных `/models` и шаблонов имён, у каждой — источник;
   догадка по имени так и подписана.
3. Паспорт — в подключении (`connections.passport`), обнуляется сменой адреса, вида или токена.
4. Проверка браузерного подключения — браузером, итог сохраняет сервер с пометкой `browser`.
5. В панели администратора проверки нет.
