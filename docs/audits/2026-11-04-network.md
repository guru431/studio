Продолжение: обе найденные ошибки исправлены локально, результаты и ограничения — в [отчёте об исправлениях](2026-11-04-network-fixes.md). Ниже сохранён исходный аудит до изменений.

Проверена версия `230413a2a8461c4484956aecfa25ecf2169dac0a`. Воспроизведены две ошибки обычного чата при обрывах связи; обе внесены в [FINDINGS.md](../../FINDINGS.md). Код приложения не менялся, выкладка и запуск настоящих моделей не выполнялись.

## Стенд и методика

- Настоящий FastAPI/uvicorn, временная SQLite и медиа, штатная авторизация, API и фронтенд. Gateway подменён `FakeGateway`, мост — `FakeMachine` через настоящий WebSocket. В «Агентах» использованы синтетические сессии Codex; настоящие Claude/Codex/OpenCode не вызываются.
- Edge `156.0.4314.58`, Playwright/CDP, 393×852; обрыв отправки и оболочка без сети дополнительно проверены на 320 px. Синтетические истории — по 20 сообщений в двух проектах, вложение — PNG 49 353 байта.
- Профили: без ограничений; 1600/750 Кбит/с + 150 мс; 400/100 Кбит/с + 400 мс; 128/64 Кбит/с + 1500 мс. Скорости — десятичные Кбит/с, задержка — параметр CDP `latency`, добавленный к настоящему времени обмена.
- Для измерения приложения service worker отключён. Холодная загрузка — новый контекст с выключенным HTTP-кэшем; повторная — настоящая перезагрузка после заполнения кэша. Отдельная проверка оболочки использует настоящий service worker и полный offline.
- В таблицах по одному измерению сценария на профиль: это наблюдения, не медианы и не процентили. Счётчики `bytes_finished` включают только завершившиеся к моменту измерения запросы; время монтирования раздела не означает завершение всех фоновых запросов.

Во всех четырёх профилях отправка с вложением вызвала модель ровно один раз; оба сообщения и ответ сохранились после перезагрузки. Необработанных ошибок JavaScript не было. Фото, видео, озвучка, расшифровка, распознавание, перевод и настройки открылись без горизонтального переполнения на 393 px.

Первое открытие отдельных ещё не загруженных разделов на самом медленном профиле: фото — 20,52 с, видео — 4,38 с, озвучка — 3,38 с, расшифровка — 3,89 с, распознавание — 3,39 с, перевод — 6,95 с. Эти цифры включают скачивание ленивых модулей; вычисление моделей не измеряется.

У локального браузерного стенда статика передавалась без сжатия: около 582 КБ вместе с заголовками, 23 JS-ресурса к появлению проектов. На рабочем сайте CSS и JS отдаются с gzip, это отдельно проверено HTTP-запросами. Попытка добавить тестовый ASGI gzip не изменила ответы браузерного стенда, поэтому её результаты исключены. **51,91 с — результат локального стенда без сжатия, а не подтверждённая скорость рабочей авторизованной Studio.** Оптимизацию холодного запуска следует оценивать по авторизованному стенду с тем же HTTPS/Apache и сжатием.

## Проверки обрывов

1. **Отправка из «Агентов» при отсутствии сети.** Появилось «Нет связи с сервером», черновик восстановился, мост не получил ни одного задания. После возвращения сети и повторного нажатия задание выполнилось один раз за 1,08 с; поле очистилось.
2. **Потеря ответа принятого POST обычного чата — ошибка P2.** Обёртка `fetch` сначала выполняет настоящий запрос и получает его ответ, затем имитирует сетевой отказ. После отказа у сервера два сообщения и один вызов модели, в интерфейсе ноль сообщений и прежний черновик. Повторное нажатие вызывает модель второй раз. После перезагрузки видны четыре сообщения, включая два одинаковых вопроса. Повторено дважды с тем же результатом.
3. **Разрыв уже открытого потока обычного чата — ошибка P2.** После первого фрагмента `ReadableStream` принудительно завершается ошибкой и его сетевой reader отменяется; одновременно браузеру отключается сеть. Через 1,2 с модель продолжает ответ на сервере, ещё через 1,2 с сеть возвращается с профилем 400/100 Кбит/с и 400 мс. За следующие 25 с ответ автоматически не восстановился: остались первый фрагмент и «Нет связи с сервером». Перезагрузка вернула полный ответ, число вызовов модели осталось равным одному.
4. **Offline-перезагрузка PWA.** Показана оформленная страница «Нет связи»; переполнения на 320 px нет. После возвращения сети ссылка «Повторить» открыла приложение с действующей сессией.

Одного `Network.emulateNetworkConditions(offline=true)` оказалось недостаточно для проверки разрыва уже открытого SSE: в первом прогоне он продолжился без принудительного обрыва. Поэтому для вывода об SSE используются данные `network-faults.json`, где дополнительно разрывается reader. Значения `network.json::outage.stream_recovery` не доказывают восстановление после разрыва потока.

Причины по текущему коду: отказ `POST …/turns` в `chat.js::turn` откатывает оптимистичные сообщения и возвращает черновик без сверки принятой операции; `readServer` после разрыва запускает `reload`, но неудачный GET во время offline не получает повторения после возвращения сети.
