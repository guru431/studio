# Ускорение интерфейса Studio — реализация 2026-11-03

Внедрены все четыре функциональных этапа [исходного плана](2026-11-03-ui-performance.md).
Переключение сохранённой сессии больше не ждёт полный каталог, панель показывает готовые строки
по мере поступления, повторные чтения объединяются на мосте. Тяжёлая история обрабатывается
порциями, инструменты загружаются при открытии, весь граф модулей имеет версию.
В исходном замере ниже цель «ни одной задачи >50 мс при CPU ×4» не достигнута.
Продолжение с исправлением WebKit, Worker и контрольным замером — [разбор FINDINGS](2026-11-03-backlog-closure.md).

Исходная точка — `893ddc1fbed3807394c48aaf7da16f937dc2c309`. Числа, условия и SHA256 исходников —
в [данных замеров](2026-11-03-ui-performance-implementation.json). Первоначальный JSON сохранён.
Это проверки на изолированном стенде с синтетическими переписками и отдельные чтения метаданных
настоящих локальных проектов. Авторизованный интерфейс рабочего сайта и настоящий iPhone не измерены.

**Что изменилось**

| Этап | Реализация | Проверка |
|---|---|---|
| 1. Переключение и панель | Проверенный снимок посещённого чата появляется после быстрого PIN/access probe, пока каталог и состояние обновляются. Сводки публикуются отдельно; снимки панели переживают переходы | Медленный каталог не задерживает текст; отправка заблокирована до свежего состояния; медленный проект не удерживает остальные строки |
| 2. Повторные расчёты | Ограниченный RAM-кэш моста объединяет одинаковые запросы; каталог проектов 5 с, локальные сводки/списки сессий 20 с, GitHub 300 с. Видимые строки приоритетны; скрытая панель не запускает очередь | Повторный вход не пересчитывает все проекты; ручное обновление форсирует чтение; изменение/завершение задания инвалидирует проект |
| 3. Движки и история | Каталоги Claude/Codex/OpenCode читаются параллельно с отдельными бюджетами; квота Codex использует другой RPC. OpenCode сохраняет соединение каталога. История начинается с 30 сообщений и ограничена 512 КиБ; закрытые шаги раскрывают содержимое лениво | Квота не блокирует каталог; ошибка одного движка отмечает неполный результат; пагинация проходит 250 сообщений без пропусков; сохранены черновики и стрелки |
| 4. Фон и загрузка | Общий снимок activity; спокойный экран сверяет Git/сессии раз в 60 с, активный — раз в 20 с. Настройки разделяют один GET списка компьютеров. Чат/файлы/Git/сведения/рабочий стол импортируются по необходимости. Версионированные ESM без сборщика | Скрытая вкладка не опрашивается; события и lock/alive сохранены; API-модуль имеет один экземпляр; тёплый граф модулей не обращается к сети |

Нормализованная история Claude/Codex кэшируется только в памяти компьютера: до 12 записей и
8 МиБ сериализованного размера, с проверкой ревизии источника до/после чтения. Изменившийся во время
чтения источник в индекс не попадает. У браузера отдельный ограниченный RAM-кэш истории, ключ
включает пользователя, компьютер, проект, движок и чат. Блокировка/отзыв доступа очищают снимки.
Переписки не добавлены в БД Studio, localStorage, IndexedDB или service worker.

Сводка локального Git доступна независимо от сетевой проверки GitHub. У GitHub собственное время
проверки и признак ожидания: старое значение не выдаётся за свежую проверку. Принудительное чтение
дожидается начатой новой проверки, даже если предыдущая ещё находится в кэше.

Markdown строится общей очередью с бюджетом кадра и отменой устаревших работ. Большой текущий
поток временно показывается безопасным текстом; после завершения создаётся санитизированная разметка.
Сохранены DOMPurify, копирование кода, ссылки, HTML-таблицы OCR и ограниченная подсветка.
Разбор одного большого токена и раскладка DOM не прерываются внутри браузерной операции.

Версия статики фиксирует байты всех файлов в памяти процесса при запуске. Основной HTML и importmap используют
тот же префикс `/static/v/<hash>/`; атомарная замена каталога при выкладке не меняет старый снимок.
Офлайн-страница сохраняет точные адреса из `sw.js::SHELL`, чтобы её стили, тема и иконки
были доступны без сети. Браузерная проверка выявила рассогласование новых адресов и прошла после исправления.
CSP разрешает хеш только этой доверенной importmap. Обычные `/static/*` продолжают сверяться через сеть;
ошибки версии получают `no-store`. Персональные API не получают immutable-кэширование.

Холодная панель из 60 проектов: названия 92,9 мс, первый счётчик 266,8 мс,
видимая очередь 767,7 мс; запросов сводок 13 вместо 60. Подсчёт видимых строк зависит от размера
экрана. Для сортировки по числовым счётчикам или полного ручного обновления читаются все проекты.
Один медленный ответ не задерживает публикацию уже готовой строки.

Первый неизвестный чат по-прежнему требует каталога движка: на стенде с искусственными 2200 мс
текст появился за 2466,5 мс. При возврате сохранённый текст виден за 50,3 мс, но готовность отправки
заняла 2849,5 мс: свежие проверки движка/прав намеренно остаются обязательными. Настоящие повторные
чтения нового моста ускоряются его TTL-кэшем, который этот искусственный сценарий не моделирует.

HTTP-замер выполнен локально по HTTP/1.1 без gzip. Боевой сайт уже использует HTTP/2 и gzip;
эти числа нельзя выдавать за его авторизованный старт. В новом документе с задержкой 80 мс
видимые счётчики появились за 702,6 мс вместо 2841 мс всех прежних счётчиков: объём работы сокращён.

Тяжёлый Markdown на CPU ×4: 42 688 знаков обработаны за 1955 мс, 85 376 — за 5160 мс,
распределённых между кадрами. Раньше один синхронный вызов занимал соответственно 1,5 и 5,9–6,2 с.
В последнем замере задачи тяжёлого Markdown достигали 69 мс, истории — 122 мс. Отдельная трассировка
подтвердила Layout до 86 мс. После этого замера был заведён P3; дальнейшее исправление и повторный
контрольный замер приведены в [разборе FINDINGS](2026-11-03-backlog-closure.md).

**Выкладка и границы**

Пакет моста имеет версию **0.13.0**. Серверная и браузерная части работают после выкладки и обновления
страницы; кэширование на компьютере и отдельный канал квоты включатся после штатного обновления моста.
Активный мост, исполняющий эту работу, принудительно не останавливается. Для его обновления после
завершения задания используется штатная кнопка ↻ и выход из трея по правилам обновлятора.

Живой вход владельца не выполняется: действующая браузерная сессия недоступна, а пароль администратора
в vault ранее подтверждён как устаревший. Приёмка боевой выкладки проверяет HTTPS/Unix health,
службы, Apache и совпадение опубликованных файлов/пакета с коммитом, без изменения учёток и переписок.
