# Studio: исправления связи и ускорение загрузки, 2026-11-04

Обе ошибки из [первого аудита](2026-11-04-network.md) исправлены. Отчёт фиксирует локальный этап перед публикацией и выкладкой: рабочее дерево поверх `230413a2a8461c4484956aecfa25ecf2169dac0a`. Схема базы повышена с 30 до 31, работающий мост не менялся.

## Потеря ответа на отправку

Каждая попытка отправки получает случайный `request_id`. Пока исход операции неизвестен, повтор того же сообщения использует тот же ключ. Сервер сохраняет подтверждение вместе с сообщениями в одной транзакции SQLite. Повтор возвращает идентификаторы уже принятой операции, не создаёт новые сообщения и не обращается к модели.

Подтверждение привязано к своему диалогу и отпечатку текста/вложений. Тот же текст с новым ключом остаётся новой намеренной отправкой. После регенерации старый ключ не создаёт ещё один ответ; после удаления диалога удаляются и подтверждения. Сведения другой учётки недоступны. Потреблённый билет Cleaner повторно не применяется, действующая очередь SSE не получает второго читателя.

После неоднозначного сетевого исхода клиент безопасным GET проверяет подтверждение и перечитывает историю. Отправленное убирается из поля только после подтверждения; новый набранный текст сохраняется. Для браузерных подключений повтор принятой операции также не запускает внешнюю модель автоматически: неизвестный исход нельзя превращать в ещё один запрос.

Контрольное воспроизведение потери ответа:

| Проверка | До | После |
| --- | ---: | ---: |
| Вызовов модели после повторного нажатия | 2 | 1 |
| Сообщений после перезагрузки | 4 | 2 |
| Одинаковых вопросов | 2 | 1 |

## Разрыв потока

При обрыве SSE повторяется только чтение состояния, с увеличением пауз и ограниченным числом попыток. Чтение объединяется, ограничено сроком 15 с и отменяется при смене диалога/уничтожении представления. Возвращение сети и видимой вкладки возобновляет сверку. Просроченный ответ не меняет другой диалог и его черновик. Ошибка первого чтения истории также больше не оставляет страницу без возможности автоматического восстановления.

Принудительный разрыв reader вместе с offline воспроизведён тем же измерителем, что до исправления. Раньше через 25 с после возвращения сети оставался первый фрагмент; теперь полный ответ появился автоматически за **0,48 с**, при одном вызове модели. Это время после восстановления канала 400/100 Кбит/с с задержкой 400 мс, без времени вычисления настоящей модели.

## Загрузка на медленном канале

1. Граф статических зависимостей вычисляется при старте службы. Оболочка заранее скачивает необходимые модули параллельно через `modulepreload`, при первом открытии и при переходах между разделами. Динамические инструменты и остальные разделы целиком не подгружаются заранее. Подсказка скачивает публичную статику; исполнение раздела и чтение API остаются за штатной проверкой доступа.
2. marked, DOMPurify и highlight.js загружаются при первом импорте Markdown, а не при каждом холодном открытии «Агентов», фото и других экранов без Markdown. Это убирает около **208 КБ** из начальной загрузки «Агентов»: 23 → 20 JS-ресурсов, примерно 583 → 376 КБ статических ответов вместе с заголовками. Санитизация обязательна; без загрузки библиотек небезопасная разметка не показывается. Срок их загрузки — 30 с.

Итоговое контрольное сравнение: исходные `app/` и `tests/` из HEAD развернуты во временном каталоге; обе версии запущены одним и тем же измерителем. Перед каждым профилем очищается только сохранённое рабочее место временной учётки, чтобы предыдущий сценарий не восстанавливал чат в фоне. Канал 128/64 Кбит/с, задержка 1500 мс, секунды до появления проектов:

| Метрика | Исходная версия | Исправленная версия |
| --- | ---: | ---: |
| Холодное открытие | 51,92 с | 37,29 с |
| Статические ответы вместе с заголовками | 582 234 байта | 375 989 байт |
| JS-ресурсы к появлению проектов | 23 | 20 |

Время уменьшилось примерно на **28%**, объём начальной статики — на **35%**. Это единичное парное сравнение, не статистическая гарантия. Предварительные повторы без восстановления рабочего места давали около 37,1 с. В финальной полной последовательности профиль 400/100 Кбит/с дал 11,37 с; 128/64 Кбит/с с восстановлением чата предыдущего сценария — 46,31 с. Последнюю цифру нельзя сравнивать с пустым рабочим местом: там дополнительно загружается чат. Измеритель исправлен, чтобы следующие сравнения явно отделяли эти условия.

Возврат к уже посещённому чату другого проекта остался около 0,21 / 0,53 / 1,68–1,78 с для трёх профилей; ускорение тёплой перезагрузки не заявляется (около 7–9 с на самом медленном канале). Первый переход в фото в полной последовательности: 20,52 → 18,02 с; перевод: 6,95 → 5,38 с. Зависимости выбранного раздела теперь начинают скачиваться вместе, но сам объём файлов и задержка API остаются существенными.

Перенос библиотек имеет цену: первое открытие текста, если Markdown ещё не скачан, ждёт эти файлы. Браузерная проверка подтверждает их загрузку ровно один раз и повторное использование при возвратах. Прямые ссылки на чат получают раннюю подсказку для его модулей и библиотек. При последующих переходах зависимости выбранного раздела тоже скачиваются параллельно.

Во всех трёх полных профилях отправка PNG 49 353 байта вызвала модель ровно один раз; сообщения сохранились после reload, ошибок JavaScript и горизонтального переполнения на 393 px не было. Страница offline и повторное открытие с действующей сессией также работают на 320 px.

## Проверки

- Основной быстрый набор: **1482 passed, 30,12 с**, ни один тест не превысил 1 с.
- Быстрый набор моста: **617 passed, 1 skipped**, ошибок нет, примерно 15 с; код моста не менялся.
- Серверные проверки чата/доставки/миграций: **94 passed**. Есть регрессии повторной отправки, второго читателя активного потока, уже использованного вложения, области учётки, намеренного повторения текста, удалённого ответа и миграции 30 → 31 с сохранением истории.
- Браузерная серия доставки и производительности: **13 passed**; дополнительные проверки WebKit и отложенных библиотек — **6 passed**; обычные сценарии чата/фото/видео/PIN — **11 passed**. Финальный прогон основных затронутых сценариев, включая Worker, WebKit и поздний ответ другого чата: **16 passed**. Это пересекающиеся серии, не сумма уникальных тестов.
- `code-selfcheck`: сверены 60 паттернов Python/JavaScript; проверены атомарность подтверждения, привязка к содержимому, закрытие ожиданий и защита от просроченного состояния. Добавлен предел ожидания библиотек. Проверки синтаксиса JS и `git diff --check` прошли.

Синтетические gateway и мост, временная база, настоящий браузер и HTTP-приложение. Настоящие модели и персональные переписки не использовались. Статика локального HTTP-стенда передаётся без gzip, поэтому эти числа **не являются замером авторизованной рабочей Studio за Apache**. Новая производственная проверка требует отдельной выкладки и живой сессии.
